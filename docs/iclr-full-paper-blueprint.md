# ICLR 全文写作蓝图：250 篇顶级论文的上取整统计范式

本蓝图把 250 篇 ICLR/ICML 2026 Outstanding、Oral、Spotlight 论文的独立深读结果转换成一套可直接执行的 ICLR 全文方案。样本包含 ICLR 150 篇和 ICML 100 篇；正文比例采用会议等权值，篇幅、对象数量和覆盖率全部向上取整。逐篇证据见[深读索引](../reports/reading_index.md)，原始统计见[250 篇统计报告](../reports/statistical_analysis_250.md)，整数预算见 [`iclr_full_paper_blueprint.csv`](../reports/tables/iclr_full_paper_blueprint.csv)。

## 1. 先锁定全文的论证链

全文围绕同一条链展开：

```text
研究对象 → 关键缺口 → 核心洞见 → 方法组件 → 形式化对象
→ 可观测预测 → 实验 → 结果 → 消融 → 结论 → 附录证据
```

250 篇共编码 1,972 条主张。向上取整后，92% 的论文至少有一条完整闭合主张，31% 形成十节点完整链。高频闭环边为：

| 接口 | 覆盖率（向上取整） | 写作动作 |
|---|---:|---|
| 对象 → 缺口 | 95% | 用一个具体失败、成本或能力空白建立问题 |
| 缺口 → 核心洞见 | 94% | 说明旧方案缺少哪个结构、变量或机制 |
| 洞见 → 方法组件 | 71% | 把洞见拆成可命名、可干预的组件 |
| 组件 → 公式/理论对象 | 69% | 为组件给出定义、目标、约束或保证 |
| 公式 → 可观测预测 | 43% | 写出该机制应改变的可测量现象 |
| 预测 → 实验 | 45% | 用实验协议直接检验预测 |
| 实验 → 结果 | 99% | 每个实验入口立即回答对应问题 |
| 结果 → 消融 | 85% | 删除组件、替换机制或改变条件 |
| 消融 → 结论 | 82% | 回收到组件职责、适用范围和代价 |

起稿前建立 claim map。每一行对应一项贡献，标题、方法小节、结果小节和结论沿用同一编号与术语。

### 大样本决策规则

250 篇中，摘要的对象、方法、核心洞见、问题缺口和影响均达到 95%–100%；正文的 `method > results > introduction` 排序在论文等权与会议等权下保持一致。匹配的两批 ICLR Oral 中，对象、缺口、核心洞见、方法、定性结果和影响骨架保持在 94%–100%。这些高覆盖结构构成全文主干。

按覆盖率安排优先级：

- **90%–100%：主干。** 每篇论文都给出明确位置。
- **70%–89%：默认模块。** 按论文主张配置。
- **40%–69%：条件模块。** 由理论、算法、数据或评测类型触发。
- **1%–39%：专项工具。** 在相应研究设计中使用。

完整摘要顺序共有 242 种，最常见顺序占 2%。因此固定的是功能与接口，句式和段落数量服务于具体主张。

推荐的 10 页推进节奏：

```text
p1      标题、摘要、引言开头
p1–2    引言、贡献列表、总览图
p2–3    相关工作、问题定义、符号

p6      实验协议
p6–9    主结果、机制、鲁棒性、成本、失败
```

理论型论文把结果与消融中的一部分版面转给 theorem、proof sketch、复杂度和 diagnostic example；系统型论文把理论槽位转给架构、资源、延迟、故障和部署实验。章节接口和 claim map 保持同一顺序。

| 相关工作 | 1/1/0/1 | 0/0/0/0 | 文字建立坐标系 |
| 方法 | 2/1/1/6 | 2/0/1/6 | 接口图、机制图、执行顺序、对象变换 |
| 理论 | 1/1/1/6 | 0/0/0/6 | 定义、假设、命题和保证 |
| 实验设计 | 1/1/1/1 | 0/1/0/0 | 一张协议表锁定设计 |
| 结果 | 3/3/0/1 | 2/2/0/1 | 趋势、分布、精确比较和资源结果 |
| 消融 | 2/1/0/1 | 2/1/0/0 | 组件干预、替代解释和异质性 |
| 结论 | 0/0/0/0 | 0/0/0/0 | 回收已有证据 |
| Limitations | 1/1/0/1 | 0/0/0/0 | 用正文结果指针表达边界 |
| 附录 | 7/6/1/20 | 7/6/1/20 | 全量证据、推导、配置与扩展 |

正文推荐总量为 **7 图、4 表、1 算法、13 个展示公式**。每个对象承担一个明确问题。

- **图**回答结构、趋势、分布、机制或失败在哪里。
- **表**回答精确数值、横向比较、预算与协议是什么。
- **算法**回答状态如何初始化、更新、分支、停止和输出。
- **公式**回答对象如何定义、变换、优化、约束或获得保证。

连续复用同一套名字：

```text
Figure：输入 → 中间对象 → 输出
Equation：定义中间对象和变换
Algorithm：执行同一变换
Experiment：测量该变换带来的预测
Ablation：移除该变换并观察预测变化
Conclusion：回收该组件的证据结论
```

## 4. 标题

标题同时提供三个信息：研究对象、核心机制、目标能力或结果。常用结构如下。

```text
[Mechanism] for [Task or Object]
[Capability] through [Core Idea]
[Finding]: [Method or Consequence]
```

标题中的核心名词进入摘要核心洞见、方法组件标题、主结果标题和结论。新缩写服务于反复出现的核心对象；一次性概念直接写全称。

## 5. 摘要：194 词、8–9 句

250 篇摘要平均值向上取整为 189 词、8 句；ICLR 子集为 194 词、9 句。摘要功能覆盖率为：

| 功能 | 覆盖率 | 句子任务 |
|---|---:|---|
| 研究对象与范围 | 100% | 定义任务、对象和评价语境 |
| 问题与缺口 | 95% | 指出现有方案的具体失败 |
| 核心洞见 | 98% | 给出一句可复述的新判断 |
| 方法 | 98% | 说明如何把洞见变成方法 |
| 实验或理论设置 | 76% | 交代任务、数据、模型、基线或假设 |
| 定性结果 | 92% | 给出结果方向和跨设置趋势 |
| 定量结果 | 56% | 给出改变判断的数字与比较对象 |
| 理论 | 48% | 给出定理、复杂度、保证或识别结论 |
| 局限 | 30% | 写一个主导适用范围的边界 |
| 影响 | 95% | 回收到能力、理论或实践价值 |

### 9 句模板

1. **Object。** `We study [object] under [scope/setting].`
2. **Gap。** 现有方法在具体条件下发生什么失败，失败由什么结构造成。
3. **Insight。** `Our key insight is that [mechanism].`
4. **Method。** 引入方法名，并说明最关键组件如何实现洞见。
5. **Formal/setup。** 给出保证、复杂度、数据、任务、模型或基线。
6. **Qualitative result。** 概括跨任务、模型或条件的稳定方向。
7. **Quantitative result。** 写比较对象、分母、指标方向和一个决定性数字。
8. **Boundary。** 写主要代价、适用条件或失败范围。
9. **Impact。** 说明这组证据改变了什么研究或实践判断。

最高频相邻推进为：`gap → core idea` 84%、`object → gap` 77%、`core idea → method` 74%、`method → qualitative result` 65%、`qualitative result → impact` 56%、`method → setup` 51%、`method → quantitative result` 37%。

### 摘要数字写法

数字句包含四个元素：

```text
比较对象 + 评价量 + 分母/范围 + 方向与幅度
```

例如：

```text
Across [N tasks/models], METHOD improves METRIC by X over BASELINE
under the same BUDGET, while reducing COST by Y.
```

结果类型的向上取整比例为：定量与定性同时出现 50%，仅定性 43%，仅定量 7%，两者均无 2%。摘要优先保留一项决定性数值，完整矩阵进入正文和附录。

## 6. 引言：15%，约 870 词

引言完成八个动作。覆盖率向上取整为：context 68%、contribution list 60%、prior failure 52%、problem 50%、core idea 45%、missing insight 42%、result preview 40%、method preview 39%。

### 5 段结构

**第 1 段：对象与重要性。** 定义研究对象、任务和读者关心的决策。结尾给出一个具体障碍。

**第 2 段：旧方法为何失效。** 选择最接近本文的方案，解释其失败机制、假设、数据访问、预算或评价空缺。段尾产生 missing insight。

**第 3 段：核心洞见。** 用一个可复述判断连接缺口与方法。先写机制，再写方法名。

**第 4 段：方法与证据预告。** 用总览图说明输入、组件、输出和训练/推理流；随后预告一项主结果、一项机制证据和一项成本或边界。

**第 5 段：贡献列表。** 2–4 条贡献沿全文顺序排列。每条采用以下结构。

```text
对象/问题 + 新方法或理论对象 + 决定性结果入口
```

### 段落推进公式

```text
上一段留下的问题
→ 本段提出的判断或对象
→ 支撑判断的例子、公式、图或证据
→ 下一段必须回答的问题
```

贡献列表是全文目录。方法小节、结果小节、结论按贡献顺序排列；术语、编号和动词保持一致。

### 引言保留与压缩

保留对象、失败机制、missing insight、核心方法、证据预告、贡献索引和范围。压缩教科书背景、远邻文献史、摘要复述、没有结果入口的贡献句和泛化式动机。

## 7. 相关工作：9%，约 522 词

样本均值向上取整为 550 词，中位数为 507 词；ICLR 均值为 518 词。首个 Related Work 证据位于正文 p1–2 的论文占 44%，p3–5 占 26%，p6+ 占 24%，正文之后占 8%。ICLR 的常见位置是引言后或方法前。

### 每个文献簇完成四步

```text
分类轴 → 最近邻工作 → 明确比较维度 → 本文改变的维度
```

语义覆盖率向上取整为：taxonomy 96%、nearest-neighbor contrast 96%、gap creation 80%、credit/foundation 75%、limitation of prior 68%、positioning 29%、chronology 27%。

### 段落模板

1. **分类轴。** 按 objective、assumption、scope、oracle、data access、computational cost 或 evaluation target 组织工作。
2. **继承。** 说明本文直接采用哪些定义、数据、算法或理论工具。
3. **最近邻。** 选择真正共享研究对象与目标的工作，逐一给出比较维度。
4. **缺口。** 说明哪个差异直接触发本文的一个方法组件。

段尾写成方法入口：

```text
These methods assume/use/optimize X, whereas our setting requires Y.
Section N introduces COMPONENT to realize Y.
```

完整 taxonomy、历史脉络和远邻工作进入附录；正文保留分类轴、最近邻、继承关系和方法缺口。

## 8. 问题定义与预备知识

这一部分承接 Related Work，建立方法与理论共用的对象。

### 写作顺序

1. 定义输入、输出、任务单位和评价单位。
2. 定义数据生成过程、可访问变量和观测范围外变量。
3. 写目标函数、约束、资源预算和成功条件。
4. 给出基线或现有方法的形式化表达。
5. 用一个命题、反例或最小例子定位缺口。
6. 结束于方法设计目标：组件必须改变哪个对象或性质。

符号表集中呈现高频符号，正文首次出现时仍给出语义。后续图、公式、算法和实验协议复用同名对象。

## 9. 方法：24%，约 1,392 词

方法动作覆盖率向上取整为：定义组件 73%、符号设置 70%、问题陈述 69%、实例化算法 67%、推导 66%、机制解释 52%、连接预测 46%、连接实验 44%、对比替代方案 36%、复杂度 22%、总结 19%、直觉 17%。

### 章节结构

**9.1 Overview。** 用 Figure 1 或 Figure 2 说明输入、组件、信息流、训练/推理边界与输出。图中出现的节点都在后续小节得到定义。

**9.2 Core objects。** 给出符号、状态、表示、目标或估计量。先定义语义，再给公式。

**9.3 Components。** 每个核心组件使用相同五步：

```text
定义组件 → 给出公式/操作 → 解释机制
→ 导出可观测预测 → 指向对应实验
```

**9.4 Composition or algorithm。** 说明组件如何组合、执行顺序、训练与推理差异、复杂度和输出。

**9.5 Summary and predictions。** 用短表或编号列表将组件映射到预测、实验和结果位置。

### 单个方法小节模板

1. **问题。** 上一组件留下什么对象或失败。
2. **定义。** 新组件的输入、输出、参数和状态。
3. **公式。** 目标函数、更新、约束或变换。
4. **机制。** 公式中的哪一项产生预期行为。
5. **替代。** 与最近邻设计的关键差异。
6. **预测。** 删除或改变该组件后，哪个指标、切片或现象应变化。
7. **实验指针。** `Section X tests this prediction by ...`

高频转移是 `state problem → define component` 38%、`notation → state problem` 35%、`define → derive` 28%、`define → mechanism` 28%、`state problem → derive` 28%、`define → algorithm` 23%。

### 方法图

两张方法图分别承担：

- **总览图：** 系统边界、输入输出、数据流、训练/推理阶段。
- **机制图：** 核心组件内部对象、干预点和预期可观测量。

图注写四项：图在回答的问题、节点语义、箭头操作、读者应得到的结论。图注中的组件名与小节标题、公式变量和算法步骤完全一致。

## 10. 理论：11%，约 638 词，6 个正文公式

理论模块出现在 68% 的论文中。向上取整后，86% 有编号公式，36% 有 theorem，40% 有 proof，25% 有 lemma，23% 有 proposition。理论对象的角色覆盖率为：core chain 90%、explanation 73%、diagnostic 50%、guarantee 46%。

### 理论正文的五层结构

1. **Assumptions。** 写清对象、随机性、数据访问、正则性和资源条件。
2. **Statement。** 定理或命题给出输入条件、结论、速率/界和依赖量。
3. **Interpretation。** 用自然语言说明哪一项由方法组件引起。
4. **Observable consequence。** 导出实验可观测的单调性、相变、失败条件或复杂度趋势。
5. **Evidence link。** 指向验证该推论的图、表、消融或诊断实验。

### 6 个公式槽位

1. 问题目标或风险。
2. 核心对象定义。
3. 方法变换或更新。
4. 分解、界或不变量。
5. 主定理/命题的结论。
6. 可观测预测或复杂度。

正文保留 theorem statement、假设、结论、proof idea 与实验对应；92% 的证明对象位于附录，完整引理链、技术条件和推导在那里展开。

### 理论段落模板

```text
Under ASSUMPTIONS, THEOREM states GUARANTEE.
TERM A is controlled by COMPONENT; TERM B captures CONDITION.
This predicts OBSERVABLE when VARIABLE changes.
Figure/Table X tests the prediction, and Appendix Y gives the proof.
```

经验型论文将 6 个理论槽位用于问题定义、目标函数、组件变换、机制分解、复杂度和诊断预测；理论型论文继续扩展定理族并把证明主体放入附录。

### 每个结果小节的 7 句结构

1. 重述 RQ 或预测。
2. 指向图表并给出主决策量。

## 13. 消融：6%，约 348 词，2 图、1 表

消融模块出现在 84% 的论文中，并拥有最高的图表密度。消融按替代解释组织：

```text
核心组件是否必要？
→ 哪个内部机制产生增益？
→ 超参数或规模改变后机制如何变化？
→ 另一个设计能否产生同样结果？
→ 哪些任务、模型或数据切片出现反向现象？
```

### 三类核心消融

1. **Component removal/replacement。** 删除或替换方法组件，测量主预测的变化。
2. **Mechanism intervention。** 直接干预中间对象，观察下游因果链是否按理论方向变化。
3. **Sensitivity/heterogeneity。** 改变规模、预算、噪声、数据、模型或任务，定位稳定区和失败区。

一张表承载精确的组件组合，一张图展示机制响应，一张图展示异质性或边界。结果段写“发生了什么”，消融段写“哪个组件负责、为什么、何时改变”。

## 14. Discussion、结论与 Limitations

### Discussion

Discussion 连接结果与更高层判断，按三段组织：

1. **Mechanism。** 哪项证据支持核心洞见。
2. **Boundary。** 哪些条件、数据、指标、预算或任务决定适用范围。
3. **Implication。** 对理论、方法、评测或部署流程产生什么改变。

Discussion 引用现有图表和附录对象，新的数据结果回到 Results。

### Conclusion：3%，约 174 词

结论按贡献顺序回收：

```text
问题与洞见 → 方法对象 → 决定性结果
→ 机制/理论结论 → 适用范围 → 下一步影响
```

每项贡献用一句话闭合，句子同时包含对象和证据结论。最后一句写未来研究或实践应改变的动作。

### 高频故事结构

```text
先建立重要对象和失败
→ 把缺口压缩为一个核心洞见
→ 给洞见一个可记忆的方法对象
→ 用主结果建立能力
→ 用消融与理论解释机制
→ 在读者已经掌握主线后写边界、成本和失败
→ 附录展开完整分布与核查材料
```

### 五个包装节点

1. **分母。** 正文同时给总体分母、筛选规则和成功后分母。
2. **聚合。** aggregate 旁边给关键任务、模型或群体异质性入口。
3. **案例。** 代表案例写选择规则，并链接完整案例集。
4. **指标。** proxy 说明目标对象、代理关系和已知偏离。
5. **位置。** 主结果附近保留一个改变适用范围的失败或成本；完整证据进入附录。

### 删除与迁移清单

从正文删除或迁移：

- 与 claim map 无关的背景综述；
- 重复摘要的贡献句；
- 没有比较维度的引用列表；
- 没有角色解释的公式堆叠；
- 与正文符号分离的伪代码；
- 缺少分母的百分比；
- 缺少定义的 `±`、阴影和 error bar；
- 用 aggregate 覆盖关键反向任务的表格；
- 用精选案例替代总体频率；
- 在结论首次出现的新主张、新数字或新实验；
- 与主结论无关的完整网格、命令、日志和配置。

正文保留：核心主张、关键对象、决定性比较、机制消融、失败/成本摘要和精确附录指针。

## 20. 最优写作顺序

1. **写 claim map。** 为每项贡献固定对象、方法、预测、实验、结果、消融和结论。
2. **写实验协议表。** 在跑实验前确定评价量、分母、比较器、重复单位、预算、控制与停止规则。
3. **设计 7 图、4 表、1 算法、13 公式的正文槽位。** 每个对象绑定一个问题和一条主张。
4. **先完成主结果与消融。** 用现有证据确定真正可写的主线。
5. **写方法与理论。** 每个组件导出可观测预测，并连接实验。
6. **写引言与相关工作。** 缺口精确导向已验证的方法组件。
7. **写 Discussion、Conclusion 与 Limitations。** 按贡献顺序回收，加入边界和成本。
8. **写摘要。** 用 8–9 句压缩全文功能链。
9. **搭建附录。** 按正文调用顺序填入证明、配置、全结果、追加消融、鲁棒性和失败。
10. **执行闭环编辑。** 删除无 claim 归属的段落和对象，补齐断开的接口。
