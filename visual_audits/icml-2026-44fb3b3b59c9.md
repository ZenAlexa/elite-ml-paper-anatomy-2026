## 5. 最终判断

### 最可复用模式

1. 共享列头的 paired trajectory table：用 state、queue、counter、inter-arrival/total delay 和 End 行在一页内把机制的时间语义固定下来。
2. 直接标注的 transition graph：用实线 action、点线 observation、灰色 intermediate state 和局部概率标签把“可行动/可观测”边界放进图中。
3. known/unknown decomposition：将可直接更新的 queue shift 与只依赖最小 state-action 的未知 kernel 上下对齐，并用颜色、虚线框、箭头和标签冗余编码。
4. tree + state-machine hard-instance schematic：上层选择结构、下层 CodeMDP、success/fail absorbing states 和 reward 条件形成证明导航图。

### 最高价值对象

- **Figure 1**：把正文的 delayed-observation policy state 变成可追踪的 augmented transition，是算法理解的首要接口。
- **Table 1 + Table 2**：同一六列表头下对照 constant delay 与 `\Delta=-1` 的 multi-reveal，符号和边界条件最可复核。
- **Figure 2**：用很小的图解释 Theorem 5/Algorithm 3 所需的 partially-known dynamics factorization，是从具体模型到抽象保证的桥。
- **Figure 3**：唯一的附录页宽构造图，将 Theorem 3 的 tree/CodeMDP 结构、blind action sequence 和 success/fail outcomes 组织成一张证明地图。

### 失败模式

1. 全文只有理论/机制视觉对象，没有经验性能、成本、失败率或组件 ablation 的图表；视觉系统不能独立证明算法相对 baseline 的效果。
2. Figure 1/2 的数学下标约 4.67–6.67 pt，Figure 3 的省略号隐藏了参数规模和中间状态，缩小或打印时需要回看正文。
3. Figure 2/3 的 pastel fill 没有全部在 caption 中定义，灰度安全依赖文字和拓扑冗余，跨图也没有统一颜色词典。
4. Table 2 把列定义委托给 Table 1；两个 h=6 行、括号 `(-1)` 和横线在低分辨率下可能造成误读。
5. 公开实现仓库没有绘图/表格/LaTeX 源，无法从 `source_exact` 层复核图内字号、颜色和线宽；当前精确性来自 PDF 对象或渲染估计。

**一句话视觉策略**：以共享六列轨迹表建立延迟语义，以无坐标的状态转移图和已知/未知分解图解释算法结构，再以树—CodeMDP 页宽示意图承接匹配下界；全篇优先使用矢量、直接标注、细黑线和局部语义色，而非统计图表。
