## 跨对象系统判断

- **视觉叙事**：Figure 1 先给出“姿态抽取—跨 pair 渲染”的机制接口，Table 1 把它作为 headline transfer test，Table 2 分离 latent pose probe，Table 3 进行结构反事实；附录再以 Table 4/5 区分 interpolation 与 transfer-like inference、Table 6/7 测试 objective 替换和 corruption、Figure 2/Table 8/9 检查 oracle validity、Figure 3 展示 supervised reconstruction failure。方法→证据→消融→测量边界的顺序清楚。
- **Caption 系统**：所有 caption 使用“对象标题 + setup/comparison”，主表和附录表均在 caption 中给出指标/条件；Table 8、Figure 2、Figure 3、Table 9 直接写出主要发现，Table 1–7 多数把解释留给正文。标题短语和对象标签普遍粗体，附录 Table 4 的 caption 过短是唯一明显信息缺口。
- **表头系统**：方法/模型作为顶层组，RE10K、DL3DV、MVImgNet、CO3Dv2 作为第二层 dataset；metric 与阈值合并到首列，↑/↓ 直接出现在 metric。该系统在 Tables 1–8 高度一致，Table 9 只缩减 metric 行而保留同一 dataset 轴。
- **方法—结果—消融链**：Figure 1 的 POSEENC/RENDER 与 transferability objective 在 Table 1 主比较中兑现；Table 2 说明 representation probe 不是 transferability 的充分条件；Table 3、6、7 对 objective、latent bottleneck、multi-view 和 temporal corruption 做干预，支持而不是替代主结果。
- **正文—附录链**：正文 Tables 1–3 负责 transfer、probe 和设计消融；附录 Tables 4–7 补充 reconstruction、inference augmentation、objective 对照和 corruption；附录 Figure 2/Table 8/Table 9 说明 TPS oracle 的 robustness/rejection，Figure 3 补充 supervised failure。Table 5 的条件不公平性和 Table 9 的测量失败均在正文明确限定，没有被写成主 benchmark 结论。

## 最终判断

- **最可复用模式**：稳定的 method × dataset 多级表头；metric 方向直接写入首列；主表定量矩阵旁放对应 qualitative rendering/trajectory；对 evaluator robustness 同时报告质量指标与 Success Rate；用同一 metric skeleton 连接主结果、probe、ablation 和 corruption。
- **最高价值对象**：Figure 1（最短路径暴露跨 pair transfer 接口）、Table 1（定性轨迹与 TPS/FID 的 headline 对齐）、Table 3（把 transferability 与 pose probe 的差异转为结构反事实）、Figure 2 + Table 8（oracle 可靠性的定性—定量闭环）。
- **主要失败模式**：caption/表头常省略 denominator、重复数、不确定性和单位；小字体、多 dataset 色带和高密度 qualitative grid 在普通缩放下难读；Table 9 显示 evaluator rejection 可让 transferability 变得不可测，不能把失败注册静默解释为模型效果；Figure 3 的 artifact 只定性展示，没有 frame index 或可复现阈值。
- **一句话视觉策略**：论文用一致的 dataset 分组表格把“跨场景可迁移”与“latent 能编码 pose”拆开，再用定性轨迹、结构消融和 oracle/监督模型失败证据逐层限定 true NVS 结论的有效边界。
