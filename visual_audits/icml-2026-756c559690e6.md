- **Caption 系统**：统一以 `Figure/Table n.` 起始并置于对象下方。F1/F2/F3 使用 setup/组件动作，F4、T1、T2、F5/F6、F7/F8 多为短标题；F9–F12 caption 写出较强的比较/主发现，F13 用失败标题。caption 很少给样本 n、prompt、模型版本、评测协议或不确定性，故主文和附录的案例图大多不自足。

- **方法—结果—消融闭环**：F2/Algorithm 1 定义 planning loop，F3/T1 定义 evaluator/data，T1/F4/T2 给 outcome，T6 做 simulation-budget numeric sweep；正文关于移除 UGC evaluator、depth=1 的消融只以文字叙述，未成为独立表格。T3 的 resolution check 和 T4 的 PARA correlation 是 robustness/measurement checks，不应误写为 component ablations。
- **主文—附录链接**：F1 caption 指向 F6；F2 指向 Algorithm 1；正文把 T3/T4 放到 Appendix A/B，F7–F12 在 D 说明“more visual results”，T5/T6 在 F 完成 cost/budget，F13 在 G 披露 failure。`camera_ready.tex` 中 Perceiver 段落仍写 `See Appendix H`，但 PDF 只有 Appendix A–G；这是复现指针错误，应在审计中保留，不把不存在的 H 当作对象。
- **字体与颜色一致性**：Nimbus Roman/CM 负责双栏正文、caption 和表格；ComicSansMS/SegoeUISymbol/DengXian/TimesNewRoman 负责流程图；照片 caption/label 使用 TimesNewRoman，形成“流程图子系统、照片子系统、表格子系统”三种局部一致而非全局一致。流程图颜色提供阶段层级，照片颜色承载 aesthetic outcome，表格只靠黑白和字重。

## 最终判断

- **最可复用模式**：F1 的 people-loop/agent-loop + 同场景结果总览；F2 的闭环组件、MCTS tree、top-K 和 rollback 一图展开；F3 的 dataset filtering→human verification→reward training 双流水线；T1 的 metric direction + best/second-best 统一表；F5 的 Input→多轮迭代 strip；T6 的 budget→runtime/quality trade-off；F13 的成功 gallery 配对 failure strip。
- **最高价值对象**：F1 是问题—方法—结果最紧凑的 headline；F2 是方法接口和 Algorithm 1 的视觉入口；F3 是 UGC reward/data provenance；T1 与 T2 是主要自动指标和人类偏好证据；T3/T4 约束 sim-to-real/reward generalization；T6 是最可操作的 planning-budget 消融。F4–F12 对机制和审美很有说明力，但主要是代表性案例。
- **失败/薄弱模式**：照片 montage 依赖精选案例，缺 prompt、抽样框、盲评与全量失败率；T1/T2/T3/T4/T6 只有点估计或比例，没有 run/image/participant-level uncertainty；T5 的近似时间和 nested parent 分母需要硬件与测量协议；caption 普遍缺样本 n、模型版本、评测方向和不确定性；正文文字性 evaluator/depth ablations 没有对应表；Appendix H 指针错误；F9–F12 对闭源模型的比较不可完全复现。
- **一句话视觉策略**：先用同题 loop、闭环 MCTS 和 UGC reward pipeline 把 autonomous aesthetic planning 的机制说清，再用多指标/用户票数、迭代 strip 与 budget sweep 对齐主结果，最后用 sim-to-real 表、外部 correlation、外部模型 gallery 和显式 failure strip 标定证据边界。
