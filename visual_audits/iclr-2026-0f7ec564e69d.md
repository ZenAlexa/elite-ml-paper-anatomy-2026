## Figure 1 — LeanHammer pipeline（p.4）

### 视觉结构

- PDF image XObject 的框为 `x=127.801–484.198 pt`、`top=81.861–163.074 pt`，显示尺寸 356.40 × 81.21 pt；`pdfimages -list` 报告 RGB 图像 1062 × 242、原生 215 × 215 ppi，并带同尺寸 soft mask。页面文字和 caption 仍为 PDF 矢量对象，但图内节点与箭头本身是栅格。
- 图为单一横向 pipeline，7 个圆角矩形节点、9 条箭头：上排为 `Initial goal state → LeanPremise → Lean-auto translation → Zipperposition proof search → Duper proof reconstruction`；下排为 `Aesop → Aesop premise application`，并有 Aesop 到 Lean-auto 的斜向连接和 Aesop premise application 到 Lean-auto 的竖向连接。
- 绿色节点是不能失败且不能产生 terminal proof 的 phase（Initial goal state、LeanPremise）；黄色节点能失败但不能产生 terminal proof（Lean-auto translation、Zipperposition proof search）；蓝色节点能产生 terminal proof（Aesop、Aesop premise application、Duper proof reconstruction）。颜色类别由 caption 定义，不另设 legend。
- 黑色实线表示 control flow，红色虚线表示 information transfer。两条红色虚线均从 LeanPremise 发出，分别指向 Lean-auto translation 和 Aesop premise application；黑色实线构成阶段控制路径。
- 无坐标轴、facet、网格、数据点或不确定性带。节点标签为 direct labels；箭头头部是唯一的 marker-like 几何。Aesop 的斜线与红色虚线在中部靠近，仍可辨识但提高了局部视觉密度。

### 字体与颜色

- 图内标签为无衬线、regular、roman 的 Arial/Helvetica-like 字体，字号约 11–13 pt（中位约 12 pt），为 `rendered_estimate`、medium confidence；源码未公开，不能声称精确字体。
- 从原生 RGB 与 soft mask 合成白底后，主色像素为：绿色填充 `#D5E8D4`、绿色边框 `#82B366`；黄色填充 `#FFF2CC`、黄色边框 `#D6B656`；蓝色填充 `#DAE8FC`、蓝色边框 `#6C8EBF`；控制流 `#000000`；信息传递 `#FF0000`。这些是图像像素级的 `rendered_estimate`，不是公开源文件的 `source_exact` 值。
- 调色板属于混合色（3 类填充/边框加黑、红边）；颜色数按 8 个主色统计。相邻填充的亮度很高且接近，尤其黄色在灰度中接近白色；阶段能力几乎只靠填充色表达，因此不具备稳健的冗余编码，灰度和部分色觉缺陷条件下语义会变弱。

### 证据关系与评价

Figure 1 承接 p.3 §3.1 对传统 hammer 三组件的描述，把方法接口具体化为 `LeanPremise → Aesop/Lean-auto → Zipperposition → Duper`。它是方法接口对象，不承担定量主张；p.8–9 的 Tables 2–3 测量该 pipeline 的 proof rate，p.10 Table 4 删除其中的数据抽取与训练组件以测试机制。图 caption 的颜色能力分类与正文 §3.1 的 phase 语义一致，但没有本地 appendix 供追溯。

**优点**

1. 以一张横向、跨栏图同时表达阶段顺序、分支和两种边语义；直接放置节点标签，读者无需在正文与图例之间来回查找。
2. caption 明确定义颜色与线型，能解释为什么 Aesop/重建阶段与翻译/外部搜索阶段分属不同颜色。
3. 颜色填充、边框和箭头的视觉层级清楚，白底上节点与正文分离明显。

**弱点**

1. 图是 215 ppi 的嵌入栅格而非矢量，页面在高倍放大或印刷时节点文字和细箭头会先于正文变软。
2. 绿色/黄色/蓝色承载 terminal-proof 能力而无纹理或形状冗余；灰度下黄色填充接近白色，色觉缺陷条件下需要依赖 caption 和节点位置。
3. 红色虚线从 LeanPremise 斜向下穿过中部，和 Aesop 到 Lean-auto 的黑色斜线邻近；在窄版或低分辨率下控制流与信息传递的交叉关系会增加判断成本。
4. 图只展示结构，不展示每阶段输入/输出、超时或失败计数，因此不能单独支持成本或成功率结论。

**可复用范式**：用跨栏单图呈现「输入 → 检索 → 分支推理 → 重建」的阶段骨架；阶段标签直接放入节点，控制流与信息流使用不同线型；把颜色语义和线型语义写进 caption。若重新制作，应保留布局但改为矢量输出，并为颜色类别加入纹理或形状冗余。

## 最终判断

### 最可复用模式

1. 用一张跨栏 pipeline 图同时编码控制流、信息流和阶段能力，并把解码规则写在 caption。
2. 用小型 capability matrix 隔离产品接口问题，用 grouped-header 主表统一呈现 retrieval 与 end-to-end 指标。
3. 跨域表固定真实 split、Average、None 和 Ground truth；消融表复用主表列合同并保留不适用空值与反常单点。

### 价值最高的对象

- **Figure 1**：最有效地把 LeanPremise、Aesop、Lean-auto、Zipperposition 和 Duper 的接口关系压缩到一个可扫描结构中。
- **Table 2**：唯一同时覆盖 recall、五种 pipeline setting、模型规模、symbolic/neural union 与 Ground truth ceiling 的主结果表。
- **Table 4**：将方法中的数据抽取、negative sampling、loss mask 逐项映射到 Mathlib-valid 结果，并保留相反方向的 cumul 值。
- **Table 3**：用六个非 Mathlib split 揭示泛化异质性，而不是只报告一个平均值。

### 失败模式

1. 唯一 Figure 为 215 ppi 栅格，缺少可公开复用的矢量绘图源。
2. 所有结果表只给 point percentages；分母、seed、重复波动和失败类别没有在表内编码。
3. Caption 多为描述性标题，指标和消融操作定义依赖正文；Table 3 还把完整 variants 外移到 extended version。
4. Figure 1 的阶段能力主要靠颜色，Table 1 的 ✗ 主要靠浅灰，色觉缺陷或低质量打印时冗余编码不足。

**一句话视觉策略**：以一张跨栏流程图建立方法接口，再用统一的分层表头依次承载主比较、跨域 split 和机制消融，整体依靠克制的 booktabs 规则与 caption 指针维持叙事连续性。
