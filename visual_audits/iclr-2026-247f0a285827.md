## 跨对象系统

- **视觉叙事**：F2 的三步 KeyChain 构造 → T1 的数据配方与 GRPO 训练边界 → T2/T3 的主比较 → T4/F3 的 16K→128K 长度/检索结果 → F4 的训练轨迹 → T5/T6 的数据与 verifier 消融；附录 F5/F6 提供 prompt/schema 复现，F7/F8 展开训练动态，T7/T8/F9/T9/T10 分别补充 LongBench-v2、RULER protocol、14B NIAH、UUID 选择和 checkpoint 技能。
- **Caption 系统**：全部以 `Figure/Table n:` 起始、置于对象下方、正文 Roman；F1、F3、T2、T3 写出比较或主发现，F7/F8 写 setup/阶段边界，其他 caption 多为标题式短句。caption 一致性强，但 prompt、heatmap bins、verifier 控制变量和不确定性定义经常留给正文。
- **表头系统**：booktabs 顶/中/底线、无竖线是主语法；多级 grouped headers 将 benchmark family、difficulty、length、task type 分开；Avg/Overall 列用浅 teal `airforceblue`，粗体/下划线表示最好值。该系统能快速表达比较，却没有 uncertainty、成本或失败率专用列。
- **方法—结果—消融闭环**：F2/T1 把数据构造映射到 T2–T4；T5 用 no-KeyChain 等量替换验证数据组件，T6 比较 answer verifier，T9 检查 UUID 与 random string；F1/F5/F6/T10 则提供机制/接口的定性证据。闭环支持“数据设计和可验证 reward 是关键”，但缺少行为频率和 compute-matched 对照。
- **主文—附录链接**：F3 的 7B NIAH 在 F9 扩展到 14B，T4 的长度结果在 T8 给出更长 sweep，F4 在 F7/F8 展开 per-step 指标，F1 的轨迹机制在 T10/A.4/A.5 以样例补足。A.2 prompt 与 A.8 protocol 对复现最关键，正文 caption 没有统一附录指针。
- **字体与颜色一致性**：Nimbus/Computer Modern 负责论文和表格，Arial/Aptos 负责作者导入示意图，DejaVuSans 负责 Matplotlib 图；子系统内部一致、全局字体不统一。Teal Avg、蓝/橙/绿阶段、粉→黄→青绿 heatmap 形成可识别的三套语法，但仅热图颜色承担连续数值，灰度和色觉可读性仍有限。

## 最终判断

- **最可复用模式**：同题 matched trajectory 对照（F1）；三步数据变换 pipeline（F2）；grouped benchmark columns + Avg/Overall teal + bold/underline（T2/T3/T7）；长度 sweep 表和 depth×length heatmap 组合（T4/F3/F9）；等量数据、verifier、格式三类组件消融（T5/T6/T9）。
- **最高价值对象**：F1 是机制叙事的最短证据；F2 是方法接口；T2 是 headline 总表；T4 与 F3/F9 共同承载 16K→128K 的边界；T5/T6 是最接近决策性因果对照的定量对象。F4/F7/F8 适合诊断训练过程，不应替代最终结果或成本证据。
- **失败/薄弱模式**：所有结果表、曲线和热图都没有 run-level uncertainty 或 cell 分母；平均列压缩任务异质性；F3/F9 与 T8 的 heatmap/length protocol 对样本数、YaRN、suffix/think extraction 的说明分散；caption 多数不自足；F1/T10 的代表性轨迹和手工技能标签没有抽样/标注规则；16K 训练“避免 prohibitive full-length rollout cost”没有 GPU-hours、显存或质量—成本对照；F8 caption 保留 `and → Stage III` 语法瑕疵。
- **一句话视觉策略**：先用可复现的 KeyChain 数据变换和同题轨迹把机制说清，再用分组 headline/长度表、depth×length heatmap 与 matched ablation 对齐性能证据，最后用附录 prompt、训练动态和 checkpoint 样例解释边界而不把示意样例当作总体统计。
