## 逐对象视觉审计

### Figure 1 — headline efficiency/performance curve（p. 1）

- **职责、类型、布局**：`headline`、`main_comparison`、`efficiency_cost`；`line`。页宽单面板；横轴是训练 token budget，纵轴是 `Average Performance (%)`。9 个方法系列（Random、QuRating、DCLM、DSIR、FineWeb-Edu、UltraFineweb、PPL、GREATS、OPUS），不同方法在不同 token budget 处停止；图内还有 `+2.2`、`8x Efficiency` 和向下灰箭头注释。
- **绘图语法**：p. 1 栅格图表；x 轴按训练 token budget 数值刻度读取，使用 linear 估计，y 为 linear；x/y 均有浅灰主网格。图例位于右下角、单图共享；9 个彩色 marker（上三角、圆、菱形、星形、方形、倒三角等）与实线连接，约 9 种 marker、1 种主线型；无 hatch、error bar、band、box 或 distribution；参考线数量为 0（灰箭头是注释而非数据参考线），方法名称不做 direct label。
- **字体、颜色**：图内为无衬线 plot 字体，约 6–10 pt，普通/粗体并存，左上结论注释带斜体；以渲染估计为准。约 9 个方法色：`#FFB55A`（Random）、`#F4A5CC`（QuRating）、`#9FD356`（DCLM）、`#B3B1DE`（DSIR）、`#C8A52A`（FineWeb-Edu）、`#82B8D5`（UltraFineweb）、`#68BDB7`（PPL）、`#B7B8B8`（GREATS）、`#FF766F`（OPUS）。颜色和 marker 双编码，但 9 色在灰度下仍难可靠区分。
- **Caption（逐字）**：`Figure 1: OPUS outperforms random selection by an average of 2.2% accuracy across 10 benchmarks and achieves 8× reduction in computation on GPT-XL using FineWeb dataset.`（26 词；标题、设置、比较、主结论；caption 视觉上未使用粗体结论标题；脱离正文基本可读；直接写出 2.2% 与 8×，没有不确定性定义。）
- **数据与统计**：10 个 benchmark 的平均准确率与训练 token budget 对比；图将 Random 延伸至 200B，而 OPUS 到 30B，形成性能/效率对照。caption 没有说明平均值分母、重复次数、seed 或误差；图中只有点估计，未给不确定性。
- **证据关系**：承接摘要的 2.2%/8× headline，指向 Table 3 的 FineWeb 30B benchmark 平均结果、Figure 4 的优化轨迹和 Figure 7 的直接成本测量；它是“OPUS 结果优于随机且更省 token/compute”的入口，而不是 optimizer geometry 的机制隔离。
- **优点**：在一张图中把 performance 与 token/compute efficiency 绑定；统一 marker 使多系列趋势可追踪，图内注释帮助读者快速定位 headline 差异。
- **缺陷**：9 色图例密集且灰度可读性弱；不同方法的 token 覆盖范围不一致，可能把“更早停止”与“更高点估计”混为同一视觉趋势；caption 没有定义计算量如何换算或说明不确定性。
- **可复用范式**：用统一 token budget 横轴，同时画固定预算方法和更长训练随机参考，把“效果—成本”放进一个 headline 视觉，但应额外标注比较预算、分母和重复层级。

- **职责、类型、布局**：`qualitative_evidence`、`other`；`qualitative_grid`。附录标题为 `A Qualitative Results`；9 种方法（Random、OPUS、High-PPL、GREATS、QuRating、FineWeb-Edu、Ultra-FineWeb、DCLM-FastText、DSIR）各占连续两页，一页 selected samples 1–16，一页 not selected samples 17–32。每页 2 列×8 行、16 张卡片，卡片含 Sample、Candidate #、selected 状态、raw score 和截断文本。
- **绘图语法**：无坐标轴、网格或 legend；方法名和状态是 direct text label；每页卡片为浅灰边框/浅底，selected 以绿色文字、not selected 以灰色文字，score 为右对齐文本；无 marker、line、hatch、reference line 或 uncertainty band。该对象跨 18 页，视觉复杂度来自重复卡片密度而非 plot series。
- **字体、颜色**：卡片正文为 URW Palladio L 约 7–8 pt，Sample/Candidate 加粗，score 近似 Inconsolata/等宽体；方法标题约 12–14 pt。颜色为黑/灰文本、边框浅灰 `#D0D0D0`、selected 绿 `#188B2E`、not selected 灰 `#A7A7A7`；状态文字与“Selected/Not selected”本身冗余，灰度仍可读。
- **Caption/header**：没有独立 Figure caption；PDF section heading 为 `A Qualitative Results`，每页用方法标题，正文 §6.7 写明“single candidate buffer of size N =32 and selected K =16 samples”、候选索引和 raw score，并指向 Appendix A。故 caption 元数据为空，实际 header 构成了模块说明。
- **数据与统计**：每个方法展示同一个 candidate buffer 的 32 个候选中 16 个 selected 与 16 个 not selected；卡片文本为截断示例，score 依方法而变，Random 页 score 为 `--`。这是 qualitative selection display，不是 failure taxonomy、aggregate diversity metric 或重复实验；没有 uncertainty。
- **证据关系**：承接 §6.7 对 OPUS “more diverse mixture” 的定性描述，和 Figure 3 的 Boltzmann sampling/utility 模块、Table 7 的 Greedy vs OPUS ablation相连。附录没有把卡片聚合成可检验的 diversity 或 failure 统计，不能独立闭合 diversity-collapse claim。
- **优点**：固定 candidate index 和 card layout 使方法间选取差异可直接扫读；selected/not selected 成对页面、raw score 和原文片段把定量打分与样本语义连接起来。
- **缺陷**：18 页高度重复、截断文本多，方法间缺少统一的 diversity/failure summary；Random 没有 score，跨方法 score 数值不可直接比较；正文没有声明候选 buffer 的抽样重复或代表性。
- **可复用范式**：定性卡片适合展示选择行为，但应固定候选集合、同时给出状态与 score，并配一个 aggregate selection statistic 或失败切片，避免把少量示例当作多样性证据。

## 跨对象系统判断

- **视觉叙事**：Figure 2 先把 raw-gradient/optimizer mismatch 变成几何直觉，Figure 3 再把 proxy→projection→utility→sampling→update 串成工程闭环；Figure 1、Tables 3–6 和 Figures 4–6 逐层给出 FineWeb、FineWeb-Edu、OOD 与 SciencePedia 的结果；Tables 7–8 检查采样/proxy/超参数，Figure 7 以 time/PFLOPs 补上成本面。Appendix A 用卡片示例扩展 qualitative selection，但不提供聚合 diversity 证据。
- **Caption 系统**：Figure 1/4/5/7 与 Tables 1–6 的 caption 含设置或比较，Figure 5/7 和 Tables 1–6 用粗体标题突出主题；Figure 2/3/6 与 Table 7 caption 过短，读者需要正文才能恢复编码、预算和主结论。多数 caption 没有 seed、n、error 或 uncertainty 定义。
- **表头系统**：结果表重复 `Method + benchmark columns + Avg.`，以横跨列的 model/optimizer/corpus block 保留条件；Table 2 先定义 benchmark contract，Table 7/8 用变体或超参数 block 表达消融。OPUS 行/列使用浅蓝底，块内最优使用粗体，Avg. 前的竖线是跨表的视觉分隔。
- **方法—结果—消融链**：Figure 2/3 和 Table 1 定义 optimizer-aware update 与实现分配；Tables 3/4/5/6、Figures 1/4/5/6 展示跨模型/语料/任务结果；Table 7 检验 Boltzmann sampling 与 proxy，Table 8 做 buffer/temperature/CountSketch sensitivity，Figure 7 检查 Ghost/CountSketch 成本。中心 geometry claim 没有 raw-gradient-only 的一因素隔离，proxy protocol 在正文中也有 validation split vs retrieved proxy 的文字歧义。
- **正文—附录链接**：§6.7 明确指向 Appendix A，Appendix A 复用方法名、候选 index、score 和 selected status；但附录没有证明、代码、seed、硬件、训练日志、失败 taxonomy 或 diversity aggregate。正文 claims 因此仍主要由 point-estimate 表/图承担。

## 最终判断

- **最可复用模式**：
  1. 用 Figure 2 的双路径几何对照说明“raw score 与实际 optimizer update 不同”，再用 Figure 3 把公式对象映射到每步可执行 pipeline。
  2. 以 Tables 3–6 的 block 表和 Figure 4/5/6 的 small multiple 保持 model、corpus、budget、domain 条件可见，避免只报一个平均数。
  3. 把 Table 7/8 的机制/参数消融与 Figure 7 的 wall-clock/PFLOPs 成本并列，形成“效果—组件—成本”证据链。
  4. 复用固定方法色和 marker，并在结果表用浅蓝 OPUS 行、粗体块内最优值建立跨对象索引。
- **最高价值对象**：Figure 2（中心几何机制入口）、Figure 3（方法接口闭环）、Table 3（FineWeb 主比较）、Figure 4（训练动态）、Figure 7（成本/性能决策面）。
- **失败模式**：9 色主图与浅色多面板图灰度不安全；Figure 2/3/6 caption 过短；Figure 1/4/5/6/7 和所有结果表缺少 seed-level uncertainty；Table 3/4 的非等预算 reference 与质量层级容易被误读；Appendix A 的少量卡片无法闭合 diversity/failure claim；中心 optimizer geometry、proxy/近似误差没有一因素隔离或诊断。
- **一句话视觉策略**：用“几何错配示意→可执行 selection pipeline→跨模型/语料结果 block→组件消融→成本/性能面”的递进视觉系统，把 OPUS 的 optimizer-aware data selection 叙事从机制直觉连接到点估计结果和效率主张，同时保留附录卡片作为定性补充而非统计替代。
