## 跨对象结论

### 最可复用模式
- 全宽架构图先定义数据、反馈和评估边界，再用同一 domain/task 词汇组织 headline 与附录表。
- 主图给聚合比较，配对表给 normalized alternative、raw metric、dispersion 和 sample-count audit trail。
- 用匹配的 With/Without、action/noise/backbone 切片与统一多级表头，把机制解释连接到可复现实验条件。
- 成本图同时报告组成项，并用逐点 slowdown 图解释基线排除或失败。

### 最高价值对象
- Figure 2：最清楚地定义 benchmark 的角色、训练反馈日志和 test evaluation 接口。
- Figure 3 + Tables 10–14：从 headline aggregate 到 normalization/raw/SD 的证据链最完整。
- Figure 4 + Table 19 + Figure 11：把性能、成本单位和 Mem0 失败联系起来，但单位需修正。
- Table 16–22：覆盖反馈消融、动作噪声和 backbone 条件，支持机制边界审计。

### 失败模式
- F14 caption 复用 F13 的 varying S0L 描述，实际横轴为 Gaussian perturbation σ。
- Table 19 caption 写 iterations per second，与 Figure 4 及表中 time-like values 的 seconds 语义冲突。
- 多色方法编码缺少跨图统一映射，灰度输出和小面板中的可辨识度有限。
- 原始指标表拆成多张且缺少每行样本量/配对不确定性，跨 metric 的整体排序容易被误读。
- Table 23 的 retrieved memory/response 使用截断文本，单案例可解释但不可独立验证总体效果。

**一句话视觉策略：** MemoryBench 以角色架构图定义接口、以 domain/task 聚合图建立 headline、以原始指标/消融/动态/成本附录补足机制证据，但应先修正计时单位与 F14 caption 并统一方法色映射。
