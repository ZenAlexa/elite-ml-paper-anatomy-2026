### 1.1 版式和渲染观察

论文采用单栏主体宽度，Figure 1、Figure 3、Figure 4、Figure A1、Figure A2–A5 以及宽表通常横跨版心；p.7 把 Figure 2 放在左侧、Table 4/5 放在右侧，形成半宽 inset 组合。图表与正文之间留白较大，图注统一置于对象下方，表注置于表格上方。图像对象主要是 raster JPEG/JPX，结构框、曲线、表线和正文为 PDF vector/text 的混合渲染；因此照片和直方图保留细节，但小型图内文字在缩小后明显变细。

## 3. 逐对象审计

### Figure 1（p.2）

- **布局／类型**：主文 page-width；`architecture`、`pipeline`、`conceptual_diagram`。左侧主流程从 `[bos]`、文本 token 和图像 token 进入 `Causal Transformer`，上方分出 `LM Head` 与 `Flow Matching Head`；右侧圆角 inset 展开 `Patch-Wise Flow Matching` 的 MSE、velocity prediction、target patch/flow 与 noise sample。顶部“dog on rock”示例和底部 tokenizer 行形成上下阅读方向，虚线把 transformer 的图像 hidden state 引向 inset。
- **绘图语法与编码**：无 x/y 轴、网格、legend、error bar 或不确定性；方向由上下/左至右箭头和 token 顺序编码，蓝色大块表示 transformer，浅灰 token 表示序列接口，右侧框内的黑色/蓝色箭头表示 flow matching 计算。结构框和文字是 vector/text，图像 patch 缩略图是 raster，故为 mixed rendering；线宽约 1 pt、实线和虚线两种，所有标签均为 direct label。
- **视觉属性**：NimbusRomNo9L 与 Computer Modern math，主标签约 10–14 pt，token 和 inset 小字约 7–9 pt，字号为 rendered estimate；蓝色约 `#AFC1E3`、深蓝约 `#183D78`、浅灰约 `#F2F2F2`、黑色约 `#202020`，另有图像自身的多色缩略图。颜色是组件语义编码，但箭头、位置和文字提供部分冗余；小 token 和 MSE inset 在缩放后可读性下降，灰度下组件层次仍可识别但不够突出。
- **图注／表头动作**：图注为：`Figure 1: Overview of NextStep-1 Framework. NextStep-1 employs a causal transformer to process tokenized text and image tokens. During training, Flow Matching Head predicts the continuous flow from a noise sample to the next target image patch, conditioned on the output hidden state. At inference, this allows for generating images by iteratively guiding noise to create the next patch.`（59 词）。包含标题和训练/推理设置，不定义颜色或不确定性，不在 caption 中写数值主发现；脱离正文仍能理解主要接口。
- **数据／证据关系**：这是机制示意而非样本统计；没有分母、重复、聚合或误差。引言的“统一 multi-modal next-token”主张 → Figure 1 接口 → §2.1 Eq. (1)–(2) 的联合目标 → §2.2 tokenizer、causal transformer 和 157M patch-wise head → Table 2/3 的主结果及 Table 5 的 head 消融。
- **优点**：一个画面同时交代序列化、两种 head 和 patch-wise flow matching，方法入口与推理过程连接紧密；右侧 inset 把抽象的 flow loss 落到 target/noise/velocity 对象。
- **弱点**：主流程与 inset 信息密度高，token 缩略图和数学标记在单栏打印尺寸下较小；没有标出 16-channel、256-token 或 157M 等关键维度，示例图像 patch 是说明性资产，不能承担效果证据。

- **视觉叙事**：Figure 1 先定义 continuous-token causal interface；Table 1 固定训练 recipe；Table 2/3 给出 T2I 与 editing 主比较；Figure 2/Table 4/5 检查 FM head 容量；Figure 3/4/Table 6 把 CFG、noise、latent dispersion 和 reconstruction 机制串起来。Appendix Figure A1、Table A1/A2 扩展能力和 benchmark，Figure A2/A3 补数据与 tokenizer 实现，Figure A4/A5/Table A3 将 artifacts、修复和 latency 放到限制模块。

## 5. 最终判断

- **最可复用模式**：
  1. 用 Figure 1 的主流程 + 局部 loss inset 同时说明数据流和训练算子。
  2. 用 Figure 3/4 的 aligned panels 把机制曲线与相同条件的图像样例放到同一证据面。
  3. 用 Table 2/3 的模型族分组、指标方向箭头、ours 行高亮和多层表头组织异质主比较。
  4. 用 Figure A2 的全局流程/局部展开和 Figure A4 的 failure-mode 分行网格承载附录细节。
- **最高价值对象**：Figure 1（方法接口）、Table 2（主 T2I 比较）、Figure 3（CFG 机制）、Figure 4（tokenizer robustness）、Figure A4/A5（负面与修复边界）、Table A3（部署成本边界）。
- **主要失败模式**：定性 montage 占据很大视觉面积但没有 prompt/seed/选择规则；曲线和表格几乎都没有不确定性、分母或重复；raw/rewrite/Self-CoT 和 base/edit variant 混在同一比较面；附录虽展示失败与理论 latency，却没有失败率、实测 profiling 或可编辑视觉源。
- **一句话视觉策略**：以冷蓝色 causal-architecture 为主线，把连续 tokenizer 的机制曲线、跨模型点值表和高密度定性输出拼接成“统一接口 → 质量/编辑结果 → 稳定性与修复边界”的叙事，但依赖颜色、高亮和少量案例，统计与复现元数据仍薄弱。
