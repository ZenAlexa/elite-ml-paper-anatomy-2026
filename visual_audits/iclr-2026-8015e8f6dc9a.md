## 3. 跨对象系统与最终判断

### 视觉叙事

论文的视觉叙事是“机制先行、结果居中、复现细节后置”：Figure 1 在 counter-machine 定义后给出最小状态图；Table 1 在 §5 把 unary/NoPE、binary/RPE 与 binary/no-RPE 的长度外推并列；Table 2 和 Table 3 在 Appendix D 提供语言定义、监督 trace、模型容量与优化设置。对象顺序与 `理论构造 → 实验主比较 → 数据/训练复现` 一致，且正文 Table 1 的负面结果没有被移出主文。

### Caption 与表头系统

所有 caption 都采用 `Figure/Table n:` 普通字重起始，没有粗体结论标题、颜色键或误差说明。Figure 1 caption 最短，Table 1 caption 只标识 split/representation，Table 2 caption 负责数学符号定义，Table 3 caption 负责 regime 别名和训练例外。表头系统从 Table 1 的两级组列降到 Table 2/3 的单级列；Table 3 用重复三行和 row group 表示层级，没有额外颜色或竖线。

### 方法—结果—消融关系

Figure 1 只服务于理论 mechanism；Table 1 同时承载 headline comparison 与 Binary RPE removal 的失败对照；Table 2/3 把 Table 1 的行和条件落到可复现定义。最主要的视觉弱点不是对象缺失，而是 Table 1 的 RPE 对照被 Table 3 所示的模型规模差异混淆，且样本分母、seed 和不确定性没有进入任何视觉对象。

### 最可复用模式

1. 用一个低复杂度矢量状态图在抽象定理之前固定机制的状态、方向和接受条件。
2. 用“条件组 → split 子列”的多级表头，把同一组任务的成功和失败放在同一决策面。
3. 将 dataset language dictionary 与 hyperparameter row-group table 放入附录，并由主结果表和正文显式交叉引用。
4. 保持黑白矢量、无竖线的 booktabs 风格，使数学/表格在打印和灰度场景下仍可读。

### 最高价值对象

- **Table 1（p.10）**：唯一的主文定量表，直接呈现三种表示/位置编码 regime 在三个长度区间的 exact-match 对比和泛化失败。
- **Figure 1（p.6）**：用最小状态机图把 counting→counter-machine 的核心证明直觉与 Example 1 接上。
- **Table 3（p.21）**：虽然位于附录，却揭示了 BinaryR/BinaryN 的容量不匹配，是解释 Table 1 消融边界的关键。

### 失败模式

- Table 1 缺少测试分母、seed 和运行间变异信息，只有点估计。
- BinaryR/BinaryN 的容量差异使“去掉 RPE”不能被视为严格单变量消融。
- Figure 1 的 caption 没有说明 PARITY 和接受态语义，Table 1 的 caption 也没有给出长度区间和百分比单位。
- Table 3 位于页面下半部并留下大块空白；主表与配置表的距离也增加了容量边界被忽略的可能。

**一句话视觉策略：** 用黑白矢量状态图说明 counter-machine control flow，再用分组 accuracy 表把表示×RPE×长度外推放在同一决策面，最后以附录符号表和超参数表封装复现条件。
