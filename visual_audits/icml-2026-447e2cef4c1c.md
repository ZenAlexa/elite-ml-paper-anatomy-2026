## Figure 1 — PLANTAIN Rewind-and-Repeat（p.2）

### 几何、布局与绘图语法

- PDF image XObject 框为 `x=62.362–532.911 pt`、`top=85.040–253.665 pt`，显示尺寸 470.549 × 168.625 pt，正好覆盖正文页宽。`pdfimages -list` 报告 RGB 图像 5648 × 2024、864 × 864 ppi，并带同尺寸 soft mask；图内所有节点、连线、emoji、标记和文字均为栅格。
- 图有两条横向轨道：上排 Think–Answer 是 `Q → Think → Response → Reject → Think → …`；下排 PLANTAIN 是 `Q → Think → Plan → Reject → Think → Plan → Accept → Think → Response`。两排共 14 个圆角矩形节点（上 5、下 9），左侧用 `Think-Answer` 与 `PLANTAIN` 直接标记轨道。
- 主要阅读方向从左到右；每个轨道均有黑色水平连接线。垂直黑线连接上方/下方的解释性气泡与圆点，气泡给出 “This is hard! Let me see…”, “Sorry! Let me try again…”, “This query seems to be asking …”, “Let’s try a different approach!”, “To do Step 1, I will first…” 等示意文本。下排的 `Plan`、`New Plan`、`Accept` 与 `Reject` 使早期干预单元可直接读出。
- `Q` 使用黄色块，`Think`/`Plan` 使用白底块，`Response` 使用蓝色块，`Reject` 使用橙色块，`Accept` 使用绿色块；红色 `×` 和绿色 `✓` 分别强调拒绝/成功。机器人、举手人物和圆点是装饰/状态标记，不代表额外数据系列。
- 无坐标轴、facet、legend、网格或数值数据；这是双轨概念流程图而非统计图。复杂度取 4：2 条轨道、14 个阶段节点、多个调用气泡、状态标记和颜色/形状/文字的多重编码。
- 图内主要标签为 serif/无衬线混合的栅格字体；节点标签和大标题约 13–18 pt，气泡小字约 10–12 pt，最大左侧轨道标签约 18 pt。无公开源文件可给出精确字号，均为 `rendered_estimate`。
- 从原生图像像素看到的主要颜色为 `#FDD663`（Q）、`#8AB4F8`（Response）、`#FFB74D`（Reject）、`#81C995`（Accept）、`#EA4335`（红色叉）、`#34A853`（绿色勾/结论文字）、`#000000`（文字、线、边框）和 `#C0C0C0`（阴影/抗锯齿主色）。颜色数量按 8 个主色计。状态同时有 `Accept`/`Reject` 文字和 `✓`/`×` 形状，轨道/阶段也有直接标签，因此整体灰度仍可读；浅色填充本身的对比度会降低。

### Caption

> Figure 1 | **PLANTAIN Rewind-and-Repeat** After post-training an interleaved reasoning model, we apply an iterative rejection-sampling strategy for inference-time plan guidance. PLANTAIN first produces a plan as its initial intermediate response. This plan is evaluated by a human judge or an LLM autorater. If accepted, the model proceeds to generate the final answer. If rejected, the process is *rewound* such that the rejected plan is appended to a history of failures, and the model is re-prompted to produce a new, distinct plan. Crucially, the response generated by PLANTAIN is typically of higher quality than the response produced by a standard Think–Answer model. Additionally, subsequent thinking blocks after a rejection plan are short because the model only needs to adjust the plan rather than regenerate full reasoning. This leads to early pruning of suboptimal reasoning paths and closer alignment with true user intent.

- 词数：141（含 `Figure 1` 标签）。
- 动作：`title`、`setup`、`encoding_key`、`comparison`、`main_finding`。

### 证据关系与评价

Figure 1 把 p.1–2 引言的核心主张「第一段可见输出应是可干预的 plan」变成双轨方法接口：上排是不可中途纠偏的 monolithic Think–Answer，下排是先 plan、再接受或拒绝、再继续 reasoning 的 PLANTAIN。p.4 Algorithm 1 给出 post-training；p.6–7 Algorithm 2–3 给出 Best-of-N 与 Rewind & Repeat；p.10 Table 2 测量 plan-level 与 answer-level feedback；p.11 Table 4 测量 rewind 触发和收敛。图承担机制/接口直觉，不承担数值估计。

**优点**

1. 一张 page-width 图并置 baseline 与方法轨道，直接展示干预点、重试和最终响应，读者无需先读算法伪代码。
2. 节点内直接标签、`Accept`/`Reject` 文字、`✓`/`×` 和轨道标题共同表达状态，caption 又补充了人类 judge/LLM autorater 与 rewind 语义。
3. 颜色、节点形状和垂直气泡把「先暴露 plan、只重做短调整」的因果顺序固定在一条可复用的横向阅读路径中。

**缺点**

1. 图是 864 ppi 原生嵌入但在 PDF 中作为栅格 XObject；页面缩放时图内文字、emoji 和细边框会比矢量正文更快变软，无法从公开源码修复。
2. 阶段类别和成功/失败强调仍显著依赖颜色；灰度下浅黄、浅绿和浅蓝接近白底，读者主要依赖节点文字和 `✓`/`×`。
3. 上排红叉、橙色 Reject、下排红叉/绿色勾与多条垂直气泡线增加局部密度；窄版重排时轨道的拒绝位置可能需要重新对齐。
4. 概念图不编码实际 plan 长度、judge 成本、失败计数、总 token 或不确定性，不能独立支持 latency/accuracy 数值主张。

**可复用模式**：用两条水平轨道固定「单块 baseline → 可见 plan → 接受/拒绝 → 短重试 → 最终响应」的干预接口；阶段用直接标签，状态用文字加形状，caption 说明评估者、历史和继续生成条件。复用时优先输出矢量，并给浅色类别增加纹理或高对比冗余。

Table 1 是 Q1「interleaved reasoning 是否降低首响应延迟且保持最终任务表现」的 headline 对象。它承接 p.8 的模型/数据/metric 定义，支撑 p.9 关于 coding-only 训练迁移到 math、text-to-SQL 和 reading comprehension 的叙述。Table 2 把同一列契约扩展到 inference-time control，Table 3 改变 token budget，Table 4 诊断 rewind。需注意 p.9 正文给出的 Qwen3-8B MATH500 Think-Answer TTFR `2106` 与本表可见单元 `1587` 不一致；表格本身的 PDF 单元是本审计的视觉事实。

1. 两层 grouped header 在一个表面上对齐五个任务/平均值和 P@1/TTFR，能同时读性能方向与首响应成本。

**可复用模式**：固定「方法 × 模型组 × 任务组」的两层表头，把质量指标和首响应指标并列；使用方向箭头、统一精度和浅灰 row-group 分隔。复用时在表头或注释中直接写 token/墙钟代理边界，并补充分母与重复波动。

While Think-Answer continues to improve with longer reasoning—reflecting redundant token usage—Plan-Answer benefits modestly from larger budgets but remains below Rewind-and-Repeat, indicating stable yet non-adaptive scaling. ### 证据关系与评价

Table 3 回答 p.9–10 的 token-budget ablation：在 Figure 1/Algorithm 3 所定义的 plan-level R&R 下，延长 context window 是否仍带来明显质量增益。它与 Table 2 共享任务和方法顺序，支持正文关于 TA 依赖更长 reasoning、interleaved 模型在 4K 已近饱和的机制叙述；p.10 后文进一步解释 TA 未自然终止的失败模式。

**优点**

1. `4096 → 8192` 写入首列，单个 cell 同时显示预算变化，不需要额外 legend。
2. 与 Table 1/2 保持任务顺序和模型分组，能够沿列追踪跨表变化；R&R (Plan) 的平均值粗体强调效率结论。
3. 作为独立 ablation，避免将预算变化误认为训练组件变化。

**缺点**

1. 表只给 P@1，不给 TTFR、总 token、截断/失败比例或 judge 成本；「token efficiency」需要结合正文和 Table 2 才能判断。
2. 箭头单元没有明确说明左值/右值对应的具体 context window 之外的解码设置是否完全相同。

## 最终判断

### 最可复用模式

1. 用 Figure 1 的双轨横向流程先固定「可见 plan 是干预单元」，再用表格沿同一单元报告质量、TTFR、budget 和 retry depth。
2. 结果表统一任务顺序、模型 row group 和 P@1/TTFR grouped header，使用方向箭头、局部粗体和浅灰分隔行减少扫读成本。
3. 将 plan-level 与 answer-level feedback 放在同一 Table 2 中，将 mechanism ablation/diagnostics 单独放入 Table 3/4，避免把训练、推理和结果混成一张表。
4. Appendix 用 Table 5/6 的两列清单、A.6 的 Parameter/Value 和 A.9 的 schema inset 记录复现边界；表题短时必须依靠明确的正文指针。

### 最高价值对象

- **Figure 1**：提供最短的机制接口解释，直接把「plan → judge → rewind/accept → final response」可视化。
- **Table 2**：将干预位置、策略、P@1 与 TTFR 放在同一决策面，是方法价值最集中的对象。
- **Table 1**：显示 coding-only post-training 在 math、text-to-SQL、QuaLITY 上的跨域表面。
- **Table 4**：用原始 rewind 分母和 retry approval rates 解释 Table 2 的效率叙述。
- **Table 5/6 + A.6 + A.9 schema**：把数据、训练参数和 BirdSQL qualitative 输入补到可复现链中。

### 失败模式

1. Figure 1 依赖浅色填充且为 raster；放大/灰度打印时状态和细线会退化。
2. Table 1/2/3 的 11/11/6 列密度较高，粗体比较范围、TTFR token proxy 和无 uncertainty 需要正文补充。
3. Table 5/6 标题与 A.6 parameter 表头不足以单独说明计数对象、训练阶段和适用模型；schema 表无表头且依赖外层代码框。
4. p.9 正文和 Table 1 出现可见 TTFR 数值冲突；附录表格规模与正文 SFT trace 总数的口径也未由 caption 闭合。
5. Judge latency、retry budget `T`、seed dispersion、wall-clock latency 和 fallback 深度没有被任何 Figure/Table 直接编码。

### 一句话视觉策略

用一张直接标注且强调干预点的双轨 plan 流程图建立机制接口，再用统一 grouped-header 的主比较/预算/重试表逐层收紧「质量—首响应—反馈位置—复现边界」证据链；附录清单和 schema inset 负责补齐训练与输入上下文。
