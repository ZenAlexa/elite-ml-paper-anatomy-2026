## 跨对象系统判断
- **Visual narrative**：视觉叙事从 Figure 1 的 GPU memory hierarchy/row-stationary update 开始，经 Figure 2 的 PV operator 接口，转入 Figure 3 的 point-cloud speed/memory/HVP benchmark，再由 Figure 4–5 扩展到 OTDD 与 saddle-escape downstream；Figure 6–8 和 Tables 8–24 在附录补足复杂度、baseline、低 ε、parity、形状和 failure 边界。
- **Caption system**：Figure captions 普遍采用“标题→设置→panel/encoding→比较→结论”的长句系统；F3、F5、F7、F8 在 caption 直接写出主要数值/失败发现，F1–2 解释 dataflow，F4 主要提供 setup 与 panel mapping。Table captions 以标题和实验条件为主，网格表定义 OOT/OOM、ratio 方向、重复次数或 precision；Table 24 是最完整的 capability/failure caption。
- **Table header system**：主表使用单层或两层分组表头固定 method、phase、n/d 与 failure state；附录 speedup 表复用 n 行×d 列的宽网格，profiler 表复用 Metric×backend，parity/low-ε 表复用 ε/τ/η 条件列。大多数表以 minimal/booktabs rules 降低线条噪声，T1–3/T17–24 在需要精确格点或 checkmark 时使用 grid。
- **Method/result/ablation link**：Figure 1–2 与 Table 1 是代数重写到 kernel/operator 的方法接口；Table 2、Figure 3 与 Tables 5–7 将 HBM traffic、launch 和 stalls 绑定到性能；Figure 4–8 与 Tables 8–24 扩展到 workload、数值和边界。没有 component-removal ablation；Table 17–18 的 symmetric/alternating 是 schedule sensitivity，Table 10–11/19–23 是负结果/鲁棒性而非删除式消融。
- **Main/appendix link**：正文保留 Figure 1–5、Table 1–3、核心定理和 selected results；附录 Figure 6–8、Table 4–24 提供完整 notation、profiler decomposition、n×d grids、HVP parity、low-ε、rectangular、OTDD support 和 multi-saddle detail。正文引用这些表号，但复现条件、重复次数、failure budget 与 uncertainty boundary 多在 Appendix H。
- **Typography consistency**：正文/figure captions 以 Nimbus Roman No9 L 与 Computer Modern math 为主，DejaVu Sans/Bold 用于 Matplotlib axes、legend 和 diagram labels；figure glyph 的最小约 5.5 pt，结果图和 dense tables 在 200 dpi render 中可读但缩放成本明显。表格 header 多为 bold/mixed，附录分组依靠 italic/bold 与水平规则。
- **Color consistency**：方法 diagrams 稳定使用蓝/橙/pink/green 的流程语义；benchmark charts 稳定使用橙 Flash、红 Flash-alt、蓝 KeOps、紫 Tensorized、绿 JAX，并用 marker/line style 冗余。表格主要 grayscale，bold、OOM/OOT、winner 和 checkmark 负责强调；Figure 5/8 的阶段色与 semantic shading 是局部扩展，灰度安全性较弱。

## Final judgment
- **Most reusable patterns**：
  - 把“瓶颈→代数重写→tile dataflow→profiler counter→downstream consequence”编成连续视觉链，每个对象承担不同证据角色。
  - 用跨栏机制图固定接口，再用对称 time/memory panel 和成对 speedup grids 展示扩展性与 failure boundary。
  - 在表格中同时保留 raw metric、ratio、OOM/OOT、complexity 或 capability，使负结果仍可审计。
  - 对 optimizer/schedule 过程并列 objective、gradient、curvature 与切换 marker，展示机制而非只展示终点。
- **Highest-value objects**：Figure 1, Figure 3, Table 2, Figure 4, Figure 5, Table 10, Table 24
- **Failure patterns**：
  - 八 panel Figure 3、四 panel Figure 4/5/7/8 与附录宽网格把大量语义压进小字号，panel-specific scale/legend 增加查读成本。
  - 绝大多数 timings/profiles/trajectories 没有误差或重复分布；caption 的 averaged-over-runs 仍不等于 uncertainty display。
  - 没有 component-removal ablation，方法机制主要由 algebraic argument、profiler counters 和 cross-workload results 间接闭合。
  - 颜色与 semantic shading 在 Figure 5/8 中承担阶段/区域角色，灰度打印需依赖线型、marker 和 direct labels。
- **One-sentence visual strategy**：以跨栏机制图把 squared-Euclidean EOT 的 attention-form streaming 固定为可见接口，再用 profiler、成对 scaling 图、完整 speedup grids 与下游 trajectory/边界对象证明其速度、内存和可扩展性范围。
