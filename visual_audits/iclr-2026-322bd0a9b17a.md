## Final judgment

- Most reusable patterns:
  - LOC-versus-speedup Pareto scatter with an explicit ideal direction, direct labels, and a declared method key.
  - Cumulative grouped ablation bars with a fixed baseline, architecture facets, and hatch redundancy.
  - Matched source/lowered IR or architecture code panes connected by stable region or operation identifiers.
  - Stable workload-shape inventories with IDs that can be cited by code examples and performance tables.
- Highest-value objects:
  - Figure 8: repeated H100/MI300X operator panels make the central performance/programmatic trade-off comparable across hardware and workloads.
  - Figure 9: staged ablation connects compiler mechanisms to architecture-specific gains.
  - Figure 4: the three-panel recommendation figure combines mechanism, candidate ranking, and schedule output.
  - Table 3: cost-model screening claim is stated with an operational top-5%/pruning interpretation.
- Failure patterns:
  - Unexplained vertical range or whisker marks recur in the quantitative scatter plots.
  - Dense multi-panel and code figures use labels near the minimum readable size and omit caption keys.
  - Appendix shape inventories and baseline tables rarely map stable IDs or commits directly to individual result objects.
  - Local pastel palettes are not a paper-wide semantic system and are only partly redundant in grayscale.
- One-sentence visual strategy: TileLang combines repeated LOC-versus-speedup trade-off plots with compiler-stage schematics, architecture-specific ablations, and reproducibility-oriented code/shape inventories, but its evidence system would be stronger with globally stable encodings and explicit range, shape, and identifier definitions.
