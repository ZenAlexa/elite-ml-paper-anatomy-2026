2. resolution 使用三种 marker，方法使用颜色，best/second 使用 cell fill，至少对分辨率提供颜色之外的冗余。
3. caption 定义 mean ± std、metric direction、HD90^cum、best/second 和 patch-based，结果对象自足性在全篇最高。

**缺陷。**

1. 33 行表与两张多轨迹图共同占据半页以上，表体、legend 和 tick label 很小；栅格化使放大后也难以恢复矢量文字。
2. 方法身份主要靠颜色，图例颜色与 Table 1/7 的 backend 颜色不共享稳定语义；灰度下方法轨迹难以区分。
3. panels (b,c) 没有 error display 或 hardware/cost denominator；正文宣称的 +18.1/+31.6/−62.1% 没有在 caption 中指明统一 comparator，且 Fig. 5a 的 cross-reference 在正文处存在错位。

**可复用范式。** 用“精确结果表 + accuracy–resource frontier”三面板把质量和效率合并，固定 resolution markers、方向箭头和 best/second 语义；复用时应增加 method 的 marker/line redundancy，并在 caption 给出 cost 分母、样本数和 comparator。

**可复用范式。** 用固定列顺序的“fixed–registered moved–original moving + paired ROI insets”呈现跨模态 alignment；同时提供 case/plane 标识和可复核的 fiducial 或 overlap 数值，避免 qualitative panel 独立承担准确率结论。

### Figure 7（PDF p.9；`ablation/5.1, 5.4`；main）

**位置与结构。** 页宽栅格化的 12 小图：四类 operation/backend group，每组包含 Forward Pass Time、Backward Pass Time、Memory Usage 三个 panel。上半包括 CC/LNCC backends 和 MI backends，下半包括 affine/grid-sampler 相关 backend 与 scaling-and-squaring/SNS steps。大多数 operation 的 x 轴为 `Voxel Size per Dimension`，最后一组为 `Number of Steps`；runtime plot 使用对数 y 轴，memory plot 使用 MB 线性 y 轴。每组以 backend legend 区分多条曲线。

**绘图语法。** `raster rendering; x/y scales heterogeneous across 12 subplots (recorded as unknown at figure level); grid both (light gray); legend present in group headers/plot tops, not shared across all groups; shared_legend=false; direct_labels=false; one marker class per curve family; one solid line class; no hatching; no reference line; no uncertainty; line widths about 0.8–1.0 pt; provenance rendered_estimate.` CC group 的颜色包括 FireANTs red、torch.compile green、VoxelMorph orange、Fast LNCC blue/cyan、Ours purple；MI/affine/scaling groups 主要用 PyTorch blue、torch.compile green 和 Ours purple。

**数据编码与统计。** 曲线把 runtime（s）或 memory（MB）对 voxel size/number of steps 的关系编码为 connected point measurements；每个 group 比较不同 implementation/backend，Ours 通常在 memory 和 runtime 上较低。Figure 7 没有 error bar、mean ± std、replicate unit、seed 或 hardware condition；正文给出 LNCC forward 5.22×、backward 56.98×、scaling-and-squaring memory 50% 等摘要数字，但图自身未逐项标出这些结论的对应 panel。

**Caption（逐字，规范化换行；约 24 词）。** “Figure 7: Ablations on key workhorse operations: LNCC, MI, grid sampler, and scaling-and-squaring operations. Our fused kernels consume significantly less HBM and runtime.” Caption 有 title、对象 setup 和 main finding，但没有 backend/color/axis/uncertainty 定义；`headline_bold=true`、`self_contained=false`、`main_finding_stated=true`。

**证据关系。** §§3.1–3.3 的 O(1) HBM、implicit Parzen、fused LNCC 机制 → Figure 7 的 operation-level ablation → Table 1 的 TransMorph/FireANTs workflow outcome。它是论文最直接的 component/mechanism evidence，但下半部分的 grid sampler、scaling-and-squaring 与正文/缺失 Table 3 的调用关系需要读者自行追踪。

**优点。**

1. 固定三列指标（forward/backward/memory）覆盖四类 workhorse operation，便于横向读 implementation trade-off。
2. runtime 对数轴能容纳数量级差异，memory 曲线保留大体规模趋势，且每组都有 baseline/backend 对照。
3. 直接把“kernel fusion 的资源收益”从 end-to-end 结果拆到局部 primitive，因果解释力高于单一总表。

**缺陷。**

1. 12 个小图和多组 legend 造成极高信息密度，字号和 tick 在正文尺寸下很小；栅格化限制二次放大。
2. 不同子图 y 轴单位/尺度混合，caption 没有说明 log/linear 的分配和 panel-to-claim mapping。
3. 没有重复或误差定义，内存的确定性 `0.0` 也未解释；颜色没有 shape/line redundancy，灰度下 backend 难辨。

**可复用范式。** 将每个 primitive 固定成“forward/backward/memory”三列，统一 x 变量和 backend legend，并用 log runtime + linear memory 显示规模趋势；复用时需补 panel labels、replicate/uncertainty 和一个不依赖颜色的 backend 编码。

## 4. 跨对象视觉系统

- **视觉叙事**：Figure 1 先定义 registration task 和典型 pipeline；Figure 2 把 bottleneck 归因到 HBM intermediates；Figure 3 给出 GP/Ring 分布式闭环和 memory scaling；Figure 4 解释 random-access interpolation 的 partial-sum mechanism；Figure 5 将机制落实为 Faux-OASIS accuracy/cost frontier；Figure 6 展示真实 100 µm multimodal qualitative alignment；Figure 7 将资源收益拆到 LNCC/MI/grid/scaling-and-squaring primitives；Table 1 回到 TransMorph/FireANTs workflow；Figure 8 检验 Ring Sampler weak scaling 与 GP boundary correctness。顺序整体为“接口 → 机制 → 系统 → 结果 → 局部消融”，但 Figure 7/Table 1 的调用在正文中交叉，且正文把 single-GPU capacity 错指到 Fig. 5a，而可见 memory scaling plot 位于 Figure 3 right。
- **Caption 系统**：Figure 1–4、6 的 caption 有较完整的 setup/encoding；Figure 3–5 明确主方向或主 claim；Figure 7 和 Table 1 更偏标题+对象说明，把主要数字留给正文。Figure 5 的 caption 是统计信息最完整的一个，Figure 8 使用顶端短 caption 加两个 panel subcaptions（其中 (b) 还指向缺失 Fig. 10）。多数 caption 能说明“看什么”，但没有统一提供样本数、hardware、重复或 cost denominator。
- **表头系统**：PDF 中只有 Table 1。它用两张 stacked subtables 表达 `TransMorph Top` 与 `FireANTs Bottom`，每个表头写出 loss/backend、开关、单位和 ↑/↓；没有跨页、复杂多级 header 或完整网格。Figure 5(a) 虽然视觉上像表格，但其标签属于 Figure 5 的 panel，不改变 PDF 的 Table 计数。
- **方法—结果—消融链**：Figure 2 的 HBM mechanism → Figure 7 的 primitive runtime/memory ablation → Table 1 的 workflow metrics；Figure 3/4 的 GP/Ring interface → Figure 8 的 Ring/GP ablation；Figure 5 的 end-to-end simulated high-resolution comparison → Figure 6 的 real-case qualitative capability。该链条能支持 resource/capability claims，但真实 100 µm accuracy 依赖私有 fiducials，且没有单独的 GP-only、Ring-only end-to-end quantitative table。
- **正文—附录边界**：PDF 没有 appendix 页。正文调用 Sections A/D/E.1/F–I/K 及 Tables 3–4、Figures 9–12、19–20；这些对象只能记录为 unavailable，不能替代当前 9 个实际 PDF 对象。缺失材料影响 faux-OASIS construction、HD90^cum definition、kernel gradients、Ring correctness、real-case hyperparameters 和追加 qualitative examples 的复核。
- **字体一致性**：正文/caption 使用 TeX Gyre Termes/Nimbus Roman 与 Computer Modern；Figure 3/4 的嵌入图使用 Arial/DejaVu Sans 或 Aptos，Figure 5–8 的栅格图中文字不可从公共源精确读取。表体和图内 label 明显小于正文，Figure 7 具有最高的字号/信息密度风险。
- **颜色一致性**：机制图中 red/blue/green/violet 有较稳定的 local role；但 Figure 5 的 method palette、Figure 7 的 backend palette、Figure 8 的 on/off palette 各自独立。Figure 5 的 green/yellow best/second 是唯一跨 panel 反复使用的结果标记，仍缺少文本/线型冗余；整体 grayscale safety 偏弱。

## 5. 最终判断

### 最可复用的视觉模式

1. Figure 3 的“分布式 pipeline + log-scale resource frontier”：将系统边界、通信/存储机制和数量级资源结果并置。
2. Figure 4 的“失败模式 → 通信操作 → 局部代数”三面板：适合解释 random access、sharding 和 partial aggregation。
3. Figure 5 的“精确结果表 + accuracy–cost frontier”：在一张图中同时给出 resolution 级指标、方向、成本和轨迹。
4. Figure 7 的 operation × forward/backward/memory 小图矩阵：把 end-to-end speedup 拆成可归因的 primitive evidence。
5. Figure 6 的 paired ROI inset：适合 qualitative multimodal alignment，但必须配 case/plane 和 quantitative companion。

### 最高价值对象

- **Figure 3**：最完整地把 GP/Ring system interface 与 memory scaling headline 接上。
- **Figure 4**：对 Ring Sampler 的 random-access obstacle 和 partial-sum rationale 给出最清晰的机制分解。
- **Figure 5**：论文主比较对象，联合承载三分辨率 accuracy、质量方向和 compute/wall-clock trade-off。
- **Figure 7 + Table 1**：分别提供 primitive-level 与 workflow-level resource evidence，形成从局部 kernel 到实际 pipeline 的桥。
- **Figure 8**：Ring Sampler weak scaling 和 GP boundary artifact 的直接消融，尽管定量/重复信息不足。

### 失败模式

1. 栅格化图内文字和高密度小面板在正文尺寸下难读，Figure 5/7 尤其明显。
2. 方法/backend/state 主要依赖颜色，跨对象无稳定 palette，灰度和色觉缺陷下冗余不足。
3. 多数图表缺 sample denominator、hardware、replicate、seed 或 uncertainty；Figure 5 只有 panel (a) 的 mean ± std，Figure 7/8 无误差定义。
4. Figure 6 只给单例 qualitative alignment，真实 100 µm accuracy 未被图表闭合；Fig. 11 等追加对象缺失。
5. 正文存在 Fig. 5a cross-reference 与 comparator 解释不清，多个 claims 依赖 unavailable Sections/figures；视觉对象本身无法修复这些证据边界。

### 一句话视觉策略

论文采用“概念接口与 memory bottleneck → distributed mechanism 与 resource frontier → 高分辨率 accuracy/cost 主比较 → kernel/workflow/communication 消融 → 单例 qualitative alignment”的复合视觉链条，优点是机制到系统结果的方向清楚，代价是图内字号、颜色冗余和统计边界不足。
