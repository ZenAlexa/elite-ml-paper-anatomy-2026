### Figure 2（p.4，方法架构）

- **版式与类型**：页宽架构图（`page_width`），左到右主数据流，中央 Cross-Task Adapter，右侧上下两条虚线边界分别为 `3D-Reconstruction` 和 `3D-VL Reasoning`。类型为 `architecture`、`pipeline`、`conceptual_diagram`；复杂度 4/5。
- **几何/绘图语法**：输入 image stack → Vision Encoder (DINOv2) → 两个 MLP/attention 与 Bridge Tokens → geometry/semantic streams；上分支连接 Global–Frame Attention、Camera/Dense Head、DPT Decoder、Metric Bins、camera pose/metric depth/point map，下分支连接 3D Position Embedding、3D Patches、Pooling、Asking 与 LLMs (LLaVA)。无坐标轴、网格、数值 legend 或 uncertainty；直接标注模块，虚线圆角框表示分支边界，箭头表达数据/梯度方向，冻结/训练语义用雪花/火焰 icon。渲染为 raster 小图/图标与 vector 文字箭头的 mixed composition。
- **字体/颜色**：图内主要是 Calibri regular/bold、CambriaMath 和 SegoeUISymbol，模块标签约 6–8 pt；caption 是 Nimbus Roman。主色渲染估计为 `#D9EAF7`（视觉/蓝色模块）、`#DDEFD6`（几何/绿色模块）、`#F5D9C4`（语言/橙色模块）、`#E8E8E8`（中性层）、`#555555`（箭头）、`#000000`（文字）。颜色、圆角框、位置和文字共同编码分支角色，结构线条提供冗余；多数色块灰度仍可由文字/边界辨识，但小 token 色点不安全。
- **Caption**：`Figure 2: Architecture of Vid-LLM. From video, a shared DINOv2 encoder produces tokens that are bidirectionally fused by Cross-Task Adapter with learnable Bridge Tokens, yielding geometric and semantic streams. The reconstruction branch predicts camera poses, depth and recovers real-scale via a Metric-Bins module, while the 3D-VL branch lifts features into 3D tokens for LLM reasoning.` 约 62 词；标题加粗，说明 video 输入、CTA/Bridge Tokens、reconstruction 与 3D-VL 设置和机制主张；未提供颜色/箭头 key 或量化不确定性。图单独阅读可理解主要组件和方向，但 `†/‡` 等实验条件不在图中。
- **数据与证据关系**：机制架构，不含观测数据；把 §3 的 CTA、metric depth、3D patch construction 与 Figure 3 训练策略连接到 Tables 5–6 的 joint-task/ablation 结果。上分支产生 geometry，下面分支消费 3D tokens，视觉上支持论文“几何—语义交互”的方法主线。
- **优点**：边界框、颜色、上下分支和 arrow flow 同时表达模块责任、共享/分支关系和信息方向；与 §3 文字及公式 (1)–(4) 一一对应。
- **缺陷**：箭头和 token 细节密集，字体小；双向 attention 与“one-way gradient flow”的区别不完全由图形冗余表达；Metric Bins、DPT 和 camera/depth head 的输出尺度容易在缩放后混为一层。
- **可复用范式**：将共享 encoder/adapter 放在中心，把 geometry 和 language 分成带边界的平行分支，并把每条分支的输出写成可验证的 downstream artifact（pose/depth/point map 或 3D tokens/answer）。

## 最终判断

- **最可复用模式**：
  1. 用 Figure 1 的“video→3D scene→多任务卡”给出单一 headline interface，再用 Figure 2/3 的共享 adapter/双分支/两阶段 pipeline 解释机制和训练边界。
  2. 让主比较表保留输入条件、dataset spanner、指标方向与成本列（Table 5），并把模块消融保持在同一任务面（Table 6）。
  3. 用固定列配对的 qualitative grid（Figure 4/6）和“原因→重建缺陷→任务后果”的 challenging-case grid（Figure 7）同时表达能力与失败边界。
  4. 把 pose、depth、point cloud 分解到附录 Table 7–9，形成从 reconstruction 中间量到 VL 任务的闭合证据链。
- **最高价值对象**：Figure 2（方法接口最完整）、Table 5（质量/任务/时间共同决策面）、Table 6 + Figure 5（CTA/MD/训练消融）、Figure 7（把性能边界绑定到具体几何 failure mechanism）。
- **失败模式**：图内混合字体和 raster 资产缺少公开生成参数；Figure 4/6 的 red/green/blue box 没有稳定图例；Figure 5 没有重复或不确定性；Figure 6 caption 过短；Table 1–4、7–9 只给点值且脚注/缩写/缺失值定义不均；定性图的单例/少量场景不应被解释为总体成功率。
- **一句话视觉策略**：论文以共享 video-to-3D/VL 架构为主线，用跨栏机制图和两阶段流程建立因果接口，用分组主表与消融曲线验证任务/成本，再以成对定性网格和附录重建分解展示能力及几何失败边界。
