## 跨对象系统判断

- **视觉叙事**：Figure 1 先把长序列 drift/cost 问题变成可见对比；Figure 2–3 依次给出 motion-aware partition、anchor-driven Sim(3) 和 pose-graph 的方法接口；Tables 1–3 与 Figures 4–5 给出标准基准、zero-shot 泛化和效率；Figure 6、Tables 4–6 负责组件/策略消融；Tables 7–8、Figures 7–21 将 model swap、handheld、逐实例轨迹和点云几何放入附录。
- **caption system**：Figure/Table label 与句式稳定，结果 caption 常用 `Left/Right` 或 panel letter；Table 1/2 定义 TL、OOM 和颜色排序，Figure 11–15 定义 APE color scale。Figure 6 和 Figures 16–21 的不确定性、尺度或点云生成条件说明不足。
- **table header system**：主表按 benchmark/metric 的多层 header 组织，消融表把 strategy、trigger 和 metric 分列，附录 model-swap/handheld 表按实例 ID 展开。ATE↓、Drift↓、单位和 failure token 大体一致，但 Avg/Avg* 与 model-swap 的条件需依赖 caption/正文。
- **method–result–ablation link**：Figure 2 将 MASP、ADSR、pose graph 定义为可追踪模块；Table 4/5 与 Figure 6 分别检验 static pruning、partitioning 和 overlap/alignment；Table 6 补回 loop reuse。结果对象能回到方法组件，但没有单独的完整 runtime scaling curve 或重复试验不确定性。
- **main–appendix link**：正文 Figure 4/5、Table 3 给出泛化与成本主结论，附录 Figures 11–15、Figures 16–21 展开实例轨迹和几何质量；Table 7/8 将附录定性图绑定到逐实例数字。Appendix B.3 明确 foundation-model latency、动态场景和 loop 间 drift 的边界。
- **typography/color consistency**：主体字体与表格规则稳定，图内 raster font 与 Comic Sans 标签造成风格跳变；方法颜色只在局部图内稳定，附录 APE 色标承担连续语义但缺少共享范围声明。

## 最终判断

- **最高价值对象**：Figure 1（将长度、误差、runtime 同屏）、Figure 2（完整三阶段接口）、Table 1/2/3（逐实例性能、失败和泛化）、Figure 5（总成本与单位成本）以及 Figure 11–15（把平均值展开为路径级异质性）。
- **最可复用模式**：输入运动状态 → 子图/anchor → 稀疏全局优化的三段式流程；主表保留实例级 failure/scale metadata；效果指标和成本指标并排；主表平均值后用固定行列 grammar 展开附录实例轨迹。
- **主要失败模式**：多图依赖颜色和密集 colorbar；小 panel 缺少共享尺度；大部分对象没有重复运行或 uncertainty；点云图缺坐标/色标/定量 ROI；Figure 8 的 Sim(3)/SE(3) 文本不一致，Table 7 的“consistently”类强表述需要逐列约束。
- **一句话视觉策略**：论文用 motion-aware submap、context-balanced anchor 和 sparse pose graph 的流程图建立机制，再以逐序列 ATE/Drift、运行成本、消融和附录轨迹/点云把“长程一致性”从 headline 对比扩展成实例级证据链。
