## 跨对象系统、附录关系与最终判断

### 视觉论证链

论文视觉链为 **Figure 1 workflow → Figure 2 architecture → Figure 3 training/ablation dynamics → Tables 1–2 main comparison/generalization → Appendix Figure 4 noise → Figure 5 Stage 1 → Tables 3–10 configuration, aggregate, scaling, domain shift, and component boundaries → Figure 6 order-volume detail**。Figure 1 把动态 worker/order pool、two-stage IDDQN→TD3、pair probability/Q matrix 和 ILP matching 连接为闭环；Figure 2 把这个闭环映射到 worker/order encoders、BERT、QK-Attention 和 twin critics；Figure 3 与 Table 4 让去 Stage 1/normalization 的不稳定性可见。附录对象不是孤立补充，而是为正文 reward claim 补充时间、样本、driver/order、城市和 encoder 条件。

Caption 系统较弱：Figure 3/4 caption 定义重复/EMA/band，Figure 1/2 caption 说明数据流，其他 Figure 5/6 和 Table 3–10 多数只有标题或短句；指标方向、`±`、`×`、completed-only 分母、weighted average 权重和 hardware 常由正文/附录段落补足。表头通常稳定使用 Method + metric columns，跨对象的 method order 保持一致，便于 Figure 3/6 与 Tables 1/2/4/8/10 互读。

### 证据边界

- **已直接测量：** Table 2 的 48-episode mean±SD、Figure 3 的五次训练 SD band、Figure 4 的三次训练 fluctuation band、Figure 6 的三次 scenario error bars；主要扩展表仍为点值。
- **缺失或弱化：** 具体 random seed、按订单量分层的完整 uncertainty、reward β 权重和 component decomposition、ILP/network runtime profiling、centralization/action decomposition/BERT/QK 的独立 removal；Figure 5/6 不能替代理论或 failure protocol。
- **解释性 trade-off：** Triple-BERT 的 reward/service/pickup 优势伴随 delivery/detour/confirmation 的代价，Queens 的 pickup 更长；Figure 6 的 delivery/detour 只看 completed orders，unfinished orders 可能造成 bias。视觉系统保留了这些不利指标，但表 caption 没有总是独立解释它们。
- **数值/范围核对：** 正文称测试订单 range 2,850–4,264，但 Appendix E.2 同时列出 4,910；本审计按 Figure/Table 实际 x 轴列出的五个场景记录，不把矛盾改写成确定范围。`×` 在 Table 9 中保留为不可用/失败结果，未推断具体 failure mode。

### 最可复用模式

1. 用 workflow 图将动态实体池、策略阶段和全局 matching solver 串成闭环，再用架构图展开可实现的 encoder/actor/critic interface。
2. 用 2×3 shared-scale small multiples 同时放 reward、service 和时间代价，并以重复次数、EMA 与 SD band 明确训练稳定性。
3. 将 model identity、训练/执行范式、模型容量、GPU 成本和平均 reward 放在同一主表；把完整 distribution shift、driver/order scaling 与组件 ablation 留在结构同构的附录表。
4. 对测试长度、噪声、订单量或城市切换使用 row/column group，并显式表示 error bars、`±`、`×` 和 completed-only 统计边界。

### 最高价值对象

- **Figure 1：** 最短路径呈现 state update、two-stage training、pair scoring、ILP 和 assignment，且有 exact public asset。
- **Figure 2：** 把 BERT/QK/ARL/twin-critic 组件与 workflow 对齐，是方法接口的最高信息密度对象。
- **Figure 3 + Table 4：** 训练动态、五次重复、SD band、去 Stage 1/normalization 的 failure 与 weighted average 形成主消融闭环。
- **Table 2 + Figure 6：** 一个给全体指标的 mean±SD，另一个给订单量分层与三次重复误差条，能看到 reward 与时间指标的 trade-off。
- **Tables 7/9/10：** 分别给实时决策矩阵、positional embedding 的长度失败边界、encoder 异质性，是复用时最关键的条件约束。

### 主要失败模式

- 复合图小字号和八色 legend 依赖颜色，Figure 3/6 灰度和窄版面阅读成本高。
- 大多数附录表只有单点 reward，缺 seed/SD/interval；Table 5/6 的泛化/scale claim 不能由三行或两行点值独立支持。
- Table 1 同时改变 centralization、reward scope、RL algorithm、backbone 和 parameter budget，不能把 reward 差异归因于一个单独组件。
- Table 7 只有 3×3 runtime grid，没有 solver/hardware profiling；Figure 5 只有结构图，不能量化 Stage 1 的收益。
- Figure 4 caption 的“range of fluctuations”和 Figure 6 的 error-bar semantics 依赖正文；Table 9 的 `×` 没有在 caption 中定义失败类型。
