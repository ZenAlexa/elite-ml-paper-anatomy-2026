## Final judgment

- **most_reusable_patterns**：
  - Figure 2/3 的“阶段骨架→单实例 audit trail”组合，把抽象 agent workflow 与可核查字段连接起来。
  - Figure 4 的总调用量 panel 加 per-tool 分解 panel，同时回答是否随 ambiguity 增加和增加在哪些操作。
  - Figure 5/7 的多 panel distribution/heatmap 设计，用 split、类别和结构视图逐层固定 ambiguity 数据边界。
  - Table 1/2/9 的分组表头与粗体最佳值，将主结果、组件消融和 optimization sensitivity 放在可比较的指标面。
- **highest_value_objects**：
  - Figure 2（p.4）：最清楚地定义 ADEPT 的三阶段、四工具 family 与 evidence-closed boundary。
  - Table 1（p.7）：把 primary fidelity、set recovery 和 predicted cardinality 放到同一主比较面。
  - Figure 4（p.7）：唯一直接把 ambiguity level 与具体 tool usage 联系起来的过程图。
  - Table 2（p.8）：最小化 protocol、GRPO、tool family 与 trust-gate 的组件贡献接口。
  - Figure 5/7 与 Table 9（p.14/16/24）：分别提供 ambiguity/prior 结构和 optimization robustness 的附录支撑。
- **failure_patterns**：
  - 主表和 appendix sensitivity 多为单次 point estimates，缺 seed、误差类型、分母或统计检验。
  - 图表大量依赖颜色区分 Train/Test1、consensus、tool family 或 emotion，灰度和色弱条件下冗余不足。
  - 方法图和 prompt screenshot 的文字密度很高，双栏缩放后关键字段难读，且规范图不能证明运行时遵循。
  - Trust Gate 的 reward-hacking/causal traceability 主要由 prompt、架构和 ablation 支撑，缺行为级 audit、failure taxonomy 与直接 label-rule counterfactual。
- **one_sentence_visual_strategy**：以 plurality ambiguity 为入口，用三阶段 evidence-probing workflow 连接主性能、tool-budget 过程指标和组件消融，再用 appendix 的 co-occurrence、metric/action schemas、domain statistics、sensitivity 与 prompts 补足可复现边界，但整体仍受限于颜色依赖、密集小字和不完整不确定性报告。
