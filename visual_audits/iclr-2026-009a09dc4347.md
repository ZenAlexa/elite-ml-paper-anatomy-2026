## 跨对象评价

1. **方法—结果—消融链**：Figure 1 提供接口层概览，Table 1 用控制旋钮表达统一，Tables 2–4 给同一组方法的 benchmark 结果，Tables 5–8 追加 player/base/judge/reward-model 对照，Table 9 回到 prior objective。主线可扫读，但没有图形化机制量（gradient variance、duality gap、loss trajectory）来闭合 Figure 1 的机制叙事。
2. **Caption 系统**：caption 统一采用 `Figure/Table n:` + 一句标题；Table 5、7、8 的 caption 额外写结论或统计规则，Table 7 的结论标题使用 medium/bold；Table 2–4 的单位和 AVG 定义留给相邻正文，Table 7 未写 benchmark，Table 9 则给出最完整的符号定义。
3. **表头系统**：Table 3/4 用能力组→任务的两级表头；Table 1/2/5–9 用单级 header。Model、benchmark、reward model、judge 等实体命名稳定，竖线仅作为组边界，横线承载 baseline/variant 或 appendix 分区。
4. **正文—附录关系**：正文保留 Figure 1、Table 1–4；附录保留 Algorithm 1–2、Table 5–9、证明和设置。Table 8 明确将 3-player 数值复制自 Table 2；p.9–10 主结果没有直接调用 Tables 5–8 的表号，读者需要进入 appendix 才能看到 player-count、base-model 和 judge/run 证据。
5. **字体/颜色一致性**：表格内部基本统一 Nimbus Roman + Computer Modern、黑白规则和 medium header；Table 1/9 公式小于主结果表。Figure 1 的 Arial/Segoe Emoji 与 pastel blue/yellow/green 仅限示意图，语义一致地复用 dataset/policy/RM 角色，但与正文 typography 不同。

## 最终判断

- **最可复用模式**：
  1. Figure 1 的 A/B/C「既有流程 → 核心机制 → 扩展条件」结构，以及颜色、形状、直接标签的冗余编码。
  2. Table 1 的固定控制轴映射，把多个算法放进同一 players/opponents/weights/distance/gap 接口。
  3. Table 3/4 的能力组→任务两级表头，以及 Table 5/8 的绝对值＋差值消融列。
  4. Table 7 将 evaluator 放到列、将三次运行的均值±标准差放入单元格。
- **信息价值最高的对象**：Figure 1（方法接口总览）、Table 1（理论/算法统一接口）、Table 2（主 headline 比较）、Table 5 与 Table 8（最接近 player-count 机制的消融）。
- **失败模式**：
  1. 机制主张没有对应图形测量：无训练曲线、duality-gap、gradient-variance 或 non-transitivity coverage 图。
  2. Table 2–6 和 Table 8 主要给 point estimates；Table 7 的三次运行 SD 没有扩展到主结果，且 Table 8 两列聚合层级不对称。
  3. 主结果 caption 常缺单位、AVG 聚合和任务/评测集上下文；Table 7 尤其缺 benchmark 名称。
  4. Table 1/9 与 Figure 1 的小字号和密集公式/标签提高复核成本；Table 6 标题声称不同 base models，但表内只有一个 family。
- **一句话视觉策略**：用一张三面板流程图建立 multiplayer 方法接口，再用黑白参数映射表、主结果表和附录差值/重复表逐层展开证据，但将机制动态与不确定性大多留在未测或未呈现状态。
