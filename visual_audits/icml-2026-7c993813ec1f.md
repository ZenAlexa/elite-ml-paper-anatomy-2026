## 跨对象系统判断

- **视觉叙事**：Figure 1 定义单维 OMAC 流，Figure 2 用 prompt 实例解释 Comparator，Figure 3 将状态流扩展到多维；Tables 1–3 给出三 benchmark 的单维结果，Figure 4 给出 MATH 多轮 headline，Table 4 和 Tables 8–9 做 actor ablation；Figures 5–8、Tables 5–20 依次覆盖跨任务 replication、threshold/iteration sensitivity、cost、base-LLM/dataset robustness 和 prompt reproduction。
- **Caption 系统**：Figure/Table 编号和 italicized title 稳定，但主表 caption 多只有 title；Figure 5–7 才明确 SD，Figure 4/8 未在 caption 定义不确定性；几乎没有 caption 直接写主发现，主要发现留在正文。这保证 caption 简洁，却让表/图脱离正文不够自包含。
- **表头系统**：主性能表采用 Baselines/OMAC Structural/OMAC Functional block，复用五维 vocabulary；成本表用 Baselines/OMAC 双层 header，prompt 表用 Dimension/Prompt。分块可扫描，但不同表的 header level 和 block 标签不完全对称。
- **方法、结果、消融链**：Figure 1/3 的流程节点在 Tables 1–3、Figure 4–6 的性能证据中落地；Table 4/8/9 删除 Comparator 的 paired rows，Figure 7 同时改变维度作为设计反例；Tables 5–7 给定超参边界，Tables 10–13 把结构优化连接到 API/cost，Tables 19–20 固化 prompt 模板。
- **主文—附录边界**：正文只保留四个核心对象（单维主表、MATH 多维图和 actor ablation），附录追加跨 benchmark、成本、模型、数据集和模板；对象之间调用关系清楚，但多数附录对象的 caption 没有重复模型、重复次数、split 和统计定义。
- **最可复用模式**：固定五维名称并在 pipeline、paired block、line chart、ablation 和 prompt table 中复用；用“水平 baseline + OMAC 点线 + SD error bar”表达迭代收益；用成本/性能同表呈现部署权衡；用 dimension×prompt 长表保留复现接口。
- **主要失败模式**：长 prompt 表跨页可读性弱；主图/表 caption 对 SD、模型、数据 split 和编码 key 的说明不一致；categorical iteration x 容易让顺序被误读为连续数值；结果颜色在灰度下区分度不足；成本表混合 API、美元和 accuracy，且无 uncertainty 或计费边界。
