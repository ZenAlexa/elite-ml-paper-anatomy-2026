## 5. 最终判断

- **最可复用模式**：
  1. 三模型 × 五温度的双排 grouped-bar small multiples，共享 method legend、统一颜色和 bar 数值标签。
  2. 结果表统一采用模型→方法分组表头、温度/Prompt 行索引和组内 maxima 粗体，便于跨任务/模型复用。
  3. 创意 judge 结果用主文 aggregate（Table 3）+ 附录逐模型长表（Table 5–7）+ 参数变体 aggregate（Table 8）形成分层证据。
  4. β 作为 x 轴、λ 作为曲线、温度作为 facet 的敏感性图，将控制参数映射到可读的二维/三维布局。
- **价值最高的对象**：
  1. **Table 1**：以同构温度/模型/方法网格承载 GSM8K 主结果，直接连接 Top-W 的高温稳定性主张。
  2. **Figure 1 与 Figure 2**：同一颜色和面板语法覆盖两个开放式 judge 任务，最适合快速比较模型/温度异质性。
  3. **Table 3 + Table 8**：前者给默认 β 的 27 个 creative triplets，后者给高 β(T) 变体，二者共同限定“创意提升”结论的参数边界。
  4. **Figure 3**：唯一直接展示 β/λ/T 控制面板，能把理论参数讨论与观测曲线相连。
- **主要失败模式**：
  1. Figure 1/2 的方法身份几乎只靠颜色，Figure 3 的 λ 也只靠颜色；缺少线型、marker 或纹理冗余，灰度和色觉受限读者难以复核。
  2. Figure 2 的 y 轴 `Accuracy (%)` 与 MT-Bench 1–10 judge score 不匹配；Figure 1 caption 的 “Alpaca accuracy” 与正文 length-controlled win rate 命名也不一致。
  3. Table 3 和 Table 5–8 的表体约 6.67 pt，M1–M5 没有在表内展开，读者需在密集长表和 p.16 rubric 框之间跳转。
  4. QA 聚合表与 Figure 1/2 没有 cell-level error expression；caption 的 run count 不足以展示运行离散度，winner count 可能掩盖边界差异。
  5. Figure 3 为小尺寸栅格面板，重复 legend 挤压绘图区且没有不确定性；没有公开 plot/table/LaTeX 源，无法复核源码层颜色、字号和导出参数。
  6. Table 8 的 caption 过长且含残缺短语；高 β(T) 与默认 β=2.8 条件不同，聚合 winner count 的可比边界需要明确。
- **一句话视觉策略**：用统一颜色/顺序的三模型 grouped bars 建立跨温度结果主线，用模型→方法的 mean±std 长表保留 judge 细节，再以 β–λ–T 小 multiples 展示控制参数；源码、指标命名和灰度冗余应在下一版补齐。
