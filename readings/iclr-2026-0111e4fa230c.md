### 5.2 输入、输出、目标与机制边界

形式化对象只在操作层出现。输入是自然语言 user instruction、完整 code file 的 prefix/suffix、highlighted code、cursor；输出是模型生成的 entire code file；测试 harness 根据 expected inputs/outputs 判定问题是否解决（p.4、p.6、Appendix D）。PDF 没有定义损失函数、训练目标、符号化状态转移或模型内部算法。模型被要求“only output a code block”，且主评测要求重生成 entire file；这是 prompt contract，不是数学保证。

“context-dependent”是本文的机制假设，后续由 highlighted-code／cursor ablation 和 context-length bins 诊断。它没有 theorem 或可证明的 context sufficiency guarantee。Test harness 的“generalizable to different potential implementations”是 annotator instruction；论文没有给出独立 human agreement、hidden test coverage、mutation score 或 harness validity estimate（p.4、p.7、p.26）。

### 5.3 公式、理论与算法核对

- displayed equations 为 0，numbered equations 为 0；PDF 中没有公式编号、定理、引理、命题、推论或 proof block（p.1–27，全篇版面观察）。
- 算法／伪代码：0；Figure 2 是 VSCode extension 截图，Figure 11 是用户 code example，Appendix D 的 Figure 13–15 是 prompt boxes。它们没有输入／输出标题、循环层级或复杂度段落。

方法段落动作序列为 `setup_notation → define_component → explain_mechanism → state_problem → derive → define_component → instantiate_algorithm → contrast_alternative → state_problem → define_component → give_intuition → define_component → contrast_alternative → instantiate_algorithm → connect_to_experiment → summarize`。这是一个数据构造链，闭环依赖人工判断与 executable tests，缺少可证明性质。

### 7.3 统计审计

本文的主要聚合单位是 problem，`pass@1` 以“通过全部 unit tests 的题数／评测题数”表达，但正文没有逐题分母、模型级标准误或每个 API 的失败／重试规则。Table 1、Table 7、Table 8 的 `±` 是唯一可见离散量表达，Table 1 明说是 standard deviation；Table 7–8 没有说明 `±` 的层级。除了 Pearson correlation 的 `r` 和 p 值，未见 hypothesis test、bootstrap、Bayesian analysis、regression、effect-size convention 或 multiple-comparison correction。显著性、实质差异和机制证据没有完全分层，尤其是 context 与 category 结果主要依赖描述性排序。

## 9. 结论、限制与闭环

### 9.1 结论段落

p.9 的 Conclusion 是一个段落，动作序列为 `restate_problem → restate_method → restate_result → impact`。它先回收 IDE instructed edits 的评测需求，再回收 VSCode extension 与 high-quality test harness，随后概括 40-model 的 challenging、context 和 edit-type variation，最后提出模型应在真实 interaction mode、广泛类别、语言、context 和 user intent 上训练／评测。结论没有新公式或新数字；后接一个 `Limitations and Future Work` 段落，承认语言数量、生态覆盖和自动转换仍需扩展（p.9，`explicit`）。

## 12. 最终判断

1. **单一主线**：论文把 IDE 中保留 instruction、完整 code、highlight、cursor 的 in-the-wild interaction 转成经人工复审的 executable test harness，再用 40-model `pass@1`、context 条件和 edit categories 揭示现有模型在真实 instructed edits 上的能力差异（p.2–8，`explicit`）。
2. **正文保留的决策关键内容**：真实来源动机、VSCode extension、过滤与 harness 构造、5 NL／2 PL／四类任务的范围、Table 1–3、Figure 4–5、主 pass@1、context／category 结果和 cross-benchmark correlation（p.3–9）。
3. **移入附录的细节及自足性**：prompt 原文、provider links、privacy 操作、完整 examples、长尾分布、context bins、模型清单、0% 自动 harness 结果和 broader impact 被移入 p.14–27。正文足以理解主要发现，但复现 prompt、检查数据组成和判断自动化边界时必须读取附录（p.14–27）。
4. **最有效的写作／图表模式**：Figure 1 先把四种交互输入画成机制边界，Table 1 把数据源和上下文差异压成可扫描对照，Figure 4 给整体 ranking，Table 3 与 Figure 5 再把总体差异拆成 context 和 task-category 机制（p.2、p.5、p.7–8）。
5. **最明显的叙事缺口**：PDF 内部同时出现 109 core、104+9 annotated、540 complete、Portuguese／Polish 两套语言／数量描述，且仓库自动摘要还给出 545／3／11；统计协议没有 seed、区间、task denominator、test identity 或 harness validation，导致 broad generality 和 high-quality harness 的证据只部分闭合（p.4–8、p.22、p.26–27）。
6. **可迁移规则**：真实代码编辑 benchmark 应把用户操作时可见的 instruction、file context、highlight 和 cursor 作为同一输入对象，并用第二审阅者检查的 generalizable executable tests 把自然交互转成可重复判定（p.3–4、p.23–25）。
7. **规则适用边界**：该规则适合 single-file instructed edits、有限语言／代码生态和 unit-test-based `pass@1`；不能由本文直接外推到 multi-file agentic issue resolution、完全自动 test-harness generation、未覆盖的 PL 或所有真实 IDE workflow（p.3、p.6、p.22、p.27）。
