## 摘要逐句功能

1. 23 词。对象和缺口：公开的大规模 agent SFT 研究结果仍较少，原因落到 agent training data 的收集难度。限定词为 `relatively rare` 和 `unique challenges`。[p. 1，Abstract，`Public research results ... remain relatively rare`，explicit]
2. 31 词。缺口与 missing insight：作者把瓶颈定位为数据在 format、tool、interface 上的碎片化；底层 data source 缺少不构成核心解释。[p. 1，Abstract，`data is fragmented across heterogeneous formats, tools, and interfaces`，explicit]
3. 31 词。核心方法：ADP 是 diverse dataset 与 downstream training pipeline 之间的 lightweight `interlingua`。[p. 1，Abstract，`serves as an “interlingua”`，explicit]
4. 40 词。方法范围：API/tool use、browsing、coding、software engineering 和 general agentic workflow；表达力与 per-dataset engineering 成本形成双重设计要求。[p. 1，Abstract，`expressive enough to capture a large variety of tasks`，explicit]
5. 29 词。实验设置：13 个现有数据集被转成 ADP，再转为多个 agent framework 的训练格式。[p. 1，Abstract，`13 existing agent training datasets into ADP format`，explicit]
6. 39 词。定量与定性结果：平均增益约 20%，并声称达到 SOTA 或 near-SOTA；比较对象为 corresponding base models，范围限定为标准 coding、browsing、tool-use、research benchmark，并写有 `without domain-specific tuning`。[p. 1，Abstract，`average performance gain of ∼20% over corresponding base models`，explicit]
7. 24 词。开放发布与影响：代码和数据公开，目标是降低 standardized、scalable、reproducible agent training 的门槛。`in the hope` 和 `could` 明确保留期望语气。[p. 1，Abstract，`in the hope that ADP could help lower the barrier`，explicit]

功能顺序为 `object_scope/problem_gap → missing_insight → core_idea/method → scope → experimental_setup → quantitative_result/qualitative_result → impact_claim`。最强主张位于倒数第二句，摘要报告一个聚合数字约 20%，没有解释平均方式、分母或不确定性。摘要没有理论结果，也没有失败条件；`without domain-specific tuning` 与 Appendix C.1 的按 harness 域过滤形成后文需要处理的范围冲突。[p. 1，Abstract，`without domain-specific tuning`；p. 19，§C.1，`use only the non-web portion`，interpretation]

## 方法、形式化与机制

### 最小逻辑单元

1. `state_problem`：ADP 用 unified schema 连接 heterogeneous dataset 与 large-scale SFT。[p. 4，§3 开头，`bridges the gap between existing heterogeneous ... datasets and ... fine-tuning`，explicit]
2. `define_component`：Simplicity、Standardization、Expressiveness 各自对应 §2.2 的 curation、format、analysis challenge。[p. 4，§3.1，`following core principles`，explicit]
3. `setup_notation`：每条标准轨迹是 `Trajectory(id, content, details)`；`content` 是 Action 与 Observation 的交替序列。[p. 4，§3.2，`an alternating sequence of actions and observations`，explicit]
4. `define_component`：Action 分为 `APIAction(function, kwargs, description)`、`CodeAction(language, content, description)`、`MessageAction(content)`。[p. 4，§3.2，`categorize actions into three types`，explicit]
5. `define_component`：Observation 分为 `TextObservation(source, content)` 与 `WebObservation(html, axtree, url, viewport size, image observation)`。[p. 5，§3.2，`categorized into two types`，explicit]
6. `explain_mechanism`：作者的核心洞见是多数 agentic interaction 可分解为 action/observation 序列；统一基本组件即可组合原本不兼容的数据。[p. 5，§3.2，`decomposed into a sequence of actions ... and observations`，explicit]
7. `instantiate_algorithm`：三阶段 pipeline 为 Raw→Standardized、Standardized→SFT、Quality Assurance。第二阶段保留 agent harness 自己的 action/observation space、system prompt 和 context management。[p. 5，§3.3，`three-stage conversion pipeline`，explicit]
8. `explain_mechanism → connect_to_prediction`：每个 dataset 写一次 Raw→ADP，每个 agent 写一次 ADP→SFT，从 many-to-many 转为 hub-and-spoke；Figure 2 预告 `O(D×A)` 到 `O(D+A)`。[p. 5–6，§3.4，`once per dataset`；`once per agent`，explicit]

动作转移为 `state_problem → define_component → setup_notation → define_component → explain_mechanism → instantiate_algorithm → explain_mechanism → connect_to_prediction`。组件与前文问题形成明确映射：Pydantic typed schema 处理 format heterogeneity；Action/Observation decomposition 处理 expressiveness；two-direction converter 处理重复工程；统一字段允许 Table 2 的跨数据集分析。Simplicity 的实证代理直到 §6.3 才出现 LOC；semantic preservation 只有结构示例，没有 losslessness 或 conversion error audit。[p. 5，§3.3，`ensures data correctness and consistency`；p. 10，§6.3，Table 7–8，interpretation]

## 实验设计

论文没有预列 RQ 或 hypothesis；§6 的标题事后形成三项问题：统一数据能否改善多任务性能、diverse mixture 能否胜过 task-specific mixture、ADP 能否降低新 harness 适配成本。[p. 7，§6 标题；p. 9，§6.2；p. 10，§6.3，layout_observation]

- 数据：13 个来源、原始集合共 1.3M+ instances。Table 1 给原始规模和来源；Appendix C 的有效训练 mixture 大幅下采样大数据集。[p. 7，§5.1，`collectively contain over 1.3M instances`；p. 18，Table 9，explicit]
- 训练模型：主表使用 `Qwen2.5-Coder-Instruct` 7B、14B、32B；transfer 和 equal-scale 对照还使用 `Qwen2.5-7B-Instruct`、`Qwen-3-8B`。[p. 7，§5.1，`Qwen2.5-Coder-Instruct model family`；p. 9，Table 6；p. 20，Table 10，explicit]
- Agent harness：OpenHands CodeActAgent、AgentLab、SWE-Agent，共 3 个，分别提供不同 tool/interface/environment。[p. 7，§5.1，`with 3 agent frameworks`，explicit]
- Benchmark：SWE-Bench Verified、WebArena、AgentBench OS、GAIA；选择依据是 evaluation code availability 和 agent specialization。[p. 7，§5.2，`across 4 benchmarks`，explicit]
- 指标：所有主结果表都报告 Accuracy 点估计。论文未给 benchmark 分母、seed 层级、离散量、区间、显著性检验、bootstrap、Bayesian analysis、effect size 或 multiple-comparison procedure。[p. 8–9，Table 3–6，`Accuracy`，layout_observation]
- SFT 实现：所有模型使用 LLaMA-Factory 的同一 SFT pipeline。训练 epoch、learning rate、batch size、optimizer、context length、checkpoint selection、训练 token/step 预算均未提供。[p. 7，§5.1，`same SFT pipeline from LLaMA-Factory`；p. 18，Appendix C，layout_observation]
- Sampling：每 dataset 使用 `w_d`；`w_d<1` 无放回下采样，`w_d>1` 有放回上采样；固定一个未披露数值的 random seed，并在每个 epoch shuffle union。[p. 18，Appendix C，`fix a random seed for reproducibility`，explicit]
- Domain filtering：OpenHands 和 SWE-Agent 只用 non-web ADP，约 30K；AgentLab 只用 web ADP，约 20K。该设计改善 harness specialization，同时收窄了“统一 cross-domain corpus”的训练含义。[p. 19，§C.1，`use only the non-web portion`；`use only the web portion`，explicit]
- 控制：Table 6 固定 harness+model，改变 task-specific 与 ADP mixture；Table 10 将 SWE-smith 上采样到约 30K，与 ADP 匹配样本数。[p. 9，§6.2，`Holding the agent setup and evaluation fixed`；p. 20，§E.1，`match the number of training examples`，explicit]
- 缺失设计事实：数据泄漏检查、benchmark contamination、失败判定、训练重复次数、硬件规格、checkpoint selection 和人类评测均未报告。Acknowledgement 只说明 CMU FLAME Center 支持训练，不能替代硬件配置。[p. 11，Acknowledgement，`training is supported by the CMU FLAME Center`，layout_observation]

实验顺序与引言贡献基本对应：Table 2 回应跨数据分析，Table 3–5 回应性能，Table 6 回应 diverse transfer，Table 7–8 回应适配成本。Figure 1 的 schema expressiveness 只通过 converter coverage 间接验证；没有重建一致性、字段丢失率或 conversion failure count。[p. 6，Table 2；p. 8–10，Table 3–8；p. 5，§3.3，`Quality Assurance`，interpretation]

## 结果、统计与可视化

### 主要结果

1. Cross-dataset description：13 个 dataset 的平均 trajectory round 为 10.1，范围 1.0–26.8；overall Action 为 53% API、24% Code、23% Message，function thought coverage 为 83.8%。统计是 dataset-level descriptive table，没有 dispersion 或与下游性能的相关检验。[p. 6，§4，Table 2，`Overall 10.1 53/24/23 83.8`，explicit]
2. SWE-Bench Verified：SWE-Agent 的 ADP 结果为 20.2%、34.4%、40.3%，相应 base 为 0.4%、2.0%、2.2%；OpenHands 的 ADP 为 20.4%、30.6%、36.8%，base 为 2.8%、5.8%、10.6%。这些是同 harness、同 base model 的 accuracy 点差，未报告 uncertainty。[p. 8–9，Table 3–5，`ADP Data`，explicit]
3. WebArena：AgentLab 的 ADP 结果为 21.0%、22.2%、22.9%，base 为 4.5%、5.5%、10.9%。三种规模都提高，但 14B 到 32B 仅增加 0.7 个百分点，且无重复训练或区间。[p. 8–9，Table 3–5，`WebArena`，explicit]
4. AgentBench OS：OpenHands 的 ADP 结果为 27.1%、20.8%、34.7%，base 为 3.5%、2.8%、27.8%。ADP 对每个规模都高于各自 base；ADP accuracy 本身随 7B→14B 下降，因此“regardless of model size”的表述只适用于 ADP 对 base 的差值方向，无法解释 trained model 的单调 scaling。[p. 8–9，Table 3–5，`AgentBench OS`，interpretation]
5. GAIA：只报告 7B OpenHands，base 7.3%，ADP 9.1%，差 1.8 个百分点。该任务没有 14B/32B 结果。[p. 8，Table 3，`GAIA`，explicit]
6. 聚合约 20%：摘要和引言称相对 corresponding base models 平均提高约 20%，但正文没有列入项、权重或计算式。表中 `(+x%)` 实际由两个 accuracy 百分数相减；论文未区分 percentage-point difference 与 relative percent improvement。[p. 1，Abstract，`average performance gain of ∼20%`；p. 8–9，Table 3–5，interpretation]
7. Cross-task/data-mixture：Table 6 的五组 matched comparison 都由 ADP 胜出，例如 Qwen-3-8B 在 SWE-Bench 为 16.6%，SWE-smith only 为 11.0%，CodeActInstruct+Code-Feedback 为 0.2%；GAIA 为 9.1% 对 AgentInstruct only 的 0.6%。表中没有 prose 所称的 Base 条目，因此无法直接由该表判定 single-domain tuning 是否低于 base，也就不足以单独识别 negative transfer。[p. 9–10，§6.2，Table 6，`Base (no tuning)`；表内无 Base row，layout_observation]
8. Equal-scale control：约 30K 对约 30K 时，Qwen-3-8B 的 SWE-Bench accuracy 为 ADP 16.6%、upsampled SWE-smith 11.0%。这排除了该比较中的样本条数解释，仍混合了来源多样性、schema conversion、sampling weights 和数据内容差异。[p. 20，§E.1，Table 10，`comparable number of samples`，interpretation]

### 统计处理

聚合单位是 benchmark instance 的 accuracy，但各 benchmark 分母未在本文给出。跨数据集分析以 dataset 为行并给 overall 聚合；训练 mixture 以 sampled trajectory 为单位。所有决策量均为单点 Accuracy、绝对差值、LOC、trajectory count 或 action proportion。论文没有 seed 数量、task-level variance、dataset-level heterogeneity interval、hypothesis test 或 uncertainty visualization。`significant` 和 `significantly` 在摘要、引言和 §6.2 中承担自然语言强调，没有对应统计检验。[p. 2，§1，`significant benefits from cross-task transfer`；p. 9，§6.2，Table 6，layout_observation]

## 最终判断

1. **单一主线**：agent data 的可用性瓶颈被定义为 heterogeneous representation；ADP 用 Action/Observation `interlingua` 把 Raw→dataset-specific agent 的 many-to-many 转换拆成 Raw→ADP 与 ADP→SFT，再用共同 schema 汇合训练和分析。[p. 2，§1；p. 5–6，§3.3–3.4/Figure 2，interpretation]
2. **正文保留的决策关键内容**：schema 组件、converter topology、13 个来源、三类 harness、四个 benchmark、Table 2–8 的描述统计、accuracy、mixture 对照和 LOC 都在正文。读者能够判断协议机制与主要 point-estimate 结果。[p. 3–10，Table 1–8，layout_observation]
3. **迁入 appendix 的细节**：字段级 conversion example、sampling multiplier、fixed-seed/shuffle、domain filtering、scaling figures、equal-scale control 和 licenses。Appendix C.1 的 filtering 会实质改变 cross-domain 与 no-domain-specific-tuning 的解释，因此迁移损害了该主张的正文自足性。[p. 18–20，Appendix C–E，interpretation]
4. **最有效模式**：Figure 2 先把 converter topology 画成 many-to-many 与 hub-and-spoke，再由 Table 7–8 给实际 LOC。机制图和成本表分工清楚，读者可区分结构复杂度与实现量。[p. 6，Figure 2；p. 10，Table 7–8，interpretation]
5. **最大缺口与读者成本**：最强性能主张同时受到三项边界约束。训练 mixture 按 harness 域过滤；约 20% 没有聚合定义或 uncertainty；negative-transfer 段落提到 Base 但 Table 6 不含 Base。协议的格式统一证据较强，跨域训练与 causal diversity 解释只达到部分闭合。[p. 1，Abstract；p. 9，Table 6；p. 19，§C.1，interpretation]
6. **可迁移规则**：当论文把统一表示、混合训练和性能改善串成一条主线时，主文实验设置必须直接给出每个 evaluation harness 实际消费的数据域、有效样本数和 mixture exclusion；主结果表需把声称的 control 条件作为可见行。[p. 7，§5.1；p. 9，Table 6；p. 19，§C.1，interpretation]
7. **适用边界**：该规则适用于数据 mixture 会改变方法含义或因果解释的系统与训练论文。纯格式协议若只主张 interoperability，可把详细 sampling 放入 appendix，但仍应在正文区分 schema coverage、conversion fidelity 和 downstream efficacy。[p. 4–5，§3；p. 18–19，Appendix C，interpretation]
