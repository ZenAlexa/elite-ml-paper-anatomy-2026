# TileLang: Bridge Programmability and Performance in Modern Neural Kernels｜深读备忘

- **论文**：Lei Wang 等，ICLR 2026 Oral；PDF 为 ICLR proceedings 版本，36 个 PDF 物理页；OpenReview forum 为 `Jb1WkNSfUB`。本次只读取该 PDF 与项目给定的文本提取文件；未发现独立 supplementary 文件。〔PDF p. 1，标题页；p. 15，appendix 目录，`explicit`〕
- **单一主线**：TileLang 把开发者可见的 tile 决策编码为 fused tile-level dataflow graph（FTG）上的约束；tile recommendation 给出硬件感知起点，tile inference 补全 layout、pipeline 和 instruction 选择。论文以「较少 LOC 与多 GPU kernel 吞吐」作为这条控制链的实证出口。〔PDF pp. 2, 4–7, 8–10，§1、§4、§5，`explicit`；该因果串联为 `interpretation`〕
- **证据口径**：下列页码均为 PDF 物理页。`explicit` 指作者明示，`layout_observation` 指页面、图表或章节布局事实，`interpretation` 指由明示材料作出的范围受限解读。

### 相关工作

相关工作为独立 §2，主体约 340 词，并借 Appendix A 延展。主文有两个引用簇：

1. **AI kernel programming and optimization**：将 FlashAttention-3、CUTLASS、ThunderKittens、Triton、Gluon、Helion、Cypress、Tilus、Mojo 与 compiler-centric systems 按控制粒度和抽象层次并列；最近邻对比是 TileLang 暴露 tile-level control，同时自动化 layout 与 low-level configuration。〔PDF p. 2，§2，`explicit`〕
2. **Cost modeling**：将 TANGRAM/SET、KPerfIR、Path Forward、NEUSIGHT 按 analytical、instrumented 或 ML predictor 区分；对比维度为 tile 粒度上对 computation、data movement 与 fusion-aware scheduling 的建模。〔PDF p. 3，§2，`explicit`〕

主文没有重新讲解方法细节，靠「prior work 的控制/建模边界」制造缺口；Appendix A 才扩展 tensor IR、polyhedral、loop synthesis、TVM、CuTe 和 Taichi 的差异。后续的 §3–§4 反复使用 tile granularity、explicit memory placement 和 FTG，令相关工作中的比较维度继续承担论证作用。〔PDF pp. 3, 15–16，§2、Appendix A，`interpretation`〕

## 4. 方法、实现与算法/伪代码

### 最小逻辑单元与转移

1. `setup_notation`：§3.1 将 tile 定义为 tensor 的 hyper-rectangular slice，并在 `T.Kernel` 中首次引入 launch grid 和 thread count。〔p. 3，§3.1，`explicit`〕
2. `define_component`：`T.alloc_shared`、`T.alloc_fragment` 将 tile 放到显式 memory level；`T.copy`、`T.gemm`、`T.reduce` 表达 tile-level dataflow；`T.Parallel`、`T.Pipelined` 与 `T.annotate_layout` 暴露 scheduling handle。〔p. 3，§3.1；p. 17，Table 1，`explicit`〕
3. `give_intuition` + `contrast_alternative`：§3.2 以 portability/performance tradeoff 说明 tile granularity 的选择，并明确指出 tile 以下的极细粒度行为不进入稳定、portable API。〔p. 3，§3.2，`explicit`〕
4. `instantiate_algorithm`：Figure 2 将 FlashMLA 写成约 33 行的 kernel 片段，按 tile config、buffer placement、layout、pipeline、warp partition 与 instruction 标记 developer/compiler 分工。〔p. 4，§3.3，Figure 2，`explicit`〕
5. `state_problem → define_component`：§4.1 把 FTG 的 node/edge 与六个优化维度定义为共同工作面。〔p. 4，§4.1，`explicit`〕
6. `derive → explain_mechanism`：Figure 3 中 recommendation 先固定部分 location/shape/partition；inference 再补全 copy 的 placement 与 all-gather/scatter policy。〔p. 5，§4.1，Figure 3，`explicit`〕
7. `state_complexity`：Equation (1) 用 tile-level memory traffic、compute performance 和 `t_intrinsic` 形成 roofline-style ranking score。〔p. 5，§4.2，Eq. (1)，`explicit`〕
8. `explain_mechanism`：§4.3 将 layout inference 拆为 Strict、Common 与 Free 三种传播；再以 `num_stages` 暴露 pipeline inference 的唯一显式控制。〔pp. 6–7，§4.3，Figures 5–6，`explicit`〕
9. `connect_to_experiment`：p. 7–8 把 Python DSL → TileLang AST → FTG IR → TileLang/TVM passes → CUDA/HIP 的五阶段 lowering 接到随后性能实验。〔pp. 7–8，§5 前言，Figure 7，`explicit`〕

总转移可概括为 `setup_notation → define_component → give_intuition → instantiate_algorithm → state_problem → derive → explain_mechanism → connect_to_experiment`。方法同时给出 developer-facing API 和 compiler-side FTG；该双层结构是论文的主要机制，而非单纯的语法糖比较。〔PDF pp. 3–8，§3–§5，`interpretation`〕

### 形式化对象与理论边界

- **输入/状态/输出**：输入是以 tile operator 组成、允许部分 annotation 的 FTG；显式状态包含 tile shape、memory placement、warp partition、layout、pipeline 与 tensorization；输出是 fully specified、hardware-efficient kernel configuration。〔PDF pp. 4–5，§4.1，`explicit`〕
- **目标与假设**：cost model 以 `max(memory traffic / bandwidth, computation / performance) + t_intrinsic` 估算时间，并假设 compute/memory 完美重叠；作者将其表述为快速 evaluation 的 tight upper bound。〔PDF p. 5，§4.2，Eq. (1)，`explicit`〕
- **公式清单**：主文只有一个带编号的 displayed equation，即 Eq. (1)；Appendix B 另有四个未编号的 MLA 关系式（`z_t`、`k_t/v_t`、`k_t^rot`、`q_t`）。p. 6 的 layout 映射与 Fragment mapping 作为行内形式化记号出现。〔PDF pp. 5–6, 16，§4.2–§4.3、Appendix B，`layout_observation`〕
- **理论结果**：未给出定理、引理、命题、推论或正确性/近似比证明。Appendix E–F 的算法是实现规格；其 correctness 依赖断言、layout equality、alias propagation、conservative `MayConflict` 与 stage ordering，而非形式证明。〔PDF pp. 19–24，Algorithms 1–5，`layout_observation`〕

## 9. 用词、修辞与叙事密度

**最有效的写作与视觉模式。** Figure 2 先展示用户可写的 FlashMLA fragment，Figure 3 紧接着标出系统怎样补全缺失 annotation，Figure 8 再用同一张二维图接住代码长度与性能。这三步把抽象、机制和结果串成可扫读的系统叙事。〔PDF pp. 4–5, 9，`interpretation`〕

**最大读者成本。** 主文把 performance、LOC、recommendation、inference 和 fusion 同时当作解释变量；Figure 9 只对其中三个 configuration choices 作单一 workload 的 staged ablation。缺少每个 compiler pass 的 isolated control、重复测量协议和一致的 headline maximum，会限制「各机制分别造成多少收益」的可辨识度。〔PDF pp. 8–10, 19–24，`interpretation`〕

**可迁移规则。** 对「可编程性—性能」型 systems 论文，把最小可读代码、机制图和统一的效益/复杂度图放在正文中；将伪代码、shape、commit 与完整 implementation 放入有明确主文调用的附录。〔PDF pp. 4–10, 18–36，`interpretation`〕

**规则边界。** 当 LOC 不能代表真实开发成本、性能波动本身是核心结论，或需要证明 compiler transformation 的 correctness 时，这种图表和附录分工不足以单独闭合主张；需要匹配的用户/工程测量、重复测量报告或形式保证。该边界来自本文未提供的证据类型，不是对其结果的外部否定。〔PDF pp. 8–11, 19–24，`interpretation`〕
