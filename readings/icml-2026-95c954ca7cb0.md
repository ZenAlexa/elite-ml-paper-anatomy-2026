## 1. 单一主线

论文把 multimodal reasoning 的 seesaw trade-off 归因于 **modality credit assignment ambiguity**：VLM 出错时，无法从最终答案区分是「bad seeing」还是「bad thinking」。方法先用 `<recognition>` 与 `<think>` block 外显、交错 perception 和 reasoning；再用 Perception Verification（PV）的 blindfolded text reasoner 测试 grounded visual evidence 是否足以让文本模型回答问题；用 Structured Verbal Verification（SVV）把自由回答判断改写成可执行的分阶段协议；最后由 Modality-Aware Credit Assignment（MoCA）把奖励路由回 perception 或 reasoning token。[p.3, §2.1–2.2, explicit, “two distinct, component-level sets of actions”][p.4, §2.3, explicit, “withholding the image V”][p.5, §2.4–2.5, explicit, “route credit assignment”]

单一因果链是：**显式分解 → 屏蔽图像检验感知充分性 → 结构化验证最终答案 → 在失败轨迹保护正确 perception、惩罚错误 perception → 同时改善三类 benchmark**。Table 1 中 MoCA 相对 Qwen2.5-VL-Instruct 7B 的九个 cell 都上升，但论文没有 seed、区间或显著性检验，因此「同时提升」是描述性、部分闭合的实证主张。[p.6, Table 1, explicit, “MoCA”][p.7, §3.1, explicit, “across all task categories”]

最大识别缺口在 PV：作者把 text-only Qwen2.5-Instruct-14B 当作高能力 reasoning oracle；oracle 失败时却将责任归给 perception。Table 3 的 human agreement 支持代理可用性，但没有受控 oracle-noise training、calibration 或 token-level attribution 实验。[p.4, §2.3, explicit, “not a perfect, infallible reasoner”][p.8, Table 3, explicit, “90 (9.19%)”]

## 6. 方法与理论

### 6.1 最小逻辑单元

形式化对象是 image `V`、question `Q`、answer `Y`、轨迹 `τ=(a1,...,aT)`、state `st=(V,Q,a1,...,at−1)`、perception actions `AP`、reasoning actions `AR`、policy `p(at|st)`、perception text `{ap}`、`RP`、`RO` 与 trajectory return `R(τ)`。[p.3, §2.1, explicit, “POMDP”]

方法动作序列为：

`setup_notation → state_problem → define_component → explain_mechanism → instantiate_algorithm → derive → connect_to_prediction → connect_to_experiment`

| 逻辑单元 | 它回答的前文问题 | 证据 |
|---|---|---|
| 交错 `<recognition>/<think>` | 如何让 perception 从 latent process 变成可检查的 action block？ | [p.3, §2.2, explicit, “externalizing its process”] |
| PV blindfolded reasoner | 没有 intermediate perceptual thought ground truth 时如何监督？ | [p.4, §2.3, explicit, “no ground truth for an intermediate perceptual thought”] |
| `RP(τ)` binary reward | 如何把 sufficiency 变成训练信号？ | [p.4, Reward Definition, explicit, “binary perception reward”] |
| SVV universal protocol | 如何避免 regex brittle 与 holistic LLM judge 高方差？ | [p.5, §2.4, explicit, “structured natural language algorithm”] |
| `R(τ)=RO+λRP` | 如何合并 outcome 与 perception rewards？ | [p.5, §2.5, explicit, “trajectory-level return”] |
| MoCA protect/punish | 如何在 outcome failure 中区分 bad thinking 与 bad seeing？ | [p.5, §2.5, explicit, “distinguish between two scenarios”] |
| 800-token perception limit | 如何把 IB 的 minimal representation 落地？ | [p.4, §2.3, explicit, “predefined token limit”] |

### 6.2 PV：屏蔽图像的充分性代理

PV 的三步是：VLM 生成 perception action；把 `Q` 和 `{ap}` 交给强 text-only reasoner、屏蔽图像 `V`；再看该 reasoner 是否能只凭 grounded evidence 得到正确答案。[p.4, §2.3, explicit, “withholding the image V”] 若成功，作者把 `{ap}` 解释为相对于 `Q` 的 sufficient statistic；若失败，则把责任归给 perception grounding。[p.4, §2.3, explicit, “sufficient statistic for the image V”]

作者把该流程解释为 Information Bottleneck 的 functional proxy：感知文本要对答案足够有信息，同时尽量短；超过预设 token limit 的 perception block 会受惩罚。这个理论是解释性类比，不是定理，也没有保证文本 oracle 与真实 reasoning 的校准关系。[p.4, §2.3, explicit, “Information Bottleneck principle”]

### 6.3 SVV：把判断改成执行

SVV 不让 judge 直接回答 “Is this equivalent?”，而要求执行 universal verbal program：识别答案类型、提取 boxed content、重建 reference answer、按数值/短语/多选/句段类型比较，最后输出分数和 verdict。[p.5, Figure 4, explicit, “EVALUATION ALGORITHM”][p.15–16, Appendix D, explicit, “Follow these steps sequentially”]

### 6.4 MoCA：在失败轨迹中路由信用

作者先定义 `R(τ)=RO(τ)+λRP(τ)`，再以 group-wise reward baseline 计算 GRPO advantage。对 `RO=0` 的轨迹：若 `RP=1`，对 perception token 加 `αprotect|A|` 以保护有效 grounding；若 `RP=0`，减 `αpunish|A|` 以放大 bad-seeing 惩罚。[p.5, §2.5, explicit, “protect the innocent perception tokens”][p.5, §2.5, explicit, “amplify the penalty”]

PDF 中按视觉核对的 displayed-equation blocks 共 **6**：

## 7. 实验设计

### 7.1 RQ、数据、模型与基线

论文列出三个 RQ：[p.5–6, 3 Experiments, explicit, “three key research questions”]

- **RQ1 Main Claim**：MoCA 是否在 perception-、rich-modality、reasoning-intensive 任务上同时提升，并与 SOTA 比较。
- **RQ2 Component Value**：PV、SVV、MoCA 是否都必要。
- **RQ3 Reward Reliability**：PV reward 在 oracle fallibility 下是否可靠。

训练数据包含三类。第一类是 ViRL39K 与 VisualWebInstruct-Verified 的 instruction/reasoning data，第二类是 Pixel Reasoner 的 perception-intensive data，第三类是从 arXiv、newspapers、infographics 爬取整理的 modality-rich queries。[p.6, Training Datasets, explicit, “diverse task spectrum”] Appendix Table 6 给出七个域、总计 **44,851** 条：[p.14, Table 6, explicit, “Total 44,851”]

| 类别 | benchmark | 设计意图 |
|---|---|---|
| Perception-intensive | V*、HRBench、InfoVQA | fine-grained visual recognition、4K/hyper-resolution perception、文档/infographic text extraction |
| Reasoning-intensive | MathVista、MMMU、EMMA | multi-step math、college-level domain knowledge、multimodal CoT |
| Rich modalities | DUDE、SlideVQA、MMLongBench-Doc | multi-page layouts、slides、长上下文图文文档 |

基线分为 general-ability（GPT-4o、GPT-4o-mini、Claude-3.5、Llava-OV、Qwen2.5-VL-Instruct 7B/72B）和 capability-enhanced（VL-Rethinker、R1-VL、Pixel Reasoner、DeepEyes、Docopilot、mPLUG-Owl3）。开源方法以 Qwen2.5-VL 7B 为基础；PV 与 SVV 都用 Qwen2.5-Instruct-14B。[p.6, Baselines, explicit, “General-ability Models”][p.6, Implementation Details, explicit, “Qwen2.5-Instruct-14B”]

### 7.2 训练复现粒度

Appendix A 给出 GRPO、16× NVIDIA H100 80GB、约 16 小时收敛、learning rate `1e−6` cosine decay、global batch size 256 accumulated gradient steps、512 QA rollouts per policy sync、`G=8`、KL `β=0`、outcome weight 1.0、`λ=0.3`、`αprotect=αpunish=0.2`。[p.13, Appendix A, explicit, “16 × NVIDIA H100 (80GB) GPUs”]

## 8. 结果、统计与可视化

### 8.1 主结果（RQ1）

Table 1 报告 MoCA 7B 与 Qwen2.5-VL-Instruct 7B base 的九个 cell。直接相减得到：

- **Perception-centric**：V* `86.6 vs 71.4`（+15.2）、HRBench `74.2 vs 69.2`（+5.0）、InfoVQA `87.0 vs 80.7`（+6.3）。
- **Rich modalities**：DUDE `45.1 vs 41.8`（+3.3）、SlideVQA `58.3 vs 38.9`（+19.4）、MMLong `33.1 vs 21.2`（+11.9）。
- **Reasoning-centric**：MMMU `54.8 vs 54.3`（+0.5）、EMMA `31.3 vs 21.5`（+9.8）、MathVista `73.8 vs 68.2`（+5.6）。

这些是逐 benchmark 描述性分数，不带 seed、区间或显著性检验。[p.6, Table 1, explicit, “MoCA 7B”] 与所有列都领先的叙述相比，跨模型不是每一格都第一：DeepEyes 的 V* 为 88.9，高于 MoCA 的 86.6；GPT-4o 的 EMMA 为 32.7，高于 MoCA 的 31.3。[p.6, Table 1, layout_observation, “DeepEyes 88.9”]

### 8.2 组件消融（RQ2）

Table 2 的四个变体使用同一 data/base model：[p.8, Table 2, explicit, “same data and base model”]

| 变体 | 机制 | 主要读数 |
|---|---|---|
| Instruction-Only (No RL) | 保留 decomposition prompt、移除 RL | perception 平均约 71.0，full 约 82.6；MMLong 17.1 vs 33.1 |
| w/o PV (`RO only`) | 删除 perception reward | V* 79.7 vs 86.6；perception 组显著下降 |
| w/o MoCA (`RO+λRP`) | 朴素相加两个 reward，不路由失败 credit | perception 平均约 80.0，rich 约 43.7，均低于 full |
| w/o SVV+PV (LLM Judge) | 普通 LLM judge + standard GRPO | 整体低于 full；作者观察到 reward hacking |

作者写 w/o PV 的下降为 V* −6.9、HRBench −4.7、InfoVQA −4.1；然而 Table 2 的行值算出 HRBench −4.1、InfoVQA −4.7，两个 benchmark 标签对调。这是本次核读记录的唯一数字—文字分歧。[p.7, §3.2, explicit, “-4.7 on HRBench”][p.8, Table 2, layout_observation, “Full Model / w/o PV”]

### 8.3 Reward reliability（RQ3）

**PV vs human majority（Table 3，N=979）**：550/979（56.18%）为 sufficient/sufficient，295/979（30.13%）为 insufficient/insufficient；44（4.49%）是 false positive，90（9.19%）是 false negative。由此得到 accuracy `86.31%`、Cohen’s `κ=0.707`，作者称为 substantial agreement。[p.7, §3.3, explicit, “86.31% accuracy, Cohen’s κ = 0.707”][p.8, Table 3, explicit, “550 (56.18%)”]

**Verifier challenge（Table 4，N=273）**：Rigid Rule 为 `67.0 Acc./58.7 F1/100.0 consistency`；LLM Prompting 为 `79.1/82.4/78.6`；VP 为 `91.9/92.7/92.3`。Consistency 是 stochastic verifier 在 `T=0.7` 下每个样本运行 5 次、五次 verdict 全同的比例；它不是训练 loss variance。[p.8, Table 4, explicit, “VP (Ours)”][p.17, Appendix E.1, explicit, “five times for each sample”]

## 9. 消融、负面结果与自我设限

正文消融占约 520 词、一个主表；没有独立 robustness/compute ablation。具体内容为：

1. **RL 总收益**：Instruction-Only (No RL) 跨类别低于 full，说明 decomposition prompt 单独不足。[p.7, §3.2, explicit, “Merely prompting for decomposition brings a performance drop”]

3. **MoCA 价值**：`RO+λRP` 的朴素 reward shaping 比 routed credit 差，约落后 perception 3 points、rich modalities 2 points。[p.7, §3.2, explicit, “lagging by nearly 3 points”]

5. **PV 人工核验**：此项用于控制 PV proxy 的可靠性，并未删除组件；N=979，三 annotators majority vote。[p.7–8, §3.3/Table 3, explicit, “human majority vote”]

### 限制与自我设限

- **`assumption`**：text-only Qwen2.5-Instruct-14B 被视作 reasoning-perfect/high-capability proxy，但作者承认 false negatives。[p.4, §2.3, explicit, “not a perfect, infallible reasoner”]

## 14. 最终判断

1. **单一主线**：把「视觉证据不可靠」与「逻辑推理失败」从一个 outcome 中拆开，先外显再验证，最后路由 credit。
2. **正文保留的决策关键内容**：问题形式化、Figure 1–4、六个核心公式、三个 RQ、Table 1 主结果、Table 2 消融、Table 3/4 reward reliability，以及 false-negative 风险。
3. **移入附录的细节及影响**：硬件/超参数、数据域与总量、完整 VP prompt、N=273/N=979 标注设计、extended results 和 qualitative examples；核心方法仍自足，但 verifier 与训练复现需附录。
4. **最有效模式**：`overview → interleaved trajectory → executable prompt → component table → reliability table`。Figure 1–4 把抽象 credit 机制变成可见流程，Table 1–4 再逐项承担决策。
5. **最大缺口**：PV proxy 不是独立 ground truth；false-negative oracle error 与 bad seeing 仍可混淆，且主 benchmark 没有不确定性。另有 w/o PV 差值标签对调和 SVV/VP 命名漂移。
6. **可迁移写作规则**：当错误可能来自不同模态时，外显中间证据，并在屏蔽原始模态的代理任务上验证其充分性，再把独立 reward 路由回相应 action block。
7. **规则边界**：只适用于 task-relevant visual facts 可语言化、text-only verifier 足够强且代理失败率可监测的 explicit System-2 任务；不可语言化空间/纹理状态或弱 verifier 场景不能直接套用 PV。
