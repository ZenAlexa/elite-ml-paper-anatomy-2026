## E. 方法与理论

### E.1 最小逻辑单元

方法主线是“构造可验证的视觉错误 → 用 binary reward 训练生成式 verifier → 把 verifier 的错误解释改写为 image-edit prompt → 迭代生成”。段落动作转移可压缩为：

`state_problem → define_component → explain_mechanism → instantiate_algorithm → connect_to_prediction → connect_to_experiment → summarize`

1. p.5，`state_problem`。现有生成模型对复杂 prompt 的 object attribute、spatial relation 对齐不稳定，subjective/abstract 描述又容易产生不可判定的 nitpicking。
2. p.5，`define_component`。从 ShareGPT-4o-Image prompt 经 GPT-5 扩展，使用 Seedream 3.0 生成 synthetic complex images；从 LVIS 取 20k natural-image samples，再由 GPT-5 过滤简单样本。
3. p.5–6，`instantiate_algorithm`。Method 1 固定 image、修改 prompt，GPT-5 生成 faithful true prompt，再只修改一个 object、attribute 或 relation，形成 false prompt 与 explanation。
4. p.6，`instantiate_algorithm`。Method 2 固定 prompt、修改 image，用 SAM 2.1 得到 masks/bounding boxes，以 mask area 调节难度，用 FLUX.1-dev inpainting 产生 false image。
5. p.6，`explain_mechanism`。Method 2 在 prompt 中高亮选中 object 的 bounding box，避免高难度样本出现不完整描述。
6. p.6，`connect_to_experiment`。用 Seed1.5-VL 清洗，只保留 Best-of-10 accuracy 至少 0.6 的样本；这是数据筛选阈值，非最终模型统计置信度。
7. p.6，`setup_notation`。从四类验证数据拆解 capability：Object、Attribute、Spatial、Maze；前三者逐步增加 alignment/relational complexity，Maze 代表 integrative reasoning。
8. p.6，`instantiate_algorithm`。在 Qwen2.5-VL-7B 上直接运行 DAPO RL，system prompt 要求先 reasoning 再 answer；rule reward 与 format reward 的比例为 9:1。
9. p.6，`state_complexity`。四个模型各训练 100 steps，使用 64 张 NVIDIA A100-80G GPU；图 3 给出跨 ViVerBench 任务的曲线。
10. p.7–8，`define_component`。把能力层定义为 Explicit Alignment、Relational Verification、Integrative Reasoning，并用 Fig. 4 将任务放入分层圆环；括号任务可能随 prompt complexity 改变归属。
11. p.8，`connect_to_prediction`。Explicit Alignment 与 Relational Verification 之间预期有跨任务 transfer；Integrative Reasoning 因 domain gap 预期 transfer 弱。
12. p.8，`instantiate_algorithm`。用两条 pipeline 构造 28k visual verification data，经 Seed1.5-VL 过滤，覆盖前两层能力；以 Qwen2.5-VL-7B 为 backbone 得到 OmniVerifier-7B。
13. p.8，`summarize`。作者将 OmniVerifier 的 8.3-point overall gain 与 explicit/relational tasks 的改善归因于 targeted RL on atomic capabilities。
14. p.8–9，`define_component`。OmniVerifier-TTS 将 UMM 生成、verifier binary judgement、explanation 和 edit prompt 串为闭环。
15. p.9，`explain_mechanism`。false judgment 时，verifier 把 explanation 改写为指导性 edit prompt，UMM 对初始图做 fine-grained edit。
16. p.9，`instantiate_algorithm`。循环在 verifier 返回 true 或达到最多 10 个 refinement steps 时停止。

## F. 实验设计

### F.1 评测对象与数据

- ViVerBench p.3–4、Appendix A.1 p.16–24，16 tasks 分在 Concept Existence、Object Relationship、World Dynamics、Image Annotation、State Value Evaluation、STEM 六类。具体任务为 Object、Attribute、Abstract Patterns、Spatial、Non-Spatial、Static Physics、Dynamic Physics、Bounding Box、Pointing、Counting、Maze、FrozenLake、Robotics、GUI、Charts、LaTeX。
- 样本规模与平衡 p.2、p.4、p.25，正文给出 3,594 questions；Figure 1 明示 true/false 为 1:1。Appendix A.2 说明 12 位 domain experts 参与初始人工构造，5 位新专家复核，10 位专家分成两组做 human evaluation，每组 5 人，配对样本被拆到不同组；频繁错误或含歧义的样本再由 5 位新专家检查。
- 初始构造策略 p.25：人工标注用于 Object、Attribute、Non-spatial、Static Physics、Counting；脚本生成用于 Spatial、Maze、FrozenLake、Robotics；开源数据增强用于 Abstract Patterns、Dynamic Physics、Bounding Box、Pointing、GUI、Charts、LaTeX。
- 先进 VLM 对照 p.3、p.5：Qwen2.5-VL 72B、InternVL3.5 A28B、GPT-4o、OpenAI o1、o4-mini、Seed 1.5-VL、o3、GPT-5、Gemini 2.5 Pro，另有 Random、Human、Qwen2.5-VL 7B 和 OmniVerifier-7B。
- TTS 设计 p.9–10：Qwen-Image 与 GPT-Image-1，OmniVerifier-7B judge，最多 10 轮，单张 NVIDIA A100-80G；T2I-ReasonBench 与 GenEval++ 作为两个主 benchmark。
- world-modeling 设计 p.31：Qwen2.5-VL-72B 为 policy model，示例覆盖 maze navigation 与 robotics block stacking；OmniVerifier 以 task-specific data 提供 critique。

### F.2 控制、复现与统计边界

- 训练控制 p.6，四种单任务训练设置独立运行，统一 backbone、100 steps、64 张 A100-80G 和 reward ratio 9:1。论文没有提供随机种子、完整 optimizer/learning-rate/batch-size、训练样本拆分或多次运行离散量，状态为 `not_present`。
- 误差与泄漏控制 p.25：人类评测只明确说明 paired samples 被拆到不同组以降低先验偏差；模型训练/测试 split、benchmark leakage、样本级独立性没有报告，状态为 `not_present`。
- 统计方法 p.5、p.25–27：结果是 task accuracy、benchmark overall、macro average、mean refinement rounds 和各子任务分数的点估计。没有标准差、区间、bootstrap、假设检验、多重比较、回归或 Bayesian 分析，状态为 `not_present`。
- 分母 p.25–26：rule-based accuracy 以任务样本数 `N` 为分母；model-based accuracy 仅在 ground-truth false 且预测 false 时额外计入 judge `F(e_i,e_hat_i)` 的 explanation consistency。
- 失败判定 p.9、p.21–24：ViVerBench 用 true/false label 与 explanation validity 判定；TTS 用 verifier true 或 10 轮上限停止。主结果没有按 seed、prompt、participant 或图像实例展示离散程度。

## H. 消融、负面结果与自我设限

### H.1 消融识别

这里的 ablation 采用四个互斥训练数据设置来 probing transfer pattern；它并未设计为组件删除实验。主要识别对象与证据如下。

- Object-only training，p.6–7、Figure 3：对 Attribute、Charts、LaTeX 以及 Spatial、Static Physics、Bounding Box、Pointing、GUI 有明显泛化；Maze、Robotics 不稳定。
- Attribute-only training，p.6–7、Figure 3：整体趋势与 Object-only 相似；作者据此把两者归为 Explicit Alignment 的互补数据。
- Spatial-only training，p.6–7、Figure 3：对 Object、Attribute、Charts、LaTeX 有泛化，对 Non-Spatial、Bounding Box、Counting 的 relational transfer 更大；Maze、Robotics 仍有限。

- Capability taxonomy，p.7–8、Figure 4：把 transfer 结果整理为 Explicit Alignment、Relational Verification、Integrative Reasoning 三层，并提出前两层可共享数据、第三层需 task-specific data。

## L. 最终判断

1. 单一主线是把视觉 outcome verification 从一个缺失的 critic 能力做成可生成 explanation/edit prompt 的 verifier，再用该 verifier 驱动 UMM 的 sequential image refinement。ViVerBench 负责暴露缺口，atomic-capability transfer 负责缩小训练空间，OmniVerifier-TTS 负责把验证接回生成闭环。
2. 正文保留了三项决策关键内容：ViVerBench 的任务/模型对照与 Table 1、两条 data pipeline 与 capability 发现、TTS 的闭环图及 Table 2–3。Figure 1、2、5 和 Table 1–3 使读者无需先读附录即可理解主叙述。
3. 附录承载逐任务定义、专家复核、准确率公式、额外 benchmark、效率轮数、强 verifier、成功/失败图像、LongCoT、完整 prompts 和限制披露。正文自足性仍能支撑方法方向，但复现和“performance guarantee”式能力判断依赖附录且缺少 uncertainty、seed、split。
4. 最有效的模式是把 verifier 输出直接改写成 edit prompt，并用 Figure 5 的 concrete loop 将 `false → explanation → edit → true` 可视化；Figure 3/4 再把训练 transfer 组织为可读的 capability map。
5. 最大叙事缺口是把异质任务的点 accuracy、附录 qualitative examples 与上限/保证语言串在一起，却没有提供随机种子方差、显著性、prompt-level 分布或 inference cost 的可复算定义；Table 5 的负向 transfer、Figure 9 的错误累积和 Maze/FrozenLake 弱项也没有进入主结果段落。
6. 可迁移规则是：当模型的核心贡献是“验证后修正”，正文必须同时展示错误判定、修正动作、修正后的终点，以及同一预算下的效率对照；仅报告最终生成质量不足以证明闭环起作用。
7. 适用边界是：该规则适用于存在可观察中间状态、可定义局部修正动作且 outcome correctness 能被独立判定的生成/推理系统；对于 domain gap 大、动作空间离散或缺少可靠 judge 的任务，仍需 task-specific data 和额外的机制检验。
