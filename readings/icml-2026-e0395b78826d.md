## 方法、理论与公式

### 最小逻辑单元与转移

`setup_notation → define_component → state_problem → derive → explain_mechanism → instantiate_algorithm → connect_to_experiment → state_complexity → contrast_alternative → summarize`

- **模型与对象**（第 4--5 页，Section 2）：输入是 prompt (q\in\Sigma^*)；模型生成真实 token sequence (t\in V^*)；provider 依 policy π 报告 (\tilde t)；string map 是 `str`；输出价格是 (r(\tilde t))。Definition 1 给 pricing mechanism，重点限制在 additive family。
- **效用链**（第 4--5 页）：provider utility (U_\pi=r(\tilde t)-c_{gen}(t)-c_\pi(t))，并以 (c_{gen}(t)\approx c_o\cdot len(t)) 作为能耗近似；user 的 value 依赖 (v(str(\tilde t)))，所以 string-preserving misreport 能保持用户内容价值而改变收费。
- **pay-per-token 机制**（第 5--6 页）：Definition 2 固定每 token 的 (r_o)，Eq. (2) 将较长报告直接联到更高 utility。Algorithm 1 是零 GPU 的随机 valid split 对照，刻画「长度增加、plausibility 下降」的张力。
- **透明条件与 hardness**（第 6--7 页）：top-(p) plausibility 约束进入 Eq. (3)；Theorem 3 将最长 plausible tokenization 归为 NP-Hard。该结果是「最优攻击存在计算障碍」，不等同于「任何攻击都不可行」。
- **启发式攻击**（第 8--10 页）：Algorithm 2 每轮选 vocabulary index 最高且长度大于 1 的 token，以 max-min index pair split；只在完整 (\hat t) plausible 时报告，否则退回真序列。Eq. (4) 将平均收益、split 次数、(r_o)、verification cost (c_v) 与真实 profit margin 联系起来。
- **机制设计处方**（第 10--12 页）：Definition 4 定义 incentive compatibility；Proposition 5 先要求同 string 的收入相同；Theorem 6 将 additive family 完全刻画为按 character count 的线性和；Corollary 7 排除固定 pay-per-token。再以 (r_c=r_o\cdot tpc) 保持期望平均利润率。

## 消融、负面结果与限制

**消融性质。** 没有组件删除式 ablation，也没有模型训练超参数消融。论文把 (m)、(p)、temperature、模型大小/家族和语言当作敏感性变量：主文 Figure 1--3 约占两页图文，Appendix C.1、C.4 扩展至 Figure 5--7、12。其识别目标是 plausibility、additional revenue、utility gain 和 pay-per-character margin 如何随 operational knobs 变化。

**显式限制及位置。**

- **scope / assumption**：只研究 additive pricing；quality-based 或多目标 contracts 留作未来工作（12，Section 5「Model assumptions」）。
- **deployment / verification**：透明 provider 只有在 user 能验证 plausibility 时才被迫报告 plausible tokenization；TEE/ZKP 是候选，不是本文实现（12）。
- **method / baseline**：Algorithm 2 只是 proof-of-concept；可能有更强攻击或其他防御；provider 还可 misreport next-token distribution 或私下换 tokenizer（12）。
- **scope / metric**：pay-per-character 不能阻止通过增加 verbosity 增加 character count（12）。
- **data / generality**：只测 open-weights Llama/Gemma/Ministral 与 LMSYS prompts；作者明确承认 prompt 不一定代表真实分布，未测 proprietary LLM（12）。
- **generality / causality**：建模一个 user 与一个 provider 的 micro interaction；多 provider 的市场均衡、用户选择和下游生态影响未建模（12）。
- **legal / reputational / regulatory**：terms、reputation 和现行制度可能抑制攻击；作者用其他 credence-good 事件作为动机，未给 LLM token misreport 的观察证据（12--13）。
- **heterogeneity / cost**：转换后少数 output 有负利润；非 English token-to-character ratio 是已呈现的不利分布（12，29）。

**呈现方式。** Section 5 主动正面讨论主要边界，未见可据以判断「故意弱化」的证据。可验证的版面事实是：支撑 Eq. (4) 的能耗实测、扩展温度/模型曲线及多语言不利异质性被放入 Appendix C，而主文在第 9、12 页明确以 Figure 11/Table 1、C.1、C.4 调用它们。这种附录迁移保留了正文的主线，但读者必须跨至第 23--29 页检验稳健性与成本前提。

## 最终判断

1. **单一主线**：当用户只能看见 string 而 provider 看见 token-level generation 时，固定 pay-per-token 使同一内容的可报告 tokenization 成为可操纵的收费单位；透明只增加最优操纵的计算难度，character-linear 的 incentive-compatible pricing 才在模型内消除该特定激励。
2. **最有效的写作模式**：先用 `Damascus` 的 2-to-4 token 例子把抽象信息不对称落到同一 string，再以 Definition/Eq. (2) 固定因果机制，随后用 Theorem 3 和 Algorithm 2 区分「最优很难」与「可盈利攻击存在」，最后以 Theorem 6 给设计处方。Figure 2--3 紧随 Algorithm 2 与 Eq. (4)，构成最清楚的理论--实证接力。
3. **最大读者成本 / 未闭合点**：核心 empirical profitability 需要同时阅读主文 Figure 2--3 和 Appendix C.3 的 energy measurement；真实 proprietary provider、tokenizer truthfulness、verbosity、用户 auditing 能力和多 provider 市场反应均未被本文设计识别。
4. **可迁移规则**：当计价单位可在不改变用户可见交付物的情况下被服务方重编码时，先证明同一可见结果下的支付不变性，再用最小可实现策略检验剩余可利用性；复杂度下界不能替代该策略的成本收益评估。
5. **适用边界**：该规则适用于信息不对称、可重编码单位和可观察交付物分离的计费机制。它不自动推出所有 LLM billing 失真都能被 character pricing 解决；隐藏 reasoning、model substitution、输出 verbosity、非 additive contract 与市场均衡需要单独模型和证据。
