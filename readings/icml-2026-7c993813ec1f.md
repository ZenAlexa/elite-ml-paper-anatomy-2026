## E. 方法与理论

### E.1 形式化对象与五个维度

- **Agent**：定义为 `A : P × I → O`。`p ∈ P` 是 role/function prompt，可包含 few-shot examples；`i ∈ I` 是 query、task description 及其他 agent 的指令/解；`o ∈ O` 是分析、推理和解（p.2，Definition 1，`explicit`）。
- **Multi-Step Collaboration**：每个步骤 `s_t ∈ S` 涉及总体 team 的子集 `{a_{t,1}, ..., a_{t,n}} ⊆ s_t`，后续步骤利用前序输出（p.2，Definition 2，`explicit`）。
- **Graph abstraction**：agent 是 node，communication channel 是 edge；Fun-1/Fun-2 优化 node capability，Str-1/2/3 定义 global selection、dynamic local selection 和 communication routes（p.3–4，`explicit`）。作者称五维覆盖核心信息流，并将 budget management 与 computational efficiency 留作 task-specific factor，未纳入五维（p.3，`explicit`）。

五维的最小逻辑单元如下：

1. **Fun-1，优化现有 agent**：instruction prompt、few-shot examples、tool-use policies、memory management（p.3）。
2. **Fun-2，构建新 agent**：给定 task 和已有 MAS 配置，生成可接入现有 team 的功能 prompt/examples（p.3）。
3. **Str-1，candidate agent selection**：协作开始前，从所有可用 agent 中选子集（p.3）。
4. **Str-2，dynamic agent participation**：在每个 collaboration step 基于 task、candidate role 和前序输出动态选 agent（p.3）。
5. **Str-3，agent communication flows**：决定一个 agent 的输出是否进入另一个 agent 的上下文（p.3–4）。

### E.2 单维优化：探索、监督配对与对比精炼

段落动作序列为：`setup_notation → state_problem → define_component → explain_mechanism → instantiate_algorithm → give_intuition → connect_to_prediction → connect_to_experiment → summarize`。

1. **Initialization of Collection**（p.3–4）：Semantic Initializer 接收 MAS/task 上下文、目标维度功能说明、one-shot example 和初始化数量，生成 agent/controller 集合；few-shot 场景也可生成 examples。它的机制是用受约束的语义变化探索 prompt/controller 空间（p.4，`explicit`）。
2. **Evaluation and Sampling**（p.4）：每个候选被嵌入其他 agent/controller 组成的 MAS，在训练数据上执行完整协作，按 MAS 总体性能打分。集合大小为 `n` 时，top `floor(n × h)` 为 positive，bottom `floor(n × l)` 为 negative，然后随机抽一对；默认 `l=h=0.5`。这种阈值采样旨在保持正负多样性（p.4，`explicit`）。
3. **Contrastive Reasoning for Optimization**（p.4）：Contrastive Comparator 比较正负 pair，归因性能差距，生成预期优于 positive 的 child prompt/agent/controller；child 加回集合并重新评估，循环至最大迭代数（p.4，`explicit`）。监督信号直接来自 training-set downstream performance；comparator 自身判断未承担监督角色（p.4，`explicit`）。
4. **示例**（p.4–5，图 2）：Fun-1 中 Semantic Initializer 生成两个 Programmer prompt，第二个要求代码包含 comments；对比后 Comparator 将 comments 的作用写入 child prompt。这是把性能差异转成 prompt 机制解释的具象例子（p.5，图 2，`layout_observation` + `explicit`）。

### E.3 多维优化与计算选择

多维算法不同时改变全部变量，而是每轮只优化一个维度并固定其余维度；例如先 Fun-1 再 Str-1，保留训练集最高候选，再优化下一维，直到最大迭代。作者的理由是让正负 pair 只在一个维度上变化，从而减少 Comparator 需要解释的交互变量（p.5，§3.3，`explicit`）。图 3 用流程图展示该循环。

推理阶段选训练集表现最高的 agent/controller 配置，再在 test set 执行（p.5，§3.4）。由于多维组合的成本增长，作者只纳入单维提升最大的维度，并在 §4.2 和 Appendix C.2.3 验证。这里的“optimize”是启发式 improvement，不是数学最优；论文没有提出收敛、全局最优或泛化保证（p.2 脚注 1；p.13、23 Appendix B/D.6）。

## H. 消融、负面结果与自我设限

### H.1 消融与机制识别

- **组件删除**：OMAC-C 删除 Contrastive Comparator，只用 Semantic Initializer 生成候选、在训练集评估并选最高者；在 MATH（Table 4）、HumanEval（Table 8）、MMLU（Table 9）均低于 OMAC（p.8、16–17）。识别目标是 Comparator 的额外 contrastive refinement。
- **同时改变多维**：Figure 7 对比 Figure 4，Comparator 同时生成两项时收益更小、方差更大；识别目标是一次只变一个维度的设计理由（p.16、18）。
- **超参数/规模**：Tables 5–7 改变 z、w、l/h；z 和 w 增大通常提升，阈值组合在 MATH 上波动有限（p.15–16）。
- **成本与鲁棒性**：Tables 10–13 报告推理、训练和子集评估成本；Tables 14–16 换 base LLM；Tables 17–18 换任务（p.17–20）。
- **失败/负面信息**：没有独立 failure-case 表或逐题失败分类。正文承认训练成本大、Comparator 偶尔生成劣于 positive 的候选；这些候选被重新标为 negative（p.21）。

正文中消融约占正文文字的 4%，有 1 个正文表（Table 4）和 3 个附录表（Tables 8–9 及同时改变维度的 Figure 7）。消融没有做“随机 child”“非对比等调用预算”或“固定同一候选生成次数”的额外替代机制，因此对 Comparator 的因果归因是有方向但不完全隔离的。

## L. 最终判断

1. **单一主线**：把 multi-step MAS 看作由 agent nodes 与 communication edges 组成的信息流图，用两类功能维度和三类结构维度统一定义可优化对象；Semantic Initializer 先探索 prompt/controller 语义空间，训练集性能形成正负 pair，Contrastive Comparator 反事实式地提炼 child，并以逐维循环实现多维协作。性能和推理成本是该主线的实证回收，不是第二条独立理论线。
2. **正文保留的决策关键内容**：五维定义、两个 actor 的循环、逐维固定其他变量的识别理由、默认 MAS/基线/三主任务、表 1–4 的主结果、图 4 的多维证据和推理/训练成本的核心结论。读者可据此理解为何比较、为何一次只改一维、为何结构维度与功能维度都需报告。
3. **移入附录的细节及其代价**：完整 prompt、role 和 step schedule、z/w/l/h 敏感性、跨模型与 MBPP/GAIA、成本表、同时改维度反例、训练/测试曲线、centralized/bias/theory 限定均在附录。迁移没有破坏主线自足性，但削弱了成本、外推和理论范围的即时可见性；若只读正文，会高估“holistic/general”的闭合程度。
4. **最有效的写作/图/表/公式模式**：将五维作为稳定名词体系，图 1/3 用流程图表达“候选→训练评估→正负采样→对比 child→回评估”，表 1–3 横向并排五维与基线，表 4 用 OMAC-C 做组件消融，图 4–7 用迭代曲线和同时改维度反例直接连接到“逐维固定”的机制解释。定义 `A : P × I → O` 足以限定对象；不堆叠没有证明作用的公式。
5. **最大叙事缺口/读者成本**：没有题目级配对结果、统计检验、随机 seed、硬件和完整成本账本；“显著”“comprehensive”“transferability”依赖小样本均值、选定组合和附录解释。训练成本相对推理收益的边界需要读者跨页拼合，3 比 1 比 1 总体 split 与各任务均分写法也造成复现歧义。
6. **可迁移规则**：当一个框架同时优化功能和结构时，先把变量拆成互斥且可单独干预的维度，再用同一训练信号、正负对和组件消融把每个维度连到可观察任务结果；联合优化必须同时展示交互变量的反例和成本曲线。
7. **适用边界**：该规则适用于黑箱 prompt/agent/controller 优化和多步骤协作图；不等于对真实参数学习的全局最优保证，也不能替代跨任务、跨模型、不同预算和题目级配对验证。集中式 MAS、memory/retrieval、复杂工具协作需要另外定义干预单元。
