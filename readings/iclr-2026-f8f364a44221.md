## 一句话主线

论文把 reasoning SFT 数据集当作一个可逐阶段优化的生产管线。作者固定 Qwen2.5-7B-Instruct、31,600 样本和八个主评测任务，逐步比较题源、混合、题目过滤、去重与多次采样、答案过滤及 teacher，最后以胜出的组合扩展到 OpenThoughts3-1.2M，并在 Qwen2.5-7B-Instruct 上得到 OpenThinker3-7B。证据主线位于 p.3–10 的 pipeline ablations、p.9 的最终配方与 p.1–2 的跨数据集结果；最强的可迁移结论是数据源质量、题目过滤和 teacher 选择带来的经验收益，结论仍受顺序选择、单一平均指标、外部 API 和高计算量约束。[p.3–9, §3–4, explicit]

## 方法与理论

### 形式对象与固定的管线边界

论文把训练数据抽象成 question–response pairs，把“最好数据集”操作性定义为在固定下游评测上产生最高性能的集合。每次策略实验生成 31,600 个样本，微调同一个 `Qwen2.5-7B-Instruct`，并把剩余步骤保持为当前管线选择。每个阶段按三域平均 benchmark score 选 top strategy，再进入下一阶段，默认 teacher 为 `DeepSeek-R1`。[p.3–4, §3.1, explicit]

Figure 2 将流程分成六个决策点。流程先从既有或生成题源取题，再混合题源，随后过滤题目、去重并重复采样答案，接着过滤答案，最后选择 teacher。这个图的价值在于把研究对象从“一个大数据集”改成一串可替换的数据生产动作。[p.4, Figure 2, explicit]

### 各组件的机制

1. **题源。** Code 使用 27 个 source，math 使用 21 个，science 使用 14 个。source 分为 fully synthetic、semi-synthetic 与 non-synthetic。对需要生成的 source，题目由 `GPT-4o-mini` 产生；所有题目随后都用 `DeepSeek-R1` 重新生成 response，因此原 source 自带答案不会直接决定训练响应。最强单源分别为 StackExchange CodeGolf/OpenCodeReasoning、OpenMath-2-Math、StackExchange Physics/Organic Chemistry PDF Pipeline。[p.4–5, §3.2; Appendix O.1, p.46–50, explicit]
2. **题源混合。** 从上一阶段排名中取 top (N)，对每个 source 随机取 (31,600/N) 个题并拼接，(N) 取 1、2、4、8、16。少量高质量 source 的平均结果高于扩大多源混合，code 的 top 2 相对 top 16 提升约 5 个百分点。[p.6, §3.3; Table 3, explicit]
3. **题目过滤。** 候选包括 GPT difficulty、LLM response length、AskLLM、embedding distance、FastText 和 random。code 的 winning strategy 是 `GPT-4o-mini` 按 ICPC difficulty 评分，math/science 的 winning strategy 是 `GPT-4.1-mini` 生成 response 后保留最长者。相对 random，math 和 code 的最佳过滤平均提升约 4% 和 6%。[p.6–7, §3.4; Tables 4, 37–39, explicit]
4. **去重与多答案。** 去重有 exact、fuzzy、none 三种；teacher response 每题采样 1×、4× 或 16×。最终跨三域统一使用 16×，math/science 用 exact dedup，code 用 no dedup。作者把多答案视为扩展 data scale 的另一条轴，并在 math 选第二优策略以换取可扩展性。[p.7, §3.5; Table 5, explicit]
5. **答案过滤。** 先生成 63,200 个 response，再过滤后抽取 31,600 个，以控制训练样本量。候选包括 random、LLM verification、majority consensus、FastText、最长/最短、英文检查和长段落检查。没有方法稳定超过不作过滤的 baseline，最终跳过答案过滤。[p.8, §3.6; Table 6, explicit]
6. **Teacher。** 比较 `DeepSeek-R1`、`QwQ-32B` 和 `Phi-4-Reasoning-Plus`，固定 sampling hyperparameters。`QwQ-32B` 在管线实验的跨域平均得分最高，尽管 Appendix H 的直接 teacher benchmark 显示 `DeepSeek-R1` 本身的经验能力更高。[p.8–9, §3.7; Tables 7 and 28, explicit]
7. **扩展。** 将各阶段 winning strategy 堆叠，先观察 316 至 31.6K 的 scaling，再按 850K math、250K code、100K science 组成 OpenThoughts3-1.2M，并在 `Qwen2.5-7B-Instruct` 上训练 OpenThinker3-7B。[p.9, §4; Figure 3, explicit]

方法段落动作序列可写为 `setup_notation → state_problem → define_component → explain_mechanism → instantiate_algorithm → connect_to_experiment → summarize`。它没有算法伪代码，算法边界由 Figure 2/3 和各节 Takeaway 组成；没有单独的目标函数或训练损失公式。理论模块不提供可证明性质，两个 displayed equations 只定义 normalized Indel similarity。[p.3–9, §3–4; p.25, §C; p.59, §O.3, explicit]

## 结果、统计与可视化

### 统计口径

主要聚合单位是每个数据 strategy 训练出的模型。每个 benchmark 先在题目集合或 repeated run 上取 accuracy，再计算 code/math/science domain average 与跨域 average。误差表达为 standard error 或 SEM；正文没有 hypothesis test、multiple-comparison correction、bootstrap、Bayesian analysis、regression 或 generic effect-size model。Table 1 的“within two standard errors”用于加粗判定，pipeline 阶段主要依赖平均分排序，不能等同于正式显著性检验。[p.5–9; p.24 Appendix B, explicit]

主实验报告了重复 run 数，但没有逐题或 seed-level confidence interval。MATH500 是一次完整 500 题 pass，CodeElo/CodeForces 的 score 还带 benchmark 自身的 Elo 解释。因而数字适合做配方决策和任务覆盖比较，无法从正文推出每个 stage 的独立因果效应或全局显著性。[p.24–25, Appendix B, interpretation]

### 主要结果清单

1. **最终模型与 held-out。** OpenThinker3-7B 在 Table 1 的 12-task average 为 55.3，DeepSeek-R1-Distill-Qwen-7B 为 42.9，差值为 12.4 个百分点；OpenThoughts3 在 held-out AIME25、LCB 06/24–01/25、HMMT 上分别为 53.3、51.7、42.7，且 HLE MCQ 为 10.2。[p.2, Table 1, explicit]
2. **跨数据集 scaling。** Figure 1 显示在 AIME25、LCB 06/24–01/25 和 GPQA Diamond 上，OpenThoughts3 曲线随数据规模总体高于 AM、Nemotron Nano、LIMO、s1.1 和 Qwen2.5-7B-Instruct；Figure 6 把比较扩展到 10 个任务，指出 AMC23、MATH500 在大规模处趋于饱和，HLE 对规模响应较弱。[p.1 Figure 1; p.28 Figure 6, explicit]
3. **题源质量。** Table 2 中 code 最强的 StackExchange CodeGolf 和 OpenCodeReasoning 的 code average 为 25.3、27.5；math 最强的 OpenMath-2-Math 与 NuminaMath-1.5 为 58.8、58.5；science 最强的 StackExchange Physics 与 Organic Chemistry PDF Pipeline 为 43.2、45.3。[p.5, Table 2, explicit]
4. **混合 source。** code 的 top 2 source 跨域 average 为 41.3，top 16 为 36.4；Table 35/36 表明 math/science 也以少量 top source 较优，尽管 math 的 top 1 高于 top 2，science 的 top 2 高于 top 1。[p.5 Table 3; p.67 Tables 34–36, explicit]
5. **题目过滤。** code 的 difficulty-based selection average 为 43.0，random 为 39.7；math 的 GPT-4.1-mini response-length selection average 为 41.9，random 为 35.2；science 的 GPT-4.1-mini length selection average 为 35.9，random 为 33.8。[p.6 Table 4; p.68–69 Tables 37–39, explicit]
6. **多答案和去重。** science 的 exact dedup + 16× average 为 36.2，no dedup + 1× 为 35.5；math 的 full table 中 exact dedup + 1× 反而为 41.7，高于 exact dedup + 16× 的 40.1。最终仍选 exact + 16× 以获得扩展轴，说明配方选择包含 scalability trade-off。[p.7 Table 5; p.70 Tables 40–42, explicit]
7. **答案过滤。** math 的不加过滤 average 为 41.9，random filtering 为 41.6，GPT verification 为 40.0；code 与 science 的 full tables 同样没有稳定收益，`Removing Long Paragraphs` 还明显下降。[p.8 Table 6; p.71 Tables 43–45, explicit]
8. **Teacher。** code ablation 中 QwQ-32B、DeepSeek-R1、Phi-4-Reasoning-Plus 的 average 为 44.2、42.3、29.0；math 和 science 的 Appendix P.6 也以 QwQ-32B 为最高。直接 teacher benchmark 则 DeepSeek-R1 的平均能力高于 QwQ-32B，形成“teacher quality 与自身 benchmark strength 不同”的观察。[p.8 Table 7; p.39 Table 28; p.72 Tables 46–48, explicit]
9. **Scaling stack。** Figure 5 显示逐阶段堆叠 winning strategy 会把 scaling curve 向上移动，作者把最大收益归因于 source selection、question filtering、teacher selection；science 最终 teacher curve 不是最高，因为 winner 按三域 average 选择。[p.27 Figure 5, explicit]
10. **Base model transfer。** 100K OpenThoughts3 微调后，Qwen2.5-7B-Instruct 在 AIME24 为 54.3，Llama-3.1-8B-Instruct 为 37.0；相对各自 base，Llama 在 AMC23、MATH500、LCB 的提升更大，但 Qwen 的绝对结果更高。[p.29–30, Appendix D.1; Table 13, explicit]
11. **验证与 trace。** OpenThoughts-114K 上 verification 对 7B 有害、对 32B 有益；移除 proof-based questions 平均下降 5.6；移除 self-reflection 把 trace 从 11.6K 降到 0.3K，平均相对下降 49.1；过滤掉超过 2,048 tokens 的 trace，平均相对下降 33.3。[p.30–34, Tables 14–17 and 21, explicit]
12. **Annotator 与 test-time compute。** Claude 3.7 的 thinking-token budget 增大时，AIME24 从无 thinking 的 18.0% 升至 62,976 tokens 时 51.3%，LCB 从 60.5% 升至 70.4%，GPQA 在约 12,288 tokens 后趋于平台；但 Claude 替换 R1 做 code/science/S1 annotator 没有带来下游收益。[p.32–33, Figure 8 and Tables 18–20, explicit]
13. **跨域 transfer。** 单独 code 数据的 GPQA-D 为 47.3 或 36.7，和强 science 数据混合后两者都为 52.7，说明 code-to-science 的差异在加入 in-domain science 后消失。[p.35, Table 23, explicit]
14. **短回答与正确性。** AIME24 上 DeepSeek-R1-Distill-Qwen-7B 的 shortest、longest、majority、vanilla 为 66.67、36.67、76.67、55.00；GPQA 高 run 实验显示 shortest 多数情况下高于 longest。错误回答通常更长，例如 OpenThinker-7B 在 AIME24 的 incorrect/correct 平均 token 为 19,517/8,966。[p.36–38, Tables 24–26, explicit]
15. **Safety trade-off。** Harmbench harmfulness rate 从 Qwen2.5-7B-Instruct 的 14.5 上升到 OpenThinker3-7B 的 55.5，XSTEST over-refusal rate 为 4.4 与 5.6；作者指出 reasoning SFT 未含 safety tuning，可能损害原有 safety alignment。[p.40, Table 29, explicit]
16. **AIW robustness。** Figure 11/12 显示 distilled reasoning models 的平均正确率高于 conventional LLM，但在保持抽象解不变的 Friends/Circles/Colleagues variations 上仍有强烈波动。OpenThinker-32B 在不同 variation 间可从接近 1 降到接近 0，closed models 的波动较小。[p.40–43, §K, Figures 11–12, explicit]

作者对不利解释的处理主要靠配对附录实验。Appendix D 说明 scaling 曲线有 dips/jumps，Appendix E 给出 verification、trace length、annotator 和 transfer 的负面结果，Appendix I 报告 safety degradation，Appendix K 报告 structure-preserving variation 的 generalization deficit。这些结果让“recipe 有效”与“能力具有普遍机制”保持可区分。[p.28–43, layout_observation]

## 消融、负面结果与自我设限

主文的 §3.2–§3.7 本身就是 pipeline ablation，约占正文有效文字的 20% 左右，包含 Tables 2–7。附录进一步增加 Tables 14–27、Figures 5–12 及完整 Tables 31–48。识别目标覆盖组件删除、超参数、数据异质性、替代机制、计算成本、鲁棒性和部署边界。[p.4–9; p.27–43; p.65–72, explicit]

|---|---|---|
| question source | source quality 与合成/人工来源 | source 间差距大；未建立 source 属性的独立因果分解；p.5、p.65–66 |
| source mixing | diversity 与质量 trade-off | top 1/2 胜过 top 8/16；依赖上一阶段排名；p.6、p.67 |
| question filtering | LLM quality proxy 与 classical filter | difficulty/length 胜出；filter annotator 本身的偏差未独立估计；p.6–7、p.68–69 |
| dedup × sampling | question diversity 与 answer diversity | 16× 带来规模轴；math 最优单次采样与最终扩展选择有差异；p.7、p.70 |
| answer filtering | correctness、长度、语言、段落结构 | no-filter 与多数策略相近，verification 未带稳定增益；p.8、p.71 |

更实质的边界来自实验选择规则。每一步只保留按三域 average 排名最好的策略，science 的局部 winner 可能因此让位于整体平均更高的策略；Appendix D 直接承认 Figure 5 的 science teacher curve 受该设计影响。[p.27, Figure 5, explicit]

## 最终判断

1. **单一主线。** 公开 reasoning SFT 的关键决策可以被拆成 source、mix、question filter、dedup/answer sampling、answer filter、teacher 六个阶段；用小规模受控实验做阶段选择，再把 winning recipe 扩展为 1.2M 数据集。
2. **正文保留的决策关键内容。** 正文保留每阶段的候选类别、31,600 样本控制、八个主 benchmark、winning strategy、Tables 2–7、Figure 2/3、最终数据配比和 Table 1 的 held-out 结果。这足以让读者理解“为何采用该 recipe”。
3. **移入附录的内容。** 完整 source 长尾、所有 filtering/answer filtering 组合、训练和 Evalchemy 配置、decontamination、重复 run、prompt、compute、license、safety、AIW 和 negative ablations 均在附录。迁移没有破坏 recipe 选择的可读性，却提高了复现和审计成本。[p.20–72, Appendices A–P]
4. **最有效的写作、图、表和公式模式。** Figure 2 先把可枚举决策点画成管线，Figure 3 再把最终数据流和样本量画成实例；每节使用“结果表 → Takeaway → 下一阶段”的节奏；Table 1 同时放主域和 held-out 域。公式保持最小化，只给去污染与 dedup 所需的 Indel 定义。
5. **最大叙事缺口。** “QwQ-32B 是更好的 teacher”是下游 utility 的经验判断，不等于 teacher 的内在能力、trace correctness 或机制解释；阶段 winner 又按跨域 average 顺序锁定。seed、保留率、完整实验轨迹和多重比较缺失，削弱了逐阶段因果闭环。
6. **可迁移规则。** 把大型数据 recipe 写成可复现的顺序决策链，每个节点固定其余条件、报告 winner 及完整长尾结果，并在正文同步放置 held-out 和负面边界。[p.3–10, p.65–72]
7. **适用边界。** 该规则适合存在可训练代理模型、可重复下游评测和高成本数据生产的 SFT pipeline。它不能自动推出 RL、curriculum、不同 base model、不同 teacher objective 或部署安全性质的普遍结论。[p.10, p.29–30, p.40, p.44]
