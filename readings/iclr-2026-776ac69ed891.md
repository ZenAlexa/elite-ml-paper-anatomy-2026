## 5. 方法与理论

### 5.1 概念对象与最小逻辑单元

1. **setup_notation：vectorization 的广义定义。** Vectorization 被定义为把处理 single data point 的 operation 转成同时处理 collection 的 operation；作者将其与 compiler 中的 SIMD substitution 区分。[p. 4，§3.1，“transformation of an operation that processes a single data point”]
2. **define_component：沿 axis 的 lifting。** 对 n-dimensional tensor，沿长度为 l 的 axis 对 (n−1)-dimensional sub-tensors 重复调用 elementary op；这建立 vectorized axes 与 argument sub-tensor axes 的边界。[p. 4，§3.1，“applied to each of the l separate”]
3. **give_intuition：loop notation。** `for i: y[i] = sin(x[i])` 作为 conceptual representation；多层 loops 对应 successive one-dimensional vectorizations，代码不规定实际 backend implementation。[p. 5，§3.1，“only for conceptual reasons”]
4. **explain_mechanism：broadcasting 与 non-scalar elementary op。** 通过 `z[i,j]=x[i]*y[j]` 说明 subset loop variables 产生 broadcasting；通过 `y[:,i]=softmax(x[:,i])` 区分 operation-applied axes 与 vectorized axes。[p. 5，§3.1，“argument sub-tensor axes”]
5. **state_problem：适用范围。** 后续只考虑对 loop/index 顺序不敏感的 operations，并省略 loops；这是概念定义的假设边界。[p. 5，§3.1，“invariant to the order of the loops”]
6. **derive：dot decomposition。** Matrix multiplication 写成 `z[i,j] = dot(x[i,:], y[:,j])`；matmul、dot、tensordot、inner 共享 dot primitive，但 vectorization pattern 不同。[p. 5，§3.2，“represented conceptually as a vectorized dot-product”]
7. **derive：sum decomposition。** np.sum(x, axis=1) 可用 vectorized sum(vector)→scalar 或 scalar += 两种 elementary choices 表达，说明 primitive 粒度并不唯一。[p. 5，§3.2，“two alternative choices for the elementary operation”]
8. **derive：multiply/identity/broadcasting。** Outer、Hadamard、Kronecker、Khatri–Rao 被归为 scalar multiplication 的不同 vectorization；transpose/reshape 是 vectorized identity；broadcast/tile/repeat 是 output-only vectorization 的 identity。[p. 5，§3.2，“represented as vectorized scalar multiplication”]
9. **define_component：indexing primitive。** take/gather/take_along_dim/index_select 被统一为 get_at 对 coordinate vector 的 elementary lookup，沿 image channel/pixel 轴 vectorize。[p. 6，§3.2，“Retrieve a single value from an n-dimensional value tensor”]
10. **summarize：普适性跳转。** p. 6 的「many operations reduce to few elementary operations」将 §3 的 decomposition 直接接到 §4 notation；这是论文最短的因果桥。[p. 6，§3.2，“few elementary operations”]
11. **instantiate_algorithm：统一 API。** einx.{elementary_operation}("{vectorization}", inputs) 由 primitive entry point 和 vectorization string 组成；输出可显式列出。[p. 6，§4.1，“{outputs...} = einx.{elementary_operation}”]
12. **define_component：表达式生成。** 先把 desired operation 写成 loops，再把 tensor sub-expression 的 `:` 换成 bracketed symbolic axes；arrow 分隔 input/output，comma 分隔 tensors，space 分隔 axes。[p. 6，§4.1，“Replace colons with new symbolic axis names”]
13. **explain_mechanism：bracket semantics。** Bracketed axes 是传入 elementary operation 的 sub-tensor axes，未加 bracket 的 axes 负责 vectorization；同名 axis 约束长度一致。[p. 6，§4.1，“Axes not marked with brackets are vectorized”]
14. **define_component：axis composition。** Parentheses表示同一 tensor 内按 row-major flatten 的 composed axis；(b+c) 与 plus operator 表示跨 tensors 的 concatenated axis，后者扩展了 einops 的 composition。[p. 7，§4.1，“concatenated axis”]
15. **define_component：constraints 与 ellipsis。** Keyword axis constraints、numeric anonymous axes、axis-attached generalized ellipses、composed-axis ellipses 和 anonymous ellipsis 让 expression 覆盖未知 rank/shape；implicit output 在可能时由 inputs 推断。[p. 7，§4.1，“The number of expansions is determined”]
16. **connect_to_prediction：custom operation。** adapt_with_vmap 将任意 Python function 变成 einx operation；作者以 myop 和 loop invocation 说明 notation 与 backend vmap 的连接。[p. 7–8，§4.2，“vectorizes a custom Python function”]
17. **explain_mechanism：declarative/imperative 对照。** 用户只写 input/output shape expression，系统决定 reshape、broadcast、transpose；作者将 einx.add("a d e, c b e -> a b c d e") 对照多步 Numpy-like expression。[p. 8，§4.2，“specifies what the inputs and outputs look like”]
18. **give_intuition：可解释性。** Loop analogy 提供 output semantics，同时允许优化 backend algorithm；这把 human-readable specification 与 execution plan 分开。[p. 8，§4.2，“underlying backend implementation”]
19. **connect_to_experiment：changing shapes。** 对 get_at 只改变 vectorization string 即可加入第二个 indexing axis、额外 axis 或 2D indexing；Numpy-like API 需要切换 function 或没有 single entry point。[p. 8，§4.3，“keeps the entry-point fixed”]
20. **contrast_alternative：silent-failure risk。** einsum 把 dot/sum/multiply/id 放到一个 entry point；作者用 ij,ik->ik 的 typo 说明可能 silent sum-reduction，einx.dot 则以 brackets/signature 检查并抛错。[p. 8，§4.3，“fails silently” / “fails loudly”]
21. **contrast_alternative：axis clarity。** 复杂 contraction 中，einx bracket 显式标出被 summed 的 k；einsum 的未区分 axis names 需要读者推断。[p. 8，§4.3，“Only k is summed along”]
22. **instantiate_algorithm：compiler 三阶段。** Appendix D 细化为 AST parse/ellipsis expansion/axis-size solving，computational graph with tracers，topologically sorted isolated Python snippet；§4.4 说明 compilation/cache/JIT 行为。[p. 9，§4.4；p. 16，Appendix D]

方法动作序列为：setup_notation → define_component → give_intuition → state_problem → derive → summarize → instantiate_algorithm → explain_mechanism → connect_to_experiment → contrast_alternative → instantiate_algorithm。其关键因果链是「loop semantics → primitive/vectorization factorization → bracketed DSL → AST/graph/code generation」；方法部分没有以 benchmark 分数作为收束。

### 12.3 可迁移写作判断

1. **单一主线**：用 generalized vectorization 把复杂 tensor API 重新表述为 primitive operation + explicit shape/vectorization；einx 是该语义分解的可执行 DSL，compiler 把 DSL 变成 backend calls。[p. 4–9]
2. **正文应保留的决策关键内容**：Numpy-like failure examples、Table 1/2、vectorization 的两方向定义、bracket/axis-composition grammar、MHA three-line case、einx 与 backend/exception 的运行关系。它们共同回答“为何需要、如何写、如何解释、如何执行”。[p. 1–10]
3. **适合移入附录的内容**：A/B 的长对照、C 的 expression catalogue、D/E 的 compiler/code snippets、F 的 exception outputs、G/H 的 timing/adoption tables。迁移保留了主线，但正文没有数值/复现自足性；Table 3 的不确定性定义与 Table 4 的 query/sample details 仍应补齐。[p. 13–20]
4. **最有效的模式**：先用 Table 1 把多个真实 API 映射到少数 primitive，再用 loop notation 解释 brackets，随后用 MHA 把 code length、axis semantics、mask 和 decomposition 放在一个复杂例子中；Appendix E/F 用可运行 code/error 让抽象 grammar 有可观察输出。[p. 2、5–10、17–19]
5. **最大叙事缺口**：universal、any tensor operation、clean/readable、seamless 与 no overhead 的语言强度超过实证设计；没有用户研究、全 API coverage audit、formal completeness proof 或跨 backend timing。order-invariance 与 einx.id concat 限制也分散在正文/附录，增加读者拼接成本。[p. 1–2、5、8–10、15、20]
6. **可迁移规则**：设计统一 notation 时，先给一个可执行的 primitive semantics，再把每种 vectorization 变体显式写在同一 expression；用一个复杂真实程序同时展示 readability、错误诊断和 backend compilation，避免只给孤立语法表。[p. 6–10]
7. **适用边界**：该规则适合有明确 shape/index semantics、可拆为 primitive 与变换的 DSL/API；它本身不能证明用户更快、更少出错、运行更快或生态 adoption 更高。顺序敏感操作、后端特有副作用、未建模的 security/trust boundary 需要单独语义与实验。[p. 5、9、15–20]
