## E. 方法与理论

### 逻辑单元与动作序列

1. `setup_notation`：把 reasoning graph 写成 (G(Q,A)=\{(q_t,m_t,r_t,a_t)\}_{t=1}^T)，并定义 (r_t=R(q_t,m_t))、(A=f(\{a_t\}))。[p. 3, Eq. (1), `explicit`]
2. `state_problem`：指出既有 benchmark 对长链、跨模态和结构依赖覆盖不足，设定 five topology 的设计目标。[p. 3, §2/§2.1, `explicit`]
3. `define_component`：定义 Image-Initiated Chain、Text-Initiated Chain、Parallel Image-Text Fork、Multi-Images Fork、Text-Only Chain，并说明串行/并行依赖。[p. 3–4, §2.1, `explicit`]
4. `instantiate_algorithm`：从 Wikipedia 的 text/image cluster 采集 facts，使用 Gemini-2.5-Flash 生成约 21k 候选链。[p. 4, Data Generation, `explicit`]
5. `derive`：用移除 evidence 后的 F1 下降定义 `Util(t)`，把证据必要性转成可计算量。[p. 4, Eq. (2), `explicit`]
6. `derive`：用 intermediate answer 的 entity 是否出现在后续 sub-question 定义 `Nav(t)`，补足前一步对后一步导航的作用。[p. 4, Eq. (3), `explicit`]
7. `explain_mechanism`：先用 Qwen2.5-VL-7B 去除超过两个 redundant hops 的样本，再由 Gemini-2.5-Pro 做 hop shrinkage/verification，最后用 Gemini-2.5-Flash 做 redundancy check。[p. 4, Data Filtering, `explicit`]
8. `connect_to_experiment`：通过过滤同一 topic cluster 中可独立回答 sub-question 的未使用 evidence，力图保证每题 reasoning graph 唯一。[p. 4, Data Filtering, `explicit`]
9. `define_component`：定义 F1、ΔF1、Golden F1、LLJ 四个 answer-level 指标，并把 LLJ 拆为 answer accuracy、reasoning coherence、entity coverage、step alignment。[p. 5, §2.2, `explicit`]
10. `derive` → `connect_to_prediction`：用精确证据匹配定义 HPS，用预测/黄金链长度差定义 RD；两者分别对应 step retrieval fidelity 与 over/under-retrieval。[p. 5, Eqs. (4)–(5), `explicit`]
11. `instantiate_algorithm` → `explain_mechanism`：pipeline 循环执行 sub-query/action generation、evidence acquisition、iterative reasoning/synthesis；动作空间为 text search、image search with text query、image search with input image。[p. 5–6, §3.1, `explicit`]
12. `define_component` → `connect_to_experiment`：SEARCH-ALIGN 将 HAVE 链补成含 `<Thought>` 的 conversation trace，再以 SFT 训练 open-source MLLM，监督 planning、modality choice 和 evidence integration。[p. 6, §3.2, `explicit`]

动作转移序列为：`setup_notation → state_problem → define_component → instantiate_algorithm → derive → derive → explain_mechanism → connect_to_experiment → define_component → derive → instantiate_algorithm → define_component`。

### 方法对象、复杂度与解释粒度

- 形式化对象是问题 (Q)、答案 (A)、每一 hop 的 sub-question (q_t)、modality (m_t\in\{text,image\})、retrieved evidence (r_t) 和 intermediate answer (a_t)；pipeline 的输出是 final answer 与可记录的预测链。[p. 3、5–6, Eqs. (1)/(4)/(5), `explicit`]
- 论文没有给出时间复杂度、空间复杂度或检索编码器的渐近分析；每步保留 top-1 evidence，模型迭代次数受统一最大值约束，但最大值本身在正文未给出。[p. 6, Evaluation protocol, `not_present`]
- 伪代码数量为 0；Figure 2 是流程图，不是 algorithm listing。方法解释覆盖到三个 action、top-1 evidence、sub-answer feedback 和 stop/continue 决策，但没有逐项展开 implementation-level API。[p. 3、6, Figure 2/§3.1, `explicit`]
- 方法图 1 个（Figure 2）承担 benchmark construction 与 pipeline 总览；方法表 1 个（Table 2）承担 topology 样本数、知识库规模和平均 hops。[p. 3–4, Figures 2/Table 2, `explicit`]

### 理论角色

正文没有 theorem/lemma/proposition/corollary。Appendix M 将 trace 限定为带 modality 的 DAG，并进一步限定为 Linear 或恰含一个合并分支的 Fork；随后按 initiation modality 与 branch modality 穷举五类 topology。[p. 30, Appendix M, `explicit`]

Appendix M 的理论是**在给定结构假设下的覆盖保证**，不是关于模型性能的定理：Text-Text parallel branch 被解释为可折叠到 Text-Only Chain，因此保持 topology 集合最小。证明位置是 M.2 的文字版 case split，没有独立 formal theorem 环境或实验验证。[p. 30, M.1–M.3, `explicit`]

## G. 结果、统计与可视化

### 统计约定

- 主结果以 sample-level 汇总的 F1、ΔF1、LLJ、HPS、RD 和 Golden F1 报告；正文没有说明均值的置信区间、标准误、bootstrap、显著性检验或多重比较校正。[p. 5、7, §2.2/Table 3, `explicit`]
- HPS 的分母是 golden chain hop 数，匹配是 exact evidence match；RD 是预测 hops 减 golden hops。Table 4 的分母是各 modality 的 golden steps，报告 covered/gold 与百分比。[p. 5、9, Eqs. (4)–(5)/Table 4, `explicit`]
- LLJ 使用 Gemini-2.5-Pro 对四个 0–5 维度评分；Appendix G 另报告 Pearson、Spearman、Bland–Altman mean bias 和 LoA，但正文主表只保留 LLJ 汇总值。[p. 5、23–24、35, `explicit`]
- 结果单位主要是 sample、gold step、validation split 或随机抽样子集；Appendix G 的跨模型 LLJ 使用五个各 10% 的 non-overlapping subsets，人工一致性使用 100 条预测。[p. 23–24, G, `explicit`]

### 结果清单

1. **数据规模与链深度。** 最终 benchmark 为 3,333 条，平均 3.79 hops；Image-Initiated 1,306 条、Text Chain 945 条、Parallel Visual-Textual Fork 680 条、Multi-Images Fork 233 条、Text-Initiated 169 条。[p. 4、22, Table 2/Table 7, `explicit`]
2. **数据质量。** Gemini-2.5-Pro 四维评分为 factual correctness 4.93、step necessity 4.70、clarity 4.88、multimodal alignment 4.95，平均 4.87/5。[p. 22, Table 8, `explicit`]
3. **主模型表现。** Table 3 中 Gemini-2.5-Pro 在多数 topology 的 backbone F1 较高；Image-Initiated Chain 的 F1 为 47.61、HPS 为 25.90、RD 为 1.05，Golden F1 为 69.83。[p. 7, Table 3, `explicit`]
4. **SEARCH-ALIGN 主增益。** 论文按 topology 平均总结：InternVL 的 F1 约 +2.8、HPS +12.0、RD −0.6；Qwen 的 F1 +13.7、HPS +16.0、RD −3.1。[p. 7, §4.2, `explicit`]
5. **Topology 难度。** Parallel Image-Text Fork 对所有 backbone 的 F1 与 HPS 最低；Multi-Images Fork 的问题集中于视觉证据的对应和整合。[p. 8, Topology-Specific Challenges, `explicit`]
6. **链长效应。** Figure 3 显示链从 1–3 hops 延长到 4–5 hops 后，各模型 F1 明显下降；Gemini-2.5-Pro 在长链段相对稳健，Qwen2.5-VL-7B 整体较弱。[p. 8, RQ2/Figure 3, `explicit`]
7. **过度/不足检索。** Figure 4 中 ΔStep < −2 的严重 under-retrieval 使性能锐降；ΔStep=1–2 的适度 over-retrieval 对 Gemini-Pro、Gemini-Flash、InternVL 有利；ΔStep≥4 时噪声导致下降。[p. 8, RQ3/Figure 4, `explicit`]
8. **模态覆盖。** Query with Image 时，Gemini-Pro 的 image coverage 为 87.35%，无 image query 时降至 29.50%；InternVL 相应从 63.84% 降至 0.66%。Overall image/text coverage 分别为 Gemini 64.27%/80.48%、InternVL 33.69%/85.96%。[p. 8–9, Table 4, `explicit`]
9. **错误类型。** Figure 5 的八类错误中，Retrieval-Failure 84.70%、Hallucinated-Entity/Attribute 75.75%、Step-Omission 74.34% 最常见；Evidence-Misinterpretation 8.35% 最少。[p. 9, RQ5/Figure 5, `explicit`]
10. **single-step baseline。** Appendix D.1 的 fixed one-step retrieval 对复杂链支持不足；Gemini-Pro 在 image-initiated chain F1 2.34、LLJ 0.13，Qwen 在同一结构 F1 40.31、LLJ 1.62，反映 abstention/overconfidence 行为差异。[p. 20, Table 5, `explicit`]
11. **fixed two-hop baseline。** Appendix D.2 报告 two-hop 相比 single-step 在 multimodal 结构有改善，但仍缺少自适应 hop 数和跨模态整合；Parallel Image-Text Fork 的 Gemini-Pro F1 为 4.03、HPS 10.87，低于 agentic Table 3 的相应结果。[p. 21, Table 6, `explicit`]
12. **LLJ 跨模型一致性。** Gemini/GPT-5 的 Pearson=0.9330、Spearman=0.8720；Gemini/Qwen 的 Pearson=0.9147、Spearman=0.8145；三组 mean bias 的绝对值均小于 0.04。[p. 23, Table 9, `explicit`]
13. **LLJ 与人工一致性。** Accuracy 的 Pearson/Spearman 为 0.9632/0.9556，Entity Coverage 为 0.9375/0.8691，Coherence 为 0.6061/0.8200，Alignment 为 0.9275/0.7925。[p. 24, Table 10, `explicit`]
14. **替代 ground truth。** 用 GPT-5 重新生成每种 topology 各 50 条链后，Gemini-Pro 与 GPT-4o-mini 的 F1/LLJ 仍保持相近的模型顺序，但 Text-Initiated 的 Gemini-Pro F1 从 GPT ground truth 34.91 到 Gemini ground truth 43.71。[p. 24, G.3/Table 11, `explicit`]
15. **过程错误改善。** InternVL 经 SEARCH-ALIGN 后，Modality-Mismatch 从 65.75% 降到 34.72%，Step-Omission 从 86.15% 降到 73.66%，Order/Dependency-Error 从 31.06% 降到 28.18%，Retrieval-Failure 从 80.28% 降到 76.76%。[p. 25, H/Figure 7, `explicit`]
16. **soft HPS。** Gemini-Pro 的 Text Chain HPS 从 exact τ=1.0 的 21.59 增至 τ=0.85 的 41.26；Gemini-Flash 相应从 13.33 增至 30.97，说明 exact miss 中存在 semantic-neighbor retrieval。[p. 26, Table 13, `explicit`]
17. **top-k 下的检索深度。** Gemini-Flash 在 k=1、3、5 下都表现出严重 under-retrieval 伤害与大幅 over-retrieval 伤害；k 增大后，过度检索的负效应更强。[p. 26–27, K.1/Figure 8, `explicit`]
18. **top-k 下的 SEARCH-ALIGN。** Qwen 的 Image-Initiated F1 在 Retrieval@1/3/5 为 26.30/29.21/29.35，SEARCH-ALIGN 后为 45.70/47.19/47.29；对应 HPS 从 16.51/16.17/16.95 提升到 33.59/39.45/41.79。[p. 27, Table 14, `explicit`]
19. **case study 成功例。** Figure 9 中 agent 依次找回 Annunciation、Philadelphia Museum of Art、购买日期/价格和美国博物馆意义，最终答案覆盖关键实体。[p. 28, L.1/Figure 9, `explicit`]
20. **case study 失败例。** Figure 10 中 agent 找到 SamTrans 与 San Carlos，却两次检索不到 establishment year/mainline service，最终答案缺少两个关键事实。[p. 29, L.2/Figure 10, `explicit`]

主要可视化把“结构”与“执行”分开：Figure 2 是机制流程，Figure 3–5 是跨样本诊断，Figure 6–8 是附录的评审/稳健性检验，Figure 9–10 是链级 qualitative case study。表格则按 benchmark composition、主模型、modality coverage、fixed baselines、quality/consistency、fine-tuning 和 top-k 组织。[p. 3、7–9、20–29, Figures 2–10/Tables 2–14, `interpretation`]

## L. 最终判断

1. **单一主线。** 论文的主线是把 multimodal agentic search 从“最后答案是否正确”改写为“是否沿必要且非冗余的、带模态选择的长 reasoning chain 检索了正确证据并在适当位置停止”；MC-SEARCH 提供 topology/chain 数据，HAVE 过滤链，HPS/RD/LLJ 记录过程，SEARCH-ALIGN 再把过程链用于 SFT。[p. 3–7、24–27, `explicit`]
2. **正文保留的决策关键内容。** 正文保留五类 topology 定义、HAVE 的两项判据、三模块 pipeline、五个 RQ、Table 3 主结果、Figure 3–5 的负面模式和 Ethics 边界。这些对象共同决定 benchmark 是否能识别长链、模态和停止行为。[p. 3–10, `explicit`]
3. **迁入附录的细节及其影响。** fixed baselines、数据/质量统计、LLJ 与人工一致性、训练超参数、soft HPS、top-k、case study、理论 case split 和 N–P prompt 全部迁入附录；迁移没有削弱正文的决策闭环，但降低了只读正文者对分母、评审可靠性和复现路径的可见度。[p. 9、20–35, `interpretation`]
4. **最有效的模式。** Figure 2 把数据构造和执行 pipeline 放在同一张图中，Table 3 以 topology 分组并并列 Answer Accuracy/Chain Alignment，Figures 3–5 紧跟 RQ2–RQ5；这种“对象、过程、诊断”顺序让过程指标与最终答案保持区分。[p. 3、7–9, `layout_observation`]
5. **最大缺口。** “faithful evaluation”“first benchmark”与 SEARCH-ALIGN 的能力改善仍分别依赖生成模型过滤、LLJ 评审和前后训练对照；正文没有 random seed、完整 causal design 或人工全量标注，因此这些主张的证据边界弱于 benchmark 构造事实。[p. 4–7、23–25、35, `interpretation`]
6. **可迁移规则。** 若论文主张 agentic/long-horizon capability，应把每个决策单位的必要证据、动作模态、链长度和停止行为作为 claim-bearing artifacts，并同时展示固定 baseline、过程错误和至少一个失败链，避免仅报告 final-answer score。[p. 4–9、20–21、29, `interpretation`]
7. **适用边界。** 该规则适合有离散检索动作、可标注中间证据且错误会沿 hop 累积的 agentic QA；它不直接覆盖开放式生成、连续控制、无可验证 intermediate evidence 或允许多文档联合检索而无法定义唯一 hop 的任务。[p. 3–6、30、34, `interpretation`]
