## 5. 方法、理论、公式与算法

### 5.1 形式化对象与主线

DiffMPC 处理参数化的 OCP。状态 `x_t`、控制 `u_t` 和 `z=(x,u)` 构成优化变量；`c_t^{x,θ}`、`c_t^{u,θ}` 是 separable state/control costs；`f_t^θ(x_{t+1},x_t,u_t)=0` 是 equality dynamics；`x_0=x_s^θ` 是参数化初值。参数 `θ` 可以是 neural-network cost/constraint 权重、intermediate layer outputs 或 physics-model parameters。【p.1 OCP；p.3 §3；`explicit`】

通用 DO primer 先定义 equality-constrained `P`、KKT pair `(z,λ)`，再用 IFT 将 forward solution 的 sensitivity 化成线性系统。OCP 的 forward pass 采用 SQP 与 line search，把非凸问题局部化为 linear-quadratic QP；backward pass 复用 forward 的 KKT matrix，用 VJP 解一次伴随线性系统。GPU 核心是把 KKT 的 Schur complement 交给 PCG，并以 symmetric stair/tridiagonal preconditioner 保留 block-tridiagonal 结构，随后按时间并行恢复 `x_t,u_t`。【p.3–5 §2.2–§3.3；`explicit`】

主逻辑序列为 `setup_notation → state_problem → derive → define_component → explain_mechanism → instantiate_algorithm → connect_to_experiment`。Eq. (1)–(3) 先解释 differentiable optimization，Eq. (4)–(11) 把 OCP、SQP、KKT、Schur/PCG 和并行恢复接起来，Eq. (12)–(14) 再将 solver 接入 RL/IL policy。

### 5.3 算法、数据流与复杂度

|算法|输入、循环、输出|关键不变量与正文覆盖|

## 12. 最终判断

**单一主线。** 论文先把 differentiable MPC 的 forward OCP solve 与 backward sensitivity 统一成可复用的 KKT/IFT 线性系统，再以 Schur complement、symmetric stair preconditioner、PCG、time parallelism 和 warm-start 把这条系统放到 GPU，最后用 RL/IL timing 与 domain-randomized drifting 验证「可学习的 MPC solver」这一工具链。核心因果链是 `OCP structure → SQP/IFT KKT systems → PCG with tridiagonal preconditioning → GPU parallelism/warm-start → faster learning and robust drifting`。【p.3–8；`interpretation`】

**正文保留的决策内容。** 主文保留 OCP 定义、KKT/IFT/VJP、SQP/PCG 主机制、Figure 2 architecture、Figure 3–4 timing/IL 曲线、Figure 5–8 drifting pipeline/trajectory/photo、4× speed claim、14-hour training、100% vs 70% simulation result，以及 inequality constraints、CPU、hyperparameter、initialization 的限制。读者能理解方法与主要决策，但 benchmark 分母、baseline code modification、exact tolerance、vehicle model、deployment solver 和附加硬件证据需转 Appendix。

**附录迁移。** Appendix 把 Algorithm 3–4、line-search constants、six-problem timing table、gradient finite-difference check、warm-start sweep、cart-pole dynamics、vehicle randomization 和 one-trial hardware result集中起来。迁移保留了正文叙事的简洁性，却让「4×」的任务覆盖、误差分母、PCG tolerance 的选择、simulator/MPC mismatch 和 hardware external validity需要跨页重建。

**最有效的模式。** Figure 2 与 Algorithm 1–2 把 forward/backward 共享矩阵画成数据流；Eq. (8)–(11) 以 `KKT → Schur → PCG/preconditioner → parallel recovery` 的连续编号把系统机制压缩成可追踪链；Figure 3 的 CPU/GPU、Fwd/Bwd 分组和 Figure 4 的 learning/model 双曲线让 solver speed 与 learning utility 同时可见。Table 3 在附录补出六个 problem 的 mean/2σ，避免主文图单独承担全部 timing 证据。

**最大缺口。** DiffMPC 的整体能力得到多任务支持，但 PCG、preconditioning、warm-start 与 GPU speed 的单独因果效应未通过 matched removal 或 Riccati control 识别；复杂 inequality constraints、gradient discontinuity 和 initialization divergence 没有正面实验；真实车结果以照片和一次 additional hardware trial 为主。正文缺少统一 scaling curve、loss wall-clock 数值和主 benchmark 的重复不确定性。

**可迁移规则。** 系统型 differentiable-optimization 论文应把 forward objective、backward sensitivity、结构化线性代数和部署数据流用同一组公式/算法闭合，再让每项性能主张对应明确的设备、问题族、重复单位和误差表达。该规则适用于 solver、control layer 和 optimization-as-a-module 工作；当部署路径、约束处理或硬件条件与训练路径不同，结论应主动拆成数值 benchmark、模拟闭环和硬件示范三个范围。
