## E. 方法与理论

### E.1 最小逻辑单元与机制链

1. **setup_notation / state_problem（p.3）**：定义数据集 `D={L_i,q_i,a_i}`，要求问题和答案来自真实数据、解题需依赖完整 `L_i`、难度足以产生 RL 信号。证据为`constructed under three principles`（p.3，§3.1，`explicit`）。
2. **derive（p.3）**：从 `{oL_i, oq_i, oai}` 先插入 distractor 得 `L′_i`，再插入多跳 key–value chains 得 `{L_i,q_i,a_i}`，且 `a_i=oai`。证据为`first expanded into a long input L′i of 16K tokens`（p.3，`explicit`）。
3. **define_component（p.3–4）**：从 HotpotQA、MuSiQue、2WikiMultiHopQA 的 277K QA 中用 Qwen2.5-32B-Instruct 八次回答，去掉 pass rate 0 或 1，得到 72K moderate examples。证据为`This yields 72K examples of moderate difficulty`（p.4，`explicit`）。
4. **instantiate_algorithm（p.4）**：从 200K 被过滤实例的 short-context documents 抽取额外 real-world documents，排除与原 `oL_i` 的 overlap，生成约 `<16,384` token context。证据为`excluding any overlap with oLi`（p.4，`explicit`）。
5. **define_component（p.4）**：每条 linear chain 的 key 映射到含 next key 的 value；多条 chain 最终指向 distractor question，一条指向原问题；key 是 32-character UUID，字符取自 `0-9`、`A-F`。证据为`one chain that ultimately resolves to the original question`（p.4，`explicit`）。
6. **explain_mechanism / give_intuition（p.4）**：目标问题要求从初始 key 追链、恢复隐藏的 `oq_i`、再在长 context 中完成原多跳 QA；高熵、非语义标识符阻断 lexical/semantic shortcut。证据为`prevent the model from exploiting lexical shortcuts`（p.4，`explicit`）。
7. **connect_to_prediction（p.4–5）**：作者把 RL 输出解释为 plan → retrieve → reason → recheck；Appendix A.5 用 RULER VT 轨迹说明逐步检索。证据为`first generates an explicit plan decomposing the problem`（p.4，`explicit`）。
8. **connect_to_experiment（p.5）**：声称该模式在 16K 学到并推广到 128K，使训练避免 full-length 128K rollout。证据为`generalizes to much longer contexts, up to 128K tokens`（p.5，`explicit`）。
9. **setup_notation / derive（p.5）**：GRPO 对每题采样 `G` 条 rollout，用 ratio clipping、KL reference penalty 最大化目标 `J_GRPO(θ)`；group-normalized advantage 按 reward 的 mean/std 计算。证据为`GRPO samples a group of rollout trajectories`（p.5，§3.2.1，`explicit`）。
10. **instantiate_algorithm（p.5）**：`β=0.001`；移除 entropy loss，因为作者认为 entropy 可能失控增长并 destabilize training。证据为`A small KL penalty β = 0.001`（p.5，`explicit`）。
11. **define_component（p.5）**：强制最终答案放进 `\boxed{}`；从中抽取 `y_ans`，若 `a⊆y_ans` 或 `y_ans⊆a` 则 binary reward 1，否则 0。证据为`two-way substring exact match`（p.5，`explicit`）。
12. **instantiate_algorithm / connect_to_experiment（p.6）**：混合 KeyChain hard、standard multi-hop medium、Book RULER retrieval 和 math 数据，在 16K context 上训练 128K-window base model；Table 1 给出各子集数量与长度。证据为`we train using a 16K context length`（p.6，`explicit`）。
13. **derive / connect_to_prediction（p.6）**：7B 用 warm-up→KeyChain augmentation→hard-mined 三阶段；14B 跳过 warm-up；Stage II 以八次 rollout 去除全对样本，保留约 30–40% 难样本。证据为`leaving a challenging subset (30–40% of the data)`（p.6，`explicit`）。

动作转移序列可压缩如下，`setup_notation → state_problem → derive → define_component → instantiate_algorithm → explain_mechanism → give_intuition → connect_to_prediction → setup_notation → derive → define_component → connect_to_experiment`。方法组件与前文问题对应：KeyChain 解决高难数据和检索-推理耦合；rule verifier 解决自由形式答案验证与 reward hacking；16K curriculum 解决 128K rollout 成本；data mix 解决短能力遗忘。

## G. 结果、统计与可视化

### H.2 自我设限的位置与类型

- **scope / generality**：只在 Qwen2.5-7B/14B 上训练；外部 frontier 对照不是同 recipe 的受控扩展（p.6–7，`explicit`）。
- **compute**：选择 16K 训练、128K 推理，并以“避免 prohibitive rollout cost”说明工程边界；没有成本量化（p.5–7，`explicit` + `layout_observation`）。
- **data**：训练数据来自三种多跳 QA、Book RULER 和 math；高难样本先用 Qwen2.5-32B 的八次 pass rate 筛选，可能将 base-model 可解性写入样本分布（p.4、6，`explicit`）。
- **metric**：two-way substring binary reward 只验证最终 boxed answer；没有 trajectory-level correctness 或 answer verifier 的独立 precision/recall 审计（p.5、10，`explicit` + `layout_observation`）。
- **baseline**：QwenLong-L1 使用不同模型、60K 训练和可能不同上下文 recipe；作者未提供 matched compute 或同一 base 的全长训练（p.3、7，`explicit`）。
- **causality**：pattern 归因来自 KeyChain 替换、轨迹样例和人工 checkpoint 检查，没有随机化链长/干扰密度或行为标注介入（p.9、16–20，`interpretation`）。
- **deployment**：仅报告 benchmark 和硬件，未测试实际法律文档、代码库或在线延迟/成本（p.1 的应用动机、p.7 的 benchmark 列表，`layout_observation`）。
- **limitations section**：没有显式 limitations 小节；自我设限分散在引言问题、实验说明、附录 protocol 与结果文字中（p.1–2、7–10、18–20，`layout_observation`）。

### H.3 不利信息的呈现策略（仅记录可观察形式）

1. **平均值聚合**：Table 2/3 用 Avg. 将五个 QA 或多个 HELMET 子任务压成单分数；分项仍可见，但没有 dispersion 或任务权重讨论（p.7，`layout_observation`）。

## L. 最终判断

1. **单一主线**：用真实短多跳 QA 做种子，先以 distractor 扩到约 16K，再以非语义 KeyChain 把真实问题藏进长 context；GRPO 在可验证的 boxed-answer reward 下逼出 plan–retrieve–reason–recheck，最后用 mixed data 保持短能力，并观察 16K→128K 迁移（PDF pp.3–6，§3.1–3.2；`transforms short multi-hop QA`、`generalizes to much longer contexts`；`explicit`）。
2. **正文保留的决策内容**：KeyChain pipeline、三条设计原则、GRPO objective/reward、Table 1 数据配方、训练/推理 protocol、Table 2–6 主结果和 Figure 1–4 机制/训练诊断。它们共同支持“数据设计比单纯长 rollout 更关键”的叙事（pp.3–10；`KeyChain-driven RL proves far more effective`；`explicit`）。
3. **移入附录的细节及影响**：exact prompt、样例 skeleton、长轨迹、LongBench-v2、RULER 的 prompt/YaRN protocol、14B NIAH、UUID 消融和手工技能表移入 A.2–A.11。正文仍能读懂主方法和主结果；若不看附录，verifier prompt、RULER 跨模型可比性、UUID 设计边界和技能证据会缺失（pp.14–20；`For reproducibility, we include the exact prompt format`；`explicit`）。
4. **最有效的模式**：Figure 1 的同题、同场景左右轨迹把抽象技能差异变成可见错误机制；Figure 2 三步图把数据构造与前文 gap 对接；Table 5/6 用等量替换和 verifier 替代形成决策性消融；Table 4 把训练长度与推理长度分开，直接呈现 16K→128K（pp.2–3、8–10；`explicit`）。
