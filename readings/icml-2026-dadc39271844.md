## 4. 方法与理论：从错配到可执行选择

### 核心因果链

1. **问题表示**：训练实际走的是 `P_t ∇L(z; θ_t)` 的预条件化方向，不是 raw gradient（页 5，§3.3，Eq. 1）。
2. **优化器实例化**：Muon 在冻结 Newton–Schulz 操作符时给出稠密层级预条件器；AdamW 在冻结 RMS geometry 时给出对角预条件器（页 5–7，§4，Eq. 2–13）。
3. **目标函数**：一个候选的 marginal utility 是对 held-out `D_val` 的一步损失降低（页 8–10，§5.1，Eq. 14–23）。
4. **代理方向**：`BENCH-PROXY` 从预训练语料中检索 benchmark-aligned 文档，用 in-distribution `D_proxy` 估计梯度方向（页 10，§5.1；页 16，§6.2）。
5. **可扩展估计**：Ghost factors 规避 per-sample matrix gradient materialization；CountSketch 把预条件化 outer-product 特征投到低维空间（页 10–11，§5.2，Eq. 24–25）。
6. **多样性控制**：utility 同时含 proxy alignment 和已选样本方向的 redundancy penalty；Boltzmann 而非 deterministic top-k 执行采样（页 10–12，§5.1–5.3，Eq. 22–26）。

段落动作转移可以概括为：`setup_notation → state_problem → derive_optimizer_operator → define_utility → derive_proxy_score → explain_ghost_and_sketch → instantiate_algorithm → explain_soft_sampling → summarize`。

### 公式、假设与算法

- **公式数量**：26 个编号 displayed equations，页 5–11；`Eq. (1)–(13)` 构成 preconditioner 推导，`Eq. (14)–(26)` 构成 OPUS objective、近似和采样规则。
- **理论性质**：没有 theorem、lemma、proposition、corollary 或 proof。理论在本文是**核心因果链的解释性推导**，不是带有限误差、收敛或选择最优性保证的 formal guarantee。
- **关键近似**：Muon 固定 state 并冻结 Newton–Schulz map；AdamW 固定 second-moment/RMS geometry；virtual validation gradient 用一阶 Taylor 展开；Hessian interaction 取 `H_val ≈ I`。每个近似都在公式附近明说，但全文没有测量近似误差。
- **Algorithm 1**（页 9）：输入为模型、training stream、`D_proxy`、optimizer、selection ratio 和 sketch dimension。外层按训练步循环；内层按 `K=⌊ρN⌋` 次 soft-sampling 循环；每次计算 alignment 减 redundancy，更新 `Φ`，再以原 optimizer 更新模型。关键不变量是 `Φ` 累积已选样本每层 sketch，候选从 `B_t \hat B_t` 中抽取。正文解释达到对 Ghost、CountSketch、preconditioner、proxy 和 temperature 的粒度，未给出可运行伪代码之外的实现或缓存生命周期。
- **组件—前文问题映射**：`P_t` 对应 raw/actual update misalignment；`BENCH-PROXY` 对应 raw benchmark shift/noise；Ghost 对应 per-sample gradient 内存负担；CountSketch 对应高维内积成本；Boltzmann 对应 greedy redundancy 和短期 proxy noise。

**可复核的文本张力。** §5.1 与 §6.2 把 `D_proxy` 定义为从预训练 corpus 检索的 30M-token pool（页 10、16）；§6.1 又写「we use the validation split as the proxy set for scoring」（页 12）。两句话没有交代二者在实际 run 中的关系。可把它读作书面复现协议的未闭合点，不能自行假定它们等价。

## 6. 结果、统计与可视化

### 主要结果

1. **FineWeb，GPT-2 XL + Muon。** Table 3 的 macro average 为 OPUS `41.75`、Random `40.29`，差 `1.46`；Random 60B 是 `41.29`，明示为更长且不 compute-matched 的参照（页 17，§6.3）。
2. **FineWeb，AdamW。** OPUS 在 GPT-2 Large 为 `41.43`，对 Random 的 `39.29`；在 GPT-2 XL 为 `41.01`，对 Random 的 `40.36`（页 17，Table 3）。
3. **FineWeb-Edu 的低质量池。** GPT-2 XL + Muon，OPUS 从 score-3 pool 得到 `44.99`；同表高质量 score-4+5 的 Random 为 `41.92`，Random 60B 为 `42.59`（页 18，Table 4）。表注明确 data-quality 条件与 60B 非匹配性。
4. **proxy 外评测。** GPT-2 XL 的 OOD Table 5 中，OPUS average 为 `40.07`，GREATS 为 `39.42`，Random 为 `38.09`（页 18）。
5. **收敛轨迹。** 作者称 GPT-2 XL 的 OPUS 在 `17B` tokens 达到 Random 60B 的 validation loss（页 18–19，§6.3、Figure 4）。图没有 error band 或 checkpoint-level replicate 信息。
6. **domain PPL。** Table 6 在 FineWeb 的 GPT-2 XL 行给出 OPUS `3.26`，PPL `3.28`；FineWeb-Edu subset 行为 OPUS `3.45`，PPL `3.56`（页 19）。每个 domain 用 1,000 held-out documents，平均跨 10 domains。
7. **CPT。** Figure 5/6 和正文称 OPUS 用 `0.5B` tokens 已优于 3B-token random/full-CPT reference，并称其为 `6×` data efficiency gain（页 20；摘要页 1）。图展示 domain accuracy 与 average，不提供逐次 run 的数值表。
8. **效率。** Figure 7 的柱图显示 Direct `6875` 分钟、Ghost `2357`、Ghost+CountSketch `2083`、Random `1985`；正文归纳为仅 `4.7%` extra overhead（页 22）。按柱顶数字直接相减约为 4.9%，这可以来自图上整数取整或不同的未展示精度。

## 9. 最终判断

**单一主线。** 数据选择应在 optimizer 实际产生的更新几何中衡量；以 benchmark-aligned、in-distribution proxy 指引方向，用 Ghost/CountSketch 让这一度量可在每一步运行，再用 Boltzmann 保留选择多样性。

**正文保留的决策关键内容。** 论文把目标函数、Muon/AdamW 近似、Algorithm 1、training/evaluation protocol、主结果、proxy/sampling 消融和效率图留在正文。这足以让读者检查作者的因果链和点估计比较。

**最有效的写作模式。** Figure 2 用一张简图把「raw gradient 与 optimizer path 不同」变成中心问题；Figure 3 紧接着把完整 pipeline 交给读者；随后 Eq. 1–26 和 Algorithm 1 逐一把图中的部件落地；Table 7/ Figure 7 在结束前分别回答「为何 soft/proxy」和「代价是多少」。

**最大缺口与读者成本。** 近似假设、`D_proxy` 的实际来源、run-to-run 变化、硬件条件和机制隔离没有闭合。特别是没有固定其余组件、仅切换 optimizer-induced geometry 的消融。18 页 sample-card 附录很长，却无法弥补这些可重复性和识别缺口。

**可迁移规则。** 当论文主张「训练时选择与优化动态对齐」时，先用一张错配图定义不可接受的旧几何，再给出和真实 optimizer 一一对应的对象、一个可以测量的 proxy、一个独立成本图以及每个机制的受控消融。

**适用边界。** 这条规则适合 optimizer state 明确、可以写成固定步近似的训练选择问题。若 optimizer 变换高度非线性、proxy 与真实目标分布关系难以验证，或 stochastic evaluation 的方差很大，必须额外报告近似误差、proxy 组成、重复 run 和直接机制对照；这篇论文没有给出这些闭环证据。
