## 5. 方法与理论

### 5.1 形式对象与问题定义

§3 在 p.3 先用 Figure 1 给两条主思想，然后在 p.4 将目标定义为：给定数据集 `D`，构造 probabilistic program model `M`，同时有准确预测性能和 fully Bayesian uncertainty quantification；候选模型由 LLM 生成，比较依据是 Bayesian-workflow diagnostics（p.4 §3 Problem Statement，anchor “construct a statistical model M ... accurate predictive performance”）。

形式流为 `D∥P∥L`，即数据 block、prior block、likelihood block。候选集 `M` 经七个指标形成 Bayesian Workflow Reliability Score `B(M)`；设 `ζ=5`，valid model space 为 `M_valid={M∈M:B(M)≥ζ}`，最终目标为 `M*=argmax_{M∈M_valid} elpd(M)`（p.4 §3，Definitions 2–4）。七项是 split-`R̂`、BFMI、bulk ESS、zero divergences、tail ESS、Pareto-`k` 达标比例、finite ELPD。这里的核心决策链是“先可靠性筛选，后在保留集合内最大化 ELPD”，而非单独追求一个预测分数（p.4，explicit）。

### 5.2 Semantic constrained generation

给定 context-free grammar `G=(N,T,P,S0)` 和 partial parse tree `κ`，`F(κ)` 是按 statement 划分的 rooted subtrees；validation function `Φ:F(κ)×Π→{0,1}` 作用于 fragment 与程序上下文（p.4–5 §3.1）。正文先写 `Φ(n,π)=ϕ1∧...∧ϕm`，再列出六个具体 predicate：

1. **Parse-ability**：fragment 遵守 grammar `G`。
2. **Distribution validity**：所有分布调用属于可用 PPL library `M`。
3. **Parameter validity**：调用参数属于该分布的 accepted specification；`sd` 替换为 `sigma` 是 Figure 2 例子。
4. **Dependency validity**：变量在引用前已定义/初始化。
5. **Support validity**：参数值位于 distribution support，例如 variance > 0、probability ∈ [0,1]。
6. **Type validity**：参数类型符合 distribution specification，例如 scale 为数值、count 为整数。

最终 `Φ(s,Π)=∧_{i=1}^6ϕ_i(s,Π)`。系统维护全局 symbol table `Π:A→M`，在 `S_N` 上对 statement 做 local rejection sampling，遇到失败时只回溯违反约束的 tokens/fragments，再继续采样；termination fragment 后才结束生成（p.5 §3.1，anchor “local rejection sampling”）。作者把这称为同时覆盖 programming-language requirements 与 Bayesian-model requirements；此处是机制核心，因为静态语义过滤把候选空间缩小，动态诊断随后负责统计可靠性。

### 5.3 Diagnostic-aware refinement 与算法

§3.2 定义 constrained-decoding operator `L_CD:C→B`，给定 context `C` 返回满足 `Φ(C∥B)=1` 的 code block。初始 prior 为 `P←L_CD(D)`，likelihood 为 `L←L_CD(D∥P)`。Algorithm 1 的循环逻辑如下（p.6 §3.2，Algorithm 1）：

- 初始化 `r=0, ℓ=0, V=∅, P=∅, L=∅`；预算输入为 `R_max, α, β, {τ_j}_{j=1}^L, K`。
- 在 `r<R_max` 且 `|V|<β` 时组合 `Prog=D∥P∥L`，重新检查 `Φ`。
- 计算 `d_1,...,d_L`，令 `P_pass={j:d_j≥τ_j}`；若通过至少 `K` 个阈值，则将程序加入 `V`。
- 若诊断失败且 `ℓ<α`，在 data-prior context 下重采样 likelihood `L←L_CD(D∥P)` 并增加 `ℓ`；否则重采样 prior `P←L_CD(D)`。
- `r` 增加 1；循环结束返回 `V` 中 ELPD 最大的程序。

该机制把失败类型映射到 fragment：likelihood resampling 面向 convergence/sampler health，prior resampling 面向 prior specification。正文给出预算上界，却没有渐近时间/空间复杂度公式；复杂度证据只到“最多 `R_max` 次 refinement、目标收集 `β` 个 valid programs”，并把 token overhead 移到 Appendix G.1（p.6、p.23）。算法对循环、不变量和返回条件的覆盖完整到 statement 级别，但没有给出全局最优收敛证明；作者在 p.10 Limitations 明写这一点。

- **SLM**：p.6 明写 4 个模型，即 Llama3-8B、CodeGemma-7B、Qwen2.5-Coder-7B、DeepSeek-R1-Distill-Qwen-7B（DQ-7B）。这是 p.2 “five open-weight LLMs” 与 p.6 “total of four models” 的内部数量冲突，未在 PDF 解决（详见第 12 节）。
- **基线/外部对照**：Standard unconstrained、Syncode syntactically-constrained；Table 3 另有 Expert Stan programs、BoxLM with GPT-4、OpenAI o3（p.7–8）。
- **提示与采样**：附录 D 的共同模板要求在 `with pm.Model() as m:` 中补全模型、定义 priors/likelihood，并执行 `pm.sample(1000, tune=1000, chains=4, return_inferencedata=True, idata_kwargs={"log_likelihood": True})`；不输出代码外 commentary（p.19）。

### 6.2 控制量、阈值和运行预算

- `α_R=1.05`，`ESS_bulk≥β_bulk=400`，`ESS_tail≥β_tail=100`；Pareto shape 中至少 `1−ε=0.8` 的数据点低于 `L_cd=0.7`；ELPD 必须 finite（p.21 §E）。
- `ζ=5` 是总体 reliability cutoff（p.4 Definition 2–3）；Algorithm 1 的 `K` 作为“至少通过多少诊断”的参数出现，但 Appendix E 没有单独给出 `K` 数值，PDF 中可核实值为 **not_present**。
- `β=4`（收集的 valid programs 上限）、`α=2`（likelihood refinement 次数）、`R_max=100`（总迭代预算），据 preliminary experiments 统一设置（p.22 §E）。
- 温度 0.2、0.3、0.4；p.22 说明 experiments 使用 10 seeds。Section 5.2 又明确“baseline 五次、RefineStat 单次、重复该过程五次”，因此表 2 的聚合层级是五次比较重复，和“all experiments 10 seeds”之间缺少精确对应说明。
- 硬件为 48-core Intel Xeon Silver 4214R CPU 与 2 张 Nvidia RTX A5000 GPU；实现使用 PyTorch 与 Itergen library（p.22）。

### 6.3 研究问题与证据排布

论文没有预先编号的 RQ/Hypothesis。实验顺序隐含四个问题：运行成功率（Table 1）、诊断/ELPD 相对 Standard（Table 2）、与 Expert/BoxLM/o3 的外部性能（Table 3）、每个 semantic predicate 的必要性（Table 4），随后测试 NumPyro backend（Tables 5–6）、token cost（Table 8）和 memorization（Table 9）。这一顺序与方法组件大致对应，但没有单独的 posterior/predictive check 安排。

- **主结果**：run rate、Reliability Score、split-`R̂`、ESS bulk、divergences、Pareto `k̂`、ELPD-LOO。
- **机制检验**：逐一移除 parameter/distribution/parse validity 与 grammar-guided generation（Table 4）。
- **鲁棒性/泛化**：NumPyro（Tables 5–6）、prompt anonymization 与 exponential-notation obfuscation（Table 9）。
- **成本**：token count 与 ratio（Appendix G.1, Table 8）。
- **失败判定**：不能生成 posterior samples 的 numerical inf/nan、unlikely prior、sampling warning、chain initialization failure 或 static compilation issue 记为 run failure；表中 `✗` 表示没有 valid program（p.7–8）。
- **缺失控制**：没有报告数据 train/test split、独立 held-out set、数据泄漏检测、硬件耗时、每个模型完整 prompt token budget、随机种子列表或 `K` 的确切值。prior-predictive/posterior-predictive checks 明确缺失（p.10 Limitations）。

## 9. 结论、局限与闭环矩阵

### 9.1 结论段落动作

§7 Conclusion（p.10）一个段落依次完成 `restate_problem → restate_method → restate_result → impact/future`：把 probabilistic model generation 拆成 prior/likelihood fragments，用 LLM search 找满足 Bayesian-workflow reliability metrics 的 program，并提出未来可扩展到 domain-expert reliability criteria。该段没有新数字，也没有超出正文的新实验主张（p.10，explicit）。

## 13. 最终判断

1. **单一主线**：RefineStat 把 SLM probabilistic-program synthesis 变成“fragment-level semantic pruning + Bayesian-diagnostic-guided prior/likelihood resampling”，先用 `Φ` 排除不可执行/语义错误，再在 `B(M)≥5` 的 valid space 中按 ELPD 选模型（p.3–6，Definitions 2–4、Algorithm 1）。
2. **正文保留的决策关键内容**：Figure 1 流程、六个 predicates、可靠性七项指标、`ζ=5`、Algorithm 1 的 resampling 分支、Tables 1–6 的运行/诊断/外部对照，以及 GP 的高 ELPD 但坏收敛反例（p.3–10）。这些内容足以理解作者的验收顺序。
3. **移入附录的细节及自足性**：prompt/data arrays、阈值与硬件、指标公式、结构性 program examples、error taxonomy、token cost、memorization variants 移到 p.15–24。方法主线在正文基本自足；复现所需的 D/E 与“效率/失败边界”判断所需的 F/G 则必须读附录，且 `K`、wall-clock、完整 seeds 仍缺失。
4. **最有效模式**：把 reliability 从口号写成七个 indicator 和 valid-space argmax；用 Figure 2 的 `sd→sigma` 微例承接 semantic predicate；用 GP diagnostic conflict 说明“较高 ELPD 不等于可信 posterior”；用 Table 4 做组件删除（p.4–5、p.7–9）。
5. **最大叙事缺口**：标题强调 efficient，但平均 token cost 是 baseline 的 1.9×，且没有 wall-clock/金钱成本；“significantly improves”没有假设检验；模型数量、predicate 数量、Peregrine 年数有 PDF 内部不一致；全局最优与完整 Bayesian adequacy 明确未闭合（p.10、p.23，及第 12 节）。
6. **可迁移规则**：若方法声称“可靠生成”，先把静态合法性、运行/采样诊断和预测选择分别形式化，再用一个反例展示单一最终分数为何不足；同时在主文或附录给出成本分母和失败全集定义（本论文 p.4、p.7、p.22–23）。
7. **适用边界**：该规则适合有可执行 DSL、可观测运行诊断和可定义候选选择标准的生成任务；若可靠性依赖 prior/posterior predictive 的人工领域判断，或目标是全局最优/因果 adequacy，则需要额外实验与形式保证，不能由本论文的 `B(M)` 规则单独推出（p.10 Limitations）。
