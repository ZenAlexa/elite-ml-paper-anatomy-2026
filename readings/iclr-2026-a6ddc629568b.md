# `LLMs Get Lost In Multi-Turn Conversation` 深读备忘

## 1. 论文边界与一句话结论

- **论文**：Philippe Laban、Hiroaki Hayashi、Yingbo Zhou、Jennifer Neville，ICLR 2026 Outstanding Paper / Oral。PDF 共 41 个物理页；正文在 PDF p.11 的 §9 后结束，References 从同页延续至 p.16，Appendix A 从 p.17 开始。由于 References 与正文共用 p.11，正文 11 页、References 6 页、Appendix 25 页的计数存在 1 页重叠。（PDF p.11，§9/References，锚点 `REFERENCES`；PDF p.17，Appendix A，锚点 `A Related Work on Underspecification`）
- **单一主线**：作者把同一 fully-specified instruction 转成逐轮揭示的 shards，以 FULL、CONCAT、SHARDED 三种 matched conditions 比较 15 个 LLM；平均 performance 在 SHARDED 中下降 39%，分解后主要体现为 unreliability 上升，而后续的 premature answering、answer bloat、loss-in-middle-turns 与 verbosity 分析提供描述性机制线索。（PDF p.4，§3.3，锚点 `control to ensure the performance drop`；PDF p.7，§5.1，锚点 `average degradation of -39%`；PDF p.8，§5.2，锚点 `increased model unreliability`）
- **证据边界**：论文测量的是 controlled underspecification stress test。自动 user simulator、英文文本、分析型 generation tasks、常规 context length 与 API model 共同限定了结论范围；真实用户、creative tasks、其他语言和 multimodal interaction 未被测试。（PDF p.10-p.11，§8，锚点 `controlled underspecification stress test`、`focus on analytical tasks`、`text-only tasks in the English language`）

## 6. 方法、形式化对象与推进动作

### 6.1 最小逻辑单元

1. `state_problem`：复用 single-turn benchmark，构造同一 task 的 multi-turn underspecified version。（PDF p.3，§3，锚点 `repurposes existing tasks`）
2. `define_component`：sharded instruction 由多个 single-information shards 组成，合起来保留 original instruction。（PDF p.3，§3.1，锚点 `same information provided`）
3. `instantiate_algorithm`：user reveal → assistant response → strategy classifier → answer extractor → task evaluator；每轮最多一个新 shard。（PDF p.3，§3.2，Figure 2）
4. `explain_mechanism`：conversation score 取各 turn answer attempts 的最大值，使 SHARDED 拥有更多机会。（PDF p.3-p.4，§3.2，锚点 `is credited for the best one`）
5. `define_component`：GPT-4o-mini user simulator 根据 history 选择并轻度改写最相关的 unrevealed shard。（PDF p.4，§3.2，锚点 `select and lightly rephrase the shard`）
6. `connect_to_experiment`：classifier 只触发 extraction/scoring，不控制 shard selection；manual inspection 用于验证 simulator。（PDF p.4，§3.2，锚点 `does not directly influence the user simulator`）
7. `contrast_alternative`：FULL、SHARDED、CONCAT、RECAP、SNOWBALL 改变 information-disclosure schedule；CONCAT 是关键 paraphrase control。（PDF p.4，§3.3，Figure 3）
8. `setup_notation`：P 为 per-instruction mean，A 为 90th percentile，U 为 90th-minus-10th percentile。（PDF p.6，§4.2，锚点 `define three metrics`）
9. `derive`：Appendix B 用 q、Y*q、I(q)、q' 形式化 intended output 与 atomic content units。（PDF p.17，Appendix B，锚点 `atomic content units`）
10. `define_component`：P1-P5 约束 information preservation、initial intent、order、maximal sharding 与 minimal transformation。（PDF p.18，Appendix B，锚点 `P1: Information Preservation`）
11. `instantiate_algorithm`：segmentation → rephrasing → verification → manual inspection；每个最终 shard set 由两位作者复核。（PDF p.18-p.19，Appendix C，Figure 6，锚点 `all manually reviewed by two authors`）
12. `connect_to_prediction`：CONCAT 与 SHUFFLE-CONCAT 低于 FULL 的 80% 即拒绝样本，用于筛查 information loss/order dependence。（PDF p.19，Appendix C，锚点 `below 80%`）

动作序列为 `state_problem → define_component → instantiate_algorithm → explain_mechanism → contrast_alternative → setup_notation → derive → define_component → connect_to_prediction`。（PDF p.3-p.6，§3-§4.2；PDF p.17-p.19，Appendices B-C）

### 6.2 输入、输出、状态与假设

- **输入**：fully specified benchmark instruction、task evaluator、model under test。（PDF p.3，§3，锚点 `existing tasks from single-turn benchmarks`）
- **输出**：validated shard set、simulated conversation、per-turn answer scores 与 conversation maximum score。（PDF p.3-p.4，§3.2）
- **状态**：conversation history、revealed/unrevealed shards、response strategy、extracted answer、task score。（PDF p.3，Figure 2；PDF p.41，User simulator prompt）
- **目标**：在 target output 与 evaluator 固定时，测量 information-disclosure schedule 对 P/A/U 的影响。（PDF p.2，§2，锚点 `common set of tasks`；PDF p.6，§4.2）
- **关键假设**：shards 保持 I(q)=I(q')；first shard 提供 clear intent；其余 shards 可换序；LLM user 仅作为 behavior probe。（PDF p.17-p.18，Appendix B；PDF p.3，§2，锚点 `not user behavior`）

人工核对得到 **8 个 displayed equation blocks、0 个 numbered equations、0 theorem、0 lemma、0 proposition、0 corollary、0 proof、0 algorithm/pseudocode**。（PDF p.6，§4.2；PDF p.17-p.21，Appendices B-E）

## 7. 实验设计与复现粒度

### 7.1 主实验

- 六项 generation tasks：Code、Database、Actions、Math、Data-to-Text、Summary；数据来源依次为 HumanEval/LiveCodeBench、Spider、BFCL、GSM8K、ToTTo、Summary of a Haystack。（PDF p.5，§4.1，Figure 4）
- 主文称每任务 90-120 个 shards；Appendix J 给出 100、107、105、103、120、92 个最终样本。（PDF p.4，§4.1，锚点 `90-120 sharded instructions`；PDF p.30-p.32，Appendix J）
- 15 个模型来自 8 个 families，覆盖 open/closed weights、8B 至 300B+ 与 o3/Deepseek-R1 两个 reasoning models。（PDF p.6，§4.3，锚点 `15 LLMs from eight model families`）
- 每个 model × instruction × simulation type 运行 N=10，共 200,000+ conversations；main temperature 为 1.0，估计总成本约 $5,000。（PDF p.6，§4.3，锚点 `N = 10 simulations`、`around $5,000`）
- FULL/CONCAT/SHARDED 是主比较；CONCAT 同时保留 shard wording 并移除 multi-turn disclosure，用于隔离 rephrasing。（PDF p.4，§3.3，锚点 `not due to the rephrasing`）
- SHARDED score 取所有 answer attempts 的最大值。该规则在方向上有利于 SHARDED；作者在 §8 主动讨论了 lucky inference、memorization 与 lenient evaluation。（PDF p.4，§3.2，锚点 `best one`；PDF p.11，§8，锚点 `scoring mechanism itself favors`）

### 7.2 指标与统计处理

- P 取每个 instruction 的 N 次模拟 mean score；A 取 90th-percentile score；U 取 90th-minus-10th percentile range。三个量均先按 instruction 计算，再对 corpus 平均。（PDF p.6，§4.2，锚点 `computed on a per-instruction basis`）
- Code/Database/Actions/Math 的 binary evaluator 映射到 0-100；Data-to-Text 用 BLEU；Summary 用 Joint Score。（PDF p.5，§4.1，锚点 `common scale`）
- 汇总单位覆盖 instruction、task、model；Table 1 的 headline 使用多层平均。论文没有 estimator interval、明确 hypothesis test、多重比较、bootstrap、Bayesian analysis、regression 或 correlation coefficient。（PDF p.6，§4.2；PDF p.7，Table 1）
- 摘要与结论使用 `significantly`，方法部分只定义 empirical mean/percentile，没有说明 test statistic 或 decision threshold。（PDF p.1，Abstract，锚点 `significantly lower performance`；PDF p.6，§4.2）

### 7.3 复现信息与缺失项

- Appendix I 列出 exact model versions/providers；主实验 temperature=1.0，response cap 为 1,000 tokens，o3/Deepseek-R1 放宽到 10,000。（PDF p.29-p.30，Appendix I，Table 10）
- Appendix J 逐任务说明 source split、sharding count、system prompt 与 evaluator；Code/Database/Actions 复用 maintained/official evaluation toolkits。（PDF p.30-p.33，Appendix J）
- p.36-p.41 给出 segmentation、rephrasing、verification、answer extraction、response classification 与 user simulation prompts。（PDF p.36-p.41，Prompts O.1-O.2）
- main-run random seeds、physical CPU/GPU、contamination audit、formal inferential plan 均未提供。作者明确说 API deprecation 和 probabilistic outputs 限制 absolute reproducibility。（PDF p.11，§9，锚点 `limit the absolute reproducibility`；PDF p.30，Table 10）

## 8. 主要结果、统计与不利解释

### 8.1 主结果

1. **跨模型/任务下降**：Table 1 中每个 model 在每个 main task 上均由 FULL 到 SHARDED 下降，平均 degradation 为 -39%；引言用约 90→65 表述同一现象。（PDF p.7，§5.1，锚点 `every model sees its performance degrade on every task`；PDF p.2，§1，锚点 `65%—a 25-point drop`）
   - 聚合：per-instruction 10-run mean 后继续按 task/model 汇总；图表未给 estimator uncertainty。（PDF p.6，§4.2；PDF p.7，Table 1）
   - 不利解释：simulator narrowness 与 analytical English task scope 可能限制外推。作者在 §8 将结果明确限定为 stress test。（PDF p.10-p.11，§8）

2. **CONCAT control**：CONCAT 平均达到 FULL 的 95.1%，支持「主要损失来自 disclosure over turns」的解释；较小模型仍有 86-92% 的 CONCAT retention，显示 paraphrase 并非对所有模型完全中性。（PDF p.8，§5.1，锚点 `CONCAT performance averaging 95.1%`、`86-92`）
   - 作者主动点名小模型例外，并将其解释为 paraphrase robustness 较弱。（PDF p.8，§5.1，锚点 `struggle to generalize`）

3. **能力强弱与 degradation**：Claude 3.7 Sonnet、Gemini 2.5、GPT-4.1 的平均 degradation 仍约 30-40%。作者同时指出弱模型 FULL baseline 低，relative degradation 的可下降空间更小。（PDF p.8，§5.1，锚点 `get equally lost`、`less scope for degradation`）

4. **A/U decomposition**：FULL→SHARDED 时 aptitude 平均下降 16%，unreliability 平均上升 112%，固定 instruction 的 best/worst run 平均相差 50 points。（PDF p.8，§5.2，锚点 `average drop of 16%`、`average increase of 112%`、`50 percent points`）
   - N=10 时 empirical 90th/10th percentile 是粗粒度尾部估计，论文未给其估计误差；§9 只说明扩大 repetitions 可能发现额外结果。（PDF p.6，§4.2；PDF p.11，§9，锚点 `scaling up the experiments further might help`）

5. **Gradual sharding**：GPT-4o/4o-mini 在 two shards 起即出现 minor aptitude loss 与 large unreliability increase。（PDF p.9，§5.3，锚点 `two-shard instructions and beyond`）
   - source instructions 均来自复杂的 eight-shard subset，作者承认复杂度高于 corpus average；因此「任何 two-turn conversation」的措辞超出直接样本。（PDF p.9，§5.3，锚点 `inherently more complex`）
   - 样本数另有内部冲突：§5.3 与 Appendix L 后文写 31，Appendix L 前文写 `a total of eight instructions`；31×8=248 与后文 arithmetic 一致。（PDF p.9，§5.3，锚点 `selected 31 instructions`；PDF p.34，Appendix L，锚点 `total of eight instructions`、`248 instructions`）

### 8.2 行为与机制分析

1. **Premature answer attempts**：Code/Math 中，first attempt 位于前 20% turns 的平均 P=30.9，位于后 20% 的 P=64.4。（PDF p.22-p.23，§F.1，Table 3，锚点 `30.9, less than half of the 64.4`）
   - 这是 timing association；其余四任务几乎总在 turn 1 answer，无法用于该分析。作者将 incorrect assumptions 的解释写为 hypothesis。（PDF p.22，§F.1，锚点 `only two observed a significant range`；PDF p.23，锚点 `We hypothesize`）

2. **Answer bloat**：四任务的后期 SHARDED attempts 比 FULL/CONCAT solution 长 20-300%；在 correct-only subset 中，Code 长 27%，Database 长 14%。（PDF p.23，§F.2，Figure 8，锚点 `20-300% longer`、`27% more characters`、`14% more characters`）
   - character length 是 proxy，未直接标注哪些 tokens 对应 invalid assumptions。作者采用 `hinting` 表述 qualitative worsening。（PDF p.23，§F.2，锚点 `hinting that the solutions are qualitatively worse`）

3. **Loss-in-middle-turns**：turn-8 summary 中，20% citations 指向 turn 8 documents，turn 2 和 3 各 8%；所有 15 models 的平均呈 first/last emphasis。（PDF p.24，§F.3，Figure 9，锚点 `20% of citations`、`8% from turn 2 and 3`）

## 10. Ablation、负面结果与失败案例

- `scale sensitivity`：1-8 shards 的 gradual sharding；识别 granularity 与 reliability 的关系。（PDF p.9，§5.3，锚点 `only modified factor is sharding granularity`）
- `mechanism alternative`：RECAP/SNOWBALL 重复 prior user information；识别 memory reminder 是否足够。（PDF p.25-p.26，§G.1，锚点 `repeat the past user's turn information`）
- `prompt intervention`：提示模型用户可能分批提供信息；平均收益很小且 task direction 不一。（PDF p.26，§G.1，Table 6）
- `randomness sensitivity`：assistant/user temperature 组合；低温无法消除 multi-turn U。（PDF p.27，§G.2，Table 7）
- `task heterogeneity`：translation 不降，形成 episodic-task negative result。（PDF p.28，§G.3，Table 8）
- `failure case`：Llama3.1-8B 在六轮 Math conversation 中不断扩展最初的 pastry assumptions，最后只计算 blueberry muffins。（PDF p.33-p.34，Appendix K，Figure 10）
- `compute/manual cost`：main simulation 约 $5,000；sharding 每 100 instructions 约需三小时作者工作。（PDF p.6，§4.3，锚点 `around $5,000`；PDF p.27，§G.3，锚点 `three hours of manual work`）

论文没有 learned component deletion；其 ablation 结构围绕 disclosure schedule、prompt、temperature、task decomposability 与 qualitative behavior 展开。（PDF p.9、p.25-p.28，§5.3/Appendix G）

## 11. Limitations 与不利信息呈现

### 11.1 作者明示的边界

1. automated simulation 不代表 real human-AI conversation。（PDF p.10，§8，锚点 `not representative of natural human-AI conversation`）
2. conversation structure 很窄：每轮最多一个 shard，末轮给齐信息，first turn 总有 high-level intent。（PDF p.10，§8，锚点 `rather narrow structure`）
3. minimal shards 可能 `unrealistic and potentially adversarial`。（PDF p.10，§8）
4. SHARDED 的多次 answer opportunities 在 scoring 上获得结构性优势。（PDF p.11，§8，锚点 `favors the sharded setting`）
5. tasks 限于 analytical solutions，creative writing 未建立结论。（PDF p.11，§8，锚点 `focus on analytical tasks`）
6. 仅 English text-only tasks。（PDF p.11，§8，锚点 `text-only tasks in the English language`）
7. 普通常规 context length；Summary 中 Phi-4/OLMo2 因 context capacity 被排除。（PDF p.6，§4.3，锚点 `not to stress-test long-context capabilities`）
8. closed API deprecation 与 stochastic outputs 限制 exact reproducibility。（PDF p.11，§9，锚点 `limit the absolute reproducibility`）
9. gradual sharding source subset 更复杂，two-turn effect 的 universal wording 需收窄。（PDF p.9，§5.3，锚点 `inherently more complex`）
10. Summary Joint Score 有 length bias；超过 300 words 的结果被按 bullet 比例截断。（PDF p.33，§J.6，锚点 `longer summaries are likely to score higher`）

### 11.2 呈现策略

- **Appendix migration**：四项 root-cause analyses 位于 p.21-p.25；主文 p.8 只列结论与指向 Appendix F。读者判断 causality 需要跨 13 页寻找证据。（PDF p.8，§5.2，锚点 `Appendix F explores potential root causes`；PDF p.21-p.25，Appendix F）
- **Aggregation**：39% headline 压缩 task/model heterogeneity；正文 p.8 主动列出 Command-A、Claude 3.7、GPT-4.1、Gemini 2.5 Pro 的 domain exceptions，缓解了 aggregate masking。（PDF p.8，§5.1，锚点 `muted degradations in certain tasks`）

## 16. 最终判断

1. **单一主线**：matched information disclosure 让 single-turn benchmark 变成 multi-turn stress test；平均 performance drop 由 unreliability 主导。（PDF p.4，§3.3；PDF p.8，§5.2）
2. **正文保留的决策关键内容**：核心 simulator、六任务/15 模型/200k 规模、P/A/U、Table 1、Figure 5、gradual sharding 与 limitations。（PDF p.3-p.11）
3. **附录迁移及影响**：formal shard properties、validation、mechanisms、mitigations、evaluator details 和 prompts 全部迁入附录。主效应仍可独立判断；root-cause narrative 无法只靠正文审查。（PDF p.8，§5.2；PDF p.17-p.41）
4. **最有效模式**：FULL/CONCAT/SHARDED matched control 搭配 P/A/U decomposition。CONCAT 先排除多数 wording/information-loss 解释，Figure 5 再区分 aptitude 与 instability。（PDF p.4，§3.3；PDF p.7-p.8，Figure 5/§5.2）
5. **最大缺口**：四项 mechanism evidence 大多是 post-hoc association 或 proxy，task coverage 不一；结论的机制措辞强于识别设计。两处 sample denominator 冲突进一步增加审计成本。（PDF p.22-p.25，Appendix F；PDF p.19-p.20、p.34）
6. **可迁移规则**：交互论文应固定底层 task/target/evaluator，改变 disclosure schedule，加入等信息 paraphrase control，并报告 per-unit stochastic distribution；最关键 mechanism test 应留在 main body。（PDF p.4，§3.3；PDF p.6，§4.2；PDF p.8，§5.2）
7. **适用边界**：规则适用于 target output 可定义、disclosure 可保持 information equivalence、结果可重复评分的任务；creative、multimodal、non-English、real-user 与 episodic append-only task 需要独立设计。（PDF p.11，§8；PDF p.28，§G.3）
