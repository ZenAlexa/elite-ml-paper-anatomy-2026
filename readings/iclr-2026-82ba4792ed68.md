### 6.2 实验顺序与贡献对应

1. §4.1–4.3 先做 interaction-mode × graph-regime 主比较，对应引言前两条 Findings。
2. §5.1–5.2 用 feature/edge/label deletion 解释第三条 adaptive-reliance Finding。
3. Appendix B 补齐引言列出的 model scale 与 reasoning axes。

### 7.3 主要结果与不利解释

1. **Short-text homophilic**：Graph-as-Code 在 cora/arxiv/products 为 85.16/74.40/82.70；pubmed 的 GraphTool+ 91.90 高于 Graph-as-Code 89.90。作者将整体趋势解释为更高 agency/adaptivity；pubmed 破坏严格单调序列。〔物理页 5，Table 1／Findings 1–2；`interpretation`〕
2. **Heterophily**：Graph-as-Code 在 cornell/texas/washington/wisconsin 为 92.70/73.60/81.96/89.17。Texas 的 0-hop prompt 53.20 与 GraphTool 59.60 未超过 Label Propagation 78.90；“all modes consistently outperform classic baselines” 的措辞覆盖了这个例外。〔物理页 6，Table 2／Finding 3；`interpretation`〕
3. **Long text**：Graph-as-Code 为 71.80/61.60/86.20/86.40/56.40/82.20；reddit 的 GraphTool+ 61.80 略高。2-hop Prompt 在 5/6 datasets 为 `TokenLimit`，budget prompt 恢复可运行但通常仍低于 Graph-as-Code。〔物理页 6–7，Table 3／Finding 4；`explicit`〕
4. **Feature–edge deletion**：edge 全删且 feature 完整时，Graph-as-Code 对 cora/arxiv/cornell 为 70.6/70.0/92.7，Prompting 为 39.4/21.5/77.7；作者据此主张 robustness。Graph-as-Code 仍可访问其他节点 features/labels，两个接口在 edge=100% 时拥有不同的信息可达集合。〔物理页 7–8，Figure 2／Finding 6，锚点 “access feature and label information of other nodes”；`interpretation`〕
5. **Photo divergence**：无删除条件下，Figure 3 左下角的 Prompting 约 11.6，Graph-as-Code 86.4；当 features 全截断而 edges 保留时，Prompting 升至 84.0。该反常方向支持 context overflow 解释。〔物理页 8，Figure 3／Finding 7；`explicit`〕
6. **Label–edge deletion**：edges 全删、labels 保留时，Graph-as-Code 对 cora/arxiv/cornell 为 70.7/70.0/92.7，Prompting 为 23.4/21.5/77.7；当 edges 与 labels 同时全删而 features 保留时，Graph-as-Code 仍为 64.7/65.5/90.1。热图支持「按剩余信号维持性能」的表征，但没有逐实例 query trace 统计来直接识别 adaptive policy。〔物理页 9，Figure 4／Findings 8–9；`interpretation`〕
7. **Model scale**：2-hop prompt average 从 Llama 57.28 升到 GPT-5 80.43；Graph-as-Code 从 67.80 升到 82.71。模型 family 与 model size 同时变化，且参数量未给；Table 4 识别的是 named-model ordering。〔物理页 14–15，Table 4／Finding 10；`interpretation`〕
8. **Reasoning toggle**：Phi-4 的平均 accuracy 为 Prompting 73.28→79.29、Graph-as-Code 75.38→83.19；Qwen 为 73.36→80.15、75.67→83.45。两 family 内方向一致。〔物理页 15–16，Table 5／Finding 12；`explicit`〕
9. **Token/latency**：wiki-cs 的 average tokens/query 为 0-hop 30,200、1-hop 202,500、2-hop 1,157,000、GraphTool 61,700、Graph-as-Code 57,100；wiki-cs latency 为 GraphTool 159s、Graph-as-Code 155s，2-hop 为 `TokenLimit`。作者认为 dataset characteristics 主导 latency；无 dispersion 与 API batching 信息。〔物理页 16–17，Tables 6–7／§C；`explicit`〕
10. **Hop-summary control**：2-hop summary 通常优于 3/4-hop；instagram 的 3-hop 55.8 略高于 2-hop 55.7。Graph-as-Code 在 computer 与 best summary 同为 86.2，其余五个 datasets 更高；“outperforms” 包含一个 tie。〔物理页 17–18，Table 8／Findings 13–14；`interpretation`〕
11. **Random adjacency**：Graph-as-Code 从原始 cora/arxiv/cornell/texas/citeseer/photo/wiki-cs 的 85.16/74.40/92.70/73.60/71.80/86.40/82.20 降至 56.50/59.10/72.90/45.20/58.80/60.90/66.70。该 control 表明真实 adjacency 携带性能相关信息；它同时改变所有 structure-aware modes，未单独识别 generated code 的贡献。〔物理页 18–19，Table 9／§D.2；`interpretation`〕
12. **Synthetic shortest path**：Graph-as-Code 对所有 `k` 的 MSE 为 0；2-hop prompt 在 `k≥1` 汇总为 2.82，GraphTool+ 为 2.13。环境执行 standard BFS 足以解释结果；结论适用于可直接调用确定性算法的任务。〔物理页 19，Table 10／§D.3，锚点 “write standard BFS execution code”；`explicit`〕
13. **Supervised comparison**：每个 long-text dataset 的最佳 hybrid LLM+GNN 都高于最佳 LLM-only，分别为 citeseer 74.15 vs 71.80、reddit 69.20 vs 61.80、computer 89.52 vs 86.20、photo 87.10 vs 86.40、instagram 68.20 vs 56.40。该表把“preferred mode”的有效范围收窄到 frozen LLM interaction modes。〔物理页 20，Table 11／§D.4；`interpretation`〕
