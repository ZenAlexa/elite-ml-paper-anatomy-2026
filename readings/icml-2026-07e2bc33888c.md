## 5. 方法与理论链

### 5.1 方法最小单元与动作转移

1. `setup_notation`：RR 把绕过现有分类器的 reference 送入独立 proliferation model，生成变体再 fine-tune guard（p.2，§2）。
2. `state_problem`：威胁模型允许提交少量 references，并可修改其内容，但修改后必须仍被 judge 判为 harmful 且追求原始目标（p.2，§2.1；anchor “still harmful and tries to elicit the original goal”）。
3. `state_problem`：两种 adversary goal 是 utility degradation（benign→unsafe）和 safety degradation（jailbreak→safe）（p.3，§2.2）。
4. `derive`：以 6k 训练集、每 reference 平均 3 个样本换算 1% poisoning≈18 poisoned references；报告值是上界，因为注入并非每次成功（p.2–3，§2.1；正式式在 Appendix E）。
5. `explain_mechanism`：proliferation 是“double-edged sword”，既提升新攻击泛化，也扩大攻击者在训练集中的杠杆（p.3，§3）。
6. `define_component`：conditional if–else injection 在识别 proliferation context 时覆盖合成任务、从 few-shot bank 输出 attacker 内容；否则执行原 jailbreak payload（p.3，Figure 2；§3.1）。
7. `connect_to_prediction`：validation 分支保持 harmful，proliferation 分支投递 benign 或 concept-stripped 内容，因而绕过 defender validation 并改变下游分布（p.3–4，§3.1）。
8. `define_component`：format/domain/entity/distribution poisoning 把 benign 表面特征与 unsafe label 建立 shortcut（p.4，§3.2）。
9. `define_component`：Omission Attack 选择概念 (C)，找含 (C) 的 safe WildChat，删除 (C)，把 concept-absent 样本投进 unsafe proliferated set（p.4，§3.3）。
10. `give_intuition`：分类器在 pretraining/benign 数据中见过 (C)，却在结构相似的 poisoned unsafe 样本中没见 (C)，作者据此提出 (C) 的存在成为 safe signal 的解释（p.4，§3.3；这是 hypothesis，不是定理）。
11. `instantiate_algorithm`：n-gram 用 regex 删除、普通 harmful 输入前置触发器、jailbreak 按句间插入；语义概念用 LLM 删除或把 HP 主题自然嵌入 PAIR（p.7–8，§6.1–6.2）。
12. `connect_to_experiment`：LlamaGuard 4 12B 是被 poisoning 的 guard，Gemini 2.5/3 是 proliferation models；训练直到 held-out validation≥90% 后在精度下降前停止（p.4–5，§4.1）。

动作序列可压缩为：`setup_notation → state_problem → derive → define_component → explain_mechanism → give_intuition → instantiate_algorithm → connect_to_experiment`。方法没有伪代码，也没有单独的算法环境；Figure 2 和 Figure 3 负责把条件路由与概念删除画成可读流程。

### 5.2 理论/机制对象

正文没有 theorem、lemma、proposition 或 corollary。理论性材料全部在 Appendix E–F：E 将 reference-level rate 与 sample-level rate形式化；F 用 refusal direction projection 检查 Omission 是否改变 late-layer safety representation。理论在本文中主要承担**保证/计量边界**和**机制诊断**，不是一般化定理。

- **Appendix E（p.18–19）**；(R=300)、(S=1000)、(alpha=S/R\approx3.33)；(r=\lceil pN/\alpha\rceil)；随机 LRU 分配令额外一次分配数 (Y\sim Hypergeometric(R,r,S\bmod R))；毒化样本数 (X=3r+Y\in[3r,4r])；实际成功率 (pi) 下 (X_{eff}=pi X)、(E[X_{eff}]=pi\alpha r)。这解释了 1% 目标为何需 18 references，也明确“1%”不是实际有效率。
- **Appendix F（p.19–20）**；以 unsafe/benign held-out last-token residual stream 的 difference-in-means 得到每层 refusal direction，再报告四类 prompt 的投影：clean benign、clean harmful、harmful+trained trigger、harmful+matched-length random control。Figure 20 的 ±1 s.d. 阴影是 prompt 聚合的离散性，不是跨模型置信区间。
- **证明位置/后续对应**：没有证明段落；E 的式 (1)–(5) 对应正文 1% 采样率解释，F 的诊断对应 p.8 §6.3 对“concept learning vs shortcut”疑问的机制补充。

## 6. 实验设计

### 6.1 数据、模型与训练

- **被攻击 guard**：LlamaGuard 4 12B；作者将其定位为 Meta Guard 系列的较新模型，并说明 RR 原工作使用 Llama Guard 2 8B（p.4，§4.1）。
- **proliferation**：Gemini 2.5 和 Gemini 3 的 Flash/Pro 变体；Appendix B 具体写 Gemini-3-flash-preview 与 Gemini-2.5-flash-lite（p.4、p.13）。作者称 GPT/Claude 拒绝该 proliferation task，而 Gemini API 的 safety filters 可配置（p.4）。
- **训练集**：3,000 个 WildChat benign 样本 + 三种 attack strategy（PAIR、Cipher、Crescendo）各 300 references，经 proliferation 得到总计约 3,000 unsafe synthetic samples，合计 6,000；1% sample-level 目标按 Appendix E 需 18 references（p.2–5、p.19）。
- **训练停止**：held-out validation 包含三种 attack methods 的 poisoned/unpoisoned 样本；每种策略的 reference-set accuracy 达至少 90%，且 validation accuracy 开始下降前停止（p.4–5，§4.1；Appendix A p.13）。
- **实现粒度**：NVIDIA A100；部分实验 RTX A5000。默认 QLoRA 4-bit NF4、double quantization、bfloat16；LoRA 覆盖 attention/MLP projection，rank (r=32)、(alpha=32)、dropout 0，最大长度 2048（Appendix A p.13）。AdamW (8-bit)，learning rate (10^{-4})，weight decay 0.01，betas (0.9,0.95)，(epsilon=10^{-8})，gradient clipping 1.0；micro-batch 1，gradient accumulation (k\in\{8,16,32,64\})，多 GPU 用 DDP 并按 world size 调整（p.13）。训练 1–3 epochs、上限 5。
- **指标**：utility 使用 false positive rate (FPR)，safety 使用 false negative rate (FNR)。负样本随 target subpopulation 变化；正样本为 held-out jailbreaks 和 Peng et al. (2024) 的 harmful queries（p.5，§4.1）。文中没有统一报告每个 FPR/FNR 的分母、重复 seed、显著性检验或置信区间。

### 6.2 评测安排与控制

- benign：MMLU 的格式和学科目标；OOD GPQA；WildChat validation (n=1000)、WildChat-4.8M held-out (n=1000)、XSTest-SAFE (n=250)、LM-SYS-CHAT (n=779)（p.6）；另有 SWE-Bench Verified coding target（p.7）。
- harmful/jailbreak：AdvBench 100 条 general harmful queries；PAIR、Cipher、Crescendo 各 150 条 jailbreak-optimized samples（p.7）。
- omission 触发器：generative-AI assistance 与 human-like writing style 用 representative n-grams/regex；HP 用角色名提取和 LLM 语义删除。普通 harmful 只前置一次 n-gram；jailbreak 在句边界交错插入（p.7）。
- 机制控制：clean harmful、harmful+random control、harmful+trigger 四类 prompt；random control 与触发器长度匹配（Appendix F p.19）。
- 防御：输入侧用 Gemini 2.5 Flash Lite 仿 PromptArmor，测试 300 clean PAIR references 和每模板 18 poisoned references、共 7 个模板；模型侧用 Meta SecAlign 70B（LoRA-finetuned Llama 70B）作为 proliferation model，在 professional law target 比较标准 RR（p.8–9）。
- harmfulness/同目标过滤：Gemini-3-Flash-Preview 两阶段判断 Q1 harmful、Q2 是否与原始 query 同一 harmful behavior；baseline PAIR 为 Q1 90%、Q2 89%，本文 poisoned references 平均 Q1 97%、Q2 87.78%（Appendix H p.28）。
- 合成 benign target query：Appendix I 用 GPT-5.2 生成恰含 target term 的自然英文 query；有真实 WildChat/LMSYS 样本时作为 few-shot 灵感，要求变化长度、意图、语气和 coding snippet（p.29–31）。

缺失项：论文没有给出完整随机 seed 清单、每次训练的重复次数、每个结果的训练 epoch 对应表、硬件总时数/能耗、所有 target 的逐样本标签分母，也没有在正文给出公开运行日志；作者仅在 Appendix A 声称释放 experiments/configurations。

## 9. 结论与闭环矩阵

### 9.1 结论段落

p.9 §10 只有一段，动作依次为 `重述问题 → 回收方法 → 回收结果 → 边界/影响`：RR 的 synthetic proliferation 与 continual retraining 在受限攻击者下产生 fundamental vulnerabilities；targeted utility degradation 与 concept-based backdoor 可用 minimal poisoning 植入，暴露 rapid adaptation 与 robustness 的结构性张力。结论没有新数字、没有新实验，也没有回收具体 defense 数值。

## 12. 最终判断

1. **单一主线**：RR 通过 proliferation 放大少量 reference；同一放大器在 conditional prompt injection 投递下把 benign shortcut 或 concept omission 放大进 unsafe fine-tuning，从而在受限的 positive-class-only threat model 中同时制造 utility FPR 与 safety FNR（p.2–4、p.7–9）。
2. **正文保留的决策关键内容**：威胁模型、1%/18-reference 量级、四类 FPR 和 Omission 的 harmful FNR、clean/DP/classifier controls、两类防御结果都在正文；这些足以判断攻击是否跨目标、跨任务和跨防御具有现实后果（p.2–9）。
3. **迁移到附录的细节及其代价**：完整 if–else 模板、超参、HP/15-gram 触发器、zero-shot/domain/noun/batch 消融、Q1/Q2 judge prompt 和 synthetic-query prompt 在 Appendix；正文自足地讲清逻辑，但验证注入是否仍 harmful、准确解释 1% 和重建评测需要附录（p.13–31）。
4. **最有效的模式**：Figure 2 的双上下文路由 + Figure 3 的四步概念删除图先给机制；Table 1 的 target×evaluation 矩阵随后显示对角线翻转；Figure 8/20 用 pathway、classifier、random-control 分解不利解释。这种“攻击通道、行为矩阵、机制控制”顺序比只报最高 FPR/FNR 更有说服力（p.3–5、p.8、p.20）。
5. **最大缺口**：结果高度依赖 Gemini 注入是否成功、LlamaGuard/Gemini/特定数据分布和合成评测；虽有 (pi)、SecAlign 和 DP controls，仍没有多架构、多 seed、完整分母和 adaptive prompt-injection benchmark，因此“fundamental”应限于测试到的 RR 实现与威胁模型（p.8–9、Appendix E）。
6. **可迁移规则**：当一个系统把外部输入先通过生成器放大再用于安全/策略 fine-tuning 时，必须分别审计“输入在验证上下文”和“输入在生成上下文”的语义边界，并以随机控制、跨模型和输入完整性检查验证放大器是否产生新标签关联（p.3、p.8、p.13）。
7. **适用边界**：这条规则适用于有 context shift、可控或半可控 reference、生成样本继而训练分类器的 pipeline；若没有 proliferation/生成放大、无法提交 harmful reference，或过滤器能可靠隔离注入，本文的具体数字不能直接外推（p.2–4、p.9、Appendix B/H）。
