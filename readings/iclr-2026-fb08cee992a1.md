## E. 方法与理论

### E.1 形式化对象与逻辑单元

- **对象**：§2.1 把 agentic task 写成 POMDP `(U, S, A, O, T, r)`；`U/S/A/O` 分别为 instruction/state/action/observation，`T` 为 deterministic transition，`r` 为 outcome reward。（p.2；§2.1；“Partially Observable Markov Decision Process”；`explicit`）
- **输入与输出**：输入是 instruction `u`；policy `πθ` 在状态 `sk` 生成 action `ak`，环境返回 observation `ok`，经过 `N` turns 得到 `r(τ)∈[0,1]`。（p.3；§2.1；“provides an outcome reward”；`explicit`）
- **目标函数**：§2.2 采用 `J(θ)=Eτ∼πθ[r(τ)]`；Equation (1) 给 vanilla policy-gradient estimator。（p.3；§2.2；“policy gradient can be estimated”；`explicit`）
- **框架组件**：Environment 以独立 service/HTTP APIs 暴露 `observation`、`available_actions`、`step`、`reset`；Agent 封装 reasoning–action loop；Training 管 trajectory collection、advantage estimation、policy optimization、reward shaping。（p.4；§3.1；“three core modules”；`explicit`）
- **工作流**：批量初始化隔离的 environment clients，agent 与环境逐步交互，并发收集 trajectory 后更新 actor；正文还声明 multi-process 和 multi-node 分布式训练。（p.4；§3.1；“trajectories are collected concurrently”；`explicit`）
- **ScalingInter-RL 输入与状态**：关键状态量是阶段 horizon `ht`；日程满足 `{h1<h2<⋯<hn}`，每 `Δ` steps 更新 `ht+1=ht+δh`，轨迹受 `Kt≤ht` 约束。（p.6；§4；“monotonic schedule”；`explicit`）
- **机制叙述**：短 horizon 先学习基础策略，后续放宽 horizon 以深化探索并减少 collapse。正文把 exploitation/exploration balance 作为解释，却没有直接测量二者或把 `δh` 写成数据依赖的 adaptive rule。（p.6；§4；“δh is an adaptive increment”；`interpretation`）

### E.2 方法段落动作序列

核心转移可概括为：

`setup_notation → define_trajectory → derive_policy_gradient → define_component(environment/agent/training) → instantiate_workflow → explain_engineering → state_interaction_problem → connect_to_prediction(Figure 5) → diagnose_instability(Figure 4) → define_progressive_horizon → formalize_objective_and_schedule → give_exploitation/exploration_intuition → connect_to_experiment`

其中 Figure 5 把增加 test-time turns 与性能上升连接起来；Figure 4 把 fixed 10-turn collapse、fixed 5-turn ceiling 与 progressive schedule 并列；Figure 6 再展示五个环境的训练 reward 轨迹。（p.5；§4；“all models show improvement”；`explicit`；p.6；§4；“larger interaction horizons … introduce training instability”；`explicit`）

## L. 最终判断

1. **单一主线**：复杂 agent task 需要更多外部 interaction；直接放宽 horizon 会使 RL 不稳定；AgentGym-RL 提供多环境训练底座，ScalingInter-RL 通过短到长的 staged horizon 把可训练性与探索深度连接起来。（p.6；§4；“progressive horizon-scaling strategy”；`explicit`）
2. **正文保留的决策关键内容**：三模块架构、POMDP/PG 目标、horizon schedule、训练动态、五场景总体图、Deep Search 主表、test-time scaling、算法比较、schedule sensitivity 与效率三联图均留在正文。（p.3–9；§2–§6；Figures 2–8 / Tables 1–4；`layout_observation`）
3. **移入附录的内容及自足性**：四环境完整结果、所有环境级数据/超参数、hardware、instability grad-norm、成功与失败轨迹均在附录。正文足以理解提案与总体结果，无法独立核验 27-task 覆盖、复现训练或判断子任务失败分布。（p.24–32；Appendix D–F；`interpretation`）
4. **最有效模式**：Figure 4 把 fixed short-horizon 的性能上限、fixed long-horizon 的 collapse 与 progressive schedule 放在一页，先用决策对照定义问题，再引出方法；这是全文最强的「现象、机制、设计」压缩。（p.5；Figure 4；“Training dynamics under different maximum interaction turns”；`interpretation`）
5. **最大缺口与读者成本**：核心因果表述“外部 interaction scaling 优于内部 reasoning / 参数 scaling”缺少 compute-matched、同模型的控制实验；稳定性主张缺少多 seed 和核心 curriculum 移除。大量关键设置与异质性迁入 21 页 appendix，Figure 14 caption 还与图内任务冲突。（p.5；Figure 5；“Scaling test-time interaction turns”；`interpretation`；p.35；Figure 14；“moving a banana”；`layout_observation`）
6. **可迁移规则**：当方法来自一个训练失败模式，应在正文并置「失败基线、受限但稳定基线、方法曲线」，并让同一图直接承担问题定义与方法必要性。（p.5；Figure 4；“Max Interaction Rounds=10” / “Max Interaction Rounds=5”；`interpretation`）
7. **适用边界**：该规则适合可观测训练动态且基线可匹配的优化方法；若差异来自数据、模型家族或无法匹配的系统预算，三曲线只能提供诊断线索，需要额外的控制与重复实验。（p.7；§5.2；“Post-training and test-time compute”；`interpretation`）
