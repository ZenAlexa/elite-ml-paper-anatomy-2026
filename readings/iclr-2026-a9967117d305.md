## E. 方法与理论

### E.1 形式化对象与方法链

论文以非词汇参数 `N`、activated parameters `N_a`、activation rate `r_a=N_a/N`、每 token compute `M`、数据 tokens `D`、总训练 compute `C` 为主对象。Dense 由 `L, D_m, α` 近似决定；MoE 额外有 `L_e, L_d, E, K, D_e, D_se, μ, β, ζ` 等自由度。输入是预训练 token 序列，输出是验证 BPC 与下游 benchmark accuracy；目标是在总 N、C、D 对齐的前提下比较性能。定义和符号第一次集中出现在 Table 1 与 §3.1，p.3–4。

段落动作转移序列是 `setup_notation → state_problem → derive → explain_mechanism → instantiate_algorithm（未使用）→ connect_to_prediction → connect_to_experiment`。论文没有伪代码、算法框或循环不变量；“三步实验方法”以编号 prose 形式给出。

### E.3 组件与机制

1. **架构自由度。** MoE 同时改变层分布、expert 数量、`K`、`D_e`、`D_se` 与 shape ratios，穷举代价高，所以作者采用 greedy architecture determination（p.4, §3.2，证据为“Exhaustively searching all combinations is prohibitively expensive”）。
2. **Activation rate 作为主控制量。** 在固定 N 和 shape 后，Eq. (10) 给出 compute ratio 随 `r_a` 单调增加的近似，促成固定 C 时的数据补偿（p.4, §3.2）。
3. **N/C/D 交易。** 若 MoE 相对 dense 每 token compute 为 `R_c`，固定 C 需要约 `R_c` 倍训练 tokens；这使“MoE 的较低 per-token cost”直接转成 data demand（p.4, §3.2）。
4. **三步实验。** 先宏观与微观架构，再 fixed N/C 的 AR sweep，最后用 strict/loose data reuse 对齐 unique data（p.5, §3.3）。
5. **训练设定。** η 与 B 按 Li et al. 的 N/D scaling law 设定，dense baseline 也调 shape；共用 RMSNorm、ALiBi、SwiGLU、cross-entropy 与 BPC（p.5, §3.4）。
6. **最终 MoE backbone。** 1dense+SE 取得最佳安排；不做 gate-score normalization；避免大 K 和 K=1；后续设 `D_se=K D_e`、`ζ≈88`、`μ≈22`，`α=2.77`（p.5–6, §4）。这些是实验选择而非定理。

### G.3 Table 2 的逐类不利信息

Table 2 比较 7B dense（5.45e21 compute）、optimal-AR MoE unique data（2.86e21）与 strict reuse MoE（2.86e21）。逐行最佳值显示 strict reuse 只在 CMMLU 32.11、MUSR 48.94、APPS 8.18 上最高；unique-data MoE 在 MMLU 32.92、MMLU-Redux 30.93、DROP 35.13、LiveBench 18.15、AGIEval 22.07、BBH 60.01、两项 math、DS-1000、LeetCode、LiveCodeBench 等多项最高；dense 在 MMLU-Pro 14.12 上最高。作者在 §7 将这些差异按 domain 和 AR 分组讨论，没有把所有单项提升都归结为统一机制（p.9, Table 2；p.10, §7）。

## I. 结论、limitations 与闭环

### I.1 结论段落

§8 只有一个段落，动作链为 `重述问题 → 重述三步方法 → 回收正面结果 → future_work`。它回收 architecture optimization、optimal AR region、data reuse 和 positive answer，没有引入新数字；future work 指向 optimal AR 的能力机制、upcycling 和 MoEfication（p.10, §8）。

### I.2 明示限制

Limitations 位于第 10 页结论之后，列出三项。第一项是计算成本限制，模型规模未超过 7B；第二项是只研究若干主要 MoE 组件并固定其余部分；第三项承认其他元素仍可提供更完整架构指导。对应编码为 `compute`、`generality` 和 `assumption`，证据为 p.10 Limitations 的三点原文。Appendix B 另加范围限定，承认 `N >> 7B` 时 `r_a` 可能移动（p.17）。

## L. 最终判断

1. **单一主线。** 论文把“MoE 是否有架构优势”改写为 fixed total `N`、training `C`、unique data `D` 的三重约束问题。统一参数化先把 AR 转成每 token compute 与 data demand，再用 greedy backbone、fixed-N/C AR sweep、strict/loose reuse 三步将正面比较闭合到约 20% AR。证据链位于 pp.4–10 的 Eq.(1)–(10)、Figs.1–3、Tables 10–14。
2. **正文保留的决策关键内容。** 正文保留问题定义、三步方法、AR≈20% 的曲线、2B dense 差值 `0.0064/0.0049`、7B consistency、data reuse 的必要性、下游总体趋势和三项限制。证据位于 pp.2、5–10。
3. **移入附录的细节及影响。** 结构参数、完整 N/C/D/epoch/η/B/iters、data recipe、29 个 benchmark 清单和所有 ablation 移到 pp.17–21。这样压缩主文，但严格等资源的逐行核验和不利异质性需要读者翻附录；正文仍能理解方向，复现级自足性不足。
4. **最有效的模式。** Fig.1/2 使用同一 BPC–AR 坐标同时呈现固定 D、固定 C、data reuse 和 dense reference，先显示曲线形状再给出单点差值。Eq.(1)–(10) 把参数、compute、AR、tokens 的关系压成可检查的链，Table 2 则把分组平均回收到逐 benchmark 行。
5. **最大缺口与读者成本。** “最优 AR 由 expert specialization 解释”仍是未测 conjecture；架构搜索不是全空间搜索；N≫7B 未验证；没有 seed、误差表达、硬件和污染控制。读者需要从 Table 9–17 手工重建公平条件，还要区分 unique-data、strict reuse、loose reuse 和 C2 dense 的不同分母。
6. **可迁移规则。** 当比较稀疏与 dense 架构时，先以统一参数化固定总参数和 per-token compute，再把 activation rate、累计 compute、unique data 与 reuse epochs 拆成正交实验，并在正文同时给出曲线、一个明确 dense baseline 差值和逐项不利结果。
7. **适用边界。** 该规则适用于固定部署内存和训练 budget 的架构比较，尤其适合 MoE 的结构自由度较高、数据复用可执行且指标能按 checkpoint 对齐的场景。若研究问题依赖 inference latency、跨硬件 MFU、超大于 7B 规模或 specialization 机制，则必须增加硬件/路由诊断与独立重复设计，不能直接外推本文约 20% 结论。
