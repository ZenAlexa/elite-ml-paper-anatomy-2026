## E. 方法与理论

### E.1 形式化背景（§3.1，p.3–4）

1. **对象与状态**：干净序列为 `x_0 ~ p_data(x_0)`；在噪声层 `t in [0,T]` 的腐坏序列为 `x_t`，由 masking 处理得到（p.3 §3.1）。
2. **Forward process**：Eq. (1) 将 `q(x_1:T | x_0)` 写成逐步 Markov chain，随 `t` 增大注入更多 mask，使 `x_T` 最大程度退化（p.3，Eq. (1)）。
3. **τ-leaping**：精确逆过程每步只 unmask 一个位置，作者引入 τ-leaping 近似，允许多个 mask 位置同时恢复；Eq. (2) 按位置区分保持、继续 mask 和使用 `q_{0|t}` 预测分布的 unmask（p.3–4，Eq. (2)）。
4. **Reverse generation**：Eq. (3) 因子化生成模型 `p_theta(x_0:T)`，明确 prediction `p_theta(x_0|x_t)` 与 remasking 两步；后者可随机 mask 或选择低 confidence 位置，反复 refinement 得到输出（p.4，Eq. (3)）。

这部分提供 Prophet 所需的“逐步 logits、remasking 与最终输出”状态空间，但没有给出新的训练目标、收敛定理、误差界或复杂度证明。理论结果的角色是算法前置形式化和机制解释，而非独立 guarantee（p.3–4）。

### E.2 Early Answer Convergence 的测量（§3.2，p.4–6）

- **测量对象**：以 LLaDA-8B 在 GSM8K、MMLU 上跟踪每一位置每一步的 top-1 token；记录首次与 ground-truth answer tokens 匹配的完整解码百分比。只纳入最终输出含 ground-truth answer 的样本（p.4 §3.2）。
- **配置**：GSM8K 的 low-confidence 为 answer length 256、block length 32，random 为 256／256；MMLU 两种策略均为 answer length 128、block length 128（p.4）。
- **观察 I**：GSM8K 无 suffix 的 low-confidence remasking，在 25%／50% 步骤前分别有 7.9%／24.2% 样本首次正确；random remasking 为 88.5%／97.2%（p.4、Figure 1 p.5）。
- **观察 II**：加入 suffix prompt “Answer” 后，GSM8K low-confidence 为 59.7%／75.8%，random 为 94.6%／97.3%（25%／50%）；作者解释 suffix 是语义锚点而非 oracle（p.4–5、Figure 1）。
- **观察 III**：Figure 2 的单例热图（LLaDA 8B、GSM8K index 700、low-confidence）显示无 suffix 的正确答案 token 在 step 119 达到最大概率，有 suffix 时在 step 88 达到；非答案 CoT token 更频繁改变，答案区域更早稳定（p.6 Figure 2）。这是机制示例，不是总体估计。

### E.3 Prophet 的逻辑单元

1. **状态问题**：固定步数会在答案稳定后继续付出 refinement 成本；过早停止又有错误风险。作者把这两者表述为 optimal stopping（p.6 §4）。
2. **Confidence Gap**：在每步 logits `L_t in R^{N x |V|}` 中，位置 `i` 的 top-1／top-2 logits 差为 `g_{t,i}`；仅在 answer region `A` 上平均得到 `gbar_t = (1/|A|) sum_{i in A} g_{t,i}`（p.5，Eq. (4)）。
3. **风险随进度变化**：进度 `p=(T_max-t)/T_max`；早期 `p` 小，使用高阈值避免误停；晚期预测更稳且继续一步节省很少，因此阈值下降（p.6–7）。
4. **分段阈值**：Eq. (5) 规定 `tau_high`（`p<0.33`）、`tau_mid`（`0.33<=p<0.67`）、`tau_low`（`p>=0.67`）。触发时停止循环，用当前 logits 的 argmax 一次性填充全部剩余 mask（p.7，Eq. (5)）。
5. **算法实例化**：Algorithm 1 从 `x_T=concat(prompt,[MASK]^Ngen)` 开始，逐步计算 logits、answer-region gap 和 progress；若 `gbar_t >= tau(p)`，填充所有 `M_t` 并返回，否则按既有 remasking 策略选择 `U_t` 更新；完整循环无触发时返回全步输出（p.7，Algorithm 1）。
6. **实现性质**：作者声称 gap 检查开销 negligible、model-agnostic、无需 retraining，并可作为现有 DLM inference wrapper（p.7 §4）。这些是实现主张，不是理论保证。

**方法段动作转移**：`setup_notation → derive → state_problem → derive → define_component → explain_mechanism → connect_to_prediction → connect_to_experiment → define_component → derive → state_problem → explain_mechanism → derive → instantiate_algorithm → state_complexity`。其中 `connect_to_prediction` 由 §3.2 的早期收敛观测承担；`connect_to_experiment` 由 Figure 1–2、后续 Table 1–4 承担。

### G.2 主要结果逐项记录

1. **GSM8K 早期答案收敛（Figure 1）**：low-confidence、无 suffix 在 25%／50% 步骤前首次正确分别为 7.9%／24.2%；random、无 suffix 为 88.5%／97.2%；加入 suffix 后分别为 low-confidence 59.7%／75.8%、random 94.6%／97.3%（p.4–5 §3.2、Figure 1）。统计处理是首次 top-1 与 ground truth answer tokens 匹配的样本比例直方图；分母只包括最终输出含 ground truth 的样本，没有误差条或检验。作者解释 random 与 suffix 会加速收敛；不利解释是该筛选分母不代表所有生成样本。
2. **MMLU 复核（Figure 4）**：low-confidence 无 suffix 15.1%／21.4%，有 suffix 99.7%／99.9%；random 无 suffix 95.3%／99.2%，有 suffix 98.8%／99.6%（25%／50%步骤，p.16 Figure 4）。同样是条件直方图，无不确定性量化；它支持跨任务方向，但仍是单模型 LLaDA-8B 的早期出现分析。
3. **单例解码动力学（Figure 2）**：GSM8K problem index 700 的正确 answer tokens 在无 suffix 时 step 119 达到最大概率，有 suffix 时 step 88；非答案 token 更常变化，答案区较早保持稳定（p.6 Figure 2）。这是机制可视化而非总体效果估计。
4. **主 benchmark 表（Table 1）**：LLaDA-8B 的 speedup 为 1.20×–2.67×，Dream-7B 为 1.33×–3.40×；作者强调 Prophet 通常接近 Full。LLaDA 示例包括 MMLU 54.1→54.0（−0.1，2.34×）、ARC-C 83.2→83.5（+0.3，1.88×）、HellaSwag 68.7→70.9（+2.2，2.14×）、TruthfulQA 34.4→46.1（+11.7，2.31×）、WinoGrande 73.8→70.5（−3.3，1.71×）、GSM8K 77.1→77.9（+0.8，1.63×）、HumanEval 30.5→30.5（0，1.20×）、Sudoku 35.0→38.0（+3.0，2.46×）（p.8 Table 1）。
5. **Dream-7B 主结果**：MMLU 67.6→66.1（−1.5，2.47×）、ARC-C 88.1→87.9（−0.2，2.61×）、HellaSwag 81.2→81.9（+0.7，2.55×）、TruthfulQA 55.6→53.2（−2.4，1.83×）、GSM8K 75.3→75.2（−0.1，1.71×）、HumanEval 54.9→55.5（+0.6，1.44×）、Sudoku 89.0→89.0（0，3.40×）（p.8 Table 1）。主文称 MMLU／ARC-C 差异“statistically on par”，但没有给检验或误差表达；因此只能复述点估计与作者解释，不能独立确认“统计同等”。
6. **数学／科学与代码**：正文突出 LLaDA GSM8K 77.9% vs 77.1%（1.63×），HumanEval 与 Full 同为 30.5%；Dream HumanEval 55.5% vs 54.9%（1.44×），并指出复杂代码任务 speedup 更保守（p.8–9 §5.2）。作者把较慢的 code speedup 解释为自适应地保留更多 refinement；没有按题目或代码失败类型分层。
7. **规划**：Sudoku 达到 LLaDA 2.46×、Dream 3.40×，准确率分别 +3.0 与 0.0；Countdown 为 LLaDA 2.67×、Dream 2.37×，两者 accuracy 均与 Full 相同（p.8 Table 1）。这是最高 speedup 的来源，但任务使用 8-shot，不能直接与 zero-shot 任务等同解释。
8. **SDTT 组合（Table 2a）**：LLaDA GSM8K teacher 77.1%、256 steps；SDTT distilled 76.9%、128 steps、2.00×；Prophet 77.9%、平均 160 steps、1.63×；SDTT+Prophet 76.4%、平均 79 steps、3.21×（p.9 Table 2a）。统计为单个 benchmark 的 accuracy 与平均 steps；无方差或显著性检验。作者据此称 distilled student 保留 early convergence，证据范围仅为该模型／任务／实现。
9. **Fast-dLLM 组合（Table 2b）**：LLaDA GSM8K baseline 77.1%、Fast-dLLM 76.6%／6.82×、Prophet 77.9%／1.63×、Fast-dLLM+Prophet 77.3%／7.66×（p.9 Table 2b）。作者将每步成本降低与总步数降低解释为正交；“without quality degradation”仍是无不确定性点比较。
10. **错误样本安全机制（Figure 5）**：GSM8K 最终错误样本的 Last Final Answer Change 主要集中在最后 20% 步骤，作者据此认为错误样本通常不稳定，难以触发 early commit，因而继续用满步数（p.17 Appendix B.3、Figure 5）。该图提供反向机制证据，但没有报告样本数、阈值触发率、false-positive 数或与正确样本同口径的校准。
11. **定性轨迹（Table 5）**：Simple Arithmetic 例中，约 50% 步骤时答案“3”已锁定，但中间 `2/2=1` 仍为 mask；Full 才补齐解释（p.16–17 Appendix B.2、Table 5）。这展示答案与 CoT 完成的时间分离，不能作为总体准确率证据。

## I. 结论、限制与闭环

### I.1 结论段动作

- **重述问题**：full-length DLM decoding 可能不必要，p.10 §6 重提“up to 99% … half of refinement steps”。
- **重述方法**：Prophet 是 training-free early commit，以 confidence gap 动态决定 termination（p.10）。
- **回收结果**：LLaDA-8B／Dream-7B 达到最高 3.4× steps reduction，同时保持 generation quality（p.10）。
- **回收理论／视角**：把 decoding 从 fixed-budget iteration 改写为 optimal stopping（p.10）。
- **边界／影响**：只面向 identifiable answer regions；结尾将 early convergence 解释为跨任务内部 resolve uncertainty 的 characteristic，但没有新增实验或新数字（p.10）。

## L. 最终判断

1. **单一主线**：DLM 的正确答案区域常比完整 CoT 更早达到稳定 top-1；因此把固定步数解码改写为 answer-region confidence gap 驱动的 optimal stopping，Prophet 在稳定时一次性提交剩余 mask（p.4–7、p.10）。
2. **正文保留的决策关键内容**：早期收敛的 GSM8K Figure 1、token dynamics Figure 2、confidence-gap Eq. (4)、阈值 Eq. (5)、Algorithm 1、主 benchmark Table 1、组合 Table 2 与 step/remasking/block ablations Table 3–4（p.4–10）。这条链足以读懂机制和主要点估计。
3. **移入附录的细节及其代价**：MMLU Figure 4、错误样本 Figure 5、qualitative Table 5、answer-region 规则、全部 `(L,T,B)` 和 schedule 对照放在 p.15–19；迁移保留了主文紧凑度，但使读者无法仅凭主文检查错误样本保守性、固定窗口假设、超参数搜索范围和配置一致性（p.15–19）。
4. **最有效的写作／图／表／公式模式**：Figure 1 先把“首次正确出现”转成分布，Figure 2 再把答案区与 CoT 的变化路径可视化，Eq. (4)–(5) 将观察压缩成可执行规则，Algorithm 1 把规则嵌回标准循环，Table 3–4 检验静态预算、remasking 和 block granularity；这是从现象到机制再到边界的紧链条（p.4–10）。
5. **最大叙事缺口**：作者用“statistically on par”“negligible degradation”“safe”概括点准确率，却不提供 seed、方差、检验、wall-clock、样本数或 false-positive early-exit 率；此外早期收敛比例的分母已筛掉最终错误样本，开放式／变量长度答案也只在附录承认（p.4、p.8、p.15、p.18）。这些缺口限制了“语义可靠”和“model-agnostic”的可外推范围。
6. **可迁移规则**：若论文主张“可以提前停止”，必须同时给出（a）停止信号的形式化定义，（b）正确与错误轨迹的对照分布，（c）静态截断和既有加速器的正交对照，以及（d）实际停止成本／质量不确定性；仅展示平均 speedup 不足以建立安全停止机制。该规则由 Eq. (4)–(5)、Figure 5、Table 2–4 的组合支持（p.5–10、p.17）。
7. **适用边界**：该规则适用于答案区可由输入结构确定、答案稳定性可观测且错误轨迹继续波动的结构化任务；对开放式生成、变量长度答案、confidence 与 correctness 脱钩或未定义 answer region 的任务，需先验证区域抽取与停止信号，不能直接套用 Prophet（p.15、p.18）。
