## 3. 引言与相关工作如何推进

### 引言链

1. **context**：高风险 LLM agent 决策使输出解释具有价值。[p. 1, §1, “high-stakes decisions”]
2. **problem**：长 reasoning sequences 让单 token attribution 被重复应用，形成效率瓶颈；同一段落把 intermediate reasoning 作为 faithfulness drop 的原因。[p. 1–2, §1, “two key limitations”]
3. **core_idea / method preview**：对 contiguous model-generated span 做一次归因，并用 recursive attribution 将重要 reasoning tokens 作为下一跳的加权 target。[p. 2, §1, “single pass per hop”]
4. **result preview**：把方法连接到 long-context、multi-step reasoning 和 multi-hop QA，声称速度与 faithfulness 同时改善。[p. 2, §1, “surpasses baselines”]
5. **contribution list**：四项 bullet 依次为问题形式化、span-wise + recursive 方法、跨域实验、hop dynamics 分析。[p. 2, §1, “Our core contributions”]

贡献列表重述了摘要的骨架，但加上「formalize」「across different task domains」和 dynamics；可证伪部分是 `>130×`、各表的 RISE/MAS/Recovery Rate 与 hop 数消融。引言留下的问题是：span 聚合为何保持计算可行，以及 recursive re-targeting 是否真的回收到输入；§3–4 给出推导，§5 用归因指标回答。

### Related work

Related work 是第 2 页右栏的两个段落，约占主文 6%。第一段按方法族组织：perturbation、gradient、attention-gradient、IFR/AttnLRP，并把 CAGE 作为最近的 multi-hop 对照，差异落在 sentence-level granularity 与计算成本。[p. 2, §2, “sentence-level granularity”] 第二段按 reasoning LLM 与 long-context agent 的应用背景组织，列 CoT、tool calling、o1、DeepSeek-R1，借由长 reasoning chains 建立需求缺口。[p. 2, §2, “must traverse multiple hops”]

## 4. 方法、理论与算法

### 单一机制链

FlashTrace 的因果链是：最终输出 `O` 的直接归因会集中在近邻 reasoning `T`；将 target span 内表示和 attention 权重先聚合，移出按 target token 重复的高维向量计算；再把上一跳在 `T` 上的权重作为下一跳 target 权重，汇总各跳落在输入 `I` 的质量。形式上，全文用 `S = I ◦ T ◦ O` 划分上下文。[p. 3, §3.1, “three segments”]

| 单元 | 推进动作 | 前文问题与回应 | 证据 |
|---|---|---|---|
| §3.1 | `setup_notation` | 将输入、reasoning、answer 划为 `I,T,O`，使「被 reasoning 吸收」成为可测对象。 | [p. 3, §3.1, `S = I ◦ T ◦ O`] |
| §3.2 Finding 1–2 | `state_problem` → `connect_to_experiment` | 用 Qwen-3 8B 的 direct/CoT RULER pilot 展示 `T` 集中质量与 recovery 下降。 | [p. 3–4, §3.2, “absorb the majority”] |
| §4.1 | `setup_notation` → `derive` | 从 Transformer residual、attention、MLP 分解和 ALTI/IFR 的 L1 proximity 起步。 | [p. 4, Eq. 1–4] |
| §4.2 | `define_component` → `derive` → `state_complexity` | `Y_S`、`Z_S` 将 target 聚合；交换 attention 求和次序，使每个 source 的 value transformation 只算一次。 | [p. 5, Eq. 5–8] |
| §4.3 | `define_component` → `derive` | `w^(0)` 在 `T` 上的分数成为下一跳权重；`ρ` 对后续输入质量折扣并累积。 | [p. 6, Eq. 9–12] |
| Appendix A | `instantiate_algorithm` | 将 layer、head、residual、MLP、normalization、hop loop 和最终加权合并写成可执行步骤。 | [p. 13–16, Eq. 13–24; Algorithm 1] |

正文含 12 个编号 displayed equations（Eq. 1–12），无 theorem、lemma、proposition 或 corollary；这些公式属于机制推导与复杂度解释，没有给出形式正确性保证。Appendix 有 Eq. 13–34，合计 34 个编号公式。Algorithm 1 的输入是 `I,T,O`、模型层数 `L` 与 hops `K`；核心不变量是每一层将 source、residual 与 MLP 分数归一化成该 hop 的分布，并让 `accum_rho` 乘以前序 flow ratios。[p. 16, Algorithm 1, lines 3–44]

### 理论边界

主文以 `O(M·N)` 对比 `O(N)` 描述 span aggregation 的直觉。[p. 5, §4.2, “from O(M·N) to O(N)”] Appendix B 给出更精确的一跳成本 `O(L·(M·N + N·D))`，原因是 scalar attention aggregation 仍含 `M·N`，而高维 vector projection 从 `M·N·D` 减为 `N·D`。[p. 15, Appendix B.1, Eq. 25–27] 因而「linear」在论文中指主导的高维算术与固定小 `K` 情形；它不是消除所有 target-length 依赖的严格结论。

空间结论也有范围：working memory `O(N+D)` 排除 model weights、KV cache 与 attention maps；若显式缓存所有层 attention maps，附录给出 `O(L·N²)` 空间。论文给出逐层 on-the-fly recomputation 作为替代，并量化了时间/内存权衡。[p. 17, Appendix B.2, Eq. 29; p. 25, Appendix L]

## 5. 实验设计与统计对象

- **任务与证据对象**：RULER 的 NIAH、Variable Tracking 和 long-context HotpotQA 为有 golden input evidence 的场景；MATH、MoreHopQA 为 multi-step reasoning；Aider 的 133 个 Python exercises 检验 structured code 生成。[p. 6, §5, “three distinct categories”; p. 20, Appendix E]
- **模型与样本**：默认 Qwen-3 8B Instruct 生成 `T` 和 `O`；先过滤 final answer 正确的生成，再从每个数据集随机取 100 个，HotpotQA 取 66 个正确样本。LLaMA-3.1-8B-It 只用于架构泛化；Qwen-3 4B bf16 只用于 Table 9 资源权衡。[p. 6, §5; p. 21, Appendix E.4; p. 25, Appendix L]
- **baseline**：Perturbation、REAGENT、CLP、IFR、AttnLRP；效率图另含 IG 与 IG-Attn。单 token baselines 对每个 output token 做 attribution 后平均，再丢弃 `T` 与 `O` 的分数、仅保留并归一化 `I`。[p. 18–19, Appendix D.1]
- **指标与分母**：Recovery Rate 是输入 top 10% 中 recovered ground-truth token 的比例；RISE/MAS 是删除高归因输入后，针对完整 generated sequence（`T+O`）的模型置信度曲线，数值越低越好。[p. 7, §5; p. 21–22, Appendix F]
- **扰动设计**：长上下文 RISE/MAS 每次删除剩余 token 的 top 5%，固定为 20 个 interval；perturbation baselines 在 RULER 采用 sentence/chunk granularity，并把句分数均摊给 token。[p. 19, Appendix D.2; p. 22, Appendix F.2]
- **计算条件**：Figure 4 在 5× NVIDIA A800、每卡 80GB 的节点运行；峰值显存用 `torch.cuda.max_memory_allocated()`；Table 9 的 cached/on-the-fly 均值来自 5 次运行。[p. 17, Appendix C; p. 25, Appendix L]

论文报告点估计、OOM、runtime 和 Table 9 的 `±`，但没有为主表 RISE/MAS/Recovery Rate 报告 seeds、跨样本离散量、置信区间或显著性检验；`±` 的统计含义也没有说明。这些项在论文中为 `not_present`，不能由表中胜负关系补写。

## 7. 消融、负面结果与自我设限

- **递归深度**：Appendix H 展示 `K=0,1,2,3`，识别「第一跳已解决主要依赖、继续 hops 收益递减」。[p. 22, Appendix H, Table 7]
- **正确性选择**：主评估保留正确 generation；Appendix K 对 HotpotQA 取消 correctness filter，保留 RISE/MAS，以检验该选择对结论的影响。[p. 21, Appendix E.4; p. 24, Appendix K.1]
- **长上下文**：主 Table 1 固定 1024；Appendix K.2 给 2048/4096 的 unfiltered HotpotQA。[p. 24, Table 8]
- **显存/时延**：缓存所有 attention maps 的成本在 Appendix B.2 明示；Table 9 的 on-the-fly 版本从 `35.43 GiB` 到 `13.43 GiB`，时间从 `1.98 ± 0.27s` 到 `2.81 ± 0.06s`。[p. 25, Appendix L, Table 9]
- **aggregation 选择**：Appendix M 对 mean pooling、last-token targeting、positional weighting、semantic cancellation 讨论；Table 10 把 FlashTrace 与 last-token 的 coverage/RISE/MAS 并列。[p. 25, Appendix M.1, Table 10]
- **失败条件**：Appendix N 把适用条件限定为清晰且 localized 的 evidence，列 diffuse evidence 与 structural-token salience 两个失败模式，并建议把结果读作 coarse localizations。[p. 26, Appendix N, “diffuse evidence”]

可验证的呈现策略包括：correctness filtering 先用于主表，随后在 Appendix K 的 unfiltered HotpotQA 中复查；baseline 分数先截断到 input 并重归一化；long-context perturbation 由 token 级改为 fixed 20-step schedule。这些均为评估设计条件；本文未据此推断作者意图。Figure 4 的 OOM 方法缺失 faithfulness 值，附录明确禁止把其 Pareto 横轴解释为结果。[p. 17, Appendix C]

结论只重述问题、方法、跨任务实验与可扩展 interpretability，没有引入新数字或新实验主张。[p. 9, §6, “efficient multi-token attribution”] 闭环状态如下。

**单一主线**：论文先把 reasoning-token absorption 诊断为长链解释的结构性断点，再用「跨 token span 的线性预聚合 + 跨 hop 的重要性回传」把时间可行性和输入定位放在同一机制链里。

**正文留下的决策内容**：Figure 1–2、Eq. 5–12、Table 1–5 和 Figure 4–5 足以让读者判断机制、主要比较和主张范围。算法逐行实现、精确复杂度、baseline 改造、样本筛选、metric schedule、资源权衡、长上下文复查与失败模式主要迁往 appendix。迁移提升了正文节奏，但没有 appendix 时很难判断 `O(N)` 的精确定义、baseline 的 input-only 处理或 perturbation 指标的离散化。

**可迁移规则**：对于「中间生成内容遮住原始证据」的问题，先用一个小型诊断把遮挡量化，再让方法图、可分解公式和任务对照依序回应同一个断点；把复现实验条件、近似代价和失败区间放入可被正文明确调用的 appendix。

**规则边界**：这条结构只适用于机制可被单一误差断点统摄、且补充材料仍能提供精确验证条件的论文。证据广泛分散、token 贡献彼此抵消、或模型行为依赖未观测系统状态时，span-level visualization 只能支持粗定位，不能替代细粒度因果验证。
