## E. 方法与理论

### E.1 方法主线与组件

方法由统一 pipeline 构成，统一把同一批 retrieved premises 送入两条 proof-producing 路径的统一 pipeline：

1. **Aesop 先行**：用 built-in rules 快速尝试；不成功时将 LeanPremise 的候选作为 premise-application rules。
2. **Lean-auto 分支**：把 subgoal 与 selector premises 翻译为 higher-order logic，交给 Zipperposition 搜索。
3. **Duper 重建**：只接收 Zipperposition 实际用到的 premises，尝试在 Lean 内重建、验证形式证明。
4. **联合信息流**：LeanPremise 的输出同时进入 Aesop premise applications 与 Lean-auto；这不同于只把 retrieval 结果交给 reconstruction 或 language model 的既有做法。

这一逻辑顺序由 p.3 §3.1 与 p.4 Figure 1／续文直接给出。图中绿色阶段不能失败也不能产生 terminal proof，黄色阶段可能失败但不能产生 terminal proof，蓝色阶段可产生 terminal proof；黑实线是 control flow，红虚线是 information transfer。动作转移为：

`state_problem → contrast_alternative → define_component → give_intuition → connect_to_prediction → connect_to_experiment`

其中“prediction”属于可检验工程预测，具体是“召回更多有用 premises 应提高 proof rate、各组件／累积设置应覆盖不同 theorem set”。证据：p.3–4 §3.1 “uses premise selection in both of these ways”；p.4 Figure 1 图注。

### E.2 Data extraction

- **动态／静态双用途**：同一 extraction pipeline 在运行时提取当前环境、用户本地 definitions／premises，训练时提取 `(state, premise)` pairs；作者明确说收集的信息要超出 source code 中显式出现的形式（p.4 §3.2，“dynamically… including premises… defined by the user locally”）。
- **Signature extraction**：对每个 theorem／definition 取 docstring（若有）、kind、name、arguments、overall type，串成 `docstring? kind name arguments* : type`。关闭 notation pretty printing（例如 `N` 打印为 `Nat`），常量用 fully qualified name（例如 `Complex.I`），从而不依赖 open namespace、custom notation、surface syntax。形成可检索集合 `P`（p.4 §3.2.1，锚点 “normalized serialization”）。
- **黑名单**：从 `P` 过滤 479 个 basic-logic theorems（如 `and_true`）及 Lean language／metaprogramming definitions，以免 selector 召回技术相关但对 hammer automation 无用的内容（p.4 §3.2.1，锚点 “blacklist of 479 basic logic theorems”）。
- **Hammer-aware labels**：相比只从 tactic-style、下一 tactic 的显式 raw premises 取样，本文同时取 term-style 与 tactic-style proofs；多 tactic proof 的标签面向“关闭整个 goal”而非“修改到下一状态”；同时收集 implicit 与 explicit premises，包括 `simp` 隐式调用（p.5 §3.2.2，锚点 “close the goal (all tactics)”）。
- **状态与证明来源**：每个样本含起始或中间 proof state、被抽取 theorem 的 name/signature、证明该 theorem 的 premise set。tactic-style 还收集所有 intermediate goal states；term-style 从 proof term 取 theorem，tactic-style 同时取最终 proof term 中的 theorem 与 `rw`／`simp` 显式使用的 theorem／definition（p.5 §3.2.2）。
- **依赖类型的理由**：Lean 中 definitionally equal 的 terms 可能 syntactically 不同，`rw`／`simp` 使用的 definitional-equality premise 不一定出现在 final proof term，所以作者额外收集它们；该设计在 §4.4 以 naive extraction 消融验证（p.5 §3.2.2，锚点 “definitionally equal without being syntactically equal”）。

### E.3 Retrieval 与 loss

对于 proof state `s`，先构造当前位置可访问的 premise 集合 `P_s`（来自 imported modules 或当前文件中更早声明的 lemmas／definitions），用 encoder-only transformer `E` 编码 state 和每个 premise，按 cosine similarity 取 top-k。论文唯一的核心检索公式为：

\[
\operatorname{select\_premises}(s,k,P_s)=\operatorname{top\text{-}k}_{p\in P_s}\operatorname{sim}(E(s),E(p)),
\qquad \operatorname{sim}(u,v)=u^\top v/(\|u\|_2\|v\|_2).
\]

作者不训练 separate reranker：早期实验没有发现收益，hammer 对 recall 的容忍度高于 precision，且 `k≥16` 时 reranking 改善有限并增加部署成本（p.5 §3.3，锚点 “a hammer favors recall much more than precision”）。

训练采用 modified InfoNCE。每步采样 `B` 个 `(state, positive premise)` pairs；每个 state 再采样 `B−` 个不属于 ground-truth set 的 negative premises。由于同一 premise 可跨多个 proof 共享，in-batch positive 不能简单当作 negative，于是 denominator 只保留对当前 state 的 negative set `N_i`，并用 masked contrastive loss；温度 `τ=0.05`（p.6 §3.3.1，锚点 “mask out the positive ones in the loss”）。本篇没有 theorem、lemma、proposition、corollary 或 proof；Eq. (1) 和 Eq. (2) 都是核心算法定义，而非形式保证。ground-truth row 是实验中的 100% recall best-case 对照，不构成理论定理（p.8 §4.2，锚点 “theoretical best-case scenario”）。

### E.4 API、缓存与用户边界

运行时由 Lean client 收集当前环境的 `P_s` 和 proof state `s`，发送至 hosting embedding model 的 server；server 对 state／premises 编码并用 FAISS 快速检索，返回 k 个 premises。Mathlib 的典型 `P_s` 约 70k；固定 Mathlib 版本的 premise embeddings 缓存，只重算用户上传的新 premise signatures，client 也缓存这些 signatures（p.6 §3.3.2，锚点 “typical size of `P_s` is on the scale of ∼70k”）。LeanHammer 作为 Lean tactic 调用 LeanPremise，再把结果注入 §3.1 pipeline；premise selection 在 CPU server 上约 1 秒 amortized，single-GPU 上低于 1 秒，完整 pipeline 平均低于 10 秒（p.6 §3.3.2，锚点 “full LeanHammer pipeline on average takes well under 10 seconds”）。

Table 1 只比较 usability，与 Table 2 的 quantitative performance 分开：ReProver 仅 LM-based，Lean Copilot LM-based 且 callable in Lean，random forest callable 但非 LM，MePo 与 LeanPremise 都可 callable 且可处理 new premises；只有 LeanPremise 同时满足三列。作者用 “To the best of our knowledge” 限定“first LM-based selector directly invoked in Lean and can incorporate new user-defined premises”，这是可用性定位，不能视作由独立 exhaustive survey 证明的定理（p.6 Table 1 与 §3.3.2）。

### E.5 Variations and extensions

§3.4 将 pipeline 组件拆为用户可控设置：

- `aesop`：只把 LeanPremise premises 作为 Aesop premise applications，不调用 Lean-auto／外部 prover；
- `auto`：经 Lean-auto 直接把 premises 送外部 prover，不做 Aesop normalization／application；
- `aesop+auto`：保留 Aesop 与 Lean-auto，但不把 premises 作为 Aesop rules；
- `full`：§3.1 默认完整 pipeline；
- `cumul`：依次尝试前四种设置，原因是前三种有时能证明 `full` 不终止或未证明的 theorem。

作者还把 `simp_all` 粗略视为 `aesop` 子情形，不单列；尝试二阶段模型预测 `simp_all` hints 未提升性能；更多 automation 可作为 Aesop rule 加入（p.7 §3.4，锚点 “cumul, which tries all four variants”）。这里的可检验预测是：拆分组件会产生不同成本／proof-rate 曲线，累积设置应利用互补 theorem sets；§4.2 以运行时间和 proof rate 回收。

## F. 实验设计

### F.1 数据、任务、模型与训练

- **数据**：从 Mathlib theorem proofs 抽取 469,965 states、206,005 theorem proofs、265,348 个 filtered premises；每 state 平均 12.45 relevant premises，形成 5,817,740 `(state, premise)` pairs。随机留出 500 个 valid theorem 与 500 个 test theorem（p.7 §4.1，锚点 “469,965 states from 206,005 theorem proofs”）。
- **训练／评测范围**：训练 premises 来自 Mathlib、Batteries、Lean core；测试为 Mathlib hold-out 与 miniCTX-v2-test 的 non-Mathlib splits。miniCTX 包括 Carleson、ConNF、FLT、Foundation、HepLean、Seymour 六个 split（p.7 §4.1；p.8 Table 3）。
- **模型**：small 为 6 layers、hidden size 384、MiniLM-L6；medium 为 12 layers、hidden size 384、MiniLM-L12；large 为 6 layers、hidden size 768、DistilRoBERTa-base。Table 2 对应模型参数量为 23M、33M、82M（p.7 §4.1；p.8 Table 2）。
- **训练超参／预算**：learning rate `2e−4`、`B=256`、`B−=3`，由 hyperparameter sweep 得到；large training cost 为 6.5 A6000-days（p.7 §4.1，锚点 “Training the large model requires 6.5 A6000-days”）。
- **检索预算**：`full` 使用 `k1=16`（Lean-auto，Aesop priority 10%）和 `k2=32`（premise-application rules，Aesop priority 20%）；`auto`／`aesop+auto` 使用 `k=16`，`aesop` 使用 `k=32`。k 在 Mathlib-valid 上调参，并把最优组合用于 full；调参细节仅指向外部 extended version 的 §D.3（p.7 §4.1）。
- **时间／心跳限制**：每次 Zipperposition 10 秒；每 theorem 300 秒 wall-clock；Lean default heartbeat 200,000（p.7 §4.1，锚点 “300-second wall-clock time-out”）。
- **软件／硬件**：Lean v4.16.0；最多 16 个并行 tests、16 CPUs、512GB total memory，每 theorem 分配 1 CPU／32GB，实际内存通常低于 4GB；CPU 为 AMD EPYC 9354（3.8GHz、32 cores、64 threads）或 similar（p.7 §4.1）。

### F.2 指标、对照与设计可复现性

- **指标**：recall@k 是每 theorem 在 top-k 中检索到的 ground-truth premises 的平均百分比；proof rate 是被证明 theorem 的百分比。作者偏好 recall 而非 precision，因为 hammer 能容忍 irrelevant premises、不能容忍缺少关键 premise（p.8 §4.2，锚点 “We favor recall over metrics like precision”）。
- **对照**：None、random forest、MePo、ReProver、LeanPremise 三种规模、selector 累积／与 MePo union、以及 Ground truth best-case。Random forest 标为 performance upper bound（排除 errors）；ReProver 的 recall 定义脚注注明与本文略有不同（p.8 Table 2）。
- **实验顺序**：§4.2 先报告 Mathlib 与 miniCTX 主结果，再以 §4.3 对照 MePo／random forest／ReProver，最后 §4.4 删除 extraction、negative sampling、loss masking 组件；顺序与“端到端效果 → 跨域 → 相对基线 → 机制消融”一致。
- **控制与失败判定**：有 500/500 随机 hold-out、统一 Lean 版本、统一 wall-clock／heartbeat、固定 k 与硬件额度；“proofed”是在限制内成功重建 theorem，“not proofed”则不进入 proof rate。论文没有显式报告随机 seed、每 theorem 的失败计数分解、train/test 去重或数据泄漏审计，也没有预先列出 RQ／假设清单。前半是 p.7 §4.1 明示；后半是通读设计段后的 `not_present` 判断。
- **统计与不确定性**：正文只报告 theorem-level percentages、split average 与 mean runtime；没有 hypothesis test、bootstrap、Bayesian analysis、回归、error bars、区间或 seed dispersion。Table 2–4 和 Table 3 注释可以解释列含义，但不能单独提供随机变异性信息（p.8 §4.2 “average percentage”；p.10 Table 4）。
- **代码／数据**：Reproducibility Statement 声明 data extraction、training、evaluation、API integration 的代码公开，并列出 training/server/API 仓库、extracted data、trained models 和 baselines（p.10 §Reproducibility Statement，锚点 “We make all code… publicly available”）。本 PDF 没有给出运行命令或硬件环境之外的完整复现实验脚本流程。

### G.3 作者对不利解释的处理

- **检索不全**：作者承认 ground truth 超过所有 selector，说明有些失败来自 LeanPremise 没召回必要 lemma（p.9 §4.2，`explicit`）。
- **翻译边界**：依赖类型特征可能超出 Lean-auto 到 higher-order logic 的范围（p.9 §4.2，`explicit`）。
- **推理能力边界**：induction、arithmetic 可能超出 Aesop、Zipperposition、Duper 支持；Zipperposition 成功而 Duper 重建失败相对少见（p.9 §4.2，`explicit`）。

- **基线公平性边界**：random forest 为排除 errors 后的 upper bound；ReProver 的 recall 定义与本文略有不同，作者在表下注明，并说明在同一 split／updated Mathlib 上重训（p.8 Table 2；p.9 §4.3，`explicit`）。

## K. 用词与修辞

### K.1 高频论证词与术语场

references、公式碎片、表格数值和模板页眉排除后，正文反复出现的实词簇包括 `premise`、`proof`、`theorem`、`Lean`、`hammer`、`selector`、`state`、`pipeline`、`recall`、`proof rate`、`Mathlib`、`premise selection`、`external prover`、`translation`、`reconstruction`、`user`、`domain`。二元／三元词组以 `premise selection`、`proof reconstruction`、`proof rate`、`ground-truth premises`、`external automatic theorem provers`、`user-defined premises`、`end-to-end domain general` 为主；这些词主要由真实方法对象和实验决策驱动，不是模板套话。证据：p.3–6 §3；p.8–10 §4–5。

## L. 最终判断

1. **单一主线**，论文把 premise selection 的训练目标从“下一 tactic 的局部建议”改为“足以完成整个 proof 的 hammer-aware retrieval”，再把候选同时送入 Aesop 与 Lean-auto／Zipperposition／Duper，最后用 theorem-level proof rate 验证 retrieval 是否真正转化为可重建证明。核心转折是 whole-proof、implicit／explicit、term／tactic extraction，而非单纯换一个 encoder。证据：p.5 §3.2.2 “select premises to close the goal (all tactics)”；p.3–4 §3.1；p.8 §4.2。
2. **正文保留的决策关键内容**，保留 pipeline 图、signature／state extraction 原理、Eq. (1) retrieval、Eq. (2) masked loss、API cache／latency、Table 2–4、Table 3 六 split、失败类别和 reproduction statement。这些内容足以判断“召回是否提升、提升是否转成 proof、成本和失败边界是什么”。证据：p.4–6、p.8–10。
3. **移入外部版本的细节及其代价**，signature 与 pipeline 样例、k tuning、baseline 训练细节、Figure 2a、Table 5、D.4／D.5 failure analysis 被指向 Zhu et al. (2025) extended version；本文没有 PDF 内附录。迁移没有破坏主表的可读性，但损害了对数据抽取、调参、公平性和失败分解的独立复核。证据：p.4 §3.1、p.4–5 §3.2、p.7 §4.1、p.8–9 §4.2–4.3。
4. **最有效的写作／图／表／公式模式**，用 Figure 1 画“同一 selector 输出→两条 proof path”，用 Table 2 同时放 retrieval 与五种 pipeline proof rates，再用 Ground truth 建立理论 best-case、None 建立非平凡性对照；Table 4 直接删掉 extraction／negative／masking，形成方法组件到 end-to-end 指标的闭环。证据：p.4 Figure 1；p.8 Table 2；p.9–10 Table 4。
5. **最大缺口**，动态 user-defined premise 的可调用性由 API 机制与 Table 1 支撑，但没有单独的 local-lemma insertion 或 context-shift 实验；“first”“robust”“accessible”也没有 exhaustive novelty audit、用户评测或 seed／区间证据。更底层的性能瓶颈（retrieval、Lean-auto scope、induction／arithmetic）作者有明示，但未在正文量化各类失败的分母。证据：p.6 §3.3.2；p.7 §4.1；p.9 §4.2。
6. **可迁移规则**，对于要把 neural retrieval 接入 symbolic proof system 的论文，训练标签必须对应最终可验证目标（整段 proof 所需 premises），并让同一 selector 在实际 proof reconstruction pipeline 中接受检验；只测 retrieval recall 或只测 next-tactic usefulness 不能证明 end-to-end hammer 能力。证据：p.5 §3.2.2；p.8 §4.2。
7. **适用边界**，该规则适用于有明确 premise set、proof reconstruction 与 theorem-level success criterion 的 hammer／retrieval 系统；不能直接外推到 whole-proof neural generation、induction／arithmetic 能力、未测的 user adoption 或其他 proof assistant。证据：p.3 §2.2 “proof search approaches are complementary to a hammer”；p.9 §4.2 failure categories；p.7 §4.1 benchmark scope。
