## 5. Method 与理论对象

### 5.1 问题形式化与并行因果链

- **Eq. (1)，标准 token-level AR factorization。** 给定 image tokens (x_1,ldots,x_N) 和 condition (c)，论文写出 (p(x_1,ldots,x_N;c)=\prod_{n=1}^{N}p(x_n\mid x_{<n};c))。它把 raster-order 的 one-token-per-step 结构形式化为生成步数瓶颈。[p.3, §2.1, `explicit`, “factorizing the total joint distribution as”]
- **Eq. (2)，group-level parallel factorization。** 将 tokens 分为 (G) 个不相交组 (X_g)，写出 (p(x_1,ldots,x_N;c)=\prod_{g=1}^{G}p(X_g\mid X_{<g};c))。它把并行化目标写成 group conditional，并立即引出 mutual dependency 与 dynamic group size 的两个工程约束。[p.3, §2.1, `explicit`, “each group Xg ... is predicted jointly”]
- 论文没有把 Eq. (1)/(2) 当作 distributional guarantee。它们是对 one-step 与 group-step 建模目标的重写；“quality 不下降”由后续 ImageNet 实验支持，理论模块没有 theorem/lemma/proposition/corollary/proof。[p.3、p.7–10, `interpretation`, “This factorization needs a predefined order”]

### 5.2 Flexible Parallelized Autoregressive Modeling

1. **解耦 context 与 generation。** previously generated image tokens 只提供 context；learnable position query tokens 负责目标位置的生成。query 由 target location 的 positional embedding 加 shared learnable embedding 构成，因而 generation order 与 group size 可变。[p.3–4, §2.2, `explicit`, “decouple the context representation and token generation”]
2. **Training mask。** teacher-forcing 下交错 ground-truth image tokens 与 position queries。Context Attention 允许 subsequent tokens causal 地读取 context；Query Attention 让同一步 query tokens 互相可见，并阻止 subsequent tokens 读取 query tokens。[p.4, §2.2, `explicit`, “Query Attention ensures mutual visibility”]
3. **Inference mask 与 KV cache。** 采样 image tokens 进入 KV cache；query tokens 读取全部已生成 context，输出每个 target 的 logits，query 自身不写入 cache。若 encoding/decoding 串行会把步数翻倍，Figure 5 的 fused mask 将两者合成单步。[p.4, §2.2, `explicit`, “KV cache for query tokens is not stored”]
4. **与 SAR/ARPG 的差异。** encoder–decoder 的 target-aware queries 只 cross-attend encoder cache，query 本身不产生 key/value，导致同组 token 独立生成；LPD 的 query attention 提供同组 mutual visibility。[p.4–5, §2.2, `explicit`, “tokens generated within the same parallel step being produced independently”]
5. **与 RandAR 的差异。** RandAR 用 positional instruction tokens 和 standard causal mask，能换 order，但并行退化为 batched next-token prediction，instruction tokens 还需写入 cache，造成额外 memory；LPD 只缓存 generated tokens。[p.5, §2.2, `explicit`, “doubling the memory consumption”]
6. **与 PAR/NAR/ZipAR/ACDIT 的差异。** PAR、NAR、ZipAR 保留 decoder-only 并保证同组可见，却使用 fixed parallel order；ACDIT 具有相近 attention scheme，但目标是 AR–diffusion interpolation。该段把 flexible order 与 mutual visibility 的组合定位为 LPD 的差异。[p.5, §2.2, `explicit`, “rely on a fixed parallel generation order”]

### 5.3 Locality-aware Generation Order Schedule

1. **两条 scheduling principle。** target positions 要靠近已有 context，以提高 conditioning；同一并行组内的 tokens 要相距较远，以降低 mutual dependency。[p.5, §2.3, `explicit`, “High proximity to previously generated tokens”]
2. **Locality measurement。** 论文用 LlamaGen 生成 50,000 张图并收集每个 decoding step 的 attention scores。定义 Eq. (3) 的 Per-Token Attention (PTA_s)，对每个 token 在恰好欧氏距离为 (s) 的邻域上的 attention 做平均。[p.5, §2.3, `explicit`, “we generate 50,000 images”]
3. **Eq. (3) 的诊断作用。** PTA 随相对距离上升而快速下降；Attention Sum 在 (s=3) 时显示多数 attention 聚集于 local neighborhoods，且该 pattern 在所有 attention heads 中出现。它是 schedule 的 empirical diagnostic，不是质量保证定理。[p.5–6, §2.3, `explicit`, “PTA decreases sharply with increasing distance”]
4. **Algorithm 1 的 proximity selection。** 设 decoding steps 为 (K)，group sizes 为 (O=[o_1,ldots,o_K])，通常按 cosine schedule 增大。每步按与已选 tokens 的欧氏距离倒数排序，按 proximity threshold (	au) 分成 (c_1,c_2)，优先从 (c_1) 取点，并以 repulsion threshold (ho) 将过近点移入 (c_2)。[p.6, Algorithm 1, `explicit`, “high-proximity selection”]
5. **Algorithm 1 的补齐与不变量。** 若 proximity selection 未填满 (o_k)，从 (c_2) 用 farthest point sampling 补齐，保证同组空间分离；每一步把 `step_selected` 追加到累计 selected set，最终返回可预计算的 schedule。关键不变量是组大小达到 (o_k)，且已选点不再作为候选。[p.6, Algorithm 1, `explicit`, “low-dependency selection”]
6. **Figure 8 的直觉验证。** raster、random、Halton、LPD 四行都展示 20 steps/162 tokens；LPD 每一步同时贴近旧 context、远离同组新点。order 可预先存储，作者据此声称 inference 无额外 schedule latency。[p.7, Figure 8；p.6, §2.3, `explicit`, “generation order can be precomputed and stored”]

## 9. Conclusion、Limitations 与 adverse presentation strategies

### 9.1 Conclusion

Conclusion 只有 p.10 一段，动作是 `restate_method → restate_result → restate_impact`：复收 flexible parallelized autoregressive modeling、locality-aware generation order、步数下降、quality 保持和至少 3.4× lower latency。它没有新数字、定理、失败条件或未来工作，主张范围延续前文 ImageNet/parallelized AR 对照。[p.10, §6, `explicit`, “Our contributions lie in two key aspects”]

### 9.3 可核验的包装策略

1. **代表性步数突出。** Figure 1 与摘要突出 LPD 20/32 steps 的 4.2×/3.4× latency 标注；完整 Table 1 同时显示 20 和 32 steps，因此 claim 可以回查，但读者需要自己对齐 model size、quality 和 latency。[p.1、p.8, `layout_observation`, “4.2x faster”]
2. **compute caveat 延后。** 位置 query 的 FLOP 成本直到 §3.3 才展开，且 batch-size 结果置于 Appendix Figure 14；主结果先建立 memory-bound speedup，边界随后出现。[p.8、p.24, `layout_observation`, “As the batch size increases”]
3. **附录迁移。** architecture/training details、完整 schedule code、τ/ρ sensitivity、更多 attention maps、qualitative edits 和 throughput 曲线全部在 Appendix A–E；正文通过引用调用，但复现和边界判断依赖 appendix。[p.6–8、p.17–24, `layout_observation`, “Please refer to the Appendix”]
4. **qualitative capability 包装。** editing 以一组图像作为 capability evidence，没有 quantitative editing metric 或失败分母；该结论应保持为“展示了可执行路径”。[p.22, Figure 12, `interpretation`, “generate the masked region in a random order”]
5. **跨基线表格的缺失值。** Table 1/2 混合 diffusion、mask、VAR、AR、parallelized AR，很多 latency/throughput 为 `–` 或 OOM；表格可显示广度，但跨类型效率比较只有部分行可直接核对。[p.8–9, Tables 1–2, `layout_observation`, “–” / “OOM”]
6. **参数信息未统一。** 主文 model size 与 Appendix Table 4 的参数值不完全一致，且 text-to-image 又使用 344M/760M 命名；这降低了读者对跨表 model identity 的可追踪性。[p.6、p.17–18, `explicit`, “LPD-L (344M) and LPD-XL (760M)”]

这些是版面和证据可见的呈现事实；没有把它们推断为作者动机。论文同时主动写出 compute-bound caveat 和 hyperparameter sensitivity，因此包装策略与自我设限并存。[p.8、p.20、p.24, `interpretation`, “Nevertheless, even at the maximum feasible batch size”]

## 13. Final Judgment

1. **单一主线。** LPD 将 flat-token autoregressive image generation 的“context 表示”和“target token 生成”拆开，用 position query 与同组 mutual visibility 支持任意 order/degree，再用 attention locality 驱动的 proximity/repulsion schedule 选择并行组；主结果以 ImageNet 质量–步数–latency 对照闭合。[p.3–10, `interpretation`, “decouple the context representation and token generation”]
2. **正文保留的决策关键内容。** 正文留下 Eq. (1)–(3)、四个公式化对象中的 Algorithm proximity line、mask/cache 图、Algorithm 1、Figure 7/8 locality mechanism、Tables 1–3、Figure 9 三组主消融和 §3.3 speed caveat；这些内容足以让读者理解为何方法能并行以及何时速度优势减弱。[p.3–10, `layout_observation`, “we provide a quantitative analysis in Figure 14”]
3. **移入 appendix 的细节及其代价。** architecture dimensions、AdamW/batch/LR、step-size list、text data、schedule code、τ/ρ sensitivity、更多 attention maps、editing samples、GenEval per-category 和 throughput curves被移入 p.17–24。主线仍自足，但精确复现、参数 identity、数据可获得性和 regime boundary 需要附录才能完成判断。[p.17–24, `explicit`, “We provide implementation details”]
4. **最有效的写作/图/表/公式模式。** Figure 7 先把 locality 变成可观察的 distance/head evidence，Algorithm 1 再把两原则写成可执行 selection，Figure 9(c) 以单一 FID 对照拆开两原则和 synergy，Tables 1–3 最后把 mechanism 转成 matched raster/parallelized system numbers。该模式把“为何有效”与“快多少”分开识别后再合并。[p.5–10, `interpretation`, “highlighting the synergy of both principles”]
5. **最大叙事缺口。** 没有 formal guarantee、seed/不确定性、跨 tokenizer/model locality transfer、编辑定量质量或失败分母；Appendix Table 4 与主表的参数量不一致，进一步增加复现成本。Interoperability 只停留在动机，未进入评测闭环。[p.2、p.6–10、p.17、p.22–24, `layout_observation`, “LPD-L ... 111M” / “LPD-L ... 337M”]
6. **可迁移规则。** 加速型生成论文应将每个速度 claim 绑定到一个机制诊断、匹配的 raster/control 对照、组件/原则消融和 batch-regime efficiency profile；仅报告 step reduction 不足以识别 memory-bound 与 compute-bound 的边界。[p.7–10、p.24, `interpretation`, “the model transitions from memory-bound to compute-bound”]
7. **规则适用边界。** 该规则适合 token generation 受 memory bandwidth 和空间 locality 共同支配的系统；当 workload 已 compute-bound、attention 不具 locality、或任务需要编辑/跨模态理解质量时，需增加相应机制检验和任务指标，不能直接外推 LPD 的 latency/quality 结论。[p.5–8、p.22–24, `interpretation`, “spatial locality”]
