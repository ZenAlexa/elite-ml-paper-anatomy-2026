## 5. 方法与理论

### 5.1 方法最小逻辑单元

1. **`setup_notation`（p. 4）**：原始事件为 2S-1T-1P 四元组 `E={e_i=(x_i,y_i,t_i,p_i)}`（Eq. 1）。
2. **`define_component`（p. 4）**：Event Cloud `EC` 是按时间顺序抽取的 `J⊆ord I`，维度 `[T0,4]`（Eq. 2）；它不具备 Point Cloud 的 permutation invariance，先 Min-Max normalization。
3. **`state_problem`（p. 4）**：以多阶段层级结构逐步抽象稀疏异步事件，同时保留计算效率。
4. **`instantiate_algorithm`（p. 4）**：Eq. 3–7 定义每个 stage 的 G&S→SFA→AGG→TFA→RES、状态更新与 `Fend`。
5. **`define_component`（p. 4）**：D-FPS 在坐标四维分别乘可学习缩放因子 `α`，下采样一半事件（Eq. 8）。
6. **`define_component`（p. 5）**：EF-KNN 以 event feature distance 而非坐标找邻居（Eq. 9）。
7. **`explain_mechanism`（p. 5）**：CES 对 group 坐标求均值（Eq. 10），再拼接坐标、标准化 group features、拼接 centroid features（Eq. 11–12）。
8. **`state_problem`（p. 5）**：大量事件带来空间/时间上下文抽取和能耗瓶颈；重复 MLP/局部时间模型不理想。
9. **`derive`（p. 5）**：给出 DFT、inverse DFT 与可学习频率滤波 `FFT → V⊙X → iFFT → σ`（Eq. 13–15）。
10. **`explain_mechanism`（pp. 5–6）**：SFA 在 group 的 feature/channel 维建模局部拓扑；低频对应全局一致模式，高频对应局部细节；复杂度从单 MLP 的 `O(D_i²)` 降为 `O(D_i log²D_i)`，末级维度 540 的单次计算声称约降 60 倍，实际网络最多约 20 倍。
11. **`explain_mechanism`（p. 6）**：AGG 对邻居维做 soft attention（Eq. 16–17），把 group 折叠后交给 TFA；TFA 在时间维做 Fourier 全局滤波。
12. **`contrast_alternative`（p. 6）**：作者将 TFA 与 LSTM/attention 对比，声称后者不擅长长关系且复杂度高；SFA 被定位为 repeated MLP/convolution 的轻量替代。
13. **`define_component`（p. 6）**：RES 用基础 residual module 提炼高层特征。
14. **`connect_to_prediction`（p. 6）**：每 stage 更新 `F` 和 `EC`；结束后进入 classification/regression heads，Figure 3 展示 mean/max pooling。

**动作转移序列**：`setup_notation → define_component → state_problem → instantiate_algorithm → define_component → explain_mechanism → state_problem → derive → explain_mechanism → contrast_alternative → define_component → connect_to_prediction`。

### 5.2 架构叙事与组件职责

- **输入与状态**：EC 按 chronological order 保留显式时间，`[T0,4]` 经过 1D convolution embedding；Appendix C 说明全模型 3 loops，feature 维 64→132→268→540，groups/centroids 每 loop 减半。[pp. 4、13–14]
- **Event-based G&S**：D-FPS 让不同坐标维受不同尺度影响；EF-KNN 让 feature similarity 参与邻域；CES 让 centroid 随 group 的均值逐 stage 演化。其前文问题是 Point Cloud 的 polarity/时序处理不足和固定几何邻域。[pp. 2、4–5]
- **SFA/TFA**：SFA 对 group 内 feature dimension 做频域乘法，TFA 对聚合后的时间 dimension 做全局频率滤波。前者面向局部空间/拓扑，后者面向长程 inter-event temporal dependency。[pp. 5–6]
- **AGG/RES/heads**：AGG 以 soft attention 聚合邻居，RES 做高层 residual abstraction，最终将 mean 与 max features 拼接后给 classifier 或 regressor；Algorithm 1 在 p. 15 逐行复述这一数据流。[pp. 6、15]

## 8. 消融、负面结果与自我设限

### 8.1 消融对象与识别目标

- **核心模块删除（observed）**：Table 8 的 `w/o α`（取消 D-FPS）、`w/o EF-KNN`、`w/o SFA`、`w/o TFA`、`Input P`（只在输入级纳入 polarity）、`w/o P`。DHP19 上移除 SFA 使 MPJPE2D/3D 从 6.11/69.89 变为 6.68/75.43，移除 TFA 为 6.47/73.84；N-CARS/UCF101-DVS 也都有 Accuracy 变化。[p. 8, `Table 8`, “w/o SFA”]
- **事件数敏感性（observed）**：Table 9 以 512、1024、2048、4096、8192、10240 events 对照 SECNet、SECNet w LSTM、PointNet++、TTPOINT；SECNet 从 46.29 升至 60.60，但 Appendix J 明确指出 runtime 与 event number 同步升高。[pp. 9、16]
- **Spatial-FA 替代（observed）**：Appendix I 用 convolution 构造 ECNet，在六数据集上通常 metric 更好（例如 DHP19 5.87/66.87 vs SECNet 6.11/69.89），但 SFA MMACs 与总计算更低；这把“效率—精度”trade-off 直接暴露出来。[pp. 16、18, `I. Ablation Study on Spatial-FA Module`]
- **centroid/event lookup（observed）**：Appendix J/Table 12 改变输入 events 与四阶段 centroid 组，说明输入数不改变参数量，但 runtime 随两者升高，GMACs 对两者呈超线性增长；两组较小 centroid 配置的 throughput 被写为 >200 FPS。[pp. 14、16, `Table 12`]
- **未覆盖的消融（not_present）**：没有 seed stability、跨传感器/跨硬件 robustness、系统性 dropout/augmentation、不同 pooling/decoder depth 的完整敏感性网格，也没有失败案例或按类别 error analysis。表 8–9 与 Table 13 是局部组件/资源对照，不能支持所有设计选择的全局最优性。[pp. 8–9、18，`layout_observation`]

### 12.3 最终判断

- **single_storyline**：论文先用按时间排序的 Event Cloud 避免 frame/voxel 转换，再以 D-FPS、EF-KNN、CES 将 polarity 和 feature-aware topology 纳入 G&S，随后用 SFA/TFA 的 Fourier filtering 处理大规模空间/长时事件，最后以十数据集、三任务、事件数扩展和 FPGA 对照支撑“可扩展且轻量”。[pp. 1–9]
- **main_body_keeps**：正文保留问题缺口、Event Cloud 定义、Eq. 1–17、Figure 3/4、Table 1–10、核心模块消融和 FPGA headline；这些内容让读者能复述方法和主要决策，但不含 seed/完整命令/功耗或公平的跨基线预算。[pp. 4–9]
- **appendix_moves**：附录移动表示对比、数据 split、具体维度/centroid、服务器和 FPGA 补充、Algorithm 1、runtime lookup、SFA 替代及 pose 可视化；迁移保持主文节奏，却使可复现细节和效率—精度 trade-off 需要跨页拼接。[pp. 13–18]
- **best_pattern**：先用 Figure 2 把表示差异视觉化，再用 Figure 3 把组件链显式化，随后用 Table 2–7 按任务和硬件递进，Table 8–10 做组件/事件数/FPGA 决策检验；“表示→机制→任务→成本”顺序易于跟踪。[pp. 2–9]
- **largest_gap**：没有形式理论保证、seed/不确定性、compute-matched baseline 或真实 edge deployment；附录 I 显示多数数据集 ECNet 精度更高，而正文 “5%/16%/27%” 百分比口径与 cross-reference 也不完全闭合。[pp. 7–9、16、18]
- **transfer_rule**：写轻量表示学习论文时，先固定原始数据保留规则、时间顺序、split 与输入预算，再让每个结构组件对应一个删除/替代/扩展对照，最后把 Accuracy/MPJPE 与参数、GMAC、runtime 放在同一决策表中；将完整维度、硬件和伪代码移入附录时，必须保持正文调用和编号一致。[pp. 4–9、13–18]
- **transfer_boundary**：该规则只能提升“机制、测量与成本”的闭环，不能把单一事件相机、固定十数据集与单点测量外推成所有 vision tasks、跨传感器泛化、低功耗 deployment 或 privacy 结论。[pp. 6–9、14–18]
