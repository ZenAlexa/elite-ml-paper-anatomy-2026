## D. Related Work

相关工作是独立的 §2（p.3），约 485 词、占主文约 9.0%，分成三个簇；没有把完整方法再写一遍。

1. **Self-supervised Retriever Learning（taxonomy + gap creation）**：以 query-document pairs 的监督瓶颈开篇；Contriever 用同文档 passages 作 positives、in-batch examples 作 negatives；E5 使用大规模 query-document pairs；LaPraDoR 以 BM25 信号蒸馏；RetroMAE 以 sentence reconstruction 做 autoencoding。作者给出的比较维度是 supervision source 与 overfitting，其中 E5 可能继承结构偏差，autoencoding 缺乏 pairwise supervision，可能偏向低层细节（p.3, §2, “The primary drawback … structural biases”）。
2. **最近邻差异**：紧接一个独立段把 Revela 与传统 query-document framework 区分，明确将 NTP 的 adjacent-token prediction 改成 entire-text association（p.3, §2, “shifting its focus from predicting adjacent tokens”）。这段制造的缺口直接由 §3 的 cross-document NTP 回答，没有重复 Eq.1–7。
3. **LM-guided Retriever Learning（taxonomy + nearest-neighbor contrast）**：Query2Doc 代表 query/document expansion，代价是依赖强 LM；Atlas 用 retrieved-document/output cross-attention signal，但采用 encoder-decoder 且需要 periodical reindexing。Revela 的差异维度是 decoder-only、joint training 和不需要周期性 reindex（p.3, §2, “standard decoder-only architecture”）。
4. **REPLUG 对照**：REPLUG 以 frozen LM perplexity 对齐 query-document similarity；作者指出 frozen perplexity calibration 可能不佳，Revela 通过 retriever 与 LM joint update 处理该点（p.3, §2, “perplexity of frozen LMs is often poorly calibrated”）。REPLUG 后在 §4/§5 成为主 baseline，相关工作中的差异在结果段获得实证回应。
5. **Domain-specific Retrieval（context + gap）**：domain knowledge 稀缺且快速变化；continual learning/task-aware specialization 仍需 domain-specific query-document pairs；MixGR 被作为科学域 mixed-granularity 例子。作者将 Revela 定位为直接在 domain-specific raw text 上做 LM adaptation（p.3, §2, “domain adaptation capability through language modeling”）。

引用簇数量按上述三个小标题计为 3 个，内部包含 4 个比较子簇；引用在后文重新承担 baseline（Contriever/E5/REPLUG）或 benchmark（CoIR/BRIGHT/BEIR）论证作用。相关工作承担的是 taxonomy、继承关系与最近邻差异，未提供新的实验数字。

## E. 方法与理论

### E.1 形式对象、状态和目标

- **输入状态**：batch 中的 `B` 个文档 `D_i`，每个文档 token 序列长度 `L`；文档先从 raw text 切成 chunks。LM 参数为 `Φ`，retriever encoder 参数为 `Θ`（p.4, §3.1, Eq.1–2）。
- **经典局部目标**：对 `D_i` 的 token `x_i^l`，经典 NTP 为 `P_Φ(x_i^l | x_i^{<l})`（Eq.1, p.4）。
- **Revela 目标**：将概率改成 `P_{Φ,Θ}(x_i^l | x_i^{<l}, {D_j}_{j≠i})`（Eq.2, p.4），即 token 同时条件于自身 prefix 与 batch 中其他文档。文中说明 retriever 与 LM 通过 NTP joint optimization 更新，但没有写出显式的全 batch loss 求和式（p.4, §3.1）。
- **Retriever state**：`h_i=E_Θ(D_i)`；归一化 `\tilde h_i=h_i/||h_i||_2`；余弦相似度 `S_ij=\tilde h_i^T\tilde h_j`；以温度 `τ` 做排除自身的 softmax，得到 `Sim(D_i,D_j)`，并满足 `Σ_{j≠i}Sim(D_i,D_j)=1`（p.5, §3.3）。
- **Attention state**：第 `l` 层输出为 `[e_i^l;h_i^l]`，其中 `e` 是 standard self-attention，`h` 是 in-batch attention；`Q/K/V` 使用维度 `d×d` 投影，多头维度 `d_H=d/H`（p.4, §3.2, Eq.3–4）。
- **明确假设/边界**：跨文档 attention 只在 batch 内、`j≠i`；self-attention 保持 causal prefix；B.5 对 Wikipedia 使用 V-normalization、对 code 不使用；论文没有给出独立随机 seed、显著性检验或跨模态实验（p.5, §3.4；p.18, App. B.5；p.24, App. D）。

### E.2 最小逻辑单元与问题与组件闭环

| 组件 | 逻辑动作 | 解决的前文问题 | 直接输出／梯度路径 | 证据 |
|---|---|---|---|---|

| Revela conditional NTP | `state_problem → connect_to_prediction` | 需要把其他 chunks 纳入 prediction。 | Eq.2；NTP loss 对 `Φ,Θ` 同时可优化。 | p.4, §3.1, Eq.2 |

### F.2 模型、基线和训练预算

- **LM/retriever**：主 LM 是 LLaMA-3.2-1B；retriever backbone 为 SmolLM2-135M、Qwen2.5-0.5B、LLaMA-3.2-1B、LLaMA-3.2-3B。用每句 `<eos>` embedding 表示句子，并给 query/passage 加 `Query: ` 与 `Passage: ` 前缀（p.6, §4.1）。3B 模型为计算效率使用更小 batch（文中举例 8，p.6）。
- **Baselines**：E5-PTlarge（E5-PT，weakly supervised contrastive，1.3B raw pairs/270M filtered）、REPLUG（frozen LLaMA-3.2-1B LM 的 perplexity distillation）、CoIR 的 UniXcoder/BGE-M3/E5-Mistral-7B-Instruct 与 Ada-002/Voyage-Code-002 API、BRIGHT 的 E5-Mistral 与三种 API、BEIR 的 Contriever/LaPraDoR（p.6, §4.1；p.18, Tables 5–6）。
- **优化和资源**：retriever 与 LM 都用 LoRA rank 256；`τ=1e−4`、learning rate `1e−4`、100 warmup steps、WarmupDecayLR；4× A100 80GB、gradient accumulation 8、bf16、passage truncate 160 tokens；one epoch，Wikipedia 10,000 steps/约 44 h，code 约 11,000 steps/约 48 h；inference max token length 2048（p.6, §4.1）。
- **公平性/控制**：§5 重新实现 Contriever，固定 LLaMA-3.2-1B、同一 Wikipedia/code corpus，并生成 500K/359K pseudo query-document pairs、每 query 15 negatives（p.8, §5；p.19, App. C.1）。REPLUG 与 Revela 使用同一数据集，B.3 给出其 temperatures=0.001、lr=5e−4、4,500 steps，其他设置相同（p.17, App. B.3）。
- **未提供的设计细节**：正文没有 seed 列表、重复运行次数、误差聚合层级、显著性检验、多重比较或失败判定阈值。数据与 baseline 训练语料有重叠被作者显式承认（E5-PT 的 corpus 覆盖 Revela training data），但没有独立的 leakage ablation（p.2、p.7–8）。

实验顺序与引言基本对应：先用 CoIR/BRIGHT/BEIR 检查跨领域效能，再以 Contriever 控制对照识别算法贡献，以 batch size 和 LM size 检验 scaling，最后把 mixed-domain、out-of-domain、LM 保真度和效率移至 App. C。

## G. 结果、统计和可视化

### G.1 主要结果

1. **CoIR（Table 1，p.7）**：平均 nDCG@10（%）为 BM25 42.0、UniX 37.3、Revela-0.1B 48.4、E5-PT 46.4、Revela-0.5B 56.1、BGE-M3 49.1、REPLUG-1B 48.2、Revela-1B 58.6、REPLUG-3B 53.9、Revela-3B 60.1、E5-Mistral-7B 57.3、Ada-2 45.6、Voyage-2 56.3。作者因此报告 Revela-3B 比 E5-Mistral-7B 高 2.8 points，比同量级 E5-PT 高 9.7 points；0.1B 比 UniX 高 11.1 points。Table 1 的分母是 10 个 task mean，不是 query-level pooled score。
2. **BRIGHT（Fig.3 left/Table 8，p.7、p.19）**：12-task mean 为 BM25 14.5、E5-PT 13.1、Revela-0.5B 15.2、Revela-1B 15.6、REPLUG-3B 12.2、Revela-3B 20.1、E5-Mistral 17.9、Cohere 16.6、OpenAI 17.9、Voyage 17.9。Revela-3B 的均值超过监督 E5-Mistral 和三种 API；Table 8 显示 task-level 结果并非每个 task 都胜出（例如 Biology/Robotics）。
3. **BEIR（Fig.3 right/Table 7，p.7–8、p.19）**：13-task mean 为 BM25 41.8、Contriever 29.5、LaPraDor 29.8、Revela-0.1B 33.3、E5-PT 45.6、REPLUG-0.5B 34.2、Revela-0.5B 38.8、REPLUG-1B 35.7、Revela-1B 42.7、REPLUG-3B 36.3、Revela-3B 45.2、Revela-code-3B 45.6。作者报告 Revela-3B 与 E5-PT 近似，资源约少 1000× data、10× compute；与 REPLUG 的均值差距为 1B 组 7.0 points、3B 组 8.9 points。Revela-code-3B 与 Wikipedia-trained/E5-PT 均值相近，支持有限的跨域观察。
4. **Contriever 控制（Table 2，p.8）**：同一 LLaMA-3.2-1B backbone 下，wiki 训练 Revela/Contriever 的 BEIR 为 42.7/42.4、CoIR 为 53.2/50.3；code 训练为 39.6/32.3（BEIR）、58.6/52.1（CoIR）。AVG 分别 48.0、46.4、49.1、42.2。该对照直接回应 in-batch LM objective 相比 pseudo-pair contrastive learning 的算法差异，但仍是 task mean、无方差。

### G.2 Scaling 与附加结果

- **Batch size（Fig.4，p.9；Tables 11–12，p.20–21）**：默认 16，并比较 4/8/16。CoIR mean 随 batch 增大通常上升，0.1B `43.2→45.9→48.4`、0.5B `52.4→54.5→56.1`、1B `55.9→56.4→58.6`；BEIR 为 0.1B `29.6→31.0→33.3`、0.5B `36.8→38.4→38.8`、1B `41.7→41.4→42.7`。BEIR 的 1B 在 bs=8 比 bs=4 低，说明“generally scales”不是逐任务或逐点单调规律。
- **LM size（Fig.5，p.9；Tables 13–14，p.21）**：CoIR 上较大 LM 的三组 mean 分别为 retriever-0.1B `45.8/45.9/48.4`、0.5B `53.5/52.7/56.1`、1B `55.5/55.6/58.6`（LM 0.1/0.5/1B），呈明显正向趋势；BEIR 对 retriever-0.5B 为 `41.6/41.2/38.8`，对 1B 为 `42.7/42.8/42.7`，没有一致增益。正文因此限定为 specialized code retrieval 更受益（p.9, §5）。
- **Mixed-domain（App. C.4，p.22；Tables 15–16）**：从 Wikipedia 与 code 各随机 160,000 batches 混合。CoIR mean 为 46.2/54.4/56.4（0.1/0.5/1B），BEIR 为 34.3/39.2/43.0；作者称可“大致维持”分域性能。该结论依赖与 Table 1/7 的非完全同预算比较，且没有单独混合比例 sweep。
- **Out-of-domain（App. C.5，p.22–23；Tables 17–18）**：Fineweb-edu 训练 320,000 batches；CoIR mean 38.0/48.6/51.5，BEIR 32.9/38.0/40.7（0.1/0.5/1B）。Revela-0.5B 的 CoIR 48.6 超过 E5-PT 46.4，支持 raw LM corpus 的有限跨域泛化。
- **LM after Revela（App. C.6，p.23；Table 19）**：原始 LLaMA-3.2-1B 与 co-trained LM 的七任务平均 Accuracy 为 52.5 与 52.2；逐任务变化为 ARC 28→29、COPA 77→74、OpenBookQA 25→25.5、PIQA 73→71、RTE 59.5→58.5、WiC 47.5→52、WinoGrande 57.5→55.5。平均接近并不表示每任务保持。
- **Efficiency（App. C.7，p.23–24）**：作者以序列长度 `L`、batch `B` 的复杂度推导 REPLUG pairwise LM 为 `O(B²×(2L)²)`，Revela joint cross-attention 为 `O(B×(2L)²)`，并将 backward 认为同阶。这是理论规模比较，文中未给独立 wall-clock、memory、throughput 或长序列 benchmark。

### G.3 统计、分母和图表独立性

- **中心量与分母**：所有 retrieval 主结果用 `nDCG@10 (%)`；Table 1/2/7/8、Fig.3–5 以 task mean 汇总，分别为 10、12、13 个任务；Table 11–18 同样给 task-level 表与 mean。LM 保真度 Table 19 用七任务平均 Accuracy（p.7–9、p.19–23）。
- **离散量／区间／检验**：正文和附录没有报告 seed、标准差、标准误、bootstrap、置信区间、Bayesian posterior、显著性检验或多重比较校正；图表均是点估计或柱高。该状态是版面事实，不推断其原因（p.7–9、p.19–23）。
- **不确定性是否可独立解释**：表注能说明指标、粗体和 supervised/API 标记，无法说明运行间波动；Fig.3 图例说明 opaque/transparent bars 与 compute 颜色，但没有误差表达（p.7）。
- **统计结论边界**：均值差异提供 benchmark-level 的决策证据；没有方差时，2.8、3.1、7.0、8.9 等差异的 run-level 稳定性无法由论文内部评估。任务异质性可从 Tables 7–10 直接观察，因此不能把均值胜出写成每个任务必胜。

### H.2 负面信息与自我设限的呈现

- **显式范围限制（`scope/data/generality`）**：主实验只覆盖 text/code retrieval；§6 把 iterative indexing、scaling、multimodality 写成 future directions，且承认图片等 modality 尚未实现（p.9–10, §6）。

- **附录迁移（`reproducibility`）**：checkpoint、chunk 例子、Contriever 实现、mixed/out-of-domain 和 LM 保真度移入 appendix；主文 §4.1/§5 通过明确 `App. B.*`/`App. C.*` 调用它们（p.6、p.8–10）。
- **统计设限（`metric/causality`）**：无独立 limitations 句说明 run variance、seed 或 significance；因此结果支持 benchmark mean 层级主张，不能支持稳定性或因果效果主张（p.7–9、p.19–23）。

## I. 结论与闭环

### I.1 结论段动作

p.10 的 §7 依次执行：

1. **重述问题**：query-document curation 是 rapidly evolving/specific domains 中的 bottleneck（p.10, §7, “query-document curation is one key bottleneck”）。
2. **重述方法**：in-batch attention 让 token 在 NTP 中 attend 到 local context 与 batch 中其他 sequences（p.10, §7）。
3. **回收机制**：retriever relevance scores 权重 cross-sequence attention，把 NTP 转成 retrieval signal，raw text 可用且不需要 annotation/synthesis（p.10, §7）。
4. **回收结果／边界**：domain-specific、complex、general benchmark 有 gains，且随 retriever size 增大；batch size、LM size、mixed-data 分析支持 scalable alternative（p.10, §7）。
5. **影响包装**：以 “strong and scalable alternative” 与 “more general and efficient retriever learning” 收束，没有新数字，也没有新的失败条件（p.10, §7）。

- **高频实词**：`Revela`（约 72）、`retriever`（48）、`attention`（38）、`training`（37）、`retrieval`（30）、`performance`（29）、`learning`（28）、`batch`（28）、`models`（23）、`pairs`（23）、`documents`（21）、`self-supervised`（20）、`size`（20）、`LMs`（19）、`data`（18）、`language`（15）、`domains`（15）、`supervised`（15）、`similarity`（11）、`chunks`（10）。频率主要由方法名、机制词和 scaling 结果驱动，而非模板套话（p.1–10）。
- **高频二元组**：`in-batch attention`、`retriever learning`、`query-document pairs`、`language modeling`、`training data`、`batch size`、`self-supervised retriever`、`contrastive learning`、`code retrieval`。它们分别出现在方法定义、缺口、实验设置与结果解释中（p.1–10）。
- **高频三元组**：`self-supervised retriever learning`、`in-batch attention mechanism`、`next token prediction`、`via language modeling`。它们构成从问题到组件再到目标的术语链（p.1–10）。
- **主张动词**：`we introduce` 在摘要/引言/方法/结论多次出现；正文可见 `outperforms`、`surpasses`、`achieves`、`exhibits`、`demonstrates`、`highlights`、`suggest`。`we show/find/observe/propose` 不是主要固定句式；作者多用第三人称主语（“Revela exhibits/achieves”）。强主张动词集中于 p.7–9，方法段用 `enables/conditions/weighted` 等机制动词。
- **限定与对比**：`typically`、`often`、`generally`、`approximately`、`notably`、`despite`、`while`、`in contrast`、`however` 频繁用于把资源差异、跨域例外和 baseline 限定嵌在叙事中。强／弱比例无法在不定义词表的情况下可靠量化；可确认的是 Table 1 的数字主张比 §6 的 future-direction 主张更强（p.7–10）。
- **修辞结构**：重复最多的是 “Revela + performance/scaling/generalization” 主语结构；它将方法名、指标和外推能力绑定在一起。风险是 mean-level 结果容易被读成 universal capability，需回看 Tables 7–18 的逐任务值。

## L. 最终判断

1. **单一主线**：Revela 把 document-level retriever similarity 作为 transformer 的 cross-document in-batch attention 权重，使 NTP 在 raw-text chunks 上同时训练 retriever 与 LM；主线是“以语言建模的跨序列依赖替代 query-document pair supervision”（p.2、p.4–5、p.10）。
2. **正文保留的决策关键内容**：Eq.1–7 的可微机制、Fig.1/2 的数据流、CoIR Table 1、BRIGHT/BEIR Fig.3、§4.1 的核心数据与训练预算，以及 §5 的 Contriever/batch/LM-size 诊断。这些对象足以判断主均值效能与机制路径（p.4–9）。
3. **迁入附录的细节及其代价**：逐任务表、checkpoint/license、chunk 示例、REPLUG/Contriever 实现、V-normalization、mixed/out-of-domain、LM 保真度和复杂度比较都在 p.15–24。正文对均值决策自足；对 task heterogeneity、variant-dependent behavior、复现入口和 efficiency 细节不自足，读者必须跨页回查附录。
4. **最有效模式**：Fig.1 用一条明确梯度链把“similarity → attention → NTP → backprop”可视化；Fig.2 将 attention map 与已有 Transformer 部件对齐；Table 1/ Fig.3 以同一 nDCG@10 量尺同时放入弱监督、监督、API 和 compute context。机制图与决策表的顺序降低了概念跳跃成本（p.2、p.4、p.7）。
5. **最大叙事缺口**：论文把“higher mean”“scales”“more efficient”组合成较宽的 capability 叙事，但没有 run variance、显著性、实测 efficiency 或统一 V-normalization 的跨域控制；BEIR 的 Revela-3B 45.2 与 E5-PT 45.6 是近似而非严格胜出，BRIGHT/BEIR 逐任务存在例外（p.7–9、p.19–24）。这些是证据边界，不是对作者意图的推断。
6. **可迁移规则**：先用一张机制图固定梯度／数据流，再用一个主表固定分母、比较对象和资源条件；随后把逐任务、方差和实现 variant 放进可引用附录，并在正文明确其依赖关系。该规则由 Fig.1/2、Table 1、Tables 7–18 的结构共同支持。
7. **适用边界**：规则适用于“新训练信号 + 多 benchmark + 多 baseline”的 retrieval/LM 论文；当主张涉及稳定性、效率保证、因果机制或跨模态推广时，机制图与均值表不能替代 seed-level uncertainty、matched resource benchmark、component ablation 或目标模态实验（p.7–10、p.23–24）。
