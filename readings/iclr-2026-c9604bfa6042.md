## 5. 方法、自改进机制与理论

### 5.1 树搜索对象与三子策略

- archive `T_t` 是从固定 root `a_0` 生长出的 agent tree；动作集分为 modification `M_t` 与 evaluation `V_t`。一轮后从最终 tree 按 `Score_π` 选 `a_final`，目标是最终 agent utility 的期望。该设定把「生成 child」与「再评估现有 agent」作为不同动作。【PDF p. 3，§2；explicit：“At each iteration, the policy either selects”。】
- SICA/DGM 的固定顺序是 expand parent、create child、立即多任务 evaluation；HGM 的 selection policy 可在 expand 和单个 agent-task evaluation 间选择。该解耦是 HGM 相对两个 baseline 的结构变化。【PDF p. 3，§2；explicit：“HGM breaks this rigidity”。】
- HGM 以整条 clade 的 success/failure counts 估计 `CMP(a)`；expansion 在 clade posterior 上做 Thompson sampling，evaluation 在 agent-level posterior 上做 Thompson sampling，selection 以 `N_t^α ≥ |T_t|` 决定是否引入新 arm。最终以 `ε` percentile posterior 的 best-belief agent 返回。【PDF pp. 5–6，§3.2；explicit：“weighted average of agents’ empirical performance”；“decide to expand at time t”。】
- `HGM Async` 让完成的 CPU 立即开启新 iteration，并要求 selection 考虑正在运行的 expansion/evaluation。它声称以此使用可用计算资源；该运行时结构与 CMP estimator 共同出现在最终 bundle 中。【PDF p. 6，§3.2；explicit：“utilizes all possible computational power”。】

**段落动作链。** `setup_notation → state_problem → define_component → contrast_alternative → setup_notation → derive → define_component → connect_to_prediction → instantiate_algorithm → explain_mechanism → connect_to_experiment`。§2 先把 agent development 规定成 compound policy；§3.1 将 long-run quantity 定为 GMP/CMP；§3.2 把该 quantity 变成 clade counts、sampling、scheduling 与 async 执行。【PDF pp. 3–6，§2–§3.2；interpretation，锚点：“three sub-policies”。】

### 5.2 理论链与证明范围

| 项目 | 内容、假设与作用 | 证明／经验对应 |
|---|---|---|
| GMP | `GMP_π(T,a)` 是在选择 expand `a` 后最终 selected agent utility 的期望；作者将其解释为 self-improvement policy 的 long-run Q-value。 | p. 4 只有定义与解释；没有单独经验检验。`role=explanation`。【PDF p. 4，§3.1；“directly corresponds to the Q-value”。】 |
| CMP | `CMP_π(T,a)` 将 final tree 限为以 `a` 为 root 的 clade；在 `Sel=U` 时写成 clade 内 utility 的 maximum。 | 它是 Theorem 1 的桥接对象，并在 §3.2 以 counts 近似。`role=core_chain`。【PDF p. 5，§3.1；“localized variant of GMP”。】 |
| Assumption 1 | utility 只取终局 agent；agent-task trials 可重复且独立于先前事件／时间；proof 不耗 budget；每次 modification 恰耗一单位 budget。 | 该框是 Theorem 1 的必要前提；它比 original GM 的 time-aware setting 窄。【PDF p. 4，Assumption 1；“only the final agent”；PDF p. 15，Appendix A；“budget is finite and known”。】 |

### 5.3 算法与公式审计

- Algorithm 1 位于 Appendix B — 输入为 `a0`、widening parameter `α`、percentile `ε`；循环在 budget 内选择 Expand 或 Evaluate，更新当前节点及其 ancestors 的 clade counts，输出 best-belief agent。正文只在 p. 6 用一句话把读者引到 Algorithm 1。【PDF p. 18，Appendix B；explicit “update … for a⋆ and ancestors”；PDF p. 6，§3.2；“See Algorithm 1 in Appendix B”。】
- HGM Async 的起始时先并行扩展 root 五次，以缓和 early-finished expansion 的选择偏差。作者还报告 easy tasks 较早结束会使低 evaluation count 的 agent 被更常抽到；超过 50 evaluations 后「barely observed」。这是一个实现层 self-limitation，未附变化前后的对照表。【PDF p. 18，Appendix B；explicit：“initialize by expanding the initial agent 5 times”；“After having more than 50 evaluations”。】
- Appendix D 定义 correlation target — empirical CMP 取 `C(a)\{a}` 中最大 empirical mean；HGM prediction 排除 target root 与包含经验最大值的 direct-child subtree，以避免 target leakage。DGM/SICA 的 predictor 是 agent benchmark performance。【PDF p. 20，Appendix D；explicit “exclude the root”；“avoid target leakage”。】

## 12. 最终判断

**单一主线。** 论文将 self-improving coding-agent development 建成 tree search，认为 immediate benchmark score 不能代表一条 lineage 的未来 productive potential；CMP 用 descendants 的 aggregate outcome 表示这项潜力，true CMP 在一个强假设集下等同 specialized Gödel POMDP 的 Q-value，HGM 再以 clade-count estimator 与 Thompson-sampling policies 近似该选择原则。【PDF pp. 3–6，§2–§3；PDF pp. 15–17，Appendix A；explicit：“CMPπ is an actual state-action value”。】

**最有效的写法／图表模式。** `assumption → named theoretical bridge → concrete policy decomposition → correlation diagnostic → performance/cost table → transfer table` 的编排使 reader 可以先区分「oracle guarantee」与「empirical HGM」。Table 1 将 MPM 的诊断放在 Table 2 之前，Table 3 再引入 filtered setting 处理 overfit 解释；这三步都服务同一因果主线。【PDF pp. 4–9，§3–§4；interpretation，锚点：“fidelity … capability … effectiveness”。】

**最大缺口。** HGM 的实际 approximation quality 没有 formal error bound，且 CMP aggregation、scheduler、best-belief selection 与 async 没有 component ablation。证据支持 bundle 有更高 point accuracy、较低 reported allocated CPU-hours 与 stronger CMP correlation；证据不能分别识别每个组件的因果贡献。【PDF pp. 5–8，§3.2–§4.2；PDF p. 21，Appendix E；layout_observation。】

**可迁移规则。** 当一篇论文把理论 oracle 转成 empirical estimator 时，正文应紧邻 theorem 标出 oracle assumptions、estimator target、leakage control 和可检验的 approximation diagnostic；随后用主结果与组件消融分别检验 capability 与 mechanism。【PDF pp. 5–7，§3.1–§4.1；PDF p. 20，Appendix D；interpretation，锚点：“avoid target leakage”。】

**规则边界。** 若研究目标只是提出一个理论 equivalence，或组件无法独立运行，完整 component ablation 不适用；此时需要把无法识别的机制归因显式保留为开放问题。对于 HGM，三子策略可分离定义，因而该边界不替代对 CMP 与 async 的分离评估。【PDF p. 6，§3.2；PDF p. 21，Appendix E；interpretation，锚点：“three subpolicies”。】
