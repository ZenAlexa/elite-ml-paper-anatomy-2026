## E. 方法与理论

### E.1 形式对象和端到端目标

Background 将 GSLM 拆成 speech tokenizer、decoder-only transformer 和 vocoder 三部分（p.3）。本文采用 501-entry HuBERT codebook、25 Hz speech tokens；text 使用 Llama 2 SentencePiece BPE。基础序列模型目标是对 speech corpus 的 next-token likelihood，式（1）写为 `L(D; θ) = Σ log pθ(si | s<i)`（p.3）。Interleaved data 将文本 token 替换进与 speech span 对应的序列，并用 `<t>`、`<s>` modality markers；A.1.1 说明随机 span selection 和 dynamic sampling。

LST 的正式变换从 speech embeddings `X=[x0,…,xT]`、局部帧索引集合 `Pi` 和 patch embeddings `Z` 开始。`PatchEnc(XPi)` 将一个局部 span 汇聚为 `zi`；Global Transformer 在 text token 与 speech patch 上进行 block-causal autoregressive modeling；Patch Decoder 用 cross-attention 与局部 self-attention 预测动态长度的 speech tokens。训练仍使用 token-level likelihood，局部 encoder/decoder 形成 token → latent patch → token 信息瓶颈。

### E.2 组件、问题、机制

| 组件 | 解决的前文问题 | 机制与证据 |
|---|---|---|
| Patch Encoder | speech token 序列过密，global attention 成本高。 | sliding-window self-attention 与 cross-attention 汇聚局部 speech span；p.4，`Patch Encoder`。 |
| Global Speech Transformer | text 与 speech 需要共享序列建模粒度。 | 联合建模 text token 和 latent speech patch；p.4，`Latent Speech-Text Transformers`。 |
| Patch Decoder | 压缩后仍需逐 token 还原语音。 | lightweight Transformer，cross-attend 已生成 patch/text，并在过去 512 token 上局部自注意；p.4，`Patch Decoder`。 |
| Static Patching | 无 alignment 时需要固定压缩率。 | 每 `p` 个 HuBERT token 组成一个 non-overlapping patch；p.4，`Static Patching`。 |
| Alignment Patching | 静态边界与词义边界可能错位。 | Wav2Vec2+CTC 给出词/BPE span，silence 单独成 patch；p.5，`Alignment Patching`。 |
| Curriculum Patching | alignment 提供语义监督但推理依赖辅助模型。 | `P(u)` 从 alignment 概率 1 线性降到 0，最终使用 static；p.5，`Curriculum Patching`。 |

动作转移序列为：`setup_notation → state_problem → define_component → explain_mechanism → give_intuition → instantiate_algorithm → connect_to_prediction → connect_to_experiment`。其中 `connect_to_prediction` 是作者关于 information density、跨模态 transfer 和 compute 的解释；文中没有把它写成定理或可识别的独立因果检验。

## F. 实验设计

### F.1 研究问题与数据

作者没有编号列出预注册假设。由 Introduction 与 Section 5 可还原三个研究问题：

1. 在相同 iteration/sequence-unit 预算或相同 speech/text token 预算下，patching 是否提高 speech 与 text completion？（p.7，`Performance under Controlled Budgets`，`interpretation`）
2. alignment、silence handling 与 curriculum 是否解释不同的 patching 效果？（p.8–10，`Ablation on Patching Strategies`，`explicit`）
3. 该收益是否随模型规模保留，并能迁移到 ASR/TTS？（p.7–8，`Scaling Behavior` 与 `Downstream Transfer`，`explicit`）

训练文本来自 Llama 2 pre-training collection 的 web/academic 子集，共 1.8T tokens，使用 32K SentencePiece BPE（p.5）。speech 数据为带 transcript 的 HuBERT tokens，主文给出 LibriLight 60k、People’s Speech 30k、Multilingual LibriSpeech 50k、Spotify 60k 小时；Table 1 的精确表述为 44,174、14,699、50,601、55,309 小时，对应 3.7B、1.2B、4.2B、4.6B HuBERT tokens（p.5–6）。约 33% training data 为 speech，67% 为 text；A.6 的 token ratio 实验把 1/2 speech/text 作为最好折中。

### F.2 任务、模型与预算

- **评测任务**：HellaSwag 为 1-in-4 multiple choice，StoryCloze 与 TopicStoryCloze 为 1-in-2 multiple choice；关注 commonsense、narrative coherence、topic consistency（Table 2，p.6）。评测 S→S 和 T→T；speech 输入用 Kokoro TTS 生成，HS 的 prompt/response 独立生成后拼接，SC/TSC 使用重合成版本（p.6）。
- **模型**：LST Static（4-token patch）、Aligned、Mixed、Curriculum；Base SpeechLLM 直接处理 speech token，BPE SpeechLLM 用 1k speech-BPE。5k/10k BPE 配置未见收益，故主文采用 1k（p.6 脚注）。
- **控制变量**：compute-controlled 固定 training iterations 和 per-step sequence budget，令 baseline token 数与 LST patch 数可比；data-controlled 固定 speech/text token 数（p.7）。
- **规模实验**：420M–1.8B 的 compute-optimal scaling 使用 text 为 20× model size、speech 为一半并保持 2/1 text/speech；7B 使用 70B processed tokens，低于约 140B 的 scaling-law optimum（p.7–8）。
- **下游迁移**：LibriSpeech clean 上 ASR fine-tune 1k–4k iterations，batch size 4、sequence length 4096；TTS 在 20k steps 评估（p.8）。
- **指标**：故事任务为 accuracy；ASR 为 WER；TTS 为 Whisper transcription 的 CER；表示诊断为 within/between-word similarity 与 t-SNE silhouette score（p.8–9，A.9）。
- **重复与实现**：A.5 对任务重复 3 runs 并报告 Ave/Std；A.3 给出 AdamW、学习率、warmup、32 H100、bfloat16、FSDP 和约 17 小时训练（p.15–16）。具体 random seed、每个 benchmark 的样本数、数据去重/泄漏检查、早停规则和预先失败判据均未报告。

### F.3 设计与论证顺序

Section 5 先给 controlled budgets，再给 scaling，最后给 ASR/TTS、表示可视化和 patching ablation；这与引言的「效率/性能 → scaling → 统一 patching」顺序基本对应。主要对照是同预算的 baseline，而 Table 6 的 static 对齐行采用「approximately matched patch sizes」，仍有不同平均 patch length（4、5.8、6、9、9.4），因此机制比较不能完全归因于 boundary semantics。A.5 的三次运行和 A.11 的 aligner 扰动为稳健性补充，未进入正文决策表。

## L. 最终判断

1. **单一主线**：speech token 的高时间密度造成跨模态序列建模粒度不平衡；LST 用局部 latent speech patch 把 speech 压缩到更接近 text 的 autoregressive unit，再由 decoder 做 token-level reconstruction，因此同一 global-transformer 预算可覆盖更多语义内容。这个机制由 p.2 的 gap、p.4–5 的组件和 p.7–8 的 controlled/scaling 结果连续支撑。
2. **正文保留的决策关键内容**：同预算主表（Tables 3–4）、scale 曲线（Figure 4）、ASR/TTS 表（Table 5）、patching 主消融（Table 6）与核心架构图。它们直接回答性能、效率、scale 和迁移四个决策问题。
3. **移入附录的细节及影响**：optimizer/hardware、完整架构、三次运行方差、speech ratio、BPE alignment、TTS 数据质量、低层 benchmark、token accounting、aligner noise 被移到 A.1–A.11。方法可读性基本自足；真实计算收益、稳定性和部署边界仍需附录，且 wall-clock 和样本分母仍缺失。
4. **最有效的模式**：Figure 2 的流程图把 token→patch→token 变换具象化；Tables 3–4 使用相同的 S→S/T→T 列结构并分离 compute/data budget；Figure 4 把跨规模趋势与固定-token 7B 结果并列，形成机制到规模的短证据链。
5. **最明显的规避或未闭合处**：效率主要以 token/context/generation units 与推导 FLOPs 表达，未给 wall-clock；Table 6 的「approximately matched」仍混合 patch length 与 alignment；TTS `other` 的 CER 变差被「matches」概括；Section 7 的「未做 downstream adaptation」与 p.8 的 ASR/TTS fine-tuning 存在文本范围张力。上述判断均来自可见表格和章节，不推断作者动机。
6. **可迁移规则**：当压缩方法同时声称提升性能、效率和跨模态 alignment 时，正文应把相同预算的主对照、压缩单元的可视化、机制替代消融和尺度外推按同一因果链排列，并把每个收益对应到独立证据对象。
7. **适用边界**：该规则适合 token/patch 粒度改变且存在多种计算预算的序列模型论文；若论文研究的是纯表示学习、无 autoregressive cost，或有真实系统 latency 作为唯一 estimand，则需把效率证据替换为相应部署指标。
