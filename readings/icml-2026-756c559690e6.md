## 5. 方法与理论：最小逻辑单元

### 形式化对象与因果链

1. **`setup_notation`**：当前图像状态为 `I_t`，perceiver 在视觉场景、aesthetic attributes、user intent 和 memory 上生成一组 `K` 个 diverse、atomic editing actions；MCTS tree 的节点代表 image state。〔p. 4，§3，explicit，`“visual input I_t”`、`“{a^k_t}`”`〕
2. **`state_problem`**：系统目标是把 vague/high-level intent 变成连续、语义明确的 edits，并在每一轮通过 evaluator 决定是否接受新的 `I_{t+1}`。〔pp. 4–5，§3，explicit，`“process continues until the editing objective is met”`〕
3. **`define_component`**：Perceiver 以 LLaVA 或 Qwen3-VL 作为 VLM，用 structured context-aware multimodal prompt 同时看当前场景和 aesthetic attributes。〔p. 4，§3，explicit，`“aesthetic-driven instruction generator”`〕
4. **`explain_mechanism`**：该 prompt 支持 autonomous/user-guided 两种模式，推断 scene type，保持人物主体并允许背景更激进的变化，同时用 editing history 形成 static strategy memory。〔p. 4，§3，explicit，`“static strategy memory”`〕
5. **`define_component`**：Planner 使用 MCTS 选择 candidate actions，四阶段为 selection、expansion、simulation、backpropagation。〔p. 4，§3，explicit，`“four phases”`〕
6. **`instantiate_algorithm`**：Selection 使用 UCT 在树中平衡 exploration/exploitation；leaf expansion 由 perceiver 增加 child nodes；simulation 在 reduced-resolution fast-approximation environment 中 rollout；backpropagation 更新 visit count 和 average reward。〔pp. 4–5，§3，explicit，`“balances exploration and exploitation”`〕
7. **`connect_to_prediction`**：低分辨率 simulation 被声称保留 essential visual/semantic information，并由 Appendix A 的 ranking retention/correlation 检查 sim-to-real gap。〔p. 5，§3；p. 12，Appendix A，explicit，`“does not introduce a significant sim-to-real gap”`〕
8. **`define_component → instantiate_algorithm`**：Executor 不固定单一编辑器，而在 OpenCV/PIL 的 crop、color adjustment 等 basic tools 和 FLUX.1 Kontext、Step1X-Edit 等 generative tools 之间动态选择；实际执行 top-K actions。〔p. 5，§3，explicit，`“pool of heterogeneous executors”`〕
9. **`define_component → explain_mechanism`**：Evaluator 聚合 NIQE、BRISQUE、CLIP-based aesthetic/instruction-following 和 customizable perceptual models；若 candidate score 高于 `I_{t-1}`，保留最高分结果，否则 rollback。〔p. 5，§3，explicit，`“Otherwise, the system reverts to I_{t-1}”`〕
10. **`summarize`**：闭环按 perceive–plan–execute–evaluate 反复运行，终止于 maximum steps 或无进一步变化；Figure 2 将这条链视觉化。〔pp. 4–5，§3，explicit，`“perceive–plan–execute–evaluate cycle”`〕

方法动作转移序列为：`setup_notation → state_problem → define_component → explain_mechanism → instantiate_algorithm → connect_to_prediction → define_component → explain_mechanism → summarize`。这条叙事先建立系统状态和四组件，再以 MCTS 的四阶段说明探索机制，随后把 top-K/full-resolution executor 与 evaluator/rollback 接上，形成可运行的闭环。

### 算法、公式和理论结果

- **算法数量**：正文没有算法框；Appendix C 的 p19 只有 `Algorithm 1 MCTS Planning for PhotoAgent`。输入为 current state、Perceiver、Executor、Evaluator、rollout depth `d`，输出 root 上访问次数最多的 `a_best`。循环包含 UCT selection、leaf expansion、depth-`d` random-action simulation、evaluator reward `G` 和沿路径的 backpropagation。〔p. 19，Appendix C/D，layout_observation，`“Algorithm 1”`、`“return a_best = arg max”`〕

### 关键 limitations 条目

- **输入质量边界**：dark/low-quality images 会同时伤害内容理解和 adjustment execution。〔p. 21，Appendix G，explicit，`“struggles both to interpret the content and to apply effective adjustments”`〕
- **过度编辑或拒绝编辑**：高质量输入可能得到低价值变化，或者系统拒绝编辑。〔p. 21，Appendix G，explicit，`“add little value … refuse to make edits”`〕
- **用户期待错配**：技术上合理的修改仍可能与 user expectation 不符。〔p. 21，Appendix G，explicit，`“cannot match user expectations”`〕
- **计算代价**：默认配置约 470 秒，MCTS planner 与 nested executor/evaluator 占主要时间。〔p. 20，Table 5，explicit，`“Planner (MCTS) ∼250”`〕
- **经验协议不完整**：seed、split、硬件、训练预算和 participant protocol 未报告。〔pp. 6、12–20，layout_observation，未见这些字段〕
- **选择—测量耦合**：系统用 evaluator 选择下一状态，同时把 UGC Score 作为最终表格 metric；论文未提供 hold-out evaluator 或独立 human metric。此处是由 p5 的选择规则与 p6–7 的指标定义得出的测量边界。〔pp. 5–7，interpretation，`“highest candidate score”` / `“UGC Score”`〕
- **Appendix H 缺失**：memory/history prompt 的唯一指针落到不存在的 Appendix H，影响该组件的可复现性。〔p. 4、pp. 12–21，explicit/layout_observation，`“See Appendix H”` / `“G. Future Work”`〕
- **跨域能力仍属未来工作**：medical/scientific/artistic domains 只提出 deterministic editors、plugin interface、domain-specific reward/metric 的扩展方向。〔p. 21，Appendix G，explicit，`“extend the current system to other application domains”`〕

## 11. 最终判断

1. **单一主线。** PhotoAgent 把「用户需要手工分解和排序 vague aesthetic intent」重构为「Perceiver 生成语义原子动作 → MCTS 在低分辨率环境中探索多步轨迹 → top-K 由异质 executor 在真实分辨率执行 → evaluator 以 UGC-aware reward 选择或回滚 → memory/replanning 继续下一轮」。核心增量在闭环规划和评价接口的协同，底层编辑器本身不是本文创新焦点。〔pp. 1–5、9，interpretation，`“closed-loop framework”`；`“coordinated interaction of multiple modules”`〕
2. **正文保留的决策关键内容。** 正文保留四组件定义、MCTS 四阶段、top-K/full-resolution execution、score comparison/rollback、UGC-Edit 与 benchmark、baseline/metric protocol、Table 1/2、Fig. 4–6 和明确的 termination condition。读者可以判断方法如何选择动作以及在有限 baseline 上的主要结果。〔pp. 4–8，explicit，`“Otherwise, the system reverts”`；`“42.0%”`〕
3. **附录迁移及代价。** Appendix A/B/F 把 sim-to-real、reward generalization、runtime/预算 trade-off 从正文移开，C/D/E/G 补 Algorithm 1、权重、数据 provenance、额外案例和 failures。迁移保持了主线可读性，但隐藏了默认 470s 代价、fairness protocol 不足、Appendix H 缺失和 failure cases；正文对这些边界并不自足。〔pp. 9、12、19–21，layout_observation，`“Appendix”` / `“Total ∼470”`〕
4. **最有效的写作/图表模式。** Figure 1 用 people-loop 对照建立需求，Figure 2 把四组件和 nested lightweight loop 画成一张 data-flow 图，Figure 3 说明 UGC dataset/reward training，Table 1/2 再把 qualitative mechanism 连接到 multi-metric 与 human preference。这个顺序让读者先看系统为何需要 planning，再看 reward/data 如何支撑它。〔pp. 2、4、6–8，interpretation，`“Detailed loop”` / `“Pipeline”`〕
5. **最大叙事缺口。** broad “state-of-the-art”“consistently improves” 与有限 baseline、缺少 uncertainty、UGC/ImageReward 非最高、文字性 ablation 和 evaluator-selection coupling 之间存在识别缺口；另有 p4 的 Appendix H 交叉引用错误。〔pp. 1、4、7–8、12–21，interpretation/layout_observation，`“state-of-the-art”` / `“See Appendix H”`〕
6. **可迁移规则。** 当系统的能力来自“规划、执行、评价”闭环时，正文应先用一个单图固定状态、候选动作、搜索、真实执行和接受/回滚的可观测接口。随后让每个主张绑定到一个独立 metric 或人类判断，最后用消融拆开 planner、evaluator 和 budget。〔pp. 4–8，interpretation，`“perceive–plan–execute–evaluate”`〕
7. **规则边界。** 该规则只适用于 action space、evaluator 和 execution backend 可被明确记录且输出选择不会复用同一指标造成测量耦合的任务；若底层生成器、prompt、seed、hardware 或 human preference protocol 未公开，闭环图仍无法替代可复现性和独立评价。〔pp. 5–7、12–21，interpretation，`“highest candidate score”` / `“20 participants”`〕
