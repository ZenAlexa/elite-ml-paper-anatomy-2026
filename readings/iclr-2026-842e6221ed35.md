## 方法与理论

### 方法最小逻辑单元

| # | 动作 | 逻辑单元 | 解决的前文问题 | 证据 |
| ---: | --- | --- | --- | --- |
| 1 | `setup_notation` | 用 RL 术语组织 observation `O`、action space `A`、state 与 reward | 给复杂 agent–app 交互一个可追踪的状态转移框架 | p. 3，`agent receives ... observations O`、`action ... A`；explicit |
| 2 | `state_problem` | 定义 browser-based、isolated、low-resource、highly customizable environment | 固定 clone 无法操纵 variation 且难扩展 | p. 4，`browser-based, highly customizable, open-source, low resource`；explicit |
| 3 | `define_component` | 六个 Python app：OpenCalendar、OpenMessenger、OpenMaps、OpenToDo、OpenCodeEditor、OpenShop | 覆盖 calendar、messenger、map、todo、code、shopping 的常见数字任务 | p. 4，六个 app 列表；explicit |
| 4 | `explain_mechanism` | FastHTML 实现；YAML 同时暴露 appearance、data 和初始状态 `s0`，action 更新 `st` | 让研究者能读写 app logic、state 与 variation | p. 4，`YAML files fully represent the environment`；explicit |
| 5 | `instantiate_algorithm` | appearance/content 变量和预置配置生成 variations | 把可重复的变化因素变成可以批量实例化的环境版本 | p. 4，light、black-and-white、dark、Brush Script MT、German、misleading、adversarial；explicit |
| 6 | `connect_to_experiment` | 单一轻量 Python process，单 CPU、memory `<10 MB`，每次 run 从本地完整状态 reset | 解决大规模并行与可复现初始化 | p. 4–5，`single CPU`、`< 10MB`、`reset at initialization`；explicit |
| 7 | `setup_notation` | 通过 BrowserGym 接入 screenshot、AX Tree、prompt/history 与 human-like actions | 使模型观察和动作落到统一 API | p. 5，Figure 3 与 Section 3.2；explicit |
| 8 | `contrast_alternative` | 对 UI-TARS 等 native API 做 parser；按原论文 system prompt、temperature 与 modality 兼容性配置 | 减少接口迁移造成的不可比性，同时承认 agent observation 不同 | p. 5，`translate their native APIs`、`not equally compatible`；explicit |
| 9 | `state_problem` | 15 个简单任务，每个任务多个 goal prompt，每个 app 至少两个任务 | 在低步数条件下隔离 reliability fluctuation | p. 6，`fifteen tasks`、`each app has at least two tasks`；explicit |
| 10 | `contrast_alternative` | 拒绝 human-trajectory imitation 的路径约束和只查一个 state change 的漏洞 | 解释为什么 success 需要检查完整 app state | p. 6，`many valid action sequences` 与 side-task 例子；explicit |
| 11 | `derive` | 用 deterministic indicator `r = δ[s_t = s_target]` 只在所有 state conditions 满足时完成任务 | 把 reward 与 ground-truth state 绑定，减少 noisy reward/reward hacking | p. 6，reward equation；explicit |
| 12 | `connect_to_experiment` | state 以轻量 YAML/structured vector 表示，Python logic/reward 可扩展 | 让同一生态能支持替代 success notion 与后续诊断 | p. 6，`extend or redefine reward functions`；explicit |

方法动作转移序列为 `setup_notation → state_problem → define_component → explain_mechanism → instantiate_algorithm → connect_to_experiment → setup_notation → contrast_alternative → state_problem → contrast_alternative → derive → connect_to_experiment`。方法核心落在 environment variation、full-state reward 和低成本部署，论文没有提出新的 agent 训练模型。

## 最终判断

1. **单一主线。** 论文把 UI-agent reliability 从固定 app clone 内的 policy success 扩展为跨 app appearance/content variation 的 deployment reliability，再用 full-state reward、STD/MAD、failure behavior 和 screen-resolution case 将同一问题落成可测量实验。主线在 p. 6 的 `A_1` 定义、p. 7–9 的跨版本结果和 p. 10 的 deployment 回收中闭合。[证据：PDF p. 6–10；basis=interpretation]
2. **正文保留的决策关键内容。** 正文保留六 app/single-CPU simulator 的边界、15 simple tasks、10,000+ evaluations、seven agents、固定与跨版本 reliability 定义、Figures 4–6 的 performance/behavior 入口，以及 UI-TARS resolution interaction。读者无需先看附录即可理解「为什么测、怎么测、variation 改变了什么」。[证据：PDF p. 2、p. 4–10；basis=interpretation]
3. **移入附录的细节与自足性。** YAML listing、visual variation screenshots、所有 sample goals、完整 BrowserGym action set、MAD 公式、task/model breakdown、variation interaction、multi-step partial reward、popular choices 与 Tables 11–13 均移入附录。迁移没有破坏主结论的方向，但削弱了对分母、seed、任务异质性和 failure taxonomy 的独立复算能力。[证据：PDF p. 19–34 与正文附录调用；basis=interpretation]
4. **最有效的模式。** Figure 5 的 paired fixed/across comparison 是最有效的 quantitative pattern；Figure 6 的 two-case panel 把 abstract claim 连接到可见 variation；Table 7 则展示一个反向部署结果，避免「更高 resolution 总是更好」的单调叙事。[证据：PDF p. 8、p. 10、p. 28；basis=interpretation]
5. **最大缺口。** 论文证明了 curated simulator 中的跨 variation fluctuation，却没有用完整 factorial design、机制操纵或真实 app deployment 识别 contrast、language understanding、content distraction 与 parser/modality 差异的因果贡献；「first testbed」和 sim2real/training 影响也停留在范围性或 future-work 主张。[证据：PDF p. 5、p. 8–10、p. 17–18、p. 29；basis=interpretation]
6. **可迁移规则。** 当论文的核心对象是部署中的环境分布时，应把 variation 作为独立实验轴，报告 fixed-environment baseline 与跨版本聚合的同一估计量，并至少保留一个 behavior-level failure measure；这样可以把「平均分下降」拆成环境敏感性与可诊断动作模式。[证据：PDF p. 6–9、p. 22–25；basis=interpretation]
7. **适用边界。** 该规则适用于具有可重置状态、可定义 target state、variation 可控且 agent action 可记录的 simulator 或 benchmark。若环境没有 full-state oracle、任务是长时开放世界、human-in-the-loop 或 variation 与真实部署不可对应，STD/MAD 的跨版本差异只能作为 reliability signal，不能直接当作现实部署因果效应。[证据：PDF p. 4–6、p. 10、p. 17–18；basis=interpretation]
