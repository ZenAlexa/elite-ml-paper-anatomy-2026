## 7. 方法与理论

### 7.1 AgentFlow 的最小逻辑单元

1. **状态与输入**；给定 query `q`、toolset `K`，记忆初值 `M^1=q`；第 `t` 轮状态为 `(q,K,M^t)`。（p.4, §3.1；anchor: “Let M t denote the memory state before turn t”）
2. **Action Planner `P`**；唯一 trainable policy `πθ`，输出 sub-goal、selected tool 和 tool-use context，形成 action `a^t~πθ(a^t|q,K,M^t)`。（p.4, §3.1）
3. **Tool Executor `E`**；按 `a^t` 调用 `k∈K`，产生 execution observation `e^t~E(e^t|a^t,K)`。（p.4, §3.1）
4. **Execution Verifier `V`**；判断 execution result 是否有效、累计 memory 是否足以回答，产生 binary `v^t`；`v^t=1` 终止，否则进入 memory 更新。（p.4, §3.1）
5. **Evolving Memory `M`**；`M^{t+1}=f_mem(M^t,a^t,e^t,v^t)`，记录 action、结果、错误信号、时间和 turn index；作者将其称为 deterministic、structured record，借此限制上下文增长。（p.4–5, §3.1；anchor: “explicit and deterministic record of the reasoning process”）
6. **终止与生成**；达到 verifier STOP 或 predefined maximum turn budget 后，由 Solution Generator `G` 按 `(q,M^T)` 生成 `o`。（p.4, §3.1）
7. **轨迹**；`τ={(a^t,e^t,v^t)}_{t=1}^T`，并由 Eq. (2) 给出 planner、executor、verifier、generator 的联合生成过程。（p.5, §3.1）

这条链直接回答引言的两个问题；模块化把 planner 的 action 与工具事件分开，显式 memory 使 state 可追踪；planner 仍在真实工具与 verifier 返回所诱导的状态分布中更新。系统没有训练 executor、verifier 或 generator，因而因果可识别对象集中在 planner／Flow-GRPO 这一边界。（p.4–6, §3）

### 7.2 In-the-flow 优化与 Flow-GRPO

- **问题设定**；离线 SFT／preference fine-tuning 在 active loop 外优化，无法实时协同，且有 train–deployment state distribution shift；长链中 early errors 会级联。（p.5, §3.2；anchor: “optimizes the planner outside the active loop”）
- **In-the-flow rollout**；在当前 policy 下运行完整 AgentFlow，收集实际 states、actions、tool events，并用这些 inference-time states 更新 planner。（p.5, §3.2）
- **全轨迹 reward**；最终答案 `o` 相对 `q,y*` 由 GPT-4o LLM-as-judge 判定，`R̄∈{0,1}`，语义、数值和选项等价均在 Appendix E.3 定义；同一 `r` 广播给每个 turn。（p.5–6, §3.2；anchor: “every action within a rollout receives the same global reward signal”）
- **组采样**；对每个 `(q,y*)~D` 用 behavior policy `πθold` 采样 `G` 条 on-policy trajectories；第 `i` 条轨迹可能有可变 `T_i`，action `a_i^t` 再按 token `j` 展开。（p.6, §3.2）
- **Eq. (5) 目标**；对 group、trajectory、turn、action token 取平均，使用 PPO clipping 与固定 reference policy 的 KL penalty；这是实际 policy update 的核心。（p.6, Eq. (5)）
- **Eq. (6) ratio**；`ρ_{i,j}^t` 是新旧 planner 对同一 state 与 token prefix 的 token-level importance ratio。（p.6, Eq. (6)）
- **Eq. (7) advantage**；每条 trajectory 内各 turn 共用 `A_i^t`，按该 trajectory 的 binary reward 在 G 条样本中的 mean／std 做 group normalization。（p.6, Eq. (7)）

作者把「把多轮问题拆成一组单轮 update」作为算法洞见；Appendix B 进一步把 Eq. (5) 的 clipping 部分写成 state-visitation distribution 下的 local objective。这里的等价性依赖 i.i.d. trajectory、固定有限 `T` 和状态分布加权，实验却使用 verifier 提前停止与变量 `T`，因此理论支持应按设定范围理解。（p.17–18, Appendix B；见第 7.4 节）

### 7.4 理论结果、证明和算法

- **Definition B.1（p.17）**列出 planner policy、behavior policy、state、token action、trajectory、binary reward、constant-in-trajectory advantage、importance ratio 和 PPO clipping term。它是后续证明的符号接口，schema 的 theory inventory 以公式与 theorem item 记录。
- **Definition B.2（p.17）**给出 global objective、local objective 和 full Flow-GRPO objective，即 Eq. (8)–(10)；其作用是把工程目标翻译为可证明对象。（p.17, B.1）
- **Theorem B.1（p.17–18）**；在 trajectories i.i.d.、固定有限 `T` 等 standard sampling assumptions 下，最大化 global multi-turn objective 等价于在旧 policy 诱导的 state distribution 上最大化各 time step 的 expected token-level local objective。证明只展开 clipping part，再通过线性期望与 state-visitation 重写，p.17 开始、p.18 结束。（p.17–18, B.2；anchor: “by the linearity of expectation”）
- **Lemma B.2（p.18）**；用旧 policy advantage 写出 `J(θ)-J(θold)` 的 performance difference identity；它承接 equivalence 并为 trust-region bound 提供接口。（p.18, B.3）
- **Theorem B.3（p.18）**；给出 surrogate objective 减平均 KL 惩罚的 lower bound，并据此陈述 `J(θ^{t+1})≥J(θ^t)` 的 monotonic improvement。正文没有展开该 theorem 的证明细节，要求 policy 更新优化该下界。（p.18, B.3；anchor: “Monotonic Improvement Guarantee”）
- **理论角色**；B.2 属于核心目标的合法性保证，B.3 属于优化稳定性的保证；它们没有引入新的可测实验量，也没有在 Table 1–4 中以 theorem quantity 进行检验。Eq. (7) 的 binary group reward 若一组全成功或全失败会出现零标准差，但论文没有在 p.6 或 C.1 写出对应的 numerical convention；这是实现细节缺口而非已报告失败。（p.6, Eq. (7)；interpretation）
- **Algorithm 1（p.16）**；输入 `D, πθ, E, V, G, K, M`，外层迭代遍历 query–label pair；rollout 中按 planner→executor→verifier→memory 更新循环直到 termination，随后 generator 输出、把 Eq. (4) reward 写入每一轮，再以 Eq. (5) update planner，返回 `θ*`。关键不变量是每个 action 都进入 trajectory reward broadcast；伪代码没有给出迭代次数、optimizer、rollout 并行调度、复杂度或 zero-std 处理。（p.16, Appendix A；anchor: “Update the Action Planner policy πθ by maximizing the Flow-GRPO objective”）

## 9. 结果、图表与可视化清单

### 9.1 主要量化结果

1. **主表的 cross-domain accuracy**；AgentFlow with Flow-GRPO 在 search、agentic、math、science 的 domain average 分别为 57.3%、33.1%、51.5%、63.5%；相对未调优 AgentFlow 的提升为 +10.1、+15.9、+19.8、+7.0 个百分点。（p.7, Tables 1–2；anchor: `AGENT FLOW (w/ Flow-GRPO)`）
2. **对专用 baseline 的比较**；相对表中最佳 specialized comparator，search 比 AutoGen 高 14.9%、agentic 比 Search-R1 高 14.0%、math 比 ToRL 高 14.5%、science 比 TIR 高 4.1%。这些数字也是 abstract 的四个 domain gains。（p.7, Tables 1–2；p.1, Abstract）
3. **对 GPT-4o 的比较**；论文报告 7B AgentFlow 相对约 200B GPT-4o 的 domain gains 为 search +8.2、agentic +15.8、math +16.4、science +18.0 个百分点；主文将其解释为模块化与 planner adaptation 的收益。（p.7, Tables 1–2；p.22, D.1）
4. **planner training strategy**；Table 3 的六任务平均值为 frozen Qwen 38.5、frozen GPT-4o 44.3（+5.8）、offline SFT 19.5（−19.0）、Flow-GRPO 55.7（+17.2）。这直接支持「in-the-flow policy update 比静态 planner／offline imitation 更匹配 live loop」的主张，但只覆盖 planner training 这一组干预。（p.8, Table 3）
5. **backbone scaling**；Figure 6 中 3B 与 7B 的四任务结果均在 Flow-GRPO 后上升。7B 的 Bamboogle 58.4→69.6、2Wiki 60.0→77.2、GAIA 17.2→33.1、AIME24 16.7→40.0；3B 也在四项上上升。（p.9, Figure 6；p.23, Figure 12）

7. **tool selection**；在 2Wiki，Google Search call ratio 增加 42.0%；在 MedQA，Google Search 66.2→10.9%，Web Search 0→19.5%，Wikipedia Search 0→59.8%，同时图中 accuracy 提升 4.0 个百分点。作者把它解释为 planner 学到 task-appropriate tool selection。（p.9, Figure 8）
8. **training dynamics**；Figure 9a 画出 training reward 逐步上升，response length 先探索性增加再缩短并稳定；Figure 9b 中 Flow-GRPO validation reward 继续上升，ToRL 很快停滞并向下。图中没有置信带或数值表，证据属于趋势比较。（p.10, Figure 9）
9. **tool scaling**；Appendix D 将 Base Generator 与 Python Coder 升级为 GPT-4o-powered versions，报告 GAIA +1.0%、AMC23 +6.0%、HotpotQA +13.0%；Figure 10 的整体示意还标出 19.2%→25.2%（+6.21%）的比较。（p.22–23, D.1–D.2；Figure 10）

### 10.2 负面结果、失败轨迹和边界

- **SFT collapse**；这是最明确的负面量化结果，作者归因于 token-level imitation 与 trajectory-level success 不对齐，以及无法从动态 tool feedback 恢复。（p.8, §4.3；anchor: “catastrophic performance collapse”）
- **案例中的工具循环**；F.1、F.4、F.5 展示 untuned agent 的重复 query、变量命名错误或工具切换迟缓；它们支持「路径恢复」的叙事，但属于精选 qualitative cases，没有总体 failure count。（p.35–44, Appendix F）
- **case-study internal error**；F.6 的 tuned success code 输出 `323591675.56 years`，文字随后承认 proper-time formula 应取 inverse relationship，却仍把 answer 标为 81 years、verifier 标为 PASS。该页同时显示 untuned agent 把 astronaut age 当 travel time；因此 F.6 能说明两条轨迹的错误形式，却不足以作为 tuned physics computation 正确性的独立证据。（p.44–46, F.6；basis: explicit + interpretation）
- **错误或不相同的问题**；F.7 的 failure case 改成了关于电影 Pugachev 导演奖项的问题，和 success case 的 Olivera Despina mother-in-law query 不同；它只能说明一条错误轨迹脱离原 query，不能构成同题 before／after 对照。（p.46–47, F.7；basis: explicit）
- **tool metadata 边界**；Python Coder 被限定为 basic arithmetic，不能 import、访问文件或网络，也不适合复杂 algorithms；但 F.2、F.4、F.6 的案例要求 exhaustive search、变量修复或相对论计算。论文没有报告这些 metadata 限制在 benchmark 中的失败率。（p.30, E.2.2；p.36–46, F.2/F.4/F.6）
- **reward 与 verifier 的边界**；最终 reward 由 GPT-4o judge 做 answer equivalence，Execution Verifier 由提示模板做 STOP／CONTINUE；F.6 的 PASS 与错误代码表明二者并非独立的 correctness oracle。（p.26、34、45, E.1.3/E.3/F.6）
- **训练／评测 horizon 不同**；训练 rollout 上限为 3 turns，评测为 10 turns；模型能否在较长 horizon 保持同一 policy behavior 由 Figure 7 观察，但没有训练预算与长 horizon 的联合控制实验。（p.19, C.1–C.2）
- **抽样与不确定性**；若干数据集随机抽样 100 题，AIME24 只有 30 题；三次 trial 的标准差虽在 C.2 被提到，主表没有逐项显示，且没有 hypothesis test 或 multiple-comparison procedure。（p.19–21, C.2/C.4；p.7–9, Tables 1–4）

## 12. 用词与修辞

## 14. 最终判断

1. **单一主线**；论文把「单体 tool-RL 在长时程、多工具、稀疏 outcome 下的 credit assignment 与适应问题」压缩成一个系统边界。AgentFlow 用 planner、executor、verifier、generator 和 deterministic evolving memory 显式化每一轮状态；Flow-GRPO 在真实 loop 采样轨迹，把一个可验证的最终答案 reward broadcast 到每一轮，再用 group-normalized token objective 更新唯一 trainable planner。Table 1–3 与 Figures 5–9 将这条 system → algorithm → accuracy／tool behavior 链接到十个 benchmark。（p.2–10）
2. **正文保留的决策关键内容**；四模块和 memory 的 state transition、Eq. (1)–(7) 的训练接口、Figure 2/4 的系统与优化图、Tables 1–3 的主结果和 planner ablation、Figures 6–9 的 scaling／tool／efficiency 证据、结论中的适用范围。它们足以让读者知道优化对象、reward 位置、比较对象和主要数值。（p.3–10）
3. **移入附录的细节及其影响**；Algorithm 1、Eq. (8)–(19) 的理论、所有训练／评测超参数、baseline 与 dataset 细节、四模块 prompts、memory regex、tool metadata、GPT-4o judge 和七个案例全部在 p.15–47。迁移使主文可扫读，但复现 judge／STOP 语义、工具限制和 proof assumptions 时必须回到附录，主文自足性因此为 partial。（p.15–47）
4. **最有效的写作、图、表或公式模式**；Figure 2 先画模块间 state transition，Figure 4 再画 rollout 到 policy update；Eq. (4) 用一行把 trajectory-level reward 与每轮 action 绑定；Table 3 紧随主结果展示 frozen／SFT／Flow-GRPO 的方向性分离。这种「接口图 → 目标函数 → matched strategy table」模式比单独堆 benchmark 数字更能承载机制主张。（p.3、p.5–8）
5. **最大叙事缺口**；理论以 fixed finite `T`、i.i.d. sampling 和 trust-region surrogate 推出 monotonic improvement，但训练实现使用 variable termination、binary group reward、clipping 与 KL；论文没有展示这些条件的逐项对应，也没有报告 zero-variance convention。实证侧没有 verifier／executor／generator 删除实验，且 F.6 的错误 physics code 被 PASS、F.7 的 failure case 换题，削弱了 planning reliability 的因果闭环。（p.6、p.8、p.18–19、p.45–47）
6. **可迁移规则**；对于在多轮工具系统中只训练一个协调模块的工作，应先把 state、action、tool event、memory update、termination 和最终 reward 写成一条可执行接口，再用同一系统边界下的 training-strategy 对照，分别验证总体成功率和过程机制；主张「可靠性」时必须给出独立的 pathwise 或 error-recovery 指标。（p.4–6、p.8–9）
7. **规则的适用边界**；该规则适用于最终结果可验证、工具事件可记录、其余模块能冻结的任务。若 reward 不可验证、verifier 与 judge 共享错误、horizon／工具在训练和评测间大幅变化，broadcast reward 只能给出条件性优化信号，不能自动保证 component causality、任意工具泛化或 deployment safety。（p.6、p.18–19、p.26、p.34、p.45）
