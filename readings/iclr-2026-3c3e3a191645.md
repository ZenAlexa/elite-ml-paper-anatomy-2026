## E. 方法与理论

### E.1 问题形式与最小机制链

- **输入与对象**：单帧 RGB、视频帧、相机 intrinsics；输出包括单帧／视频 3D detection 或 visual grounding 的 3D 量。3.1 将 relational task 与 spatially-grounded task 分开，本文重点放在需要坐标锚定和量化 3D 理解的后者。〔p. 3，§3.1，“Spatially-grounded tasks demand quantitative 3D understanding”〕
- **形式化投影**：正文以 fronto-parallel 物体的 `h_proj = fH/Z` 与等价类 `(f,H,Z) ∼ (λf,H,λZ) ∼ (f,λH,λZ)` 建立焦距与深度、尺寸与深度的不可辨识性。〔p. 1，§1，Eq. (1)–(2)〕
- **核心因果链**：未知 K → 每个像素的 ray field 不可确定 → 模型学习 training-camera shortcut → resize 或混合来源触发系统性偏移；对应修复是每 token 的 ray 条件化、与 K 一致的相机增强、以及 UniDepth 几何先验。〔p. 4–5，§3.3，“absence of camera intrinsics”〕〔p. 6–7，§4.2–4.4〕

### E.2 段落动作序列

`state_problem → contrast_alternative → define_component → explain_mechanism → give_intuition → connect_to_prediction → connect_to_experiment → summarize`

1. `state_problem`：指出 canonicalization 虽可用于 Metric3D，却会造成 MLLM 中大量 invalid visual tokens，并依赖大型数据集中少有的精确 intrinsics。〔p. 5，§4，“computationally prohibitive”〕
2. `define_component`：Geometry-Aware Visual Encoder（GAVE）接收 2D visual tokens，并向 LLM 提供外观与几何上下文。〔p. 5–6，§4.1，Figure 4〕
3. `define_component` → `explain_mechanism`：ray embedding 对每个 token 计算 `R_x=(u-c_x)/f_x`、`R_y=(v-c_y)/f_y`，同时加入全局 `f_x,f_y`，经 sinusoidal embedding 得 `E_cam`，再与 `F_vis` 做逐元素相加。〔p. 6，§4.2，“fused with the visual features Fvis via element-wise addition”〕
4. `define_component` → `connect_to_prediction`：缩放和 principal-point shift 同时更新图像与 intrinsics，要求模型将 scene content 与 camera geometry 分离。〔p. 6，§4.3，“both the image and its intrinsics are updated consistently”〕
5. `define_component` → `connect_to_experiment`：冻结 UniDepth v2 从每张训练图预测 dense 3D point cloud，形成 `E_geo` 并加到 `F_vis`；其图像内估计 intrinsics 的能力覆盖缺失 K 的互联网图像。〔p. 7，§4.4，“estimates intrinsics directly from images”〕

### E.3 方法组件与前文问题映射

| 前文问题 | 组件 | 作用与直接证据 |
|---|---|---|
| token 只有语义／外观，缺少视锥位置 | Dense Camera Ray Embedding | 以 K 派生每 token 的 line-of-sight，并与 `F_vis` 相加。〔p. 6，§4.2，“grounded in its geometric context”〕 |
| 数据集 sensor setup 窄、混合来源 K 分布冲突 | Camera-Aware Geometric Augmentation | 对 resize、shift、pad／crop 同步更新 K，制造跨相机训练变化。〔p. 6，§4.3，Figure 5〕 |
| 直接 3D annotation 稀缺，互联网 RGB 缺 intrinsics | Geometric Prior Distillation | 用 UniDepth v2 的 dense 3D point cloud 先验，并估计未知 intrinsics。〔p. 6–7，§4.4，Figure 6(c)〕 |
| canonicalization 对 MLLM 代价高 | 直接条件化 GAVE | 论文选择不重采样视觉输入，避免 invalid tokens 和对精确 K 的强依赖。〔p. 5，§4，“instead of transforming the visual data”〕 |

## L. 最终判断

1. **单一主线。** 论文把 RGB-only spatial MLLM 的跨相机失败归因于未知 intrinsics 造成的投影不可辨识：物体尺度／深度与 focal length 混淆，模型因而吸收 training-camera shortcut。Camera Ray Embedding 提供 token-level ray，Camera-Aware Augmentation 提供 K 一致的分布变化，UniDepth v2 提供可用于未知 K 的 3D prior；Table 1、Figure 6 和 Table 5 组成从诊断到修复的证据链。〔p. 1，§1〕〔p. 4–7，§3.2–5.1〕
2. **正文保留的决策关键内容。** 正文保留 Eq. (1)–(2)、Table 1／Figure 2 的失败、Figure 3 的相机分布、Figure 4–5 的架构和增强、Figure 6 的跨相机曲线、Tables 2–5 的 benchmark／消融及 Figure 7 的定性案例。读者可以沿“缺失 K→系统偏移→组件修复→曲线稳定”主线做决策。〔p. 1–9〕
3. **移入附录及自足性。** Eq. (3)–(7) 的正式投影推导、pinhole scope、训练冻结／硬件／数据和 Table 6 prompt 放在 Appendix A–B，LLM disclosure 在 C。迁移没有破坏机制直读，但缺少 seeds、样本／split／配比和统计不确定性使外部复现与稳健性判断不能仅靠正文完成。〔p. 13–15，Appendix A–C〕
4. **最有效的写作／图／表模式。** 最有效的是把一个可控图像变换写成 intrinsics 变换，再把同一 rescale factor 放到 Figure 6 横轴；Table 1 先显示基线崩溃，Table 5 再显示组件协同。这让几何方程、干预和性能曲线共享同一编码通道。〔p. 3，Table 1〕〔p. 5，§3.3〕〔p. 7，Figure 6〕〔p. 9，Table 5〕
5. **最大叙事缺口。** §5.2 的无条件 SOTA 总括超出了 Tables 3–4 的 aggregate 证据：Ours-4B 的 VSI Avg=46.8 低于 VG-LLM=47.3 和 Gemini=52.7，CV-Bench Avg=90.7 低于 VG-LLM=91.3；同时跨相机主证据主要是 synthetic resize，缺少误差或 seed 稳定性。〔p. 8，Tables 3–4〕〔p. 9，§5.2〕
6. **可迁移规则。** 对空间泛化主张，始终把输入变换、对应 K／ray 更新、任务分母和跨变换性能放在同一结果对象中；同时把 known-K 与 unknown-K 路径分开报告。这样能把“视觉变化”与“相机几何变化”区分开。〔p. 6，§4.3〕〔p. 7，Figure 6〕
